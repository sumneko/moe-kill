# Design

## Context

动机见 `proposal.md`。与做法相关的现状：

- 「用牌」的校验现在写在 `UseCard:settle()` 里：取定义 → 找牌（牌在使用者手上）→ 逐个调用钩子，钩子返回 `false` 即失败 → 取出牌 → 跑「使用」回调 → 触发 `'卡牌-结算后'`。
- 牌的钩子是**固定集合**，清单以 `server/core/loader/env-meta.lua` 为准、不留 `string` 兜底（写错名字在编辑期就报）。
- `Moe.CardDef` 的 `getHandlers(事件)` 返回该事件的回调快照（按声明顺序）—— 多钩子的场景天然存在（跨文件也可以追加）。

## Goals / Non-Goals

**Goals:**

- 钩子一次调用同时服务**校验**与**枚举**（"能选谁"），为将来的协议层"可用目标列表"打底。
- 失败口径 fail-closed：漏写钩子 ≠ 谁都能打。
- 让「杀」的合法目标写全（顺手修掉"能杀自己"）。

**Non-Goals:**

- 目标数量（至多 / 至少 N 个）、目标去重检查。
- 非角色目标（无懈可击那类"以锦囊为目标"）—— 遇到时再定。
- "技能改目标"（放宽 / 追加目标）：现在只有牌的声明能收窄，将来要放宽得另加介入点（时机）；本批不动。

## Decisions

### D1 钩子返回「合法目标列表」，而不是逐个回答合法性

`'获取目标'` 的钩子收到 `UseCard` 上下文，返回 `Player[]`。机制在 `settle()` 里取一次列表，然后：
- 校验：调用方给的 `targets` MUST 是它的**非空子集**；
- 将来协议层要"可用目标"时，同一份调用直接复用。

**为什么**：枚举比校验信息量大（前端/AI 要的是"能选谁"）；而且写筛选会逼你把条件写全（现有的「杀」就是漏了"排除自己"）。

**备选**：保留"逐个回答合法性"（信息量少，且前端只能反向试探）；再加一个专门的"可用目标"查询钩子（同一件事两处实现，容易不一致）。

### D2 fail-closed：拿不到列表 / 空列表 ⇒ 不能用

没声明钩子、钩子没返回列表、返回空列表 —— 一律以明确失败暴露，牌留在原处。

**为什么**（用户 2026-09-19 定）：漏写钩子要是被当成"不限制"，那就是个静默的规则漏洞（谁都能打）；宁可它当场用不了。附带好处：写牌的人一定会意识到"必须声明目标"。

**备选**：拿不到 = 不限制（宽容但对漏写不安全）；拿不到 = 报"没有合法目标"但这个错误只在 debug 级别记（同样隐蔽）。

### D3 多个钩子取交集

同一张牌声明多个 `'获取目标'` 时，逐个取列表再求交（每个声明只能收窄）。空集自然落到"不能用"。

**为什么**：与既有的"多个钩子都不能否决才通过"语义等价（交集 = 全部通过）；也让"跨文件补充限制"成为自然写法。

**备选**：只认第一个钩子（后声明的静默失效，难查）；并集（等于允许放宽，与"声明只能收窄"冲突）。

### D4 调用方给的目标必须非空

`game:play(user, card, {})` 以明确失败暴露。

**为什么**：子集检查对空集是**空洞通过**的，会让"没用目标也照样结算"成为漏洞；而本批的牌都至少需要一个目标。将来真出现"不需要目标"的牌（如只对自己生效的锦囊），再放开这条。

**备选**：允许空目标（漏洞）；要求"至少 1 个"作为可配置的数量（提前引入数量概念，本批明确不做）。

### D5 钩子名 `'获取目标'`，落在 `env-meta.lua` 的 `CardDef` 重载里

```lua
---@field on fun(self: CardDef, event: '获取目标', handler: fun(ctx: UseCard): Player[]): CardDef
```

**为什么**：钩子是固定集合，类型清单就放在唯一事实来源里；返回类型写明 `Player[]`，写包的人能拿到检查。

**命名说明**：这条走的是内容侧的中文句式（与原来的 `'目标合法'` 同风格），不套用时机的 `分类-动作` 形式（用户直接定的名字）。

## Risks / Trade-offs

- [枚举"所有角色再筛"在人多时比"检查给定目标"多算几次距离] → 座位数 4~10，可忽略；将来真成热点再优化（同一个钩子可以缓存）。
- [本批没有"目标数量"，所以「杀」的多目标版（如未来的"杀多个"）无法表达] → 等真有多目标牌时再定形状（列表外挂 min/max，或单独的钩子），本批不做。
- [技能将来要"放宽目标"（别人的牌能打更远之类）] → 交集模型下只能收窄；放宽需要新的介入点（时机），届时应通过"改合法列表的时机"实现，而不是让钩子返回并集 —— 已写进 Non-Goals。
- [探针与既有用例都要补钩子] → 是好事（原来那些牌按新口径本来就"用不了"）；一次性补齐，用例同时覆盖"没钩子 ⇒ 不能用"。

## Open Questions

- 「合法目标」将来要不要支持非角色目标（无懈可击指向锦囊、装备指向自己）？遇到时再定，可能需要在钩子里加"目标种类"。
- 要不要给内容侧一个"查询合法目标"的公开入口（如 `game:getLegalTargets(user, card)`）？本批只在内核内部与测试里用；等协议层真需要时再以它对外的形状定下来。
