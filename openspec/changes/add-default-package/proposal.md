# Proposal

## Why

每个调用方都得在清单里手写 `基础`（默认值、体力属性、牌堆机制都在里面），漏写就整局跑不起来 —— 它属于「没有它就没法开局」的那一类包。希望用**来源侧的一个标记**表达「这一包默认加载」，清单与依赖都不必再提它。

## What Changes

- **默认加载标记**：包目录名以 `@` 开头（如 `package/@基础/`）⇒ 该包**默认加载**：`load(清单)` 会把它自动排在清单**最前面**，清单里不用写它。
- **`@` 不进逻辑名**：引用（清单项、`rule.depends`、限定名 `标准.杀`、`rule:getPackageMeta`）一律写**不带 `@`** 的名字 —— `@` 只是来源侧目录上的标记。
- **仓库落地**：`package/基础/` 改名为 `package/@基础/`；`package/身份场/开局.lua` 里的 `rule.depends { '../基础' }` 保持原样（不带 `@`）。
- **约束**：`@` 只认**包目录名的开头**这一个位置；逻辑路径里其它位置出现以 `@` 开头的名字 SHALL 报错，避免出现「看起来在标记、其实没作用」的写法。
- **BREAKING**（对规则集编写者）：`package/基础/` 这个目录名不再存在（改名为 `@基础`）；但**引用方式不变** —— 清单与依赖本来就写 `基础`。
- 明确**不做**：不做「按名字关掉某个默认包」的入口（要排斥就声明互斥 `rule.depends { '!基础' }`）。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `package-vfs`：来源目录名以 `@` 开头时，逻辑路径第一层 SHALL 去掉这个 `@`；并规定 `@` 只允许出现在逻辑路径第一层。
- `rule-loading`：新增「默认加载的包」要求 —— 带标记的包自动排在清单最前、清单不必列举它、显式写进清单也仍然只执行一遍。

## Impact

- 代码：`server/rule/vfs.lua`（来源枚举时剥离 `@`，并记录哪些逻辑包是「默认加载」）、`server/rule/init.lua`（`load` 把默认包前置；`loadFile` 校验 `@` 位置）。
- 测试：新增用例（默认包自动加载与排序、引用不带 `@`、`@` 位置非法报错）；既有 `server/test/rule/{base,identity,setup}.lua` 的清单去掉 `基础`（正好验证默认加载）。
- 数据：`package/基础/` → `package/@基础/`（目录改名，文件内容不动）。
- 文档：`architecture.md` 第 9 节、`moe-kill-dev/SKILL.md` 目录表、`sanguosha-rules` 第 9.1 节、`code-style.md` 命名表的「包名」一行。
