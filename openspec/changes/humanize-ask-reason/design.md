# Design

## Context

`reason` 的格式语法是 2026-10-16 落的（`format-ask-reason`）：当时把值**内联**在文本里（`@{card:杀}`），够用，但有两处到顶了 —— ① 值只能是字符串，角色 / 牌这类带 id 的值表达不了；② 值的位置被服务端**拼死**，客户端的翻译表没法重排词序（英文的「3 cards」与中文词序不同）。

用户给的新形状：**参数表独立成 JSON、内联在 `reason` 里**，服务端另封装构建器。

渲染这一侧用户的口径是：**服务端只传「类型 + 值」，怎么画归客户端** —— 所以服务端文案里**不写**装饰（写 `打出一张 {card}`，不是 `打出一张【{card}】`）。

## Goals / Non-Goals

- 目标：`reason` 能带**结构化参数**；词序归翻译表；渲染完全由客户端按类型决定。
- 非目标：不改询问的**控制流**（谁被问、能否取消、要几张牌）；不给类型定死清单；本批只实现 `locale` 一个模板函数（`suit` 等以后再说）；不动判定的缘由（见下）。

## Decisions

### 1. 两段式：`${模板}@{"JSON"}`

`${…}` 是模板（函数名 + 内容），紧跟其后的 `@{…}` 是参数表 —— 它是**标准 JSON 对象**。没有参数时省略整段 `@…`，`reason` 就是一段普通文本。

### 2. 边界按括号配对，不靠「第一个 `@`」

解析器按**括号配对**扫：`${` 开始、找配对的 `}`（内容里可以嵌配对的花括号，如 `{num}`）；再往后看是不是紧跟 `@{`，是就同样按配对取到 `}` 为止。这样文本里出现裸 `@`、或 JSON 字符串值里出现 `@` 都不会切错。

### 3. 只渲染模板内部

只有 `${…}` 内容里的 `{名字}` / `{名字#类型}` 会被替换；模板之外（含花括号、`@`、JSON 片段）一律原样输出。翻译表查不到 ⇒ 用内容原文（与旧口径一致）。

### 4. 键即类型，渲染表按类型查

| 类型 | 当前渲染 |
| --- | --- |
| `card` | 黄（`#ffcc00`） |
| `skill` | **新增一档**，与牌名区分 |
| `player` | 蓝（`#7fd4ff`） |
| `num` | 无额外样式 |

键名同时是「从参数表里取哪个值」与「默认类型」；`{名字#类型}` 可显式指定类型。客户端认不出的类型 ⇒ 值照常显示、只是没有额外样式（不报错）。

### 5. 构建器放进内容包自己的工具 `util`

`reason` 是**内容侧**产出的文本，构建器也放内容侧：`package/@tools/util.lua` 已经建了内容侧全局 `util`（现有 `util.defer`）。`@tools` 目录带 `@` 前缀 ⇒ 它是**默认加载**的包（`Vfs:getDefaultPackages()` 收它），所以每个内容包直接可用、不必各自 `Depends`。本批往 `util` 上加一个方法：

- `util.locale(内容, 参数表?)`：有参数 ⇒ 返回 `${locale:内容}@{JSON}`；没参数（或参数表为空）⇒ 返回**裸文本**（省掉整个 `@…` 与模板外壳）。
- 参数表的 JSON 编码写在 `util.lua` 里（内容侧拿不到 `moe.json`）：支持 `string` / `number` / `boolean` / 数组 / 表，字符串要正确转义。

⚠️ **内核一行不改**：`reason` 本身就是字符串，格式归客户端解释。

⚠️ **不能混用 `%` 格式**：`reason` 里一旦有 `{…}` 占位，就不能再用 `'{}' % {}` 拼（`enableFormatString` 会把 `{num}` 当占位符吃掉）。需要拼的值一律走参数表。

### 6. 参数值只要求「可 JSON 序列化」

数字 / 字符串 / 布尔 / 表都行；**构建器不猜对象**（不认识 `Player` / `Card`）—— 要传角色或牌时由内容侧自己给 `player.id` 之类，**含义由类型约定**、客户端按类型去自己的状态里查名字。服务端 MUST NOT 解释值的含义。

### 7. 判定的缘由不在本次范围

`package/标准/武将/甄姬.lua` 在读 `judge.reason == '洛神'` —— **判定的缘由被当标识用**（与之前那批测试里的 `reason == '杀'` 同类）。改它的文案会直接破坏【洛神】，故本批不动，只记录待办。

## Risks / Trade-offs

- **文案没有测试兜着**：判据早已换成结构判据，改文案不会红 —— 写错了也不会红。缓解：真链路逐类看一眼（出牌阶段 / 濒死 / 装备触发 / 主公技）。
- **解析变复杂**：多了「括号配对 + 可选的 `@JSON`」两层。缓解：解析入口只有一个（客户端 `formatText`），并有真链路双保险。
- **JSON 编码自己写**：内容侧拿不到 `moe.json`，`util.lua` 里手写的那份要顾及转义（引号 / 反斜杠 / 换行）与嵌套表；范围只到「JSON 能表达的」那几个类型。

## Migration

无。`reason` 一直是展示文本：5 处已定的保持原样（纯文本形态照样合法），其余 26 处换文案；**旧的内联 `@{名字:值}` 语法退役**。
