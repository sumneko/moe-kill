# Design

## Context

`setup-backend-infra` 已经提供：luamake 构建出的 exe + 脚本树、`moe` 命名空间（工具集 / 类系统 / 语法糖）、单线程事件循环 + 协程 await、`--test` 无头测试入口与冒烟测试。

本变更的边界由用户明确：**只做外壳**（不含规则）、**只支持测试驱动**（不做 CLI / 协议入口）、**保持精简**。

本次要解决的核心问题只有一句：**"逻辑侧要输入" 与 "外部给输入" 之间的那个挂起点，长什么样。** 在规则（怎么玩）与协议（怎么连前端）都还没定的情况下，把这一个接口定死，后续两边各自填内容即可。

`openspec/specs/` 目前仍为空（`setup-backend-infra` 尚未归档），所以本变更只新增能力，不涉及既有能力的修改。

## Goals / Non-Goals

**Goals:**

- 定下会话容器与决策通道的接口形状，让后续"规则"与"协议"都能挂在同一套外壳上。
- 让外壳在没有任何协议、网络、客户端的情况下就能被完整验证。

**Non-Goals:**

- 任何游戏规则、流程判断、阶段推进、AI。
- JSON-RPC / 传输 / 网络 / 前端 / 重连。
- 命令行入口（本变更只支持测试驱动）。
- 多会话并发、多进程、持久化（接口不封死，但不实现）。

## Decisions

### D1 外壳只做容器，不做流程

外壳不判断回合阶段、不决定何时需要输入、不生成决策内容；它只知道"逻辑侧现在要一次输入"和"有人提交了结果"。

- 理由：规则口径尚未确定，把流程写进外壳等于提前锁死；外壳越薄，规则怎么改都不用动它。
- 备选与取舍：让外壳自己跑"准备→判定→摸牌→…"的主循环（把阶段写进外壳）—— 否决，规则未定且必然返工。

### D2 「驱动者」是一种调用形状，不是一层抽象

驱动侧只需要两个动作：**读当前待处理事项** 与 **提交结果**。本变更只实现"测试里的脚本化驱动者"，不引入 driver 目录、插件注册或中间件。

- 理由：接口越少越不容易错；将来协议层按同一形状实现即可，不需要额外的抽象层。
- 备选与取舍：定义 `Driver` 类并允许注册多个—— 否决，当前只有一个驱动者，抽象是空转成本。

### D3 决策通道复用协程 await，不用回调或状态机

逻辑侧请求输入时让出当前协程；提交时唤醒并回传提交值（支持多个值）。超时复用已有的定时器。

- 理由：`moe.await` + 事件循环已经就绪，挂起/恢复天然匹配"等玩家输入"这个语义；回调或显式状态机会让规则代码满屏分支。
- 备选与取舍：把"等待中"的状态暴露给逻辑侧自行轮询——否决，会把挂起语义泄漏到规则层。
- 代价与约定：逻辑处理器的入口必须是可被协程承载的异步函数（写进使用说明，不作为规格约束）。

### D4 事件先收集，不分发

逻辑侧发出的事件按序累积在会话内，提供只读快照给调用方；本变更不实现订阅、推送、过滤。

- 理由：协议层未定，过早定义分发形状会返工；而"无头也能断言表现序列"只需要收集。
- 备选与取舍：现在就做 `onEvent` 订阅回调——否决，订阅者的生命周期与线程边界都会顺带被提前定死。

### D5 单会话可用，门面按可扩展形状命名

门面提供 `createSession` / `destroySession` 这类动宾命名；内部先只维护"当前会话"，创建第二个会话时**明确报错**而不是静默覆盖。

- 理由：精简是目标，但"静默覆盖"会让后续排查极其痛苦；明确报错的成本只是一行判断。

### D6 外壳不接管事件循环

`server.start` / `server.stop` 只做初始化、清理与状态标记，**不启动也不停止事件循环**；事件循环仍由各自入口负责 —— 服务模式由 `main.lua` 常驻，测试模式由 `test.lua` 控制。

- 理由：让外壳的启停是同步的、可直接测试的，避免"测试里嵌套启动事件循环"这种死结；主循环归属保持单一。
- 备选与取舍：让 `server.start` 内部启动事件循环（"服务器"更名副其实）—— 否决，会在测试中与测试入口的循环冲突。

### D7 决策请求的内容由逻辑侧定义

外壳只约定请求带一个类型标识与一个可选负载表，其余语义（有哪些类型、负载字段是什么）由逻辑侧自定；提交值原样交回。

- 理由：规则未定，外壳不定义任何游戏语义。

## Risks / Trade-offs

- **[外壳过早抽象]** → 只固定两个动作（请求输入 / 提交）与三个动词（启动 / 停止 / 建会话），不引入插件、注册表、中间件；接口数量作为评审标准。
- **[外壳与引擎职责重叠]** → 评审口径：在外壳代码里应当找不到任何"牌、阶段、技能、胜负"的字样。
- **[挂起语义与测试入口的循环归属混淆]** → D6 明确主循环归入口所有；外壳自身同步。
- **[异步入口被误用为同步函数]** → 在 `moe-kill-dev` 技能的使用说明里写明"逻辑处理器入口按异步函数约定"；否则会表现为"会话卡住不动"。
- **[事件集合无限增长]** → 当前只用于测试与短对局；协议层接入时再定消费与上限策略（见 Open Questions）。

## Migration Plan

纯新增 `script/server/` 与 `test/server/`，外加 `main.lua` 服务模式的一处改动（启动外壳后常驻事件循环）。回滚即删除新增目录并还原该分支。

## Open Questions

- 事件读取的消费语义（只读快照 / 读后清空 / 带上限）—— 当前实现为只读快照，等协议层确定推送策略后再调整；不影响规格与任务拆分。
