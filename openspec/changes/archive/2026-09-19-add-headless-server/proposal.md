# Proposal

## Why

基础设施已经能构建、能启动、能无头跑测试，但进程里**还没有"服务器"这一层**：没有会话概念，没有把"需要玩家输入"表达成挂起点的地方，也没有给逻辑侧发事件的出口。当前 `main.lua` 的服务模式只是空转事件循环。

在做规则（怎么玩）和协议（怎么连前端）之前先把这层外壳定死，之后规则往里填、协议往外接都不返工。

## What Changes

- 新增 `headless-server` 能力：**单进程、无头、无任何协议**的服务器外壳。
  - **会话生命周期**：创建 → 就绪 → 运行 → 结束 / 中止 → 销毁，并提供状态查询；非法迁移以错误暴露。
  - **逻辑挂载点**：会话挂载一个"逻辑处理器"，外壳对其内容不做任何假设（不判断牌、不判断阶段、不驱动流程）。
  - **决策通道**：逻辑处理器发起"请求输入"后会话挂起；驱动侧提交输入后恢复并把提交值交回逻辑侧（支持多返回值）。
  - **决策超时与取消**：可配置超时；超时或被取消时，挂起方以错误形式得到通知，不静默卡住。
  - **事件收集**：逻辑处理器发出的事件按序落入会话的事件列表，可被读取；测试在没有任何协议层的情况下即可断言表现序列。
  - **服务模式接线**：`main.lua` 的服务模式改为启动外壳后常驻事件循环；测试模式继续由测试入口控制事件循环。
- 新增 `test/server/` 测试套件：用一个"假逻辑处理器"覆盖外壳的全部机制，**不需要任何游戏规则**。
- **Non-goals（本变更明确不做）**：JSON-RPC 协议、传输层、网络、前端、重连、游戏规则（卡牌 / 武将 / 阶段 / 结算 / AI）、持久化。

## Capabilities

### New Capabilities
- `headless-server`: 单进程无头服务器的外壳行为 —— 会话生命周期、逻辑挂载、决策挂起与恢复、决策超时与取消、事件收集、服务器启停。

### Modified Capabilities
（无。`openspec/specs/` 当前仍为空，本变更只新增能力。）

## Impact

- **新增**：`script/server/`（外壳）、`test/server/`（外壳测试）。
- **修改**：`main.lua` 的服务模式分支（改为启动外壳）。
- **依赖**：复用 `backend-runtime` 已提供的事件循环与协程 await（本变更不修改它们）。
- **为后续铺路**：`game-engine`（规则）挂在"逻辑处理器"上，`game-protocol`（JSON-RPC / 传输）实现同一个"驱动者"接口 —— 两者都不需要改外壳。
- **不影响**：前端（尚不存在）、规则（尚不存在）、网络。
