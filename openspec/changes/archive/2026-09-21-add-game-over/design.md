# Design

## D1 结束信号由内核出、判据由内容出

「这一局结束了」+「结果是什么」是**通用**的（任何玩法都有终局，装配侧 / 会话 / 协议都要消费它）⇒ 放内核；「什么条件算赢」是**身份场规则**⇒ 放 `package/身份场/胜负.lua`。内核不认识身份、不认识标签、也不认识存活之外的任何概念。

- 内核：`game:endGame(result)` / `game:getResult()` / `'游戏-结束'` 时机。
- 内容：订阅 `'玩家-死亡'`，读 `player:getTag('身份')` 与 `desk.alivePlayers` 判定，再调 `endGame`。

`endGame` **幂等**：已有结果就直接返回，后来的「结束」不会覆盖（多个判定点、或主公孙死时的连锁都不会打架）。

## D2 流程怎么停干净：`flowTask` + `Task:cancel()`

`runFlow()` 建出来的任务记进 `Game.flowTask`（private），`endGame` 调 `self.flowTask?:cancel()`。

这一下为什么能真的停住：`Task:cancel()` = `reject(CANCELED)` → `Delete(self)` → `__del` 把**还挂着的协程 `coroutine.close` 掉**。终局通常发生在「伤害 / 濒死结算内部」，此刻流程正挂在 `game:useCard(...):await()` 上（挂起态）⇒ 直接被关掉、不再往下跑，收尾（`<close>` 守卫）照常发生。

反面情形（2026-09-21 实测过的坑）：**从流程自己的协程里**取消它时，它此刻是「运行中」而不是「挂起」，`__del` 关不掉 ⇒ 必须保留 `Task:cancel()` 里那句「就地停住」（`if moe.task.getCurrentTask() == self then coroutine.yield() end`）。两条路都得在。

流程任务以「取消」收尾（`err` = `canceled`）**不代表失败** —— 这局是不是正常终局看 `game:getResult()`。装配侧要收尾就认 `task.err == 'canceled' and game:getResult() ~= nil`。

## D3 结束后不再起新的结算

`Effect:apply()` 开头查一次结果：已结束 ⇒ 建一个**已取消**的任务并返回（不触发「即将生效」、不结算、`err` = `canceled`、没有结果）—— 复用「取消」那套语义：不算失败，只是这次没发生。

不这么做就会出现「游戏已经结束了，主公以外的目标还在掉血」：多目标【杀】是逐目标 `apply()` 的，打死主公的那次之后，循环还会给下一个目标起 `CardEffect`。同一道检查顺带覆盖「已记账、还没起的濒死」（`flushDying` 起 `Dying` 也走 `apply()`）。

**不做**「把已发起、正在跑的结算全部取消」：那需要一张「正在结算的效果」清单，而记牌器是**只增的历史**（`game:getEffects()`），不是结算栈 —— 硬做等于凭历史猜「谁还在跑」。当前这次结算正常收尾，只是不再起新的。

## D4 结果的形状

```lua
---@class Game.Result
---@field side string # 胜方阵营：主公方 / 反贼 / 内奸
---@field reason string # 胜负依据（中文短句，给人看 / 前端可直接显示）
```

- `side` 用**官方术语**，**不**拆成「哪些玩家赢」—— 同一阵营的人未必都活着（反贼可能已经全灭，仍算反贼胜）。
- `reason` 是**给人看的**：日志、调试、前端提示直接用；**不做 i18n key** —— 真需要再做一层映射，别现在设计。

## D5 判据（官方口径，见 `sanguosha-rules` §2）

挂在 `'玩家-死亡'` 上，每次有人死就判一次（已有结果就直接返回）：

1. **主公阵亡** ⇒ 此刻场上只剩一个存活者、且那人是内奸 ⇒ **内奸胜**；否则 ⇒ **反贼胜**（含「反贼已全灭」与「内奸与反贼同归于尽」两种情形，官方都算反贼胜）。
2. **主公还活着**，且存活者里已经找不到反贼与内奸 ⇒ **主公方胜**。

主公固定坐 1 号位（项目既有简化假设，见 `sanguosha-rules` §1）⇒ 直接 `desk:getPlayer(1)`，不用翻标签。

## D6 与「奖惩」的先后

官方时序是「死亡 → 奖惩 → 胜负判定」。本批不做奖惩；将来加时写在**同一个时机**上、**注册在胜负判定之前**（注册顺序 = 执行顺序）⇒ 不需要动内核，也不需要在 `endGame` 里留钩子。

## D7 「再开一局」将来怎么做（本批不做，先把方向记下）

用户 2026-09-21 定：**重新建一个 `Game` 实例**，不是重置当前局。于是：

- `resetContent()` **不清** `result`（重装规则 ≠ 重开一局；牌面/血量也都不回滚）。
- 想来第二局就 `moe.game.create { desk = 新桌子, random = 新随机源, ... }`，旧实例连同它的流程任务、记牌器一起丢弃。
- 这条决定也意味着内核**不需要**「重置一局」这套入口。
