# Design

## Context

现状（见 `proposal.md` 的 Why）：内核**一个区名都不认识** —— `server/core/` 里搜不到 `'抽牌'` / `'弃牌'` / `'手牌'`。这不是随手写的，而是「**内核只发时机、落点归内容**」这条模式的一贯结果：`Draw` 只 `fire('摸牌')`、`Judge` 只发判定三个时机、`Damage` / `Heal` / `Dying` 只发时机，搬牌与扣血都写在 `@基础`。`'效果-收尾'` 也是这样，并且 `add-effect-temp-zone` 的 D3 明确写过「**内核不挪牌**」。

于是「有哪些基础区」与「结算完的牌回哪去」落在 `package/@基础` 的装配文件里。约束：

- 区是**局/玩家的属性**，不参与 `resetContent()`（重装规则不清空区），所以建区必须发生在「建局」「建玩家」这两个构造点上。
- 玩家**由装配侧创建**（`moe.player.create(game, …)` + `desk:sit`），不是内核在建局时按座位造 —— 所以玩家侧三个区只能建在 `Player:__init`。
- 时机表每次装载都会 `events:clear()`（`architecture.md` 第 10 节），**内核行为不能挂在自己的时机上**（会被清掉）；只能在代码路径里直接做。

## Goals / Non-Goals

**Goals:**

- 把「五个基础区的存在」与「结算完的牌默认进弃牌堆」这两件**没有变体**的事收进内核，让 `@基础` 只剩「可配置 / 有变体」的东西。
- 区名成为**包作者可见的契约**（内核保证存在、包不得重建），并把契约写进 `env-meta.lua` 与 `architecture.md`；契约的直接收益之一 = 内核能提供「从 `抽牌` 堆顶抽 N 张」的常用工具。
- 保持行为等价：用过的牌 / 判定牌 / 打出的牌仍在**各自那次结算结束时**进弃牌堆（那四处已由 `inherit-temp-zone` 核对过）。

**Non-Goals:**

- 摸牌本身（`'摸牌'` 时机与摸几张）、弃牌阶段、判定流程的时机 —— 都留在内容侧；本变更只把「从 `抽牌` 堆顶取 N 张并把牌放到某个区」这一步做成工具（见 D8）。
- 洗回策略与「两堆都空 ⇒ 平局」、牌表与造牌洗牌、起始手牌 —— 「策略 / 数据」也留在内容侧。
- `手牌` 可见性：内核建的区一律 `visible = true`，标暗仍由 `@基础` 做。
- 给「默认收尾」开口子（覆盖 / 关掉）—— 现在没有第二种口径，真需要时再加。
- 装备牌进装备区、延时锦囊进判定区的实现点 —— 本变更只保证**不挡路**。

## Decisions

### D1 换切分轴：「固定 / 可配置」取代「机制 / 内容」

旧口径问「这是不是通用引擎机制」，在弃牌堆上给不出答案：它不是通用机制（换个游戏就没这个概念），却也没有任何变体。新口径问「**包作者会不会改它**」：

- 固定 ⇒ 内核：五个基础区、结算完的牌进弃牌堆。
- 可配置 ⇒ 内容：可见性、牌表、数值、策略、以及一切「什么时候把哪些牌放到哪个区」的动作。

代价是内核从此认识**五个具体区名**（`architecture.md` 里「内核不预设任何区名」那句要改）。换来的是：装配目录里不再混着不能改的东西，也不会再出现「漏建区 ⇒ 收尾报错被时机系统隔离成一条日志 ⇒ 牌静静留在临时区」这种静默故障。

### D2 区名用契约字符串，不加 `game.deck` / `game.discard` 字段

用户 2026-09-24 选：照旧 `game:getZone('弃牌')` / `player:getZone('手牌')`（传参读取，本来就该用 `getZone`），只在 `env-meta.lua` 的类型注解里声明这五个名字保证存在。

- 备选一（已否决）：给两个公共区加字段 `game.deck` / `game.discard` —— 符合「无参读取用字段」的风格，但只有两个区有字段、玩家三区仍要按名取，不对称。
- 备选二（已否决）：建一个 `moe.zoneName = { 抽牌 = '抽牌', … }` 常量表 —— 门面里只放工厂（`kernel-facade` 口径），而且名字本身就是值，多一层间接没有收益。内核里就地写字符串字面量（共 5 处），契约靠文档收口。

### D3 默认收尾写在 `Effect:bindFinish`，`fire('效果-收尾')` **之后**，同步挪牌

```lua
local function finish()
    if self.tempZone then
        game:fire('效果-收尾', self)   -- 内容侧先挑（要留走的先搬）
        -- 剩下的牌进弃牌堆（默认收尾）
    end
end
```

- **顺序**：内容侧订阅 `'效果-收尾'` 的处理器在 `fire` 里跑完，内核再清剩下的 ⇒ 「默认固定」与「例外可写」同时成立，且不靠注册顺序。
- **同步挪**（直接 `Zone:move` / `Zone:put`）而不是 `game:moveCard`：这是这次结算的收尾，不是一次新结算；此刻已在任务的完成点上（`Task` 的 `onResolved` / `onRejected` 回调里），再起一个效果会让「谁等谁」变得难说。`MoveCard:settle()` 同样是直接 `Zone:move`。
- **不挂在时机上**：内核不能在 `'效果-收尾'` 上注册处理器（`events:clear()` 会把内核的长期订阅清掉）。所以写在 `bindFinish` 的代码路径里。
- 只在 `self.tempZone` 非空时做 —— 即只由**区的归属者**收尾（继承来的那块由归属者清），与 `inherit-temp-zone` 的触发条件一致。

### D4 公共两区建在 `Game:__init`，玩家三区建在 `Player:__init`

- 与「桌子由局自己建」「对象构造就带局」同一条思路：**构造点就是建东西的地方**，不存在「还没建区」的中间状态。
- 玩家侧不能等到建局：玩家是装配侧造的（`moe.player.create`），内核在建局时不知道会有几个玩家。
- 公共 `抽牌` 必须是有序区：`self:createZone('抽牌', true)`。

### D5 洗回留内容侧（用户 2026-09-24 选）

`deck:setShortageHandler(...)` 仍写在 `@基础/牌堆.lua`：洗回是「动作」，而「两堆都空 ⇒ 平局」是身份场口径。内核只保证 `抽牌` / `弃牌` 存在，不预设不足时怎么办。

### D6 内容侧的改动面

- `@基础/牌堆.lua`：不再建区，改成 `getZone` 取 `抽牌` / `弃牌`，其余（造牌 / 洗牌 / 标暗 / 洗回回调）不动；顶部那行说明同步改。
- `@基础/抽牌.lua`、`@基础/判定.lua`、`@基础/回合.lua`：`getZone(...)` 换成直接取，并**去掉**为此写的 `assert(... , '局上没有抽牌区')` 一类防御 —— 区现在由内核保证，符合「不要过度防御」。
- **删除 `package/@基础/收尾.lua`**（内核接管其全部职责）—— 已随本变更一起讨论、由用户确认（见 proposal）。

### D7 用例的改动面

- `server/test/core/**` 里 `game:createZone('弃牌' | '抽牌' | '手牌')` → `game:getZone(...)`；`player:addZone('手牌' | '装备' | '判定')` → `player:getZone(...)`（约 25 处）。
- `server/test/core/game.lua` 里「撞名建区报错」「ordered 与默认」这两条用例改成用别的名字；`server/test/core/zone.lua` 的 `addZone('手牌')` 同样换名字。
- 新增三类断言：① 建局 / 建玩家后五个区都在，且 `抽牌` 是有序区；② 撞名再建报错；③ 结算收尾把临时区剩下的牌送进 `弃牌`（含「内容侧先在 `'效果-收尾'` 里搬走的那张不会被收尾动到」）。

### D8 抽牌工具 `game:drawCards(player, count, to?)`：只抽牌，不管摸牌

用户 2026-09-24 定（「内核认了区名之后，抽 N 张牌应该非常常用」）：

- **形状**：`to` 省略 ⇒ `player:getZone('手牌')`（内核现在保证这个区在）；给了就用它 —— `useCard:getTempZone()` / `judge:getTempZone()` 就是「抽到处理区」。返回**实际抽到的牌**。
- **只是工具，不是「内核实现摸牌」**：`'摸牌'` 现在的干预模型是「内容侧在时机里真的取牌，注册更早的技能可以先改」；把取牌搬进 `Draw:settle` 会让干预点后移到「牌已经进手牌之后」。所以 `Draw` / `'摸牌'` / 摸几张照旧归内容侧，`@基础/抽牌.lua` 缩成一行。
- **走 `MoveCard`**（`deck:draw(count)` 取顶 ⇒ `game:moveCard(cards, to)` ⇒ 返回牌）：抽到的牌照旧触发 `'即将生效'`、可被拦，与内容侧现有写法一致 —— 搬牌仍然只有一条路（`收尾` 那处是明确记录的例外）。因此它是 `@async`。
- **不足时**：`OrderedZone:draw` + `setShortageHandler` 已就位，「洗回弃牌」与「判平局」仍由内容侧挂的回调决定；工具**照实返回**实际抽到的张数（可能是 0），不报错、不自己兜。
- **不新增时机、不管可见性**：把牌抽进 `抽牌` 之外的地方时，「亮出」这类表现是协议层的事（`'判定-亮牌'` 那种时机仍由各自的流程发）。
- 备选（已否决）：去向必填 + 玩家侧 `player:draw(count)`（`player:draw` 与 `game:draw` 这个效果容易看混）；扩展 `OrderedZone:draw(count, to?)`（调用方得先有牌堆，而且会让「取顶」这个基础接口的语义变重）。

## Risks / Trade-offs

- [区名进入内核契约，第三方包不能改名] → 名字只有五个、且是官方术语；包仍可自建别的区（`game:createZone` / `player:addZone` 照旧）。
- [删掉 `@基础/收尾.lua` 后没有「换一套默认收尾」的口子] → 内容侧在 `'效果-收尾'` 里提前搬牌已经能表达所有已知例外（装备牌 / 延时锦囊 / 技能改落点）；真出现第二种默认口径再加口子（YAGNI）。
- [用例改动面大，可能掩盖回归] → 全量 `server/bin/moe-kill.exe --test`，基线 490 用例 0 失败；「牌最终进弃牌堆」的那几条规则级断言（`rule.slash` / `rule.trick` / `rule.dying` / `rule.judge` / `rule.turn`）**不改**，正好当行为等价的证据。
- [`game:createZone('手牌')` 这类「公共区与玩家区同名」会让 `moveCard` 的名字解析有歧义（先找当前回合角色）] → 用例改成直接用玩家区；内核不新增跨层重名校验（那是过度防御）。

## Migration Plan

一次性改完（本项目无部署概念）：① 内核建区 + 默认收尾；② 用例跟上；③ 内容侧改取区、删 `@基础/收尾.lua`；④ 文档收口。回滚 = revert 这次提交（区是运行期构造的，没有持久化状态要迁移）。

## Open Questions

- 「抽牌堆与弃牌堆都空 ⇒ 平局」这条结局口径仍待核对规则集原文（已记在 `references/progress.md` §3），本变更不动它。
- 装备牌用后进装备区、延时锦囊进判定区的**实现点**（在哪次结算的哪个时机搬走）留到做这两个功能点时定；本变更只保证内核的默认收尾不挡路。
