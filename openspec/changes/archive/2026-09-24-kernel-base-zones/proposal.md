# Proposal

## Why

「有哪些基础牌区」和「结算完的牌回哪去」现在都写在**规则装配目录**里：`package/@基础/牌堆.lua` 建 `抽牌` / `弃牌` 与每人的 `手牌` / `装备` / `判定`，`package/@基础/收尾.lua` 订阅 `'效果-收尾'` 把临时处理区剩下的牌送 `弃牌`。

这两件事**没有任何变体**：官方规则里这五个区永远存在，「处理区里的牌在结算结束后置入弃牌堆」也从不改。把它们摆在「用户可改」的位置上，读者分不清哪条能改、哪条不能；漏建或改名时失败还会被时机系统**隔离成一条日志**（`fire` 本身不算失败），牌就静静留在临时区、没人发现。

用户 2026-09-24 定：切分轴改成「**固定 / 可配置**」—— 固定的一律进内核，可配置的（手牌可见性、洗回策略、数值）留在规则。原口径「机制 / 内容」在弃牌堆这类东西上给不出答案（弃牌堆不是通用引擎机制、却也没有任何变体），因此换轴。

## What Changes

- **内核建五个基础区身份**：建局时建 `抽牌`（有序）/ `弃牌`；建玩家时（`Player:__init`）建 `手牌` / `装备` / `判定`。玩家由装配侧创建（`moe.player.create`），所以玩家侧三个区不能等到建局。
- **BREAKING（对包作者）：这五个区名成为内核契约** —— 内容侧照旧 `game:getZone('弃牌')` / `player:getZone('手牌')` 取用，但**不得再建同名区**（`createZone` / `addZone` 撞名会报错）。契约写进 `server/core/loader/env-meta.lua`（包作者可见的类型契约）与 `references/architecture.md`。
- **内核做「结算的自然收尾」**：`Effect` 结完、`fire('效果-收尾')` **返回之后**，内核自己把临时处理区里还剩的牌**同步**送进 `弃牌` 区。内容侧要先留走牌（将来装备牌进装备区、延时锦囊进判定区）就在 `'效果-收尾'` 里先搬，内核只清剩下的 —— 「默认固定」与「例外可写」同时成立。
- **删除 `package/@基础/收尾.lua`**（内核接管了它的全部职责）；`package/@基础/牌堆.lua` 不再建区，只造牌 / 洗牌 / 给 `手牌` 标暗 / 挂洗回回调（该文件与 `@基础/判定.lua`、`@基础/抽牌.lua` 改成 `getZone(...)` 取区）。
- **新增内核工具 `game:drawCards(player, count, to?)`**：从 `抽牌` 堆顶抽 `count` 张，`to` 省略就进该玩家的 `手牌` 区、给了就用它（`effect:getTempZone()` ⇒ 抽到处理区），返回实际抽到的牌。它只是**工具**：`'摸牌'` 时机与摸几张仍在内容侧。三个调用点（`@基础/抽牌.lua`、`@基础/判定.lua`、`标准/卡牌/五谷丰登.lua`）改用它，各自缩成一行。
- **不做**（明确非目标）：牌表与造牌 / 洗牌、洗回策略与「两堆都空判平局」、摸牌本身（`'摸牌'` 时机与数量）、弃牌阶段的搬牌、`手牌` 可见性 —— 都是「动作 / 数值 / 策略」，继续留在内容侧；内核建的区默认 `visible = true`，由规则自己标暗。

## Capabilities

本变更不写 specs 增量（`.openspec.yaml` 设 `skip_specs: true`）：这是「谁建区、谁收尾」的**归属搬迁**，玩家可见的最终结果没变（用过的牌 / 判定牌 / 打出的牌照样在各自那次结算结束时进弃牌堆），没有 requirement 级的行为变更；新加的 `game:drawCards` 是**新增 API**（把「取顶 + 挪到某区」合成一步），它替换掉的三处调用点行为不变。区名契约是包作者要遵守的约定，但它的**真相源就是代码**（`server/core/loader/env-meta.lua`），且 `openspec/specs/` 是冻结的探索期快照、不随实现更新。

### New Capabilities

- 无。

### Modified Capabilities

- 无。

## Impact

- 内核：`server/core/game.lua`（`__init` 建两个公共区、新增 `drawCards`）、`server/core/player.lua`（`__init` 建三个玩家区）、`server/core/effect/effect.lua`（`bindFinish` 里 `fire('效果-收尾')` 之后加默认收尾）。
- 内容：删 `package/@基础/收尾.lua`；改 `package/@基础/牌堆.lua`、`package/@基础/抽牌.lua`、`package/@基础/判定.lua`、`package/@基础/回合.lua`、`package/标准/卡牌/五谷丰登.lua`（取区 / 改用抽牌工具）。
- 用例：`server/test/core/**` 里约 15 处 `game:createZone('弃牌' | '抽牌' | '手牌')` 与约 10 处 `player:addZone('手牌' | '装备' | '判定')` 改成取内核建的区；`server/test/core/game.lua` 与 `server/test/core/zone.lua` 里几条「建同名区」的用例要换名字；新增「内核建出五个区」「结算收尾把剩下的牌送弃牌」「抽牌工具的三个去向与不足时照实返回」「撞名建区报错」几类断言。
- 文档：`references/architecture.md`（第 9 / 10 / 12 节里「内核不预设任何区名」的表述要改成新口径：内核认这五个名字、其余区名仍由内容侧定）、`references/progress.md`、`package/@基础` 各文件顶部的一行说明。
- 冻结的 `openspec/specs/core-zones` / `core-room` 里「内核不写死任何具体区域名」一句成为历史快照的一部分，**不回头改**（探索期口径）。
