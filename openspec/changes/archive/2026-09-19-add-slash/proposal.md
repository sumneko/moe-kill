# Proposal

## Why

内核现在只有「容器与工厂」：牌能建、能在牌区之间移动、能被洗，但**没有「把一张牌用出去」的机制**，也**没有「造成伤害」的机制**。`package/标准/牌表.lua` 里已经躺着一张「杀」，却没有一条路径能让它产生后果。

本变更补齐这两个通用机制（使用牌 / 伤害），并让规则包第一次写出**一张真正有效果的牌**（杀），把「牌定义 → 使用 → 后果」这条链路走通。这是规则侧的第一个功能点，也是后续一切牌与技能的地基。

## What Changes

- **新增「使用牌」机制（内核）**：调用方给出「谁用、哪张牌、对谁」，机制负责 —— 校验牌在用者手上、按牌自己的声明校验目标合法性、把牌取出、执行该牌声明的结算、结算完成后触发一个收尾时机（牌的去向由内容侧决定）。机制 MUST NOT 预设任何区域名 / 牌名，MUST NOT 内置任何具体牌的规则。
- **新增「伤害」机制（内核）**：`game:damage(来源, 目标, 点数)` 改目标体力，并在改之前 / 之后触发「伤害-前」「伤害-后」两个时机。本批**不做**濒死与死亡（体力允许降到负数），也**不做**属性伤害、伤害值修改与伤害防止。
- **基础规则包**：新增属性 `攻击范围`（开局写默认值 1）；约定两个区域名 —— 玩家侧的 `手牌` 与局侧的 `弃牌堆`，开局建好；用掉的牌统一由基础规则放进弃牌堆。
- **内容包（标准）**：新增第一张牌 `package/标准/卡牌/杀.lua` —— 声明它的目标合法性（目标距离 ≤ 使用者攻击范围）与效果（对目标造成 1 点伤害）。
- **本批明确不做**：回合与阶段（因此不限阶段、不限次数）、「闪」的响应与「打出」、结算栈、濒死 / 死亡 / 奖惩 / 胜负、装备与距离修正、判定、无懈可击、技能、摸牌与弃牌阶段。

## Capabilities

### New Capabilities

- `core-play`: 使用牌的通用机制 —— 校验（牌在使用者手上、目标合法）→ 取牌 → 牌的结算回调 → 收尾时机；机制不含具体牌规则、不预设区域名
- `core-damage`: 造成伤害的通用机制 —— 改体力 + 「伤害-前 / 伤害-后」时机；本批不含濒死与死亡

### Modified Capabilities

- `base-rules`: 新增 `攻击范围` 属性（默认 1）与 `手牌` / `弃牌堆` 两个区域名约定

## Impact

- **内核**：`server/core/game.lua` 增加使用入口 `play` 与伤害入口 `damage`（含新时机的触发）；不新增内核模块，不改动现有接口语义。
- **类型面**：`server/core/loader/env-meta.lua` 增加 `'游戏-开始'` 之外的新时机上下文类型（`卡牌-结算后` / `伤害-前` / `伤害-后`）。
- **规则包**：`package/@基础/`（攻击范围、手牌与弃牌堆、结算后的去向）、`package/标准/卡牌/杀.lua`（新文件）。
- **测试**：新增 `server/test/core/damage.lua`、`server/test/core/play.lua`、`server/test/rule/slash.lua`；既有用例不受影响。
