# Proposal

## Why

规则集目前只从**单一根目录**（`<仓库根>/game`）加载，这挡住两件事：目录要按包组织（`package/`），以及将来要支持用户自定义包时从**多个位置**找同一份内容。把「多个位置合并成一棵逻辑目录树」抽成独立的一层能力，后面的依赖解析与分包命名才有干净的地基。

## What Changes

- 目录改名 `game/` → `package/`（该目录**尚未创建**，改动 = 默认来源 + 文案）。
- 新增**包来源**配置：`moe.rule.setRoots { './package/*', 'D:/某个自定义包', 'D:/某合集/*' }`。
  - `X`（无 `*`）= X **本身**是一个来源，逻辑第一层 = 它的目录名；
  - `X/*` = X 是**包容器**，其下每个子目录各是一个来源，容器名 MUST NOT 进逻辑路径；
  - `*` 是**特殊语法**（不是通配匹配），目前只允许「结尾 `/*`」这一种写法，其余形式报错；
  - 默认 = `{ './package/*' }`（基准 = 仓库根）。
- 新增**虚拟文件系统**：来源按列表顺序合并成一棵逻辑树，**同一逻辑路径只取最后一个来源的文件**（文件级覆盖），不同路径取并集（目录内容跨来源合并）；**不缓存**，每次加载当场重新枚举并合并。
- 加载器改在虚拟文件系统之上工作：清单项与依赖项都是**逻辑路径**；来源路径不存在 ⇒ 报错，`X/*` 匹配到 0 个包 ⇒ 允许。
- `rule.depends` 支持**相对路径**：以 `.` / `..` 开头按**声明它的文件所在目录**解析，其余按逻辑根解析。

## Capabilities

### New Capabilities

- `package-vfs`: 包来源语法、来源合并规则（后者覆盖前者、文件级、目录内容并集）、不缓存重扫。

### Modified Capabilities

- `rule-loading`: 「清单驱动加载」改为在虚拟文件系统的逻辑路径上解析（含跨来源覆盖）；「文件级依赖声明」增加相对路径；「加载失败明确暴露」增加「来源路径不存在即报错」。

## Impact

- `server/rule/`：新增虚拟文件系统实现；`init.lua` 的默认来源改为 `{ './package/*' }`，清单项与依赖项的解析改走虚拟文件系统。
- 主规格 `rule-loading` 文案里的 `game/` 全部改为 `package/`；技能文档同步（`moe-kill-dev` 的 `SKILL.md` 与 `references/{architecture,infrastructure}.md`、`sanguosha-rules`）。
- 协议 / 事件里的 `game/`（如 `game/submitDecision`）是**协议域前缀**，与目录无关，本变更不动。
- **不含**任何「包 / 名字路由」语义 —— 那是后续变更 `add-package-routing`（前置 = 本变更）。
