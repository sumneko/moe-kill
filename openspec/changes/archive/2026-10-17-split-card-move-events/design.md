# Design

## 背景

- 内核搬牌**一步到位**：`Zone:takeIn` 逐张「从旧区摘 → 置入本区 → `bindZone`」，随后 `Zone:notifyMoved` 发事件。**没有「在途」这个状态**，也不打算有（见「不造在途状态」）。
- `notifyMoved` 发两段区域事件（先所有「卡牌-离开区域」、再所有「卡牌-进入区域」），并在末尾补一条汇总的 `'卡牌-批量移动'`。
- 节拍（`package/@基础/动画.lua`）与通知（`server/user/card-sync.lua`）**都订那条汇总事件**；`SimpleEvent:fire` 同步顺序跑回调 ⇒ 注册在前的那位 `yield` 就把后面的挡住。

## 决策一：拆三个时机，「让出」独立成一条

```
fire '卡牌-批量移动前'      ← 两端区域事件都没发（表现起点）
notifyLeave(每一条)         ← 「卡牌-离开区域」（牌自己 → 区主人）
fire '卡牌-批量移动时'      ← 让出点（离开发完、进入没发）
notifyEnter(每一条)         ← 「卡牌-进入区域」
fire '卡牌-批量移动后'      ← 两端都发完（落位）
```

- **为什么必须有第三个（「时」）**：只有「前 / 后」的话，节拍就得挂在某一条上 —— 挂「前」会挡住 `Card.Remove`（又回到同一个病），挂「后」等于节拍之后再落位、客户端仍然要提前猜总时长。让出点**自己就是一条**，两边都不占。
- **协议层不订「时」**：那条只给内容侧让出用（而且往往没人订 —— 没有节拍的内容包照样能跑）。
- **内容侧只改一个词**：`动画.lua` 从订 `'卡牌-批量移动'` 改成订 `'卡牌-批量移动时'`，`BEAT` 表一行不动。

## 决策二：不造「在途」状态

内核里让牌先进行途区、节拍后再进目标区，能让状态与表现严格同步，但：

- 「在途的牌」在规则上**没有任何意义** —— 官方规则里牌的移动是一个流程，不是一个位置；
- 状态机要多一个中间态，所有读牌区的地方都得考虑「它是不是在途」；
- 客户端的**输入**与**判定**全在后端，视图滞后于真相没有危害（前端只是把服务端讲的事重演一遍）。

⇒ 拆的是**通知**，不是状态。代价是「在途这一秒里，内核已是终点状态、客户端画的是在途」，这是**有意的**，写进 `architecture.md` §16。

## 决策三：账跟着两头走（`removeCards` / `createCards`）

原来账的更新全靠 `markDirty` + `moe.await.wake` 那笔「下一调度统一发」（`Card.Remove` + `Card.Create`），而搬牌之后紧接着就有节拍让出 ⇒ 那笔 flush 被推到一秒后，于是**手牌里那张牌赖着不走**。

现在：

- 「前」当场发 `Card.Remove`（按**账里记着的旧区**摘号 —— 内核此刻已经把它挪到新区了）；
- 「后」当场发 `Card.Create`（建新号，并按老规矩洗一次目标区的暗号）；
- `updateCards` 只留两类：**没换区**的内容变化（`Card.Update`）与**兜底换区**（`Zone:remove` / `clear` 这类没有搬动通知的归属变化）。

## 决策四：在途闸门（`Game.CardSync.moving`）

节拍的让出点是**真的让出**（`coroutine.yield`），期间事件循环照跑 —— 早先积下的那笔脏卡 flush 可能在「前」与「后」之间落地，那时这张牌在账上已经不存在（旧号刚被摘掉），`updateCards` 会把它当「新牌」建一个号，于是「后」再建一次 ⇒ **一个实体两个号**。

⇒ 「前」把移动中的牌记进 `moving`，这期间它产生的一切变化**一律不置脏**（落位时重建的号带的就是当时的最新状态，所以不丢），「后」清掉标记。

## 决策五：换区的判据用「账里的区 vs 新区」

不能比 `toPZone(from) ~= toPZone(to)`：新牌（无归属）与无名区（临时区）的协议区名**都是 `'#0'`** ⇒ 协议名相同，可账里根本没有它、必须建号（`server/test/user/card-sync.lua` 的「无名区之间互移」那条用例当场抓到）。

⇒ 两条都改成读账：`(pcard?.zone or '') ~= toPZone(move.to)`。

## 决策六：「进 / 出」两段不对称（有意）

- **离开**的钩子（`notifyLeave`，即 `'卡牌-离开区域'`）在「前」之后立刻跑 ⇒ 「牌离开手牌」当场生效（【枭姬】那类响应跟得上）；
- **进入**的钩子（`notifyEnter`）在「时」之后跑 ⇒ **牌飞到了才算进区**。

用户 2026-10-17 明确「是的，服务器也一起走延迟」。副作用要说清：**规则上「牌进了弃牌堆」也会晚一秒**（同一协程被让出挡住，期间没有别的流程会跑，所以安全）。

## 备选方案（已否决）

| 方案 | 否决理由 |
| --- | --- |
| 给事件订阅**分相**（`game:on(名, 回调, { phase = '通知' \| '表现' })`，fire 先跑通知相） | 通用但多一个概念；**节拍仍然挂在事件上**，以后每加一个「会让出」的订阅者都要重新想相的问题 |
| `fire` 改 async + `waitAll` 让通知与节拍**并发** | 效果等价，但要把一串调用点 async 化（`Zone:accept` → `notifyMoved` → …），改面大得多 |
| 只修顺序：通知订阅者排到节拍前面 | 依赖**注册顺序**的脆办法（包加载期 vs 客户端接入时），换个加载方式就破 |
| 内容侧把 `BEAT.moveCard` 调成 0 | 最省事，但**丢掉节拍本身的能力**（服务器等动画播完，动画才不会被下一拍挤掉） |

## 遗留（本变更不做）

- 前端拿到「落位时刻由服务端说了算」这个自由度之后，可以做「飞早了悬停 / 落位先到就加速收尾」；现在仍是**飞满 `FLY_MS` 再消失**，只是与 `Card.Create` 的到达时刻天然接近（都是 1 秒 + 网络往返）。等真的出现「节拍与 `FLY_MS` 不一致」的观感问题再做。
- 「在途」若将来有规则需求（例如「移动途中」类技能），那时才考虑给内核加状态。
