# Proposal

## Why

`reason`（询问缘由）是玩家在询问条上**唯一**看到的文字，而内容侧还有 **26 处**询问写的是**一个词**（`'出牌'`、`'弃牌'`、`'护驾'`、`'过河拆桥'`…）—— 玩家看到的抬头就是「出牌」「护驾」，既不知道要他做什么，也不知道是谁在问。上一批只把 5 张牌改成了整句，本批补齐剩下的。

两处形状问题一并解决：

1. **同名表达不了两种询问**：【借刀杀人】要问使用者「指定谁」、又要问持有者「出不出杀」；【雌雄双股剑】要问主人「发不发动」、又要问目标「弃不弃牌」。现在两处都写同一个名字，抬头完全一样。
2. **值内联在文本里**：现行语法把参数写成 `@{名字:值}`，值只能是一串字符 —— 角色 / 牌这类带 id 的值表达不了；而且值的位置被服务端**拼死**，客户端的翻译表重排不了词序（英文的「3 cards」词序与中文不同）。

## What Changes

- **参数表独立成 JSON**：`reason` 的格式从「值内联在文本里」改成**模板 + 参数表**两段：

  ```
  ${locale:弃置 {num} 张牌强制命中 {name#name}}@{"num":2,"name":"XXX"}
  ```

  - 边界**按括号配对**认定：先扫出配对完整的 `${…}`（模板），**紧跟在它后面**的那个 `@{…}`（配对完整的 JSON 对象）才是参数表。
  - **只在模板内部渲染**：只有 `${…}` 内容里的 `{名字}` / `{名字#类型}` 会被替换；模板之外（含花括号）一律原样输出。
  - 没有参数时 `@…` 整段省略，`reason` 退化成一段普通文本。
- **渲染按类型**：`{名字}` 的键既是**取值用的键**、也是**默认类型**；`{名字#类型}` 显式给类型（如 `{name#name}`）。客户端按类型自行决定怎么画（上不上色、什么色、要不要加书名号…），服务端**不规定**类型清单、也不解释类型含义。
- **内容侧有构建器**：加在**内容包自己的工具**里 —— `package/@tools/util.lua` 已经建了内容侧全局 `util`（现有 `util.defer`），而 `@tools` 目录带 `@` 前缀 ⇒ 它是**默认加载**的包，所有内容包直接用得上；往它上面加 **`util.locale(内容, 参数表?)`** —— `util.locale('弃置 {num} 张牌', { num = 2 })` 直接返回上面那个字符串；参数表缺省/为空时返回纯文本。
- **内容侧 26 处 `reason` 改成整句**（名字写进句子），分布：阶段 3 处（出牌 ×2 / 弃牌）、基础规则 2 处（濒死 / 选将）、牌与装备 12 处（雌雄双股剑 ×2 / 青龙偃月刀 / 贯石斧 / 麒麟弓 / 过河拆桥 / 顺手牵羊 / 借刀杀人 ×2 / 五谷丰登）、技能 11 处（护驾 / 激将 / 鬼才 / 反馈 / 刚烈 / 突袭 / 反间 / 流离 / 遗计 / 观星 —— 其中【吕布】那处沿用上游 `ask.reason`，不改）。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `jsonrpc-protocol`: 「询问缘由的文本格式」—— 参数从「内联在文本里」改成**独立的 JSON 参数表**（边界按括号配对）；明确 `{名字}` 的名字即**文本类型**、渲染方式由客户端按类型决定，且只渲染模板内部。

## Impact

- **内容侧工具**：`package/@tools/util.lua` 加 `util.locale` 与一个私有的 JSON 编码（内容侧拿不到 `moe.json`）；**内核一行不改**。
- **前端**：`client/src/view/format.ts`（配对扫 `${…}` + 紧跟的 `@{…}`、只在模板内部渲染、按类型查渲染表）、`client/src/view/Ask.ts`（抬头片段）、`client/src/ui.ts`（`formatPlain` 调用方）。
- **内容侧**：`package/**` 26 处 `game:ask*` 的 `reason` 改用 `util.locale(...)`。
- **协议文本**：`server/proto.d.lua` 里 `reason` 的注释、活规格 `openspec/specs/jsonrpc-protocol/spec.md`。
- **文档**：`architecture.md`（`ask*` 行的 `reason` 说明）、`progress.md`。
- **测试**：文案改动**不影响**既有判据（判据已换成结构判据），但需全量回归确认。
- **不在本次范围**：`package/标准/武将/甄姬.lua` 在读 `judge.reason == '洛神'`（**判定的缘由被当标识用**），本批不动，仅记录。
