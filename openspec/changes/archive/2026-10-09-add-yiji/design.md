# Design

## Context

- 【遗计】文本（库内底本 `标准包.md`）：「当你受到 1 点伤害后，你可以观看牌堆顶的两张牌并任意分配它们。」
- 现有件：`game:askCardWithTarget(被问者, 缘由, 条件?)`（`AskCardWithTarget : AskCard`，2026-10-08）—— 条件 = `AskCard.Condition` 全部（`zone` 可传**区对象**、`name` / `color` / `min` / `max` / `cancelable` …）+ `targets` / `minTarget` / `maxTarget`；答复 = `{ card, targets }`，读 `.cards` / `.target`。**「怎么给出去」不归它管**，发起方拿到答复自己搬。
- 「观看牌堆顶 N 张」的两种落法（本批取了后者的变体）：就地读、不动牌堆 vs 抽到某块区。用户 2026-10-09 定：**抽到临时区**。
- 临时区：`Effect:getTempZone()`（自建）；`Cast : Effect` 也有 ⇒ `skill:tryCast(function (cast) … end)` 的 body 里 `cast:getTempZone()`。

## Goals / Non-Goals

**Goals:**

- 【遗计】按库内文本落地，不动内核、不开新询问类。
- 把「结算中的一次分配」这条写法记下来（将来【反间】这类还要用）。

**Non-Goals:**

- 不做「未分配的牌置回牌堆顶 / 底」—— 本技能的链保证不会剩牌（见 D2）。
- 不动【天妒】与判定那套（上一批 `add-judge-player-event`）。
- 不改 `askCardWithTarget` 本身（一行都不改）。

## Decisions

### D1. 复用 `askCardWithTarget`，不新开 `askCardToPlayer`

草稿里的 `askCardToPlayer { min = 1, zone = tempZone }` 与 `askCardWithTarget` 的**条件字段一一对应**：`zone`（区对象）+ `min` / `max`（张数，`max` 省略 = `min`）+ `minTarget` / `maxTarget`（目标个数，省略 = 1）。再开一个同形状的类只会让协议面分叉（前端要认两种 `kind`、内核要维护两套校验）。

⇒ 落地为 `game:askCardWithTarget(skill.owner, '遗计', { zone = 临时区, min = 1, max = 临时区:count() })`。

### D2. 「观看」= 抽到临时区，且**必须有去处**

抽到临时区的代价是「牌离开了抽牌堆 ⇒ 得交代去向」。本技能的去处由**两个分支覆盖**：

- 答复给出牌 ⇒ `moveCard(答复的牌, 目标:getZone('手牌'))`；
- 答复为空（玩家取消）⇒ `moveCard(临时区剩下的全部, 自己手牌)`，这一轮结束。

⇒ 循环结束时临时区必空，**不需要**「插回牌堆顶 / 底」（那条能力缺口留给【观星】）。顺带：这也让「取消」有了自然语义 —— **取消 = 剩下的都归自己**（用户定）。

### D3. `max` 给「当前剩余张数」（用户纠的一处）

第一次写成「每次正好 1 张」（`max` 省略 = `min` = 1），用户纠正：**`max` 得是剩余牌的数量** ⇒ 一次答复可以给**同一名角色** 1~N 张（想分给两个人时再问第二轮）。`maxTarget` 保持默认 1（一次答复只指一个目标）—— 「给几个人」由反复询问表达。

### D4. 触发粒度：按点

「受到 **1 点**伤害后」⇒ `for _ = 1, damage.amount do … end`，**每轮各是一次 `skill:tryCast`** ⇒ 每轮一次 `Cast`（照【洛神】「一轮 = 一次发动」的既有口径；用例钉住「受 2 点 ⇒ 两轮、四张」）。每轮的观看 / 分配完全独立。

### D5. 分配权在被问者手上

`askCardWithTarget` 问的是**发起方（郭嘉）** ⇒ 由他决定给谁、给几张。与【五谷丰登】「逐目标各自选一张」的方向刚好相反 —— 两条都合法，区别是文本写的是「**你**观看…并**任意分配**它们」。

### D6. 「观看」的可见性：**私有临时区** + `setVisible` 改成名单语义（用户 2026-10-09 定，分两轮）

用户先给两个想法：① 加一个「秘密临时区」（对自己可见）；② 不移动、就地指定 2 张，另加「牌级临时展示」的机制（可见性覆盖）。

**第一轮：选①的最小形式。** 区级那套早就有了（2026-09-23 落地的 `Zone.visible` + `setVisible` / `isVisibleTo`），定位也契合 —— 它**不是给候选筛选用的**（服务器侧一律看得见），而是**协议层遮蔽要读的声明**，这正是「观看」需要的；而 ② 更通用但要先定三条口径（谁可见（观看 / 展示是两个不同动作）・时效与谁撤・牌级与区级的合并规则），遗计的首个真需求只是「别亮给全场」⇒ ② 放到【反间】或协议层那批一次定透。当时写成 `bindOwner(郭嘉)` + `setVisible(false)`（旧语义：暗区只有持有者看得见、无归属的暗区谁都看不见 —— 所以两行要一起）。

**第二轮：把 `setVisible` 的语义修对（用户：「完全按照参数语义」，别留『总是对自己可见』的潜规则）。** `Zone:setVisible` 扩成 **`boolean|Player|Player[]`**：

| 参数 | 含义 |
| --- | --- |
| `true` | 所有人可见 |
| `false` | 谁都看不见（**连持有者也是** —— 潜规则去掉） |
| 一名或一批角色 | **只有他们**看得见 |

⇒ `isVisibleTo(视角)` 就是「名单里有没有他」，**`owner` 不再参与**（它回归「这个区属于谁」这一个事实，仍是「牌的主人」的读法来源）。连带两处：

- `@基础/牌堆.lua` 的 `手牌`：`setVisible(false)` → **`setVisible(各自的持有者)`**（旧写法在新语义下会让持有者自己也看不见自己的手牌）。
- 【遗计】：两行缩成一行 **`shown:setVisible(skill.owner)`**。

**为什么不加便利 API**（如 `getPrivateZone(owner)`）：目前只此一个消费者，加 API 反而多一个口径；`setVisible` 本身已经把话说清。

### D7. 「反复询问」的循环用带上限的 `for`，不用 `while`（用户 2026-10-09 定）

遗计的分配循环第一版写成 `while shown:count() > 0 do`，用户要求改成 **`for _ = 1, 1000 do`**（并把这条记成约定）。

- **理由**：这类循环退出条件是「答复不再前进」，而 `while` 把询问写在头部条件里（`while X do` 与「先问后判」的顺序绑死，改一处就容易写反）；带上限的 `for` 顺带兜住「答复不前进 ⇒ 死循环」（到上限就停，不报错；首个用户是【洛神】）。
- **连带改了【濒死】的求桃圈**（`while game:askUseCard(…).useCard do` → 先问、答不上就 `break`，等价且带上限）。
- **`while` 的白名单**：`回合.lua` 里「轮转到只剩一个存活角色」的**整局主循环**保持 `while` —— 它不是反复询问，加上限会变成「一局最多 1000 回合」（语义变化）。
- **记下来**：`moe-kill-dev/references/code-style.md` 新增 **§14**；`sanguosha-rules` §9.15 / §9.24 的写法与示例同步。

## Risks / Trade-offs

- **「观看」的可见性**：临时区默认全桌可见，而官方是「**你**观看」（别人不该看到）。现在没前端 ⇒ 无实际差别；先记在文档里，等协议层再表达（不为它新开区）。
- **一轮多问**：一次答复最多只能给一个目标 ⇒ 「两张给两个人」要问两轮（前端两次交互）。这是 `maxTarget` 默认 1 的直接后果；真要一次分配完就得新开询问类（本批明确不做）。
