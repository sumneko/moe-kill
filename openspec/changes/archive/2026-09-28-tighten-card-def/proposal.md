# 把「牌必须有内容定义」收紧到建牌时（去掉 `getDef()`）

## Why

`Card` 一直允许「牌名查不到内容定义」这种状态存活：`getDef()` 返回空、`fireHandlers()` 静默跳过、`canUse` 把「没有同名内容定义」当成一条**用不了**的原因。这在实践里没有价值 —— 牌名对应的内容定义是**内容侧建牌时就该给的东西**（分类 / 限额 / 数据 / 钩子全挂在定义上），查不到只可能是内容侧写错（漏定义、名字打错）。

用户 2026-09-28 定：**`def` 不会是空 —— 初始化时 `getCard` 拿不到就直接报错，这是后端错误、直接炸局**。

## What Changes

- 删 `Card:getDef()`，内容定义就是**公开字段 `card.def`**：`Card:__init` 里查一次 `game:getCard(名字)`，查不到 `error('没有叫「{}」的内容定义')`。
- 跟着去掉所有「定义可能为空」的形态：`card:fireHandlers()` 不判空、`isKind` / `getValue` / `fullName` 直接转发 / 读 `def`、`game.lua` 的 `checkCardItself` 删掉「没有内容定义」那条分支（**建牌时就挡住了**）。
- 用例侧：测试框架给一份**公共牌定义来源**（`lt.cardSource`），三条「前提已死」的用例改写成「建牌时就报错」。
- 内容侧补上被新规则炸出来的**真缺口**：标准包牌表里列着 `八卦阵` / `仁王盾`，但从来没有这两张牌的定义。

## Impact

- **BREAKING（对内容侧）**：「先建牌、之后再补定义」不再可行；建牌时定义必须已经装好（装包在 `'游戏-开始'` 之前完成 ⇒ 正常流程不受影响）。
- 受影响文件：`server/core/card.lua`、`server/core/game.lua`、`server/core/effect/use-card.lua`、`server/test/ltest.lua` 与若干内核套件、新增 `package/@基础/卡牌/防具牌.lua` 与 `package/标准/卡牌/{八卦阵,仁王盾}.lua`。
- 口径变化：`canUse` 的原因清单少一条（不再有「没有同名内容定义」）；牌名的契约从「非空字符串」收紧成「**非空字符串 + 局里查得到同名定义**」。
