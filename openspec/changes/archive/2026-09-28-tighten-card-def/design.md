# Design

## 1）为什么放在 `Card:__init`

- **定义是建牌的必要输入**：牌名 → 定义决定这张牌有什么钩子、什么分类、限额与数据（`kind` / `limit` / `value` / `on(事件)`）。建牌时不查定义 = 造一个「谁都不认识」的对象，之后每条读法都要问一遍「万一没有呢」。
- **报错位置正确**：建牌处是**唯一入口**，栈里有调用方 ⇒ `error(msg, 2)` 直接指出是谁造了这张牌。
- **真正会缺的仍然会缺**：内容侧建牌发生在 `'游戏-开始'` 之后，而装包在那之前完成 ⇒ 「拿不到定义」只可能是**内容侧漏定义 / 名字打错**（`标准/牌表.lua` 与 `标准/卡牌/` 对不上这种），正是要炸出来的那类后端错误。

## 2）为什么不保留 `getDef()`

- 无参读取用字段（`code-style.md` §11）：它不带参数、返回恒定不变的值 ⇒ 就该是字段。
- 字段化之后「可能为空」从类型上消失：`card.def.skipsEffect` 直接读，不必到处写 `?:`。

## 3）测试环境怎么提供定义

- 内容侧既然规定「牌必须有定义」，用例里那些「只是要一张牌」的临时牌名（`甲` / `第N张` / `回收牌`…）就必须有定义 ⇒ 测试框架给一份**公共定义来源**（`tmp/lt-fixture/@测试/牌.lua`，暴露成 `lt.cardSource`），要用它的套件把来源加进 `sources` 即可（`@` 前缀 ⇒ 自动装载，不用改 `packages`）。
- **各套件自己的探针优先**：探针里已声明过的名字（`测试杀` / `抵消牌`…）继续用探针；公共来源只放「不关心语义」的通用名字。
- **一个副作用要注意**：公共来源是默认包（加载顺序排在清单项之前）⇒ 某个套件若一边挂公共来源、一边在探针里声明同名但**带钩子**的定义，会被公共来源那份空定义遮住。这类套件（`ask-card`）改成只往探针里补名字，不挂公共来源。

## 4）不做

- 不给「查不到定义」留任何降级路径（返回空 / 跳过钩子 / 当成用不了）—— 语义只有一条：**炸局**。
- 不动各钩子返回值的校验（那是另一回事）。
