# Design

## Context

动机见 `proposal.md - Why`。这里只记影响做法的现状与约束：

- 结算栈与 `<close>`：`Effect:apply()` 现在用 `local pop <close> = self.game:pushEffect(self)` 保证退栈，这条依赖「栈只能从栈顶退」。
- 时机系统：`game:on` 只能在加载期注册（`game-events`），`fire()` 已经用 `xpcall` 逐个隔离订阅者，错误走 `log.error`。
- 挂起原语：`server/tools/await.lua`（照搬 LuaLS 4.0.0）提供 `await.yield(callback)`——**callback 里同步调用 resume 时不真的让出**（快路径），以及 `await.call` / `await.sleep` / `setErrorHandler`。
- 日志钩子：`server/moe-kill.lua` 的 `createLog` 已经用 `Log.Options.print(timeStamp, level, sourceStr, message)` 这个钩子写文件并把 error / fatal 镜像到流；`moe.args.TEST` 决定测试模式。
- 测试框架：`server/test/ltest.lua` —— `M.test(name, callback)` 注册、`M.runAll()` 逐个 `xpcall`、已有 `M.assertError`（断言"会抛错"）。
- 内容侧现状：【杀】在 `'使用'` 回调里 `for` 循环直接 `game:damage`，没有响应步骤，顺序也不保证是行动顺序。

## Goals / Non-Goals

**Goals:**

- 内核具备「中途要一个决策」与「问完之后可以否决这次生效」两项能力，且取消的作用域精确到**一个目标的一次生效**。
- 挂起引入的新失败模式（挂住没人答、答复路径出错、外部要关掉它）全部有兜底，不会永久挂死。
- 内容包代码出错不让一局崩掉，同时测试**不会假绿** —— 错误必须变成用例的失败。

**Non-Goals:**

- 不在本批引入 `ls.task`，也不给"挂起"另造一套生命周期对象（决定见 D6）。
- 不做会话层接线：`ask` 的答复在本批由测试注入的回答者同步给出，前端接线留给协议批次。
- **不做异步答复与超时**：询问当场取答案；"游戏已挂起 / 恢复"的会话通道留到接线批次（见 D11）。
- 不做"同一响应窗口里的多个候选技能"（八卦阵 / 龙胆）。本批的响应即【闪】本体。
- 不做无懈可击（嵌套取消）、濒死与死亡的插入结算、判定、"作废尚未结算的目标"。

## Decisions

### D1 效果改为协程驱动，`apply()` 是唯一的驱动点

`Effect:apply()` 变成：创建协程（协程体内做"记父 → 压栈 → fire「即将生效」 → 执行结算"，退栈交给 `<close>`）→ 循环 `coroutine.resume` → 按让出原因分派（`'ask'` 答复后继续、`'cancelled'` 收尾）→ 结束时清掉句柄。因为**每个效果一个协程**，协程边界就等于效果边界 ⇒ 取消的作用域天然是"这一个效果"，取消了内层也不会波及外层。

**备选**：① 用一个"已取消"标志 + 每个 `settle()` 开头自己检查 —— 只能覆盖"尚未开始执行"的取消，一旦有人在结算更深处要求中止就无能为力；② 直接照搬 `ls.task`（见 D6）。

### D2 取消协议：运行态让出、挂起态直接关闭

`Effect:remove()` 按驱动协程的状态分派：

| 状态 | 谁在调 `remove()` | 处理 |
| --- | --- | --- |
| 正在运行 | 只可能是它自己调用链上的代码（【闪】在「即将生效」里） | `coroutine.yield('cancelled')`，这个调用不返回；由驱动点 `coroutine.close` |
| 挂起（在等答复） | 外部 | 直接 `coroutine.close` |
| 已结束 | 任何人 | 报错（不静默） |

关键约束：**`coroutine.close` 不能关闭正在运行的协程**，所以运行态取消必须先让出，这也是"调入点负责 close"的原因。close 会触发协程内待处理的 `<close>` 变量 ⇒ 结算栈自动弹掉，不需要另写退栈逻辑。

**备选**：让 `remove()` 只置标志、由驱动点在 resume 返回后检查 —— 运行态那条路径根本回不到驱动点（代码还在往下跑），不成立。

### D3 「即将生效」由 `apply()` 统一触发，不由子类各自触发

`apply()` 在压栈之后、执行结算之前统一 `fire('即将生效', self)`。好处：所有效果（用牌、伤害、询问、以后的一切）自动都带这个时机；取消只有一个入口；fire 时 `self` 正好在栈顶（撤销函数"只能从栈顶退"的约束天然满足）。

**备选**：每个子类在自己的 `settle()` 里 fire —— 漏一个就少一个可取消点，而且取消实现要跟着分散。

### D4 用牌改为逐目标生效，生效是独立效果

`UseCard` 的结算变成：校验 → 取牌 → 按**行动顺序**对每个目标各产生一次**生效**（`parent` = 这次用牌）→ 全部处理完 → 触发收尾时机。生效本身是一个效果，因此：有自己的「即将生效」（可以被单独取消）、在结算栈上能一路查到使用者与牌、它引发的伤害等插入结算挂在它下面。

目标顺序由一个通用入口给出（从使用者的下家开始按行动顺序排序），放在桌上（`Desk`）以便后续机制复用。

**备选**：在 `UseCard` 上记"已作废的目标"、由一次循环内部决定跳过谁 —— 表达不了"每个目标各有一次独立时机"，而且"被闪掉"这件事就没法用取消表达。

### D5 内容包的钩子从「使用」换成「生效」

牌的内容定义不再声明"被使用时做什么"，而是声明**"对这个目标生效时做什么"**（每个目标各调一次，上下文带使用者、牌、该目标）。原来在 `'使用'` 回调里第一句就造成伤害的写法随之消失。**BREAKING**，但当前只有【杀】一个使用者。

「使用」钩子本批直接删掉（不留"存在但没人调"的接口）；将来真需要"使用牌时"的时机再加。

### D6 不引入 `ls.task`，让出协议由 `Effect` 自己定

`ls.task` 的取消通道与我们的主路径错位：它的 `__del` 只 close **挂起**的协程（运行态的取消它不处理），而我们的主路径（【闪】取消当前正在跑的生效）恰恰是运行态；另外它是"一套 Task + 一套 Effect"的双生命周期，取消语义还得在它外面打补丁。所以自己在 `Effect` 层实现，取消/错误收口全部收敛到一处（超时见 D11）。

让出用**我们自己的**协议：`coroutine.yield(原因)`，原因在**这次结算唯一的驱动点**（`apply()` 的循环）里分派 —— 现在只有 `'cancelled'`。**不用** `await.call` / `await.yield` 驱动效果协程：前者把协程里的错误交给它的 `errorHandler`（吞掉），并且 resume 后只检查成败就返回，会把我们 `yield('cancelled')` 的信号丢掉；后者把 resume 的所有权交给答复方，与"`apply()` 独占驱动"直接冲突。

### D7 两类错误、两条路

- **内核契约违犯**（校验不通过、栈乱序、子类未实现结算）：在驱动点 `error(debug.traceback(co, err), 0)` 原样上抛，带上完整协程堆栈。测试里当场红，服务里也是"这个 bug 必须被看见"。
- **内容包代码**（时机订阅者、牌的生效回调）：沿用 `fire()` 的 `xpcall` 逐个隔离 + `log.error`，不让一局崩掉。

### D8 测试可见性：错误记账 + 显式预期（方案 A）

不改 `game-events` 的隔离语义（"一个回调报错不打断其余"、"触发本身不失败"在两种模式下完全一致），改为**把错误变成可断言的账**：

- `server/moe-kill.lua` 的 log 钩子在测试模式下把 error / fatal 记进测试框架的账（复用现成的 `print` 钩子，懒 `require` 测试模块，不给内核引入新概念）；
- `ltest` 在**每个用例结束后**检查账：非空 ⇒ 该用例失败并打印错误文本；提供"声明预期有错误"的入口（如 `M.expectError`），供现有故意报错的用例（重载失败、没有牌表）显式使用。

**备选**：测试模式下把错误重抛。会顶掉 `game-events` 的两条语义，且测试跑的是生产上不存在的分支，只在测试里存在的控制流不可信。

### D9 询问是效果，答案存在它自己身上

`Ask` 是 `Effect` 的子类：构造时给"被问者 + 询问内容"，答案写在实例字段上（供发起方读），`parent` 天然是"谁在问"。因为它是效果，取消与在栈上可见全部免费。回答者由**局**持有（`game` 上可设，像属性系统一样是"一局一份"），测试里注入脚本化回答者，将来前端接线时换实现即可。

本批的询问**当场取答案**：回答者同步返回，回答者拿不出答案就明确失败。"稍后答复"要求最外层调用链能挂起（`game:play` 要能把"还挂起着"交回调用方、答复方接管后续驱动），属会话接线批次（D11）。

### D10 打出 = 取出 + 触发一个时机，去向仍由基础规则决定

「打出」只做"把牌从持有者手上取出"并触发一个收尾时机（与「使用」的去向机制同构）；**内核对牌的去向零知识**，由基础规则订阅该时机把打出的牌放进弃牌堆。理由：`core-*` 的规格里明确写了内核不认识 `手牌` / `弃牌堆`。

**备选**：内核直接"打出并进弃牌堆" —— 破坏内核无区域名的既有约定。

### D11 超时与异步答复推到会话接线批次

本批询问当场取答案，不存在"挂起等答复"，因此 `Effect:setTimeout` 没有用武之地 —— 现在**不**预埋接口。将来做接线时必须一起解决三件事：① 最外层 `apply()` 不能 yield ⇒ "挂起"只能作为结果一路传回 `game:play` 的调用方；② 答复方接管后续驱动；③ 超时（用现成 `moe.timer` + `GCHost:bindGC`，宿主被删时定时器一起删）。

## Risks / Trade-offs

- [整条链必须可让出] 协程里 `yield` 不能穿过不可让出的 C 边界（`include`、`table.sort` 比较器、C 上的 metamethod）→ 记进代码风格约定；真踩到会以 `attempt to yield across a C-call boundary` 立刻暴露，不会静默。
- [既有用例要复核] 结算模型的改变会波及所有"断言结算中抛错 / 依赖一次回调"的用例（273 个里的一部分）→ 实现时逐条跑，红了就改用例而不是改语义。
- [挂起可能没人答复] → 取消（D2）、超时（D11）、回答者（D9）三条兜底同时在，且"无回答者时明确失败"。
- [错误隔离 + 记账需要显式预期] 漏声明会让用例红（可见，不是假绿）；但"故意的错误"会变多一句声明 → 只给真的故意的用例加，其余保持自然红。
- [让出协议只有一个驱动点] 一旦有人绕过 `apply()` 去 resume 效果协程，错误传播与取消都会失效 → 代码风格文档写死：效果协程只能由 `apply()` 驱动，取消的让出只能由驱动点收尾。
- [取消的让出写在 `__del` 里] `__del` 本该是同步的析构钩子，但运行态取消必须当场让出（`coroutine.close` 不能关运行中的协程）→ `Delete` 保持同步，只有 `__del` 里那一行 yield 用行内诊断禁用；该路径只由 `remove()` 触发（它先校验过状态）。
- [隔离不回滚] 内容包回调跑到一半出错会留下半个效果（没有事务语义）→ 本批只保证"记日志 + 跳过"，需要更强保证时另开变更。

## Migration Plan

一次性替换，无外部使用者，不做兼容层：

1. 内核：`effect.lua`（协程驱动 + `remove()` + fire）、新增 `ask.lua`、`use-card.lua`（逐目标生效 + 新钩子）、`game.lua`（回答者/驱动入口）、`desk`（行动顺序排序）、`env-meta.lua`（时机与新钩子的类型面）。
2. 内容：`package/标准/卡牌/杀.lua` 改写、新增 `闪.lua`、基础规则订阅"打出后"的去向。
3. 测试：改既有用例 + 新增取消/挂起/超时/错误记账用例。
4. 文档：`moe-kill-dev`（挂起模型、错误口径、异步标注约定）、`sanguosha-rules` §7。

回滚策略：整个变更是内聚的一次切换（内核 + 唯一使用者），出问题按 commit 粒度回退，不需要灰度。

## Open Questions

- 「生效」「即将生效」这两个内容名的最终叫法（中文词，实现时定；规格用中文词描述行为，实现时保持一致）。
- 询问内容的形状（"是否打出一张【闪】"如何表达成结构化的问句）—— 本批只需表达杀的响应，形状可以最小。
- 异步答复的落点（会话接线批次）：“还挂起着”如何交回 `game:play` 的调用方、答复后由谁继续驱动。
