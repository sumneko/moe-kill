# Proposal

## Why

内核件已经够跑「一张牌」了（用牌 / 打出 / 询问 / 伤害 / 挪牌 / 效果栈 / 挂起），内容侧也有牌堆、身份开局、体力、攻击范围、【杀】与【闪】—— 但**没有任何东西在推进时间**：没有回合、没有阶段、没有摸牌、没有弃牌。于是：

- 【杀】的「出牌阶段限一次」、技能的「出牌阶段发动」这类规则**无处安放**；
- 验收硬约束（**无头时也能通过导出接口跑完整对局测试**）目前做不到 —— 一局跑不起来；
- `standard-cards` 与 `sanguosha-rules` 都写着「回合与阶段留给后续变更」，这笔债该还了。

## What Changes

- **新增「回合流程」**：`准备 → 判定 → 摸牌 → 出牌 → 弃牌 → 结束`（口径见 `sanguosha-rules` §3：摸牌阶段摸 2 张、弃牌阶段手牌数须降到当前体力值、首回合由主公开始 —— 主公坐 1 号位，按座位递增的行动顺序天然满足）。
- **回合与阶段都是时机**：`'回合-开始'` / `'回合-结束'`、`'阶段-开始'` / `'阶段-结束'`（上下文给出这次是哪个阶段、谁是回合角色），技能与规则按需挂上去。
- **新增「摸牌」这一内容侧动作**（从 `抽牌` 拿 N 张进 `手牌`；抽空时的口径见 Open Questions）—— 回合流程需要它，将来的【无中生有】也要它。
- **出牌阶段需要问玩家**（用哪张牌、打谁、还是结束阶段）⇒ 内核按需补一个**通用决策询问**（`Ask`：问什么 / 答什么都由发起方解释，与 `AskCard` 的「要一张牌」并列；出牌阶段的答复可以是「用这张牌 + 这些目标」或「结束阶段」）。弃牌阶段同样用它（答复 = 要弃的牌）。
- **本批不做**（各自另开变更）：判定区与判定结算、装备与距离修正、濒死（体力 ≤ 0 的插入结算）与胜负判定、无懈可击、武将技能、【杀】的次数限制（它要等「出牌阶段的次数口径」与技能的"使用前"钩子一起定）。

## Capabilities

### New Capabilities

- `turn-flow`: 回合与阶段的推进（阶段顺序、每阶段的时机、摸牌、出牌阶段的驱动、弃牌、交给下一个存活角色）。

### Modified Capabilities

- `core-decision`（新增能力，若本批补 `Ask`）: 内核提供**通用决策询问**（问什么、答什么都由发起方解释），与 `core-response` 的「要一张牌」并列。
- `base-rules`: 补「摸牌」动作与「手牌」区的产出（摸牌阶段把牌从 `抽牌` 移到 `手牌`）。

## Impact

- 内核：`server/core/ask.lua`（新，通用询问）或扩 `ask-card.lua`；`server/core/game.lua`（入口）；`server/core/loader/env-meta.lua`（新时机与新入口的类型）。
- 内容：`package/@基础/回合.lua`（新）、`package/@基础/摸牌.lua`（新，或并进回合文件）；`package/身份场/开局.lua`（若要写"回合角色"状态）。
- 测试：`server/test/rule/turn.lua`（新）+ `server/test/driver.lua` 一类**脚本化玩家控制器**（出牌 / 弃牌的应答脚本）；`server/test/rule/support.lua`（开局辅助要能跑回合）。
- 规格与文档：新增 `turn-flow`（+ 可能的 `core-decision`）；`base-rules` 补摸牌；`sanguosha-rules` §3 把「已实现 / 本批不做」划清；`moe-kill-dev` 的 `architecture.md` 补「流程怎么被启动」。

## Open Questions（动手前要先定，见 design.md）

1. **回合流程住在哪一层**：内容包（`package/@基础/`）还是装配侧的「流程」模块？—— 决定了它怎么被启动、能不能被扩展包覆盖。
2. **抽牌堆抽空时**：是否按标准版口径「把 `弃牌` 洗混成新的抽牌堆」？不确认就实现会踩规则口径。
3. **本批边界**：弃牌阶段要不要一起做（它需要"选牌"的决策与挪牌，但会让本批明显变大）；【杀】限一次要不要一起做。
