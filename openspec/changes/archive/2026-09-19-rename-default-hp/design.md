# Design

## Context

- 现状：`package/@基础/配置.lua` 写 `体力上限 = 4`，`package/@基础/体力.lua` 读它并把每个玩家的 `体力上限` 与 `体力` 都设成这个值；身份场的主公再 `add(+1)`。名字叫「体力上限」容易让人以为这是"规则规定的上限"，其实它是**开局初值**（同时也是上限的初值）。
- 用户口径（2026-09-19）：改名 `默认体力`，值设成 5。

## Decisions

### D1 名字叫 `默认体力`：它描述的是"开局给每个玩家多少体力"

- 这个值同时充当了两件事：玩家的 `体力上限` 初值、以及玩家的 `体力` 初值（因为「体力初值 = 上限」）。
- 所以它**不是**"规则上限"（上限还会被主公 +1、将来被武将改写），只是"没别的信息时的默认体力"。
- 属性名 `体力` / `体力上限` 保持不动 —— 改的只是这条**规则数值的键**，调用点（`attrs:get('体力上限')`、`define('体力上限', ...)`）不受影响。

### D2 默认值 4 → 5

- 纯数值调整（用户口径），期望值连带改：普通人 5、主公 6。测试与文档里所有"4 / 5"的期望一并跟着改。

## Risks / Trade-offs

- [文档与规格里散落着"默认 4"的说法] → 一并改：`sanguosha-rules` §1 的已实现口径与 §9.1 示例、`architecture.md` §9.7 的示例、`base-rules` 规格。
- [老包如果自己写过 `rule:setValue('体力上限', ...)` 覆盖] → 这是行为变更（那个键不再被读），但本批还没有这样的包；将来第三方包要覆盖开局体力就写 `默认体力`。
