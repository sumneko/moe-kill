# Design

## Context

- 官方时序（三则依据）：Ch1/S1 雌雄例 —— 「指定第一个目标（钟繇）后……**然后**指定第二个目标（伏皇后）后……」（**逐目标**）；Ch1/S2 无双例 —— 「在此【杀】**指定目标后**发动【无双1】，**首先对蔡文姬进行结算**……轮到对 A 进行结算」（指定目标后 **先于**任何目标生效）；Ch2/S7 —— 「成为目标时发动【千幻②】取消，【铁骑】的时机（指定目标后）就没有了」（它排在「成为目标时」之后）。
- 现状：青釭 / 雌雄借 `'卡牌-结算前'`（牌进处理区后的通知点，整张牌一次）当近似，技能自循环 `actionOrder` 处理全目标；两个订阅者之间还会出现「各自跑完所有目标」的顺序。

## Goals / Non-Goals

**Goals:**

- 逐目标、结算之前的「指定目标后」独立成时机（名字与份数由用户定）。
- 青釭 / 雌雄迁过去，不再自循环。

**Non-Goals:**

- 「成为目标时」/再入标/编号重排、同时机多技能排序、对牌使用侧。

## Decisions

### D1. 位置：在 `'卡牌-结算前'` 之后、牌的 `'使用'` 钩子之前

`UseCard:settle()` 的次序成为：校验 → 记账 → 牌进处理区 → `'卡牌-结算前'`（全局 + 使用者）→ **逐目标「指定目标后」（本轮新增）** → 牌的 `'使用'` 钩子 → 逐目标 `CardEffect` → `'卡牌-结算后'`。

- 官方「指定目标后」先于**牌的结算**（五谷亮牌 / 延时锦囊置判定区都是结算的开头，在我们的模型里就是 `'使用'` 钩子）⇒ 插在钩子之前。
- 它与 `'卡牌-结算前'` 不合并：后者是「整张牌开始结算了」的粗粒度通知点，保留（青釭 / 雌雄迁走后暂无消费者，留给将来的粗粒度需求）。

### D2. 逐目标 + 三份（用户定名与份数）

```lua
for target in self.game.desk:actionOrder(self.targets) do
    self.game:fire('卡牌-指定目标后', self, target)
    self.user:fire('卡牌-来源-指定目标后', self, target)
    target:fire('卡牌-目标-指定目标后', self, target)
end
```

- 每目标一轮、按 `desk:actionOrder`（官方多角色结算顺序）。
- 份数照「全局先发、再对当事人发」的惯例；这个时机有**两个**当事人（使用者、目标）⇒ 全局 → 来源 → 目标（顺序照 `'效果-来源-能否生效'` / `'效果-目标-能否生效'` 的先例）。
- 载荷统一 `(useCard, target)`。
- 只 `UseCard` 发（`UseCardToCard` 的对牌使用没有角色目标、没有消费者，不发）。

### D3. `skipEffect` 照发

`skipsEffect` 跳的是「生效」（不建 `CardEffect`）；「指定目标后」属于使用流程的一部分（延时锦囊被指定时也有这个时机，它的「置进判定区」写在 `'使用'` 钩子里）⇒ 声明 `skipEffect` 的牌照发。

### D4. 青釭 / 雌雄迁移

- 青釭：`owner:on('卡牌-来源-指定目标后')`，对**这个目标** `useCard:bindGC(target:addBuff('防具无效', useCard))`（从「一次做完」变逐目标；窗口语义不变 —— 状态仍挂给那次使用）。
- 雌雄：`owner:on('卡牌-来源-指定目标后')`，处理**一个**目标（原来的 `for` 与 `goto continue` 删掉、改 `return`）。
- 好处：两个订阅者之间从「各自跑完全目标」变成官方的「按目标分组」。

### 用例面

| 场景 | 期望 |
| --- | --- |
| 两个目标 | 每目标三份：`全局2 → 来源2 → 目标2 → 全局3 → 来源3 → 目标3`，全在 `'使用'` 钩子与「生效」之前 |
| 非目标角色 | 收不到 `'卡牌-目标-指定目标后'` |
| `skipEffect` 的牌 | 照发（三份），但照旧不进「生效」 |
| 零目标 | 不发（循环不跑） |
| 青釭窗口内换防具 / 半路收局 | 行为不变（订阅点换到新事件） |
| 雌雄一组 | 行为不变（同一顺序） |

## Risks / Trade-offs

- **与官方仍差一层**：「成为目标时」（【求援】再入标）与同时机多技能排序没做 —— 记录在 `sanguosha-rules` §9.11 与 `HANDOVER.md`。
- 事件从一个变三个（每目标三份 fire）；订阅者少时开销可忽略，全量套件用时不变。
