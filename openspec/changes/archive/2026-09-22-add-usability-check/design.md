# Design

## Context

出牌阶段现在这条链是：`game:askCard(回合角色, '出牌', {})` → 应答方自己从手牌里挑一张（连目标一起答）→ `game:useCard(玩家, 牌, 目标)`。**"能不能用"没有任何检查**：`UseCard:settle()` 只校验「牌在手 / 有牌名 / 有内容定义 / 有「获取目标」/ 目标非空且是合法目标的子集」，且失败全走 `error`、失败点在 `zone:take()` 之前 —— 牌没动，于是"答复不变 ⇒ 一直转"（靠 1000 次的有界循环兜住）。

相关既成口径（不要在本批推翻）：

- **内核零语义**：`reason`（缘由）与旧的 `condition`（匹配条件）都是"发起方定、内核原样带给规则层"的不透明值（`architecture.md` §12）。
- **内核零区域名**：内核不预设「手牌 / 弃牌」，区域名是内容侧的事（`@基础/牌堆.lua` 建区）。
- **`error` 只表示报错**，不许拿来跳出（`code-style.md` §10）。
- **前端不做规则判断**（`moe-kill-dev` §1）：可选什么必须由后端算好。

## Goals / Non-Goals

**Goals:**

- 内核给出一套**唯一的「能不能用」判定**（`game:canUse`），供**两个消费点**共用：出牌阶段**筛选项**、`useCard` 结算前**二次校验**。
- 把「用不了」从"报错"变成"正常结果"：`reject` 进 `.err`，不触发错误处理器、不记成故障。
- 询问带上**合法选项**（发得给客户端），并且**答复必须落在选项里**才收。
- 【杀】每出牌阶段限一次（数据表，将来靠改数据放宽）。

**Non-Goals:**

- 不做可等待的（要问玩家的）使用前判定 —— 校验条目**必须同步**。
- 不做装备 / 距离修正 / 锦囊 / 无懈可击 / 武将技能的规则本身（它们以后挂同一套校验）。
- 不做询问的超时与 race（`timeout` / `askSkill` 那批）。
- 不动 `Ask`（弃牌阶段还在用）。

## Decisions

### D1 两侧都做，但校验只有一份（用户 2026-09-22 定）

用户原话：**"ask 和 use 两边都要做。ask 负责筛选牌和可用目标发给客户端，客户端回复后 use 要进行二次校验"**。

```
        ┌──────────── 一份校验（内建条目 + 内容侧条目）────────────┐
        │                                                          │
ask 侧：筛选 ⇒ 选项 = 「能用的牌 → 它的可用目标」⇒ 带给客户端
use 侧：settle 前再跑一次 ⇒ 不过就 reject（不取牌、不结算）
```

- ask 侧筛选**就是**"对每张手牌跑一遍 `canUse`" ⇒ 两侧天然同一口径，不存在"筛的时候能用、用的时候说不能用"的漂移（除**时序**造成的差异：客户端想半天，期间该玩家又用了别的牌 ⇒ 二次校验正是为这个兜底）。
- 二次校验**不能省**：答复来自外部（协议 / AI），必须当外部输入看待（`code-style.md` §9）。

### D2 校验是「一个普通函数 + 一个普通事件」（不造对象）

用户 2026-09-22 定：**`canUse` 用 `Effect` 不合适 —— 筛选一遍手牌就调用十几次，量很大；做成普通函数 + 普通事件就行**。

```lua
--- 这张牌此刻能不能用（能用就给合法目标）
---@param user Player
---@param card Card
---@param targets? Player|Player[] # 要校验的目标（省略 = 只判「此刻能不能用」）
---@return boolean ok
---@return any reason             # 不能用时的原因；能用时为空
---@return Player[]? legalTargets # 能用时的合法目标（非空）
function M:canUse(user, card, targets) end
```

- **落点**：`game.lua` 上的普通方法 —— **没有** `UseCheck` 类、**没有** `moe.useCheck` 门面（它不进记牌器、不 `settle()`、不 `await()`，本来就不是「效果」）。
- **内建条目**（就是现在 `UseCard:settle()` 里那 8 条，逐条改成"返回原因"而不是 `error`）：牌没牌名 / 没有同名内容定义 / 使用者手上没有这张牌 / 没声明「获取目标」/「获取目标」没返回列表 / 合法目标为空 / 未指定目标 / 目标不在合法目标里。
- **内容侧条目 = `'卡牌-能否使用'` 时机**：内建条目全过之后 `game:fire('卡牌-能否使用', { user = user, card = card, targets = targets })`；**名字用疑问式（能否…）** —— 约定「**疑问式的名字 = 期望返回值的事件，返回值即结论**」，与 `'卡牌-结算前'` 这类通知型事件一眼分得开（写进 `architecture.md` §10 的命名约定）。
- **不能用"试一次 `useCard`"代替**（用户指出过）：`Effect:apply()` 会把根效果记进局上的**只增记牌器** ⇒ 筛选一遍手牌 = 灌进一堆垃圾效果。
- **校验条目必须同步**：`canUse` 在筛选里逐张手牌跑（一副手牌十几张），条目里 `await` 会把它变成"每个候选都挂起一次"。要问玩家的（"你确定要用吗 / 是否发动某技能"）留给以后单独的可等待时机。

**事件系统的「快速返回」**（用户 2026-09-22 定：**"任意触发中明确返回了返回值后就跳过之后的事件，并以该返回值为结果"**）：

- **落点**：`server/tools/simple-event.lua` 的 `fire` —— **照搬件改动，用户已同意**（记账到 `infrastructure.md` 的照搬件表）：循环里收 `xpcall` 的返回值，**第一个返回值非 nil 就立刻返回它并停止调用后续回调**；一圈下来谁都没返回值 ⇒ 返回空。`server/core/event.lua` 的 `M:fire` 把结果透传给调用方。
- **必须同时看 `ok` 标志**：`log.error` 自带堆栈**并把消息作为返回值返回**（`code-style.md` §6），而 `xpcall(callback, self.onError, ...)` 在回调报错时也会产生一个非 nil 的"结果" ⇒ 报错**不该**被当成"明确否决"。实现用 `table.pack(xpcall(...))`：`pack[1]` 为真 且 `pack[2] ~= nil` 才算快速返回。
- **递归 fire 天然没问题**：返回值是靠 `return` 从循环里带出去的，**不共享任何跨调用的状态**（没有"短路标志"可串）⇒ 内层触发不会污染外层。
- **否决的判据**（用户 2026-09-22 定）：`nil` = 没意见（继续问下一个）；**任何非 nil 返回值 = 否决，且该值就是原因** —— `return false`（无原因）或 `return '本阶段已经用过「杀」了'`（带原因），一个返回值就把原因带出来了。
- **代价**：所有现有时机的回调都要过一遍"有没有意外返回值" —— 有返回值就会**短路掉后面注册的回调**（注册顺序即优先级 ⇒ "谁先说话谁算数"）。本批实现时逐处核（`@基础/抽牌.lua` 里那个 `return true/false` 是局部函数、不在回调本体上，但要确认）。

### D3 「用不了」= `reject` 进 `.err`，不是 `error`（用户 2026-09-22 定）

用户原话：**"不用 error，但是要调用 reject 进 .err"**。

- `Effect` 加一个 `reject(原因)`：`task:reject(原因)` + **就地让出**（`if moe.task.getCurrentTask() == self.task then coroutine.yield() end`）—— 照搬 `Task:cancel()` 的写法：`Task:execute` 发现"任务已结完但执行体还挂着"就 `coroutine.close` 收掉它 ⇒ `reject` 之后的代码再也不会跑。
- `UseCard:settle()` 改成：`local ok, reason = game:canUse(user, card, targets)`；`not ok` ⇒ `self:reject(reason)`（**不 `zone:take()`、不触发 `'卡牌-结算前'`**）；`ok` ⇒ 照旧 take → 结算 → 收尾。
- **与今天的差别不是"有没有 `.err`"**（今天 `error` 也被 `Task:execute` 的处理器收进 `.err`），而是**语义**：`error` 会走全局错误处理器（测试的错误日志计数当故障），`reject` 是**正常结果**。
- 顺带的形状变化：`.err` 从"错误对象（带 traceback 的字符串）"变成**原因**（内建条目各自的中文短句 / 内容侧回调给的值）—— 用例里的断言跟着改。
- **`.err` 不能是 falsy 值**：回调只 `return false` 时归一成一句通用原因（否则调用方 `if effect.err then` 会把失败看成成功）。

### D4 询问的第三参数：`condition` → `options`（合法选项）

```lua
---@class AskCard.Option # 一个合法选项：可以用 / 可以打出的一张牌
---@field card Card
---@field targets Player[]? # 这张牌的可用目标（省略 = 不限目标，如「打出」）
---@field package options AskCard.Option[]? # 挂在询问上（= 第三参数），应答方读 ask.options
```

- **选项由发起方算、内核只持有 + 校验**：内核不解释牌名、不认区名（两条既成口径），它做不到"从手牌里挑闪" —— 会挑错的例子：将来有装备区之后，装备区的牌**不能打出**，内核按"被问者名下所有牌区"枚举就会把装备区的牌也列进候选。所以：**谁发起、谁给选项**。
- **答复校验（内核，写进 `AskCard:answer`）**：答的牌不在选项里 ⇒ `reject('答复不在可选项里')`（`.err` 有原因、`.card` 不存在 —— 对调用方来说与"没答上"同一个分支）；选项给了 `targets` 时，答复的目标必须是它的子集。
- **不给选项 = 不做限制**（与今天等价，留给"确实什么牌都能答"的场合）。
- **`condition` 退役**：它的位置被 `options` 顶掉 —— 上一批留的"内核不解释条件、也不校验答复"是个空洞（谁都能乱答），现在补上。旧口径（`architecture.md` §12、`sanguosha-rules` §6 / §7 里那几段）要同步改。

### D5 出牌阶段：先筛、再问、后用

```lua
local function usableOptions(player)
    local hand = assert(player:getZone('手牌'), '这个玩家没有手牌区')
    ---@type AskCard.Option[]
    local options = {}
    for _, card in ipairs(hand:list()) do
        local ok, _, legalTargets = game:canUse(player, card)
        if ok then
            options[#options + 1] = { card = card, targets = legalTargets }
        end
    end
    return options
end

local function playPhase(player)
    for _ = 1, MAX_PLAY_COUNT do
        local options = usableOptions(player)
        if #options == 0 then
            return                       -- 没有能用的牌：不问、直接结束阶段
        end
        local ask = game:askCard(player, '出牌', options)
        if not ask.card then
            return                       -- 答不上（含答复被拒收）：结束阶段
        end
        game:useCard(player, ask.card, ask.targets or {})
    end
end
```

- **每轮重新筛**：用掉一张牌（或【杀】用完次数）之后选项就变了 —— 重筛是最省事也最不会错的做法（前端拿到的永远是最新候选）。
- **没有可选项就不问**：问一个注定答不上的问题没有意义（也让测试里的脚本应答方少一条"垫"答复）。
- **`MAX_PLAY_COUNT`（1000）保留**：它管的是**规则允许无限出牌**这种打法的终止条件（用户 2026-09-22 定），不是用来兜"答复用不了的牌"的了（那个已经由筛选项 + 拒收解决）。
- 拒绝的答复 ⇒ `ask.card` 不存在 ⇒ 阶段结束：**宁可结束阶段也不空转**（1000 次兜底仍在，但它不该再被触发）。

### D6 每出牌阶段每牌名限一次：数据 + 阶段作用域的计数

- **落点**：新文件 `package/@基础/使用限制.lua`（用户 2026-09-22 定），内容侧不持模块级可变状态（热重载要求）。
- **数据**（上限表，作用域 = 出牌阶段）：`local PLAY_PHASE_LIMIT = { 杀 = 1 }` —— 将来「诸葛连弩 / 咆哮」这类放宽是**改数据**，不是改流程。
- **计数**：写在**回合角色的标签**上（`player:setTag('本阶段用过', {})` / `getTag` / `removeTag`），`'阶段-开始'`（出牌）建、`'阶段-结束'` 删 ⇒ 作用域天然等于这个出牌阶段，也天然把"回合外用牌不受该限"表达对了。
- **两条钩子**：
  - `'卡牌-能否使用'`（**校验**）：牌名在表里且已达上限 ⇒ **返回原因**（`return '本阶段已经用过「杀」了'`）—— 非 nil 返回值即否决（D2）。这条同时管住筛选与二次校验（D1）。
  - `'卡牌-结算前'`（**计数**）：这次使用已经成立（牌已 `take`）才 +1 ⇒ `'卡牌-结算前'` 只在 `UseCard` 里触发，**打出不算使用**、不会被误计；筛选期的 `'卡牌-能否使用'` 也不会改状态。
- 牌名取自 `card:getLabel()`（与 `UseCard` 查内容定义同一个来源）。

### D7 三处调用点

| 调用点 | 选项从哪来 |
| --- | --- |
| `package/@基础/回合.lua`（出牌阶段） | `canUse` 过一遍手牌（D5） |
| `package/标准/卡牌/杀.lua`（打出【闪】） | 被问者手牌里**牌名是「闪」**的牌（打出没有目标 ⇒ 不给 `targets`） |
| `package/@基础/濒死.lua`（求桃） | 当前被问者手牌里**牌名是「桃」**的牌，`targets = { 濒死者 }`；用 `game:canUse(current, card, { player })` 过滤（桃的「获取目标」自己会筛"已受伤 / 濒死"） |

- 三处都要**重新筛**（选项随牌区变化），但**不预先抽公共函数**：现在只有"筛手牌"这一种形状、内容包之间也没有共享函数的机制（只有 `game:setValue/getValue` 传数据）。等出现第三、四张牌再抽（自底向上、最小可用形状）。

### D8 用例怎么锁

| 用例 | 锁什么 |
| --- | --- |
| `core.can-use`（新套件） | 内建条目逐条（没牌名 / 没定义 / 牌不在手上 / 没「获取目标」/ 钩子没返回列表 / 合法目标为空 / 目标为空 / 目标不合法）、内容侧条目否决（`return '原因'` / `return false`）、**`ok` 时给得出合法目标**、**跑校验不进记牌器**（`game:getEffects()` 不变） |
| `rule.event`（补一条） | **快速返回**：第一个返回非 nil 的回调胜出且**后续回调不再触发**；回调报错（`log.error` 有返回值）**不算否决**；递归 fire 不串 |
| `core.effect.play` | 现有「…报错」那批改成「…用不了」：`.err` = 原因、**牌还在手**、`'卡牌-结算前'` 未触发；`ok` 的路径行为不变（`settle` 顺序、父效果、逐目标顺序、取消） |
| `core.effect.ask-card` | 选项挂在询问上（`ask.options` 读得到）、答复 ∈ 选项才收、**答复不在选项里 ⇒ `.err` 有原因且 `.card` 不存在**、不给选项时不限制 |
| `rule.turn` | 出牌阶段选项只含"能用的牌"（【闪】不在里面）、**没有可选项时阶段直接过**、答一张选项外的牌 ⇒ 阶段结束且牌没动、【杀】用了一张之后选项里没有第二张杀 |
| `rule.slash` | 打出：答一张不是【闪】的牌会被拒收（视为没打出 ⇒ 不受伤） |
| `rule.dying` | 求桃：选项 = 手牌里的【桃】 |

## Risks / Trade-offs

- [改 `tools/simple-event.lua` 是动照搬件] → 用户 2026-09-22 已同意；语义向后兼容（原先返回值被直接丢弃），但要在 `infrastructure.md` 记账，避免以后同步上游时被覆盖。
- [现有回调若有"意外返回值"会静默短路后面的回调] → 实现时逐处审（`package/**` + `server/test/**`）+ 用例锁住；注册顺序即优先级（§10 已有此语义，现在多了一条"谁先说话谁算数"）。
- [`'卡牌-能否使用'` 会在**筛选**时逐张手牌触发（不是每次使用一次）] → 条目必须**只读判定**（不写状态、不 `await`）；要改状态的计数走 `'卡牌-结算前'`（D6）。文档里写明，避免以后有人把"消耗"写进校验条目。
- [选项与答复之间隔着"客户端想多久" ⇒ 可能过期] → 正解就是二次校验（D4）：过期选项里的牌/目标会在 `useCard` 那里被 `reject`；出牌阶段每轮重筛把窗口压到一次询问。
- [`condition` 退役会牵动测试的脚本应答方] → 脚本应答方本来就该按"从 `ask.options` 里挑"来写（那正是前端的形状）；用例顺带把"乱答被拒"锁住。
- [上限放内容侧 ⇒ 绕过流程直接 `game:useCard` 也受该限，但"直接改标签"能绕] → 这是内容侧自己的数据，本工程不做防篡改（`code-style.md` §9）；将来放宽类技能改数据 + 改标签即可。
- [`.err` 从错误对象变成原因 ⇒ 任何按"错误消息字符串"断言的用例会失败] → 本批一并改（那是内部用例，不是对外契约）。
