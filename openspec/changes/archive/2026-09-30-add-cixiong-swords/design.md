# Design

## Context

- 官方描述：当你使用【杀】指定一名异性角色为目标后，你可以令其选择一项：弃置一张手牌，或令你摸一张牌。（攻击范围 2）
- 官方例子（伏完 / 伏皇后）：每个目标各有「指定目标后」，逐个「选择是否发动装备技能【雌雄双股剑】」⇒ 发动权在装备主、选择权在目标、逐目标结算。
- 官方（Ch2/S9）：**没有性别的角色不能判断其他角色与其性别是否相同**。
- 询问家族现状（见 `architecture.md`）：`askCard` / `askUseCard` / `askPlayCard` 共用「条件筛候选、答复给牌」；`Ask`（问什么答什么都由发起方解释）与 `AskPlayer` 走 `'决策-询问'`。

## Goals / Non-Goals

**Goals:**

- 三条基础能力落地（`AskChoice`、`askCard` 张数与答复形状、`player.sex`），都有首用消费者。
- 【雌雄双股剑】技能本体与用例。

**Non-Goals:**

- 精确的「指定目标后」点位、协议层、武将系统、其余技能。

## Decisions

### D1. `askChoice` 的用途与形状（用户 2026-09-30 定）

「是否发动」是**发起方的选择**、不是拿牌 —— 用新类表达：

```lua
game:askChoice(owner, '雌雄双股剑', { '发动' }).choice ~= '发动'
```

- 选项 `any[]` 由发起方给、原样挂在 `ask.options`；答复必须**在选项里**（不在 ⇒ 拒收「答复不在可选项里」）—— 与 `AskPlayer` 的名单校验同口径。
- **取消不用当选项传**（用户 2026-09-30 补充）：否定项（「不发动」）走「没有 choice」那一路 —— 不答 / 答复 nil 即取消（`AskCard` / `AskPlayer` 早有「给 nil 等同没答」的守卫，`AskChoice` 这批补齐）。
- 时机沿用通用决策的 `'决策-询问'` / `'决策-答复'`（`env-meta` 载荷联合类型加 `AskChoice`）；读 **`.choice`**；没答 = 没有 choice（不发动）。

### D2. `askCard` 的「可以不给」= min 0 + 归一化（用户 2026-09-30 定的形状）

目标的「选择一项」不单独问：**给一张手牌 = 弃置；给不出 = 令你摸一张** —— 全部收在一个 `askCard` 里：

```lua
local given = game:askCard(target, '雌雄双股剑', { zone = '手牌', min = 0, max = 1 }).card
if given then
    game:moveCard(given, '弃牌')
else
    owner:draw(1)
end
```

- **无法执行**（没手牌 ⇒ 没候选）与**不想执行**（不答 / 答错 ⇒ 拒收）都归一成「没拿到牌」，调用者只看 `.card`。
- `min?` / `max?` 不填 = 1 / 1（既有调用不受影响）；`answer` 接受 `Card | Card[]`、入库统一成 `Card[]`；`.cards` = 全部（没答 = 空表）、`.card` = `cards[1]`（既有读法一处不改）。
- 拒收三则：张数不在 `[min, max]`（「至少要给 N 张牌」/「至多给 N 张牌」）、不在选项里、重复给同一张。
- `askUseCard` / `askPlayCard` 恒为一张：**不传 min/max** 即默认 1 / 1（它们的条件类型仍共享 `AskCard.Condition`，注释写明「别带」）。

### D3. 性别 = `player.sex` 字段（用户 2026-09-30 定：少用 setTag）

- `@基础/meta.lua`：`---@alias 基础.性别 '男'|'女'` + `---@field sex? 基础.性别`。
- 由将来的**武将系统**写入；两边都已知且不同才发动（缺了就跳过 —— 官方「不能判断」）。
- 不另开「是否异性」帮助函数：现在只有这一个消费者，等【离间】那类落地再提炼。

### D4. 触发点沿用【青釭剑】先例

- 官方时点是「指定目标后」（逐目标）；精确点位（成为目标时 / 逐目标再入标与编号重排）尚未开 —— 青釭剑（同为「指定目标后」）落在 `owner:on('卡牌-结算前')`，雌雄保持一致。
- 逐目标顺序 = `game.desk:actionOrder(useCard.targets)`（与逐目标生效同序）。
- 边界写进 `sanguosha-rules` §9.11：等【享乐】/【流离】那批一起迁移。

### 用例面

| 场景 | 期望 |
| --- | --- |
| 异性 + 给牌 | 顺序「是否发动 → 要牌 → 要闪」；手牌 -1、进弃牌堆；照常掉血 |
| 异性 + 不给 | 装备主摸一张；目标手牌不动 |
| 目标没手牌 | 问了但没有候选 ⇒ 归一化摸一张 |
| 目标答错 | 拒收 ⇒ 一样归一化摸一张 |
| 不发动 | 不问要牌；双方手牌不动 |
| 同性 / 缺性别 | 不发动（问都不问） |
| 旁人用【杀】/ 拆下后 | 不发动 |
| `askChoice` | 选项往返 / 乱序不收 / 不在选项拒收 / 没答 / 答复 nil 等同没答 / 重复应答 |
| `askCard` | 2、2 收两张（`.cards` / `.card`）/ 张数超了就拒收 / min 0 空表合法 / 重复拒收 |

## Risks / Trade-offs

- 「不答 = 选『令你摸一张』」把「主动选另一项」与「超时没答」归一成一类 —— 与既有的「不答 = 弃权」口径一致（麒麟弓 / 无懈窗口同款）；真要区分留给会话层的超时策略。
- `askChoice` 的选项按 `==` 匹配（字符串 / 具名值自然）；放表进去要自己保证同一引用。
- `player.sex` 在真实对局里暂时恒为空（武将系统未做）⇒ 雌雄暂时不会发动，这是**正常态**，不算缺陷。
