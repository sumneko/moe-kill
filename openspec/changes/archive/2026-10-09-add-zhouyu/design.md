# Design

## Context

- 底本：【英姿】「摸牌阶段，你可以多摸一张牌。」；【反间】「出牌阶段限一次，你可以令一名其他角色选择一种花色，然后正面朝上获得你的一张手牌。若此牌花色与其所选花色不同，你对其造成 1 点伤害。」
- 可见性现状（2026-10-09 改过一轮）：`Zone.visible`（默认 `true`）+ `zone:setVisible(true|false|一名或一批角色)` / `zone:isVisibleTo(视角)`，定位 = **协议层遮蔽要读的声明**（不参与候选筛选）。
- 「摸牌数」现状：玩家属性 + `phase:bindGC(owner:addAttr('摸牌数', …))`（【裸衣】`-1`、【突袭】`-1000`）。
- 询问现状：`game:askChoice(被问者, 缘由, 选项数组)`（选项是 `string[]`、结果读 `.result`（`string?`）—— 本批按用户要求收窄了这两处；**不答复 = 空**，没有「强制答复」的开关）；
- 搬牌现状：`Zone:accept(牌|一批)` 是唯一入口（`takeIn` 记 `Zone.Move` → `notifyMoved` 统一发「卡牌-离开区域」/「卡牌-进入区域」）；`game:moveCard(牌, 区)` 是 `MoveCard : Effect` 的便利入口。

## Goals / Non-Goals

**Goals:**

- 周瑜整将落地。
- 把「可见性判定」收成一处（三家共用），并把「**搬动过程**的可见性」补上 —— 这是【反间】唯一需要的机制。

**Non-Goals:**

- **不做牌级可见性**（`Card:setVisible` / 牌上的朝向状态）—— 用户定「card 目前用不到」；语义之争（牌的状态 vs 它在当前区里的状态）留给协议层那批。
- 不改 `Zone.visible` 的既有语义与默认值（`true` = 全员）。
- 不给「可见性」做对象 / 可组合语法（下面 D1 说明为什么）。

## Decisions

### D1. 可见性做成**纯函数模块**，不做成对象

`Visibility` 这套判定现在有三家要共用（区的写入与读取、`moveCard` 的参数、将来协议层的读取），不封装就是三份 `type()` 分支。

- 形状：`server/core/visibility.lua`（`moe.visibility`）= 类型别名 `Visibility` + `normalize(值)` + `isVisibleTo(值, 视角)`。
- **为什么不是对象 / 类**：它的值本身是纯数据（boolean / 一批角色 / 一个谓词），谓词形态没法塞进对象里带着走；三处共用的是**判定规则**，不是一份状态 ⇒ 函数最省。
- `normalize` 只做「单值 ⇒ 一批」，谓词与 boolean 原样（`Zone:setVisible` 沿用这个行为）。

### D2. 两层可见性**正交**（用户 2026-10-09 纠正过两轮）

| | 管什么 | 落点 |
| --- | --- | --- |
| 区（`Zone.visible`） | 这个**区**里的牌默认对谁可见 | 字段长期有效 |
| **搬动**（`moveCard` 第三参） | **这一次移动**对谁可见 | `Zone.Move.visible` + 事件第三参，**不写进牌** |

- 我第一版理解成「搬完之后这批牌在目标区的可见性」，被纠正；
- 第二版理解成「牌的状态（正面朝上）」，又被纠正 —— 用户定：**它只描述移动过程**，与牌自身无关 ⇒ 于是 `Card:setVisible` 本批不做。
- 用户给的判据原话：「允许卡牌正面朝上从一个不可见区域进入另一个不可见区域，也允许背面朝上从一个可见区域进入另一个可见区域」⇒ 两个维度可以任意组合，互不写入。

### D3. 默认（不给参数）由**读的人**算

「源区可见 or 目标区可见」—— 「可见」永远相对某个视角，**存不了单一值**。

- 于是 `Zone.Move.visible` / 事件第三参给的只是**发起方显式声明的那份**，`nil` = 没声明 = 读的人自己按「源区 or 目标区」算。
- 好处：内核零解释（与 `Buff.payload` / `ViewSkill.source` 同一待遇）。

### D4. 落到 `Zone.Move` + 事件第三参（协议层两种读法都有）

- `Zone:accept(牌, 可见性?)` → `takeIn` 逐张把 `visible` 记进 `Zone.Move` → `notifyMoved` 发事件时把它作为**第三参**：牌自己的钩子（`CardDef:on`）与区主人那份（`Player:on` / `SkillDef:event`）都能拿到。
- 备选（否掉）：只在 `Zone.Move` 里、不改进区事件载荷 —— 协议层订阅事件是最自然的读法，少了它就得另找搬动记录。

### D5. 【反间】三块

- **「正面朝上」= 这次搬动对所有人可见**：`game:moveCard(牌, target:getZone('手牌'), true)`。
- **花色格式 `${红桃}`**（用户定）：`askChoice` 的四个选项写成 `'${红桃}'` / `'${方块}'` / `'${黑桃}'` / `'${梅花}'` —— 内容侧拼、协议层认（渲染成花色图标），**内核不解释**；判定直接用同一个格式拼出期望串 `'${' .. (card.suit or '') .. '}'` 相比 ⇒ **不需要解析函数**，也没有「无色」这个选项（牌自己没花色时拼出 `'${}'`，永远匹配不上）。
- **不选 = 总是算「花色不同」**（用户定：「不能作废，否则相当于对方逃避技能效果」）：`askChoice` 不答复 ⇒ `.choice` 为空 ⇒ 与任何选项串都不等 ⇒ 照常给牌 + 造成伤害。
- 伤害来源 = 周瑜（官方「**你**对其造成」）：`game:damage(cast.from, target, 1, card)`（把牌一起传下去，伤害技能能追到来源牌）。

### D6. 【英姿】= 【裸衣】同款 + `auto(true)`

`'阶段-开始'`（认 `phase.name == '摸牌'`）→ `tryCast` 里 `phase:bindGC(owner:addAttr('摸牌数', 1))`。

- 与【裸衣】逐字同款（只差 `+1` 与没有 Buff 那段）；`auto(true)` 因为「多摸一张」是纯收益（【裸衣】少摸一张是有代价的，所以它每次都问）。

## Risks / Trade-offs

- **牌级朝向仍然没有**：协议层要遮蔽「目标手里这张牌公开 / 暗置」时只能靠**区级**（手牌区对他的持有者可见）+ 搬动级，看不到「这张牌是正面朝上的」。真需求来时先定语义（牌的状态 vs 它在当前区里的状态），再决定 `Card:setVisible` 还是别的形状。
- **搬动可见性没有消费者**（除了【反间】这个写入方）：读它的是协议层 —— 现在只有内核用例钉住「参数原样交到事件第三参」。
- **`Zone:accept` 的签名多了一参**：内核内部与测试都能用；内容侧仍应走 `game:moveCard`（口径不变）。
