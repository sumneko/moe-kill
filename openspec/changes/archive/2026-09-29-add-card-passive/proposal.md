# Proposal

## Why

装备的「效果」现在只有一种形状：**进区时往属性上写一条修正 + `card:withZone` 保证离区时撤掉**（`武器牌` / `坐骑牌`）。它能跑通，只是因为现有装备的效果恰好都是「纯属性修正」：

- **装备自带的技能**（诸葛连弩的无限【杀】、八卦阵的替换响应……进度里记着的 8 项）不是属性修正 —— 它们要在生效期间**注册**（订阅时机、放宽限额），失效时**反注册**。没有「生效 / 失效」的生命周期，这些技能无处安放。
- 也缺「**不离开槽位也能停用**」：将来「装备技能无效 / 技能封印」类效果，需要能临时把一件装备的被动压住、再松开，并且支持**多个来源各自压制**（计数互不踩）。
- 顺带一个隐患：`withZone` 是「牌一离开这个区就撤销」的通用兜底，撤销点隐式，且与「装备生效状态」的语义没有绑在一起。把效果的撤销收进一个显式的状态机（启用 / 压制）更可控。

用户定的形状：新增 **『被动』钩子**（效果写在里面、返回撤销函数）＋ 牌的**被动状态**（出厂被压制；启用时应用并记下撤销函数；停用时按记录撤销，幂等）＋ **装备模板负责启停**（进入正确区域的正确槽位才启用，离开就停用）。

## What Changes

- **牌的钩子集合新增第 7 个 `'被动'`**：`on('被动', function (card, zone) ... return 撤销函数 end)` —— 在牌的被动被**启用**时跑一次，回调返回的撤销函数由内核记在牌上。
- **`Card` 新增被动机制**（`server/core/card.lua`）：
  - 每张牌出厂即**被压制**（压制计数 1 = 未启用：被动不生效、也不曾应用过）；
  - `card:enablePassive()` 松开一层：松开到 0 时**同步**跑所有『被动』回调、**记录**返回的撤销函数；
  - `card:disablePassive()` 压上一层：压回到 1 时**先清空记录、再逆序调用**那些撤销函数（幂等：重复压制不会重复撤销、已撤销过再压制无效果）；
  - 两个入口都返回撤销函数（符合「可叠加操作必须返回 disposer」的项目约定）；
  - 计数可叠加：多个来源各自压制 / 松开，谁压的谁松开。
- **`装备牌` 模板接管启停**：进入一个槽位、且槽位名在这张牌的分类里 ⇒ 启用被动；离开该槽位 ⇒ 停用（「正确区域的正确槽位」由内容侧设定的槽位名与牌的分类共同承载）。
- **`武器牌` / `坐骑牌` 的效果迁到『被动』**：加成不再写在 `'进入区域'` 里、也不再挂 `withZone`（行为不变：装上加攻击范围 / 距离修正，拆下即撤；**装备模板里不再有第二条撤销路径**）。
- **`env-meta.lua` 补第 7 条钩子声明**（包作者可见的契约）。
- 用例：内核套件加「被动机制」一组、`rule.equip` 加「进槽启用 / 离槽停用 / 压制与恢复」；文档更新（`moe-kill-dev` 的 references）。

## Capabilities

### New Capabilities

- `core-card`: 卡牌实例与内容定义的运行时机制 —— 固定钩子集合的新成员『被动』、牌的被动状态（出厂压制 / 启用时应用并记录撤销 / 停用时按记录撤销 / 计数可叠加 / 撤销幂等 / 同步调用）、装备在正确槽位里启用被动的约定。

### Modified Capabilities

无（`core-play` 的用牌流程、`core-zones` 的牌区契约都不动；本批只给卡牌加机制、给装备换承载）。

## Impact

- `server/core/card.lua`（被动机制）、`server/core/loader/env-meta.lua`（钩子声明）
- `package/@基础/卡牌/装备牌.lua`（启停）、`package/@基础/卡牌/武器牌.lua` / `坐骑牌.lua`（迁移到『被动』）
- 用例：`server/test/core/card.lua`、`server/test/rule/equip.lua`（既有装备用例应一行不改、保持全绿 ⇒ 行为等价）
- 文档：`moe-kill-dev` 的 `references/{architecture.md,progress.md}`
- 行为变化仅限新能力：既有对局行为（攻击范围 / 距离修正的加与撤）保持等价；`Card:withZone` 接口保留（只是装备模板不再用）

## Non-goals

- **装备自带技能的实现**（诸葛连弩 / 八卦阵 / 仁王盾……）—— 本批只做地基，技能各自仍是一个功能点。
- **『被动』里发动结算**（比如「进装备区摸一张」）—— 它保持**同步**的「应用 / 撤销」；要发结算归别的钩子（`'进入区域'` 或技能时机）。
- **改 `Card:withZone` 接口本身**（只停用装备模板里的旧用法；删它要单独讨论）。
