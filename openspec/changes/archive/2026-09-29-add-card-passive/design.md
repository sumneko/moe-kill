# Design

## Context

现状（见 proposal.md 的 Why）：

- 内容侧卡牌钩子是**固定集合**（六个：`'进入区域'` / `'离开区域'` / `'获取目标'` / `'获取卡牌目标'` / `'使用'` / `'生效'`），登记在 `CardDef` 上，运行时由 `Card:fireHandlers` **顺序跑全部回调、丢弃返回值**。
- 装备现在的效果形状：类别基类在 `'进入区域'` 里 `zone.owner:addAttr(...)`，撤销函数挂 `card:withZone(...)`。
- `withZone` 的撤销执行点在 `Card:bindZone`（换区时），**早于** `'离开区域'` 的发出；`'离开区域'` 发出时牌**已经不在**那个区里（`unbindZone` 已做）。
- 局级时机（`game:on` / `game:fire`）是另一套：`fire` 遇到第一个非 nil 返回值就停（快速返回），**不适合收集多个回调的返回值**。

## Goals / Non-Goals

**Goals:**

- 给牌加一个「持续效果」的生命周期：启用时应用（可注册 / 可加修正）、停用时撤销；要能叠加压制、且撤销幂等。
- 装备的启停跟随槽位；武器 / 坐骑迁移后行为与现在**逐字等价**（既有用例一行不改、全绿）。
- 撤销路径唯一（不能出现「同一修正被撤两次」的路径）。

**Non-Goals:**

- 不做装备自带技能（本批只铺地基）。
- 不动 `Card:withZone` 接口本身（只停用装备模板里的旧用法）。
- 『被动』不发起结算、不让出（同步语义）。

## Decisions

### D1. 『被动』做成第 7 个固定钩子，而不是局级时机

要在一处**收集每个回调的返回值**（撤销函数）。局级时机的 `fire` 是「第一个非 nil 返回值即停」，语义正相反；固定钩子本来就是「全部跑一遍」。所以：

- `env-meta.lua` 的 `CardDef` 重载里加一条：`on('被动', fun(card: Card, zone: Zone): (fun())?)`；
- 触发由内核（`Card`）自己驱动，不经过 `game:fire`。

备选：`game:on('xxx')` + 订阅方各自收集（否决：快速返回截断收集；且「牌的效果」理应挂在牌上，不用局级时机表达）。

### D2. 出厂即被压制（计数初始 1），不需要「创建时调一次 disable」

用户定的「装备默认禁用」，用「内核不自动启用任何牌的被动」来实现：

- 压制计数出厂 = 1（未被启用）；普通牌没有『被动』回调，初始值无观察差异；
- 免得为「创建时执行一次」新增创建期钩子；「默认禁用」不再需要装备定义额外声明。

### D3. 实例状态与边界动作

`Card` 上加两份实例状态：压制计数（`passiveSuppress`）与本次应用的撤销函数记录（`passiveDisposers`）。

- `enablePassive()`：计数 −1；减到 0 时**同步**跑 `def:getHandlers('被动')` 的每个回调（直接调用），把非 nil 返回值收进记录；
- `disablePassive()`：计数 +1；加回 1 时**先取出并清空记录、再逆序调用**（后应用的先撤销）——「先清后调」是幂等的来源：重复压制 / 已撤销过再压制都不会重复调；
- 两个入口都返回 disposer（项目约定）：enable 返回「再压一层」、disable 返回「再松一层」；**先改计数、再执行动作**，重入（撤销函数里又 enable/disable）时状态不漂。

备选：把效果描述存下来、停用时重放（否决：disposer 记录更直接，且应用本来就是幂等重来的）；只用一个布尔（否决：不支持多来源叠加压制）。

### D4. 装备模板的启停条件：`slot and card:isKind(slot)`

「正确区域的正确槽位」由两件事共同承载：槽位名是**内容侧在装备区设的**（`@基础/装备.lua` 的 `setSlots`），牌的分类与槽位名同名。所以装备模板只需要：

- `'进入区域'`：`slot` 存在且 `card:isKind(slot)` ⇒ `card:enablePassive()`；
- `'离开区域'`：同样条件 ⇒ `card:disablePassive()`（发出时牌已不在区里，但槽位名在参数里）。

公共区 / 手牌 / 处理区不是槽位区（`slot` 为 nil）⇒ 自动跳过；「进了错的槽位」（分类里没有这个槽位名）⇒ 不启用。

### D5. 迁移后装备不再用 `withZone`（撤销路径唯一）

`withZone` 的撤销在 `bindZone`（换区）时执行，比 `'离开区域'` 钩子更早；如果保留它、又由 `disablePassive()` 撤销，**同一个属性修正会被撤两次**（离开后修正变负）。迁移时一律去掉：

- `武器牌`：`'进入区域'` 改为 `'被动'` —— `return zone.owner:addAttr('攻击范围', range - 1)`；
- `坐骑牌`：`'进入区域'` 改为 `'被动'` —— 按分类判修正属性名（`card:isKind('进攻马')` ⇒ `进攻修正`，否则 `防御修正`），`return zone.owner:addAttr(name, card:getValue('距离修正'))`；原「槽位名 → 属性名」的映射表不再需要（启用条件已保证是正确槽位）。

`Card:withZone` 接口保留（其它场合仍可用；要删单独讨论）。

### D6. 回调载荷与同步语义

- 『被动』回调收 `(card, zone)`：`zone` = 触发时牌所在的区（`card:getZone()`），回调能从 `zone.owner` 读持有者；
- 启用 / 停用**同步**执行（直接调用回调 / 撤销函数，不另起任务、不让出）；『被动』不是结算 —— 要发结算归别的钩子。

### D7. 契约与文档

- `env-meta.lua` 补第 7 条钩子声明（包作者可见）；
- `moe-kill-dev` 的 `references/architecture.md`（钩子清单处）与 `progress.md` 更新；
- 「撤销函数要在应用时捕获上下文」写入文档提醒（`'离开区域'` 时牌已不在原位；`addAttr` 的撤销自带精确回退，写技能类被动时要自己存）。

## Risks / Trade-offs

- **[双撤] 迁移漏掉某处 `withZone`** → 既有 `rule.equip` 用例断言「离开装备区后修正回到原值」，双撤会让它失败（修正变负）⇒ 迁移后**先跑全量用例**再继续。
- **[重入] 撤销函数执行期间又 enable/disable** → D3 的顺序（先改计数、后执行动作）保证嵌套时边界判断基于新状态；不做额外防御（正常流程不会出现）。
- **[顺序] 『进入区域』处理途中被动已生效** → 被动在装备模板的『进入区域』回调里同步启用；同批次其它『进入区域』回调若关心「被动是否就绪」需按登记顺序（基类在前）对齐 —— 现在没有这类回调，记入文档。
- **[回退] 需要回退本批** → 单批内自洽：把装备两个模板改回 `'进入区域'` + `withZone`、删掉 `Card` 的两个方法与钩子声明即可；用例还原到本批之前。
