# Proposal

## Why

客户端要能「看到盘面」，而一切交互都建立在这份视图上：询问要把候选摆给玩家看、答复要指回具体的牌、动画要知道牌从哪飞到哪。目前后端只有玩家基础信息与 `custom` 的下行（`Player.Update`），**区域与卡牌的下行完全没有** —— 客户端手里一张牌也没有，`askCard` 也就没法接。

## What Changes

- 新增**卡牌同步协议**（下行通知）：客户端持有一份「卡牌实例」视图，实例的生命周期由后端驱动。
- **卡牌实例是不可变的**：任何变化都用三种通知表达 ——
  - `Card.Create`：出现（含开局把场上所有牌灌一遍）；
  - `Card.Remove`：消失（按 id 列表）；
  - `Card.Update`：**原地更新**（id 不变）—— 用于转化、翻明这类「没换区」的变化，免得重播动画、打乱客户端自己排好的手牌顺序。
- **`Card.Move` 是动画专用的预通知**：搬牌那一刻**当场发**（带 `from` / `to`），并保证在 `Card.Remove` 之前到达。
- **判定口径**（用户 2026-10-10 定）：卡牌变化后**置脏**；flush 时把「新的 `Proto.Card`（沿用旧 id）」与「上一次同步出去的那份」逐字段比 ——
  - 完全一致 ⇒ 什么都不发；
  - 有变化、且**协议 zone 相同** ⇒ `Card.Update`；
  - 有变化、且**协议 zone 不同** ⇒ 更新 id + `Card.Remove` + `Card.Create`。
  每次搬牌时另外算一次协议 zone，与搬之前不同才发 `Card.Move`。
- **协议 zone 只认「玩家 + 区名」**：临时区（既没有名字也没有归属）在协议里一律是同一个空 zone ⇒ **临时区之间互移不算 zone 变化**，既不发 `Move` 也不换 id。
- **视图与 id 住在传输层、每个连接各一套**（用户 2026-10-10 定）：协议用的 id **不进内核** —— 由 `server/transport/card-sync.lua` 按**每个连接**维护一份「这个客户端当前看见的卡牌视图」，id 由这个连接自己的号源分配。内核的 `Card` **不加任何协议字段**。
- **背面牌的 id 是匿名代号**：对某个连接而言，看不见内容的区里每张牌都只有 id（没有牌面），客户端只知道「这个区里有几张」。因此**从这种区移除牌时，从该客户端看到的该区背面牌里随机挑一个 id** 移除 —— 否则「移除 + 创建」是对称的，客户端能把刚消失的匿名牌与刚出现的明牌配起来，学到一个它不该知道的事实。
- 组装**按收件人视角裁剪**（沿用 `Player.Update` 那套「每个有 `user` 的玩家各组装一份」）：看不见的牌省掉 `template`（客户端渲染成背面），不泄露牌面。
- 批量：`Remove` / `Create` / `Update` 攒到一次调度末尾合并发（与 `player.custom` 的置脏 + flush 同一套）；`Move` 例外，当场发。
- 内核**完全不动**：不新增字段、不改任何构造签名。`Card` 上那个由 `game:nextId()` 发的 `id` **留着当调试号**（用户 2026-10-10 定）—— 它只被 `Card:__tostring` 读、与协议无关，协议用的 id 只在连接侧的视图里（见上一条）。

## Capabilities

### New Capabilities

- `card-sync`: 区域与卡牌的下行同步协议 —— 卡牌实例的生命周期（创建 / 移除 / 原地更新）、移动动画的预通知、按视角裁剪（背面牌），以及「哪些变化要发、该发哪一条」的判定口径。

### Modified Capabilities

（无。不涉及任何已有规格的需求 —— `Card.id` 的语义变化在现有规格里没有描述，`core-card` / `core-move` / `hot-reload` 三份相关规格都核对过。）

## Impact

- **新增**：`server/transport/card-sync.lua` —— 每个连接一份卡牌视图（`id → Proto.Card`）、视图 id 的号源、脏卡表、四类通知的组装与 flush；`moe.cardSync` 门面。
- **改动**：`server/user/*`（新增一条卡牌数据的下发出口，与 `update` 并列）、`server/core/game.lua`（脏卡表 + 登记一次 flush；`createCard` / `createVirtual` 里那个没人消费的号视情况处理）；内核**不需要认识协议**。
- **接线点**：`'卡牌-进入区域'` / `'卡牌-离开区域'` 两个既有时机，加上 `Zone` 搬牌的收口（`Move` 需要同时看到 `from` / `to`）。
- **协议类型**：`server/proto.d.lua` 里的 `Proto.Zone` / `Proto.Card` / `Proto.CardTemplate` / `Proto.MovingCard` 与四条 `Proto.Notify.Card.*` 已就位。
- **测试**：新增套件覆盖创建 / 移除 / 原地更新 / 移动 / 背面裁剪 / 临时区互移不发 `Move` / 同一笔调度合并。
- **对前端**：这是前端第一次拿到「盘面」契约，后续的询问（`askCard`）与快照 / 重连都建立在它上面。
