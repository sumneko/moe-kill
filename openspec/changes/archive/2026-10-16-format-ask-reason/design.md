## 语法

```
${locale:打出一张 {card}}@{card:杀}
```

| 片段 | 名字 | 做什么 |
| ---- | ---- | ---- |
| `${函数名:内容}` | 模板 | 查**函数表** `tables[函数名][内容]`；查不到就用「内容」原样 |
| `@{名字:值}` | 参数 | 给这次文本的参数；**只解析第一个**，之后的 `@{…}` 原样输出 |
| `{名字}` | 占位 | 换成参数值，用**默认样式**（按名字查颜色表） |
| `{名字#代码}` | 占位（指定样式） | 同上，并用**颜色代码** `代码` 上色 |

## 为什么分成「函数名」与「颜色代码」两层

- **函数名**（`locale` / `suit` / …）= **语义**：这里是句要翻译的话、这里是个花色。
- **参数名**（`card` / `player`）= **类型**：这是个牌名、这是个角色名。
- **颜色代码**（`name` / `warn` / …）= **呈现类别**：画成什么颜色 —— **色值由客户端分配**，内容侧只写代码。

把颜色绑死在参数名上就表达不了「同一个类型要不同颜色」（红牌 / 黑牌、正面 / 负面）。加一层代码的代价只是模板里多一个 `#` 字符。

## 定死的规则

1. **只解析第一个** `@{…}` —— 不需要「参数区」这个概念，也不会有分隔符歧义。
2. **认不出就用原文**：函数名不认识 ⇒ 输出「内容」；缺参数 ⇒ 占位 `{名字}` 原样留着（看得出漏了什么，比默默吞掉好）。
3. **颜色代码认不出 ⇒ 不上色**（不报错）。
4. `locale` 的**值将来可以是模板**（递归展开），带 **`visited`**（记内容 = id）—— **同一个 id 只展开一次**，撞上就不展开、原文留着。这条防住 `%{a:${locale:{a}}}` 这类死循环。

## 落点

| 文件 | 做什么 |
| ---- | ---- |
| `client/src/view/format.ts` | 新增 `formatText(text, tables)`：扫描器拆模板 + 参数 → 片段数组（`{ text, color? }`） |
| `client/src/view/Ask.ts` | `askTitle` 返回值从 `string` 换成片段数组，`reason` 走 `formatText`；抬头按片段渲染（色值内联到 `style`，不另开 CSS 类） |
| `package/标准/…` 5 张牌 | `reason` 改新语法 |

## 客户端拼的那一半

`reason` 之外，客户端自己拼「 → 牌名（A → B）」那段（用户定：拼接是客户端的自由）。两件事都放客户端、**不交给服务器**：

- **配色**：牌名走 `card` 那档、角色名走 `player` 那档；色值由客户端分配。
- **「你」**：任一角色是自己 ⇒ 显示**高亮的「你」**（`me` 那档色）。理由是**视角**：`reason` + `responseTo` 是**广播给所有人**的同一份数据，而「谁是『你』」每个连接都不同 —— 交给服务器就得逐连接生成文案，为一句不值当。

## 取舍

- **扫描器而非正则**：占位可以嵌套在模板里（`${locale:…{card}…}`）、还要找配对的括号，正则写不稳；一个小字符扫描器（含深度计数）更好读也更好测。
- **不用 `innerHTML`**：颜色代码来自内容包（外部输入），渲染成 preact 元素 + 内联 `style`，并只在 `#rrggbb` 形状时才用。
- **表格由客户端注入**：`formatText` 不自己持有翻译表 / 颜色表 ⇒ 内容侧与主题解耦，测试也好写（传一张假表即可）。
