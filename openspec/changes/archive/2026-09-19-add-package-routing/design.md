# Design

## Context

- 前置：`add-package-vfs` 提供虚拟文件系统 —— 清单项与依赖项都是**逻辑路径**，逻辑路径第一层已经是「包目录名」（`X` 与 `X/*` 两种来源写法都被归一成这一形状）。
- 现状（`server/rule/init.lua`）：规则表是一张平表 `cards[名字]`，`M.card(name)` 是「取或建」，因此**同名会合并**，同名冲突无法察觉。
- 用户 2026-09-19 定的口径：跨包同名 **合法并存**；裸名路由到**最先加载**（= 优先级最高）的那个包；要指定版本用**限定名**（`军争.杀`）；**同包重名直接报错**（「自己的包自己维护好」）；名字里**不许带 `.`**，完整名由加载器拼。
- 约束：`server/rule/` 是 `require` 加载的**不可重载**模块（状态挂门面表 `M`）；规则集执行环境只注入 `rule` + 标准库白名单。

## Goals / Non-Goals

**Goals:**

- 规则表按包分组，条目归属清晰，同包重名在**加载期**就报错。
- 裸名 / 限定名两种查询，语义确定；两者是同一个对象。
- 条目带来源信息（裸名 / 包名 / 完整名 / 声明文件）。

**Non-Goals:**

- 跨包**改写**别人的定义（本变更没有这个能力：要改就改那个包的文件，或用来源覆盖）。
- 包的**声明式元数据**（版本、依赖声明文件、显示名）—— 只在真需要时再加。
- 名字的模糊匹配 / 别名表。

## Decisions

### D1 包 = 逻辑路径第一层目录，且与来源写法严格对齐

- 包名就是第一层目录名；包内子目录只作组织。这与 `package-vfs` 的两种来源写法天然一致：`X` 的 `X/卡牌/杀.lua` → 包名 = X 的目录名；`X/*` 的 `X/军争/卡牌/杀.lua` → 包名 = `军争`。
- 「根下散落文件」在解析阶段就能判定（逻辑路径只有一段）⇒ 直接报错，不需要额外扫描。
- 包名禁 `.`（与条目名一致）：否则限定名的分隔符无法无歧义解析。

### D2 同包重复声明**报错**，而不是合并

- 合并（旧的「取或建」）会让真重名静默通过；用户要的是「自己的包自己维护好」。
- 代价：跨文件给同一条定义追加回调时，第二个文件不能再用声明入口 —— 必须 `rule.getCard` 拿到同一条再 `:on(...)`，并且要靠 `rule.depends` 保证那一条已经存在（顺序不对会取不到）。
- 备选（未采纳）：声明入口返回「已在别处声明过」的警告而不报错 —— 会被忽略，等于没做。
- 实现要点：每条定义记 **声明文件（逻辑路径）**，报错信息给出两处来源。

### D3 路由实现：包表 + 包顺序表

- 规则表结构：`cards[包名][名字] = 定义` + `packageOrder[包名] = 顺序号`（包的首次出现顺序 = 清单顺序）。
- 裸名查询：按 `packageOrder` 升序找**第一个**有该名字的包；限定名查询：按第一个 `.` 切分后精确查表。
- 不为别名建表：两种写法都**直接返回同一条定义对象**，因此「同一个对象」是天然结果，不需要同步机制。
- `.` 的切分方向：包名禁 `.` ⇒ 第一个 `.` 之前是包名、之后是条目名，无歧义（条目名也禁 `.`）。

### D4 定义入口只在加载期可用；裸名查询带**包内作用域**

- `rule.card`（声明）与 `rule.depends` 一样只在加载过程中有效，加载之外报错 —— 避免「运行期凭空长出一条定义」。
- `rule.getCard`（查询）在加载期与加载后都可用。
- **裸名的解析带作用域**（用户 2026-09-19 补定）：在**包内**（加载过程中、当前上下文有所属包）查询裸名 → **优先取本包**，本包没有才 fallback 到默认路由（按包加载顺序取第一个定义者）；**包外**查询（游戏运行期、内核、测试等没有「当前包」的地方）→ 直接走默认路由。
  - 这与用户最初定的「游戏中使用这个名字时路由到最先加载的版本」一致：游戏运行期没有「当前包」，就是包外语义。
  - 后果：**包内引用他包的同名条目 MUST 写限定名**（军争的代码里想用标准版「杀」要写 `标准.杀`）；写裸名拿到的就是本包版本。
  - 理由：包内代码默认自洽（自己的包自己维护好），跨包引用是例外，显式写出来更安全。
  - 实现方式（「当前包」怎么记、怎么在查询时判定）**按用户要求留到实现时再想**，见 Open Questions。

### D5 条目元数据

- 定义对象带 `name`（裸名）、`package`（所属包名）、`fullName`（`包名.名字`）、`source`（声明它的文件逻辑路径）。
- **字段叫 `package` 时注解要显式写访问修饰符**：LuaDoc 里 `package` / `private` / `protected` / `public` 是访问修饰符，直接写 `---@field package string` 会被解析成「修饰符 + 名字」，于是报 `luadoc-miss-type-name` / `undefined-doc-name`；写成 `---@field public package string # 所属包名`（显式 `public`）就正常。
- 用途：报错信息、日志与排查；前端将来若要显示「这张牌来自哪个包」也能直接用。

## Risks / Trade-offs

- [两套排序方向相反：「来源合并」后者胜 vs 「包路由」清单先者胜] → 在 `architecture.md` 第 9 节与两个规格里都写明方向，并给一个具体例子。
- [包内裸名 = 本包优先 ⇒ 想引用他包同名条目的人容易忘记写限定名] → 包内跨包引用一律写限定名；文档 + 用例各写一份。
- [同包重名报错 ⇒ 多文件协作搭同一张牌变麻烦] → 用 `rule.getCard` + `rule.depends` 的固定写法，并写进 `sanguosha-rules` 的规则集侧写法。
- [清单顺序即路由优先级：调整清单顺序会悄悄改变裸名解析结果] → 路由结果带上完整名（`标准.杀`），排查时一眼可见；用例钉住「先加载的包胜出」。
- [包数量增长后裸名解析要遍历包表] → 包数量级很小（个位数到几十），线性遍历可忽略；真成问题时再加索引。

## Migration Plan

- 内部结构变化（规则表按包分组）；规格 `rule-loading` 的「规则定义入口」被 MODIFIED，`package-routing` 为新增能力。
- 既有测试 `server/test/rule/init.lua` 适配：探针改为「来源目录 / 包目录」结构，定义与查询按包进行，把「同包重复声明」的断言改为报错。
- 回滚 = 还原规则表结构与 `rule.card` / `rule.getCard` 的实现（规格同步回退）。

## Open Questions

- 「当前包」如何判定与实现（在加载上下文里记包名，还是别的机制）—— 用户 2026-09-19 明确要求**留到实现时再想**，不影响规格与任务拆分。
- 将来要不要「跨包覆盖」（例如某包声明替换另一个包的某条目）—— 目前明确不做；真有需求时另开变更，届时要定「替换是整条还是叠加」。
- 包的显示名 / 版本等元数据 —— 等前端要显示包信息时再定。
