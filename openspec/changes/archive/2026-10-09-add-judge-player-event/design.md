# Design

## Context

现状（`package/@基础/判定.lua`，判定 2026-09-28 整体从内核搬到内容侧）：

- `Judge:settle()` = 亮牌（`game:drawCards(player, 1, judge:getTempZone())`）→ `fireReplaceWindow(judge)`（发 `'判定-前'`）→ 发 `'判定-后'`。
- 两条时机都只 `game:fire(…)`（**全局一份**）。消费者：【鬼才】订 `'判定-前'`（「一名角色的判定」都能改）、【洛神】订 `'判定-后'` 并自己筛 `judge.reason == '洛神'`。
- 既有口径（2026-09-30 用户定，`architecture.md` §12）：**对当事人再发一份时，玩家那份带方向词**（`'伤害-开始'` ↔ `'伤害-来源-开始'`）；`'阶段-开始'` / `'效果-收尾'` 是**早期同名两份**（无方向可用，未追改）。

## Goals / Non-Goals

**Goals:**

- 「**你的**判定」类技能不再需要自己筛 `judge.player`。
- 存量行为零变化（【鬼才】照旧订全局、【洛神】迁移等价）。

**Non-Goals:**

- 不替判定加方向词（判定既不是「来源」也不是「目标」）。
- 不动改判窗口的语义与 `Judge:replace` 的守卫。
- 不做【遗计】（另批）。

## Decisions

### D1. 名字：**同名两份**

判定的当事人是「判定者」，但判定**没有方向** —— 既不是「谁对谁」的两方关系（不像伤害 / 治疗），也不像卡牌那样有「使用者 / 目标」。可用的方向词（`来源` / `目标`）在这里都说不通。

⇒ 沿用 `'阶段-开始'` / `'效果-收尾'` 的先例：**同名两份**（`'判定-前'` / `'判定-后'`），归入「同名两份」那一类（文档里点明它是这一类）。

### D2. 顺序：全局先、当事人后

照既有口径（`enterPhase` / 效果收尾都是「全局先、当事人后」）。改判窗口的两份**都**在窗口内（`fireReplaceWindow` 的 `replacing` 守卫覆盖两次 fire）⇒ 当事人那份也能 `judge:replace(…)`。

### D3. 发射点留在内容侧

判定整体住在 `@基础/判定.lua`（2026-09-28 已搬出内核）⇒ 两行 `judge.player:fire(…)` 就写在 `fireReplaceWindow` 与 `Judge:settle()` 里，**内核一行不用改**。类型面同样住内容侧：`@基础/meta.lua` 的 `Player` 块（判定是内容侧的时机，与伤害 / 治疗同处理）。

### D4. `globalEvent` 的判定候选**保留**

【鬼才】那种「**一名角色**的判定」（官方语）必须订全局那份 —— 它不是「你的判定」，凭什么给判定者？⇒ `SkillDef` / `CardDef` 两块**既列 `event` 也列 `globalEvent`**，选哪条由技能文本决定（写进 `sanguosha-rules` §9.15 的硬口径 (a)）。

### D5. 【天妒】按库内文本做成「可问」

库内底本（`.agents/skills/sanguosha-rules/references/武将牌/标准包.md`）写的是「当你的判定牌生效后，**可以**获得之」，且**没标「锁定技」** ⇒ 实现成 `: auto(true)`（默认自动同意、玩家可关），要发动走 `skill:tryCast`。若将来口径改成锁定技（无条件拿），把 `tryCast` 换裸 `cast` 即可（一行）。

### D6. 【洛神】保留 `reason` 筛

改成订自己那份之后，「（任何）自己的判定」仍多于「本技能发起的那次判定」（【闪电】【乐不思蜀】、别人的技能引发的判定…）⇒ `judge.reason == '洛神'` 必须保留。对外行为等价（原来筛 `player` + `reason` 两条，现在玩家份天然保证前一条）。

## Risks / Trade-offs

- **同名两份又多一对**：同名意味着「谁在订哪一份」只能从代码看。判定的场景里可接受（全局那份基本只有改判类技能会用），文档点明「你的判定 / 一名角色的判定」这条选法。
- **两份都跑一次回调**：全局那份的订阅者若也要处理「自己的判定」，会收到两次 —— 与 `'阶段-开始'` / `'效果-收尾'` 的既有情形一致，按老口径处理（订一份就好）。
