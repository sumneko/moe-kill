# Design

## Context

现状（见 `proposal.md` 的 Why）：装备区与判定区在 2026-09-24 由内核建好，但都是**空的**；`@基础/攻击范围.lua` 只把属性「攻击范围」写成 1；`desk:getDistance(from, to)` 只按座位算（不认任何修正来源）；牌表里 16 张装备牌没有定义。用牌链已经齐备（校验 → 取牌 → `'卡牌-结算前'` 进临时区 → 逐目标生效 → `'卡牌-结算后'` → 收尾送 `弃牌`），所以本批只需给「装备牌不指定目标」与「一张牌自带数据」两个口子，其余全在内容侧。

约束（延续既有口径）：

- 内核**不认识具体分类、属性名与数值**（`kind` 只记录、不解释）；
- 「使用」与「打出」是两个动作，本批只动「使用」；
- 内容侧共享函数靠**直接写全局函数**（整轮装载共用一份环境），共享数据靠规则数值 / 定义上的数据；
- **装载器与文件位置**（2026-09-24 核对）：`vfs:listFiles` 按逻辑路径前缀**递归**枚举（子目录里的 `.lua` 照常执行），而名字路由与「同包重复声明」检查用的是 `Card('基本牌')` 声明的**牌名**、不是文件名 ⇒ 把基类牌挪进 `@基础/卡牌/` 不影响路由，也不影响同包内的执行顺序（按逻辑路径排序）；
- **内核行为不能挂在内核自己的时机上**（`events:clear()` 每次装载都会清掉）—— 所以「结算的默认收尾」写在 `Effect:bindFinish` 的代码路径里，槽位区也不发时机。

## Goals / Non-Goals

**Goals:**

- 装备牌能按官方口径用出去并**置入装备区**，同槽旧装备进弃牌堆。
- **武器改攻击范围、坐骑改距离**，两条都作为**求值**（不缓存）。
- 内核只加两个很窄的定义项（`noTarget` / 数据袋），不动「使用」链的形状。
- 落地【借刀杀人】—— 最后两张普通锦囊之一，也是「装备区里有武器牌」这条目标口径的第一个消费者。

**Non-Goals:**

- 防具与「替换 / 追加一次响应」类能力（八卦阵、仁王盾）。
- 装备自带的技能（诸葛连弩的无限【杀】等 8 项）—— 各自是一个技能功能点。
- 无懈可击（已定「当打出 + 分层循环」，另批）。
- 「非玩家目标」（把一张**牌**当目标）—— 本批只需要「无目标」。
- 装备区的协议层表达（明牌、前端展示）。

## Decisions

### D1 只加「无目标的使用」，不加「非玩家目标」

官方装备牌**不指定目标**。给 `CardDef` 一个新定义项 `noTarget()`（与 `zone()` / `kind()` 同形），`canUse` 声明了它就跳过三条目标判据，`useCard` 允许零目标。

- 备选（已否决）：把装备牌写成「目标 = 自己」（`'获取目标'` 返回 `{ target.user }`）—— 零内核改动，但会让「装备牌使某角色成为目标」成立：`targets` 里冒出一个无意义的 `CardEffect`（还会进 `actionOrder` 的结算循环），污染将来的「成为目标时」类技能。官方口径是不指定目标。
- 「目标是**一张牌**」那种（无懈可击的官方写法）本批不做 —— 无懈可击已定按「打出」处理，用不上。

### D2 数据袋放 `CardDef`，不在内容侧另开一张牌名表

`CardDef:value(名字, 值)` / `getValue(名字)`，内核**只存不解释**（与 `kind` 同一条口径、同一套写法）。武器范围与坐骑修正就写在各自的牌定义里。

- 备选（已否决）：`标准/装备数据.lua` 里一张 `牌名 → 数据` 的表 —— 零内核改动，但把「这张牌的数据」从这张牌的定义文件里搬走（每个牌文件顶部本来就写着官方描述），而且将来技能数值要再来一次。

### D3 攻击范围与距离修正走**属性 + 撤销函数**（属性保留）

用户 2026-09-24 定：不要为了「怕漂」把属性删掉 —— **武器进装备区就加修正、离开就 dispose**，读法保持 `player:getAttr('攻击范围')`（`标准/卡牌/杀.lua` 的调用形状一行不改）。

- **状态载体 = 属性**（`攻击范围` 默认 1；`进攻修正` / `防御修正` 默认 0）：「当前生效的修正」只有一处真相。
- **修正的形状 = 增量 + 撤销函数**（`Attributes:addModifier(名字, 增量)` 返回的闭包**精确减掉这次加的量**）⇒ 与将来的技能加成可以叠加、不会互相覆盖。武器用「差值」（麒麟弓 ⇒ `攻击范围 +4`，因为默认 1），±1 马就是 ±1。
- **「加修正」收在内容侧 `@基础/装备.lua` 的 `equip(玩家, 牌)`**：按数据 `addModifier` 加，并把撤销函数 `card:bindZoneGC(撤销函数)` 挂在那张**牌**上（修正属于这张牌）。**没有「卸下」** —— 撤销由「牌离开区」自动触发（D3b）。
- **于是「谁在什么时候撤」不再是约定**：同槽替换、被【过河拆桥】/【顺手牵羊】拿走、死亡弃牌、将来任何挪牌路径，都会经过 `Zone` 的 `put` / `take` / `move` / `clear`，而它们**都调 `card:bindZone`** ⇒ 容器在那里被清空 ⇒ 修正精确撤销。上一版那条「先撤旧、再换、后加新」的顺序约定随之作废。
- **上一版担心的「缓存会漂」不再成立**：撤销挂在牌自带的容器上、由 `bindZone` 触发（D3b），与「谁在什么时候挪牌」无关 —— 只有 `bindZone` 被绕过才会漂，而它没有别的入口。
- 备选（已否决）：改成求值函数 —— 不可能漂，但读法与其它属性不一致（有的读属性 / 有的读全局函数），且每次读都要遍历装备区。
- 备选（已否决）：在 `MoveCard` 的 `'即将生效'` 里自动撤 —— 零调用点改动，但只在「经 `game:moveCard` 挪走」时有效（`take` / `clear` / 将来别的路径盖不到），且那次挪牌可能被 `remove()` 取消 ⇒ 撤早了。

### D3b 承载「随牌走」的两样内核小东西（用户 2026-09-24 定：牌上一个随区存活的容器，不加时机）

- **`Card` 上一个私有字段 `zoneGCHost`：懒建、离开区即丢**（用户 2026-09-24 改定）：`Card:bindZoneGC(撤销函数)` 有容器就复用、没有就 `moe.gc.host()` 现建一件，然后把撤销函数塞进去；`Card:bindZone(zone)` 里发现**区真的变了**（`self.zone ~= zone`）就 `Delete(self.zoneGCHost)` 并置空 ⇒ 撤销函数随即跑。
  - **不继承 `GCHost`**（用户指出）：`GCHost:__del` 把容器绑在**牌对象被销毁**上，而这里要绑的是**「牌在区里」**这一段 —— 同一张牌会反复进出区，继承的容器只在牌对象消失时清一次；为此还得给 `GCHost` 加 `clearGC()`（照搬件，能不动就不动）。
  - 懒：没挂过东西的牌零成本（字段为「不存在」、容器没建）；牌对象真被 `Delete` 时容器由现成的 `GC` 照旧兜底 —— 这一层共用 `moe.gc.host()` / `bindGC`。
  - `bindZone` 是 `Zone` 的 `put` / `take` / `move` / `clear` 的**唯一收口点** ⇒「牌离开区就撤销」覆盖所有路径（同槽替换、被拆、死亡弃牌、将来任何挪牌），一条都不用靠约定；也**不需要新时机**（时机清单是契约，能不加就不加），更不需要给牌 / 区记局。
  - `self.zone ~= zone` 这个判断让**区内部调序**（`move` 到自己）不算「离开区」—— 牌没出这个区，修正不该撤。
  - **它不返回撤销函数**（与 `bindGC` 不同）：这里的「撤销」就是「牌离开那个区」，没有「提前撤销」的用法 —— 要提前撤就把牌挪走。
  - 备选（已否决）：给「牌离开区」加一个时机让内容侧订阅 —— 内容侧要自己管订阅、要能拿到局（公共区没有 `owner`），而且时机清单会为了内容侧自己的簿记而膨胀。
- **`Attributes:addModifier(名字, 增量) → 撤销函数`**：`add` 是单向变化（扣体力那种），而项目约定「添加 / 附加类操作一律返回 disposer、不让调用方自己回滚」—— 缺的就是这一条。

### D4 距离的**求值**在内容侧，**修正值**走属性

`desk:getDistance(from, to)` 只按座位算（内核不认识属性名）⇒ `@基础/距离.lua` 提供 `distance(from, to)` = `desk:getDistance` + `to:getAttr('防御修正')` + `from:getAttr('进攻修正')`，结算后仍最小 1。

- 修正值本身由装备的 `equip(玩家, 牌)` 写进属性（D3；撤销交给牌的 `zoneGCHost`）⇒「加修正」与攻击范围共用同一处代码；`杀.lua` / `顺手牵羊.lua` / `借刀杀人.lua` 都用这个求值函数。
- 方向固定：`进攻修正` 读**自己**的（进攻马 = -1），`防御修正` 读**对方**的（防御马 = +1）—— 求值处一边一个，不会写反；将来【马术】这类「你算距离 -1」也加 `进攻修正`。
- 备选（暂不采纳）：内核加「距离修正来源」注册口子 —— 等**技能**也要改距离时再看（那时才看得清口子该长什么样）。

### D5 「槽位」是内核的一个**区子类**，槽位名由内容侧**加载期声明**（用户 2026-09-24 定）

原先打算把槽位当**内容侧约定**（靠 `kind` 判定、自己维护同槽替换）—— 用户指出这应该是**区域自己的结构**：与「有序能力用子类表达」（`OrderedZone`）同一个道理，加一个 `SlotZone`；「同槽旧牌进弃牌堆」也由**区域类**自己做。

- **槽位名从哪来**：内容侧**加载期声明** —— `game:setSlots('装备', { '武器', '防具', '进攻马', '防御马' })`（与 `attributeSystem:define` 同一形状：加载期声明一次、随重装清空；`game:getSlots(区名)` 读回来）。**不挂 `'游戏-开始'`**（用户明确不要：那是「每个玩家设一次」的形状，而槽位布局是**定义**，不是每个玩家的值）。`Player:__init` 建 `装备` 区时带上这份名单（`moe.slotZone.create(self.game, self.game:getSlots('装备') or {})`）⇒ 中途建的玩家也拿得到。
- **API**（内核只认「槽位名」这个字符串，不解释它是什么）：
  - `zone.slots` —— 这个区声明了哪些槽位（结构）。
  - `zone:getSlot(槽位名) -> Card?` —— **懒校验**：槽位记的那张牌若已不在本区（被拆走 / 被拿走），就地失效并返回「不存在」⇒ **拆牌路径一行结构代码也不用改**。
  - `zone:putInto(槽位名, 牌) -> 无` —— 把牌放进那个槽位（**牌不必先在本区**：内部「在别的区就 `move`、没有归属就 `put`」）；**同槽已有牌 ⇒ 内核把它同步送进 `弃牌`**（建区时带上局，走 `self.game:getZone('弃牌')`；旧牌离开区 ⇒ 它挂的修正由 `zoneGCHost` 自动撤销，见 D3b）。
- **为什么「送弃牌」能进内核**：与五个基础区名、结算的默认收尾同一条轴 ——「同一槽位的旧装备置入弃牌堆」是官方固定口径、没有变体；将来真出现「改为置入别处」的技能，再给它开口子。
- **这一步不走 `MoveCard` 效果**：`putInto` 是内核方法（内容侧的放置仍一律走 `game:moveCard`）；官方「装备牌置入装备区」没有可选 / 可取消性，用不上效果的可取消能力。
- `装备` 区由内核建成 `SlotZone`（`player:getZone('装备')` 的 `@overload` 随之收窄）；判定区将来用 `OrderedZone`（它要的是顺序）。
- 备选（已否决）：继续用内容侧约定 —— 每条拆 / 换路径都要自己判同槽，漏一处就出现两张武器。

### D6 分类既说「是什么」也给出去哪个槽；数据只给数值

`: kind { '装备', '武器' }` / `{ '装备', '防具' }` / `{ '装备', '坐骑', '进攻马' }` / `{ '装备', '坐骑', '防御马' }`（`kind` 是**覆盖**语义 ⇒ 子类写全，与延时锦囊 `{ '锦囊', '延时锦囊' }` 同一写法）；数据只剩数值：`value('攻击范围', 3)` / `value('距离修正', -1 | 1)`。

- **槽位名不再另写一份数据**：装备牌基类遍历 `装备区.slots`，命中自己分类的那条就是它的槽位（`{ '装备', '坐骑', '进攻马' }` ⇒ 进 `进攻马` 槽）；匹配不到（分类写错）⇒ 明确报错。
- 分类里带方向（`'坐骑'` 与 `'进攻马'` 并列）而不是只写 `'坐骑'`：技能将来判断「你装备了坐骑」看 `'坐骑'`，槽位匹配看 `'进攻马'` —— 一层分类同时满足两件事，且不靠「最后一条即槽位」这种隐式约定（匹配是拿区声明的名字去分类里查，**顺序无关**）。
- `距离修正` 的方向约定写死在**数据语义**上：`'进攻马'` 记 `-1`（你到别人 **-1**）、`'防御马'` 记 `1`（别人到你 **+1**）。

### D7 装备牌的落点在**装备牌基类自己的 `'结算后'` 钩子**里

用户 2026-09-24 定：通用的使用效果写在 `@基础/卡牌/装备牌.lua`（基类牌）上，而不是在 `@基础/装备.lua` 里统一订阅 `'卡牌-结算后'` —— 谁 `extends '装备牌'` 谁自动获得，规则贴着牌走。

- 时序：牌自己的 `'结算后'`（载荷 = `useCard`，此刻牌在临时区）⇒ 遍历 `装备区.slots` 匹配分类 ⇒ `putInto(槽位名, 牌)`（内核把同槽旧牌送 `弃牌`，旧牌的修正随之自动撤销）→ `equip(useCard.user, 牌)`。
- 「从**手牌区**使用」由 `: zone '手牌'` 保证（`canUse` 的内建条目），钩子里不重复判。
- 收尾不冲突：内核的默认收尾在**效果结完**时执行，而 `'结算后'` 在结算内部、早于收尾 ⇒ 来得及把牌搬进装备区（`kernel-base-zones` 的「内容侧先留走」路径）。

### D8 「指定一名角色」用通用 `Ask`

【借刀杀人】的「由你指定的另一名角色」用 `game:ask(使用者, '借刀杀人', { candidates = … })`（键名英文，与项目命名口径一致）：答复是一个玩家，**内容侧校验它在候选里**（不在 ⇒ 按"没指定"处理，不报错）。

- 备选（已否决，暂缓）：新提 `AskPlayer : Ask` 子类（答复必须在候选里、内核校验）—— 本批只有这一个消费者，而 `Ask` 正缺用途（现在只剩弃牌阶段在用）；等「选角色」在武将技能里成片出现时再提子类，那时形状更清楚。

### D9 借刀杀人的三步，被指定的角色**不是**目标

① `'获取目标'`：其他角色、装备区里有武器牌、且**其攻击范围内还有别的角色**；② 使用者指定一名角色；③ `askUseCard(被借刀者, '借刀杀人', { name = '杀', target = 被指定的角色 })` ⇒ 答复（牌 + 目标）由现成的 `AskUseCard` 校验（`condition.target` 收窄可用目标，用不了【杀】/ 不在范围内 ⇒ 选项为空 ⇒ 没用出来）；④ 没用出来 ⇒ `game:moveCard(武器牌, 使用者:getZone('手牌'))`（官方「交给你」= 进手牌）。

被指定的角色**不进 `targets`**（官方他不是这张牌的目标），所以不触发「成为目标」类技能、也不进多目标结算顺序。

### D10 装备的技能本批不做

14 张牌本批只有「分类 + 数据」：能用、能改范围与距离，自带技能（诸葛连弩无限【杀】、雌雄双股剑、青龙偃月刀、丈八蛇矛、贯石斧、方天画戟、麒麟弓、青釭剑）为空。逐项记进 `references/progress.md` §2 的候选表（各自是一个技能功能点）。

## Risks / Trade-offs

- [无目标牌让 `AskUseCard.Option.targets` 从「恒非空」变成可空，读它的调用点可能漏判] → 出牌阶段已经写 `ask.targets or {}`（写法天然兼容）；用例覆盖「无目标牌在出牌阶段被选中并使用」。
- [属性是缓存：会漂] → 「**牌离开区即撤**」把缓存的生命周期钉在牌的归属上，不再依赖调用点 ⇒ 只要 `bindZone` 没被绕过就不会漂（它是唯一入口）。
- [「牌离开区就撤销」要求 `bindZone` 真的是唯一收口点] → 已核对：`Zone` 的 `put` / `take` / `move` / `clear` 都经它（`Zone:move` 内部也只调一次）；用例覆盖「同槽替换 / 被拆 / 死亡弃牌后修正都撤了」。
- [区内部调序（`move` 到自己）会被误当「离开区」] → `bindZone` 里比的是新旧区是否为同一张东西（`self.zone ~= zone`）；用例里断言「在装备区里挪一下位置，修正没动」。
- [槽位记的牌被别的路径取走后槽位会「哑」] → `getSlot` 里有**懒校验**（牌不在本区就地失效）；用例覆盖「拆走武器后 `getSlot` 读不到」。
- [14 张装备的数据写错（范围、马的方向）] → 数据集中在各自定义的顶部并逐张对牌表；`rule.equip` 逐张断言攻击范围与距离修正。
- [借刀杀人的「其攻击范围内还有别的角色」这条口径未核对原文] → 先按「没有可指定角色 ⇒ 不能使用」实现，只影响 `'获取目标'` 的一处过滤。
- [“指定角色”用 `Ask` 时答复不合法] → 内容侧按「没指定」处理（不报错、不当失败），用例覆盖。
