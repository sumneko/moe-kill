# Proposal

## Why

牌表里有 **16 张装备牌**（8 武器 / 2 防具 / 6 坐骑），但**一条定义都没有** —— 装备区从建出来那天起就是空的，`攻击范围` 恒为 1，距离修正没有来源。而且装备牌连「使用」这一步都过不了：`canUse` 的内建条目要求 `'获取目标'` 给出**非空合法目标**，而官方装备牌**不指定目标**。

同时【借刀杀人】是**最后两张没落地的普通锦囊**之一，它的目标合法性直接写着「装备区里有**武器牌**」。所以「装备能用」与「普通锦囊收尾」在这里是同一件事：本批做装备的最小可用形状（**武器 + 坐骑 + 装备区槽位**），顺手把【借刀杀人】做掉。

## What Changes

### 内核：几处小口子（都是包作者可见的契约，改 `env-meta.lua` 与 `architecture.md`）

- **无目标的使用**：新增定义项 `CardDef:noTarget()` ⇒ `canUse` 跳过「目标非空 / 是合法目标的子集 / `'获取目标'` 给出非空列表」三条，`useCard` 允许零目标（牌自己的 `'结算前'` / `'结算后'` 照旧各跑一次，逐目标循环空转）；**`AskUseCard` 对这种牌给出的选项不带 `targets`、答复也不用给目标**（`AskUseCard.Option.targets` 由「恒非空」改成「可空」，只有无目标牌会为空）。
- **定义的数据袋**：`CardDef:value(名字, 值)` / `getValue(名字)` —— 内核**只存不解释**，与 `kind` 同一条口径。武器的攻击范围、坐骑的距离修正放这儿；将来的技能数值同用。
- **槽位区的子类 `SlotZone`**（与 `OrderedZone` 同形：**结构性能力用子类表达**）：按**槽位名**寻址、**每个槽位至多一张** —— `slots`（这个区声明了哪些槽位）、`getSlot(槽位名) -> 卡`（**懒校验**：槽位记的牌已不在本区就地失效）、`putInto(槽位名, 牌)`（放进那个槽位；**同槽已有牌 ⇒ 内核把它送 `弃牌`** —— 与「结算完的牌回弃牌堆」同一条轴：官方固定、没有变体）。内核**不认识**「武器 / 防具 / 进攻马 / 防御马」这四个词。`装备` 区由内核建成 `SlotZone`（`player:getZone('装备')` 的重载随之收窄成它）；判定区将来用 `OrderedZone`（它要的是顺序，不是槽位）。
- **槽位名清单由内容侧在加载期声明**：`game:setSlots('装备', { '武器', '防具', '进攻马', '防御马' })` / `game:getSlots(区名)` —— 与 `attributeSystem:define` 同一形状（**加载期**声明一次、随重装清空），建玩家时 `装备` 区就带着这份名单，**不必挂 `'游戏-开始'`**；中途建的玩家也拿得到。没声明就是没有槽位（`putInto` 明确报错）。
- **`Card` 上挂一件「随区存活」的容器，离开区即丢**：私有字段 `zoneGCHost` 懒建（`Card:bindZoneGC(撤销函数)` 时才 `moe.gc.host()` 现建一件），`Card:bindZone` 发现区真的变了就 `Delete` 掉它并置空。于是内容侧把「属性修正」的撤销函数 `card:bindZoneGC(撤销函数)` 挂上去 —— **牌一离开装备区（同槽替换、被拆、死亡弃牌、任何路径）修正就自动撤销**，不需要每个调用点记得调 `卸下`。**不继承 `GCHost`**（那会把容器绑在牌对象被销毁上，而不是「牌在区里」），也**不用新时机**（`bindZone` 是 `put` / `take` / `move` / `clear` 的唯一收口点；也不需要给牌 / 区记局），**不改照搬件**（`moe.gc.host()` / `bindGC` 直接用）。
- **`Attributes:addModifier(名字, 增量)` 返回撤销函数**：`add` 是单向变化（扣体力那种），而「加一条修正」按项目约定必须返回 disposer（撤销即**精确减掉这次加的量**，与将来的技能加成可以叠加、不会互相覆盖）。
- **不做**：距离与攻击范围的**修正来源**仍在内容侧 —— 内核不认识「马」与「武器」，`desk:getDistance` 保持「只按座位算、最小 1」。

### 内容侧：装备能用了

- **模板文件挪到 `@基础/卡牌/`**：`基本牌.lua` / `锦囊牌.lua` 从 `@基础` 根目录移过去，新的 `装备牌.lua` 也放那里 —— 让「给内容包 `extends` 的**基类牌**」与「内核机制的接线」分开（`标准/卡牌/` 放的是具体牌）。装载器按逻辑路径**递归**枚举、名字路由用的是 `Card('基本牌')` 声明的**牌名**而非文件名 ⇒ 移动不影响路由与执行顺序。
- `@基础/卡牌/装备牌.lua`（新模板，与 `基本牌.lua` / `锦囊牌.lua` 同形）：`kind '装备'` + `noTarget()` + `zone '手牌'`；**基类上实现通用的使用效果** —— 牌自己的 `'结算后'` 钩子里遍历 `装备区.slots`，命中自己分类的那条槽位名 ⇒ `装备区:putInto(槽位名, 牌)`（内核把同槽旧牌送 `弃牌`，**旧牌的修正随它离开区自动撤销**）→ `equip(使用者, 牌)`。**「从手牌区使用」由 `: zone '手牌'` 保证**，钩子里不重复判。
- `@基础/装备.lua`（新）：只剩两件事 —— 加载期 `game:setSlots('装备', { … })` 声明那四条槽位；`equip(玩家, 牌)`（按 `value('攻击范围')` / `value('距离修正')` 用 `addModifier` 加修正，并把撤销函数 `card:bindZoneGC` 挂上去）。**没有「卸下」** —— 撤销由「牌离开区」自动触发（见上文内核那条），所以【过河拆桥】/【顺手牵羊】/ 奖惩那些路径**一行都不用改**。
- `@基础/攻击范围.lua`：**属性保留**（默认 1），读法不变（`player:getAttr('攻击范围')`）⇒ 装备进了武器区就加修正、离开就撤销，`标准/卡牌/杀.lua` **一行不用改**。
- `@基础/距离.lua`（新）：定义两个修正属性（`进攻修正` 默认 0，进攻马给它 -1；`防御修正` 默认 0，防御马给它 +1）+ 求值函数 `distance(from, to)` = `desk:getDistance(from, to)` + 对方的 `防御修正` + 自己的 `进攻修正`，**结算后仍最小 1**；`标准/卡牌/杀.lua`、`顺手牵羊.lua`、`借刀杀人.lua` 改用它。
- `标准/卡牌/` 新增 **8 张武器**（诸葛连弩 1 / 雌雄双股剑 2 / 青釭剑 2 / 青龙偃月刀 3 / 丈八蛇矛 3 / 贯石斧 3 / 方天画戟 4 / 麒麟弓 5）+ **6 张坐骑**（进攻马：赤兔 / 大宛 / 紫骍；防御马：的卢 / 绝影 / 爪黄飞电），每张一个文件、顶部写官方描述；**分类既说「是什么」也给出去哪个槽**（`{ '装备', '武器' }` / `{ '装备', '坐骑', '进攻马' }`），数据只给数值（`value('攻击范围', 3)` / `value('距离修正', -1 | 1)`）。**装备区的四条命名槽位就叫 `武器` / `防具` / `进攻马` / `防御马`**。

### 内容侧：【借刀杀人】

`标准/卡牌/借刀杀人.lua`（新）：目标 = **装备区里有武器牌、且其攻击范围内还有别的角色**的其他角色；结算 = ① 问**使用者**指定一名角色（用通用 `Ask`，答复是一个玩家，内容侧校验它在候选里）→ ② 问**被借刀者**要不要对那名角色使用一张【杀】（`askUseCard` + `condition.target` 收窄）→ ③ 没用出来就把它装备区里的**武器牌交给使用者**。
### 内容侧：奖惩补上「弃装备牌」

`package/身份场/奖惩.lua` 顶部自己记着「装备区还没做 ⇒ 现在只弃手牌，等装备批次补上」—— 以前装备区必然为空、只弃手牌没有行为差异，**本批之后不再为空** ⇒ 主公杀死忠臣时把它装备区的牌也一并弃掉（`game:moveCard(装备区的牌, '弃牌')`，与已有的弃手牌同形），并把那行记号改成已落地的说明。
### 明确不做

- **防具**（八卦阵 / 仁王盾）：要的是「替换 / 追加一次响应」的新能力，与武器坐骑不是一个量级，另批。
- **装备自带的技能**（诸葛连弩的无限【杀】、雌雄双股剑、青龙偃月刀、丈八蛇矛、贯石斧、方天画戟、麒麟弓、青釭剑…）：各自都是一个技能功能点，另批。（本批这 14 张牌只有分类、攻击范围 / 距离修正两个数据。）
- **无懈可击**：已定「当打出 + 分层循环」（用户 2026-09-24 拍板），另批。
- 延时锦囊与判定区、装备区的可见性协议层表达。

## Capabilities

本变更不写 specs 增量（`.openspec.yaml` 设 `skip_specs: true`）：`openspec/specs/` 是探索期的冻结快照、不随实现更新；本批新增的是**内容（装备牌与借刀杀人）**＋几处很窄的内核口子（无目标使用、定义数据袋、牌上的 `zoneGCHost`、属性修正的撤销函数、槽位区与槽位的加载期声明），实施契约由 `server/test/` 的用例承担（`core.effect.play` 的无目标使用、`core.zone` 的槽位区、新增的 `rule.equip` 套件、`rule.trick` 的借刀杀人）。

### New Capabilities

- 无。

### Modified Capabilities

- 无。
