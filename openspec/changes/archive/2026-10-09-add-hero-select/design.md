# 设计：选将流程（内核这一层）

## D1 武将分类（`HeroDef`）

照 `CardDef` 那套**逐字搬**（`server/core/hero.lua`）：`kind(名或名单)`（一次调用定下、重复调以后写的为准）、`addKind(名或名单)`（只追加）、`isKind(名)`、`getKinds()`（快照）。

- **不做继承 / 公共模板**（用户 2026-10-09 定：`HeroDef:extends` 不加）—— 「哪些武将能当主公」直接在**具体武将**的声明里打 `addKind('君主')`（标准包：曹操 / 刘备 / 孙权 —— 他们带主公技）。
- 分类名用**底本的「君主」**（`Chapter2/Section3` 的「君主武将」）；「主公」留给**身份**名。
- 内核只存不解释（与卡牌分类同款）；`@基础` / 具体包都不必改任何装配代码。

## D2 `AskHero`（新的询问类）

形状照 `AskPlayer`（`server/core/effect/ask-player.lua`），三处差异：

| 面 | `AskPlayer` | `AskHero` |
| --- | --- | --- |
| 候选 | 四态（一名 / 一批 / `true` / 谓词），谓词在**存活角色**里筛 | **一份名单**（`HeroDef|HeroDef[]`；**不给条件 = 不做限制**）—— 武将**没有「全部」这个可用全域**（`game:getHeroes()` 本批不做），所以既没有 `true` 也没有谓词 |
| 时机 | `'决策-询问'` / `'决策-答复'` | **单开 `'武将-询问'` / `'武将-答复'`**（照 `'技能-询问'` 的先例：武将既不是牌也不是角色，应答方要能分别处理三路） |
| 读法 | `.player` / `.players` | `.hero` / `.heroes`（`= .result` 的语义化读法） |

```lua
---@class AskHero.Condition
---@field hero? HeroDef|HeroDef[]   # 候选（发起方算好；不给 = 不做限制）
---@field min? integer              # 至少选几个（省略 = 1）
---@field max? integer              # 至多选几个（省略 = min）

game:askHero(被问者, 缘由, 条件?)   -- 返回 AskHero（已经结完）
```

- 校验复用 **`moe.askCard.checkTargets`**（个数 / 在候选里 / 不重复）⇒ 拒收文案与别的询问同一套 ✓
- `min` 为 0 ⇒ 「一个都不选」是合法答复、没人表态也算成立（照 `allowNone` 口径）
- 入口 `game:askHero` ✓；`moe.askHero.normalizeCondition` 露出（照 `askPlayer` / `askCard` 的门面）

## D3 `'游戏-准备'`

- **时机名**：`'游戏-准备'`（`env-meta` 里给 `Game` 声明 `on` / `fire`）。
- **谁发**：**装配侧**（无头测试 / 房间 / 会话）—— 照 `'游戏-开始'` 的先例（现在也只有装配侧 fire，内核不代劳）。
- **顺序**：`'游戏-准备'`（发身份 + 选将）→ **`'游戏-开始'`**（体力默认值只给没武将的 / 主公体力加成 / 建牌堆…）。主公加成**留在「开始」**（它是 `addAttr` 叠加，得排在武将体力写完**之后**）。

## D6 坐次与身份给全（第二批判定）

- **身份要么不给、要么给全**（用户 2026-10-09 定）：给了 `config.identities` 就要求每个座位都有（缺一个报错），并且**不再校验「身份配置」** —— 全是主公也接受（测试里就有 4 个主公同时在场）。
- **坐次**（用户 2026-10-09 定）：没给 ⇒ **开局前先洗一遍座位**再定身份归属的落点 —— 经典洗牌（从最后一个座位往前、每次与随机一个座位交换）**并把主公换到 1 号位**；给了 ⇒ 照列表排（**必须给全**，也是靠两两交换实现）。
- **给了坐次就不挪主公**：允许用配置让**非主公走第一个回合**（回合流程照旧从 1 号位开始）—— 所以这时不能强制主公在 1 号位；而「洗」那条路径反过来一定要把主公摆到 1 号位。
- **主公先选按身份判定**，与座位无关；「先亮将」是表现层的事。
- **洗牌用内核已有的随机源**（`game.random`），测试里固定种子 ⇒ 同一份配置可复现（用例就靠它钉住「洗过牌」）。
