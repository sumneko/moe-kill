# Design

## 1）语义（2026-09-29 用户拍板）

1. **牌不能用**：区里的牌过不了 `canUse` / `canUseToCard`；
2. **被动不生效**：区里的牌被 `disablePassive()` 压住；
3. **可叠加**：多个禁用者各一层，`disable()` 返回撤销函数（幂等）；
4. **不拦搬入搬出**：禁用是逻辑状态，不是物理封锁。

## 2）压制同步的三个时刻

| 时刻 | 做什么 |
| --- | --- |
| `disable()`（0 → 1 层） | 对区内每张牌 `disablePassive()` |
| 恢复（1 → 0 层） | 对区内每张牌 `enablePassive()` |
| 进区（`notifyEnter`） | **先补区级压制、再跑内容钩子** |
| 离区（`notifyLeave`） | **先跑内容钩子、再松开区级那层** |

- **为什么区级那层放在钩子外侧**（2026-09-29 实现时定，与用户过目 —— 与本文初稿的表格相反）：被动回调要从区里取归属者（`assert(zone.owner)`）、`Card:applyPassive` 也要 `assert(self:getZone())`，所以**任何一次「松开到 0」都必须发生在牌确实还在那个区里的时候**：
  - **离区**：牌被 `moveCard` 拿走时 `takeIn` 已把它绑到**新区**（弃牌堆，`owner` 为空），走 `clear` / `draw` 时更是**已解绑**。这时松开区级那层就会拿新区（`assert(zone.owner)` 炸）或空区（`assert(self:getZone())` 炸）去跑被动；**先跑内容钩子**（装备模板会 `disablePassive` 补一层）**再松开**，计数落在 1 上，一次应用都不会发生。
  - **进区**：先跑钩子的话（装备模板会 `enablePassive`），压制计数会从 1 掉到 0、**真的应用一次**，紧接着又被补压撤销；**先压**（1 → 2）则钩子那下只落到 1，全程不应用。
  - 两种次序的**计数配平是一样的**（区级那层始终只 ±1，随进出 / 禁用恢复精确配平，不必记「我给谁压过」）；差别只在**中途会不会误应用一次**。
- **离区的净效果仍由牌自己的钩子决定**（装备模板在 `'离开区域'` 里停用被动）；区级那层只负责把牌从「禁用区」的账上摘掉。
- **对称性**：区级永远只 ±1 层，随进出 / 禁用恢复精确配平 —— 不需要记「我给谁压过」。

## 3）为什么去掉「不能放进 / 清空 / 洗牌」

那三条把一个**逻辑状态**做成了物理封锁：禁用一个防具子区不该让【顺手牵羊】拿不走牌。官方「不准置入」的概念是**封印**，与「牌不能用」是两回事 —— 将来按封印实现；本批先把物理部分全部去掉。

## 4）形状细节

- 字段：`private enabled: boolean` → `private disabled: integer`；`isEnabled()` = `disabled == 0`。
- `disable()` 返回 disposer（多次调用各返回一只、各自幂等）；`enable()` 删除（每一层自带撤销）。
- `checkCardItself` 的新原因：`'「{}」在的牌区被禁用了，用不了'`；判在 `user:findCard(牌)` 之后、`CardDef:zone` 那条之前。
- 用例把「压制」观察在**牌自己的行为**上（探针牌的 `'被动'` 回调写 `game:setValue` 计数），不直接读 `passiveSuppress`（牌的私有字段）。
