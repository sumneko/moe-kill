# Design

## Context

- 官方口径（规则集 3.0）：【无懈可击】**使用时机 = 一张锦囊牌对一个目标生效前**、**使用目标 = 一张对一个目标生效前的锦囊牌**、作用效果 = **抵消此锦囊牌**；§2.7 定义「抵消」= *此牌对该目标不生效*（另有『取消』= 令其不再是此牌的目标，本批不用）。§3.2 把「使用结算中」列成逐目标的五个时机：**使用结算开始时**（测有效性）→ **生效前**（可以对此牌进行响应；响应可能令此牌被抵消 ⇒ 跳过「生效时」「生效后」）→ 生效时 → 生效后（执行效果）→ 使用结算结束时。
- 内核现状：`CardEffect` 是「一张牌对一个目标的一次生效」，`Effect:apply()` 里**先问一次 `'效果-能否生效'`（订阅者**返回非 nil 值即阻止**，返回值就是原因）、再 `settle()`**（载荷 = 这次生效的实例）⇒ 这个时机**就是官方的「生效前」**，而且天然逐目标。
- 现有响应只有【闪】，它写在【杀】自己的 `'生效'` 钩子里（用的是 `askPlayCard`）。无懈不能这么写：它对**任何**锦囊都要起作用，写进每张锦囊的定义就漏了，也违反「插入点与单张牌无关」。而官方给【无懈可击】的是**使用**（有使用时机 / 使用目标 / 作用效果），不是「打出」
- 询问侧的形状是现成的：`game:askCard` / `askUseCard`（候选逐张跑 `canUse`）、`desk:actionOrder(允许列表?, 起点?)` 给「按行动顺序问一圈」（省略起点 = 顺序锚点）。
- **两条实测约束**（本批开工时踩到，决定了几何形状）：
  - `canUse` 对 `noTarget()` 的牌是「给了非空目标才不成立」⇒ 声明 `noTarget()` 的【无懈可击】**会被出牌阶段正常提供**（探针：`canUse(给空表)=true`、候选里有它）；而“不声明 `noTarget()` 又不写 `'获取目标'`”又会让 `canUse` fail-closed ⇒ `askUseCard` 的候选把它排除。⇒ 想在窗口里用 `askUseCard` 问无懈，就必须让 `canUse` 能表达「此刻它可用」，而它的合法目标只在窗内存在 ⇒ 要么给钩子一个「当前生效对象」的上下文，要么另开一支。
  - **阻止只能由被阻止的那次生效自己的问句给出**：从别的效果的执行体里想阻止外层**没用** —— `task:cancel()` 会让外层当场以 `canceled` 收尾（`.err` 读得到、收尾也跑了），但**外层的执行体照旧跑完**（`settle()` 照跑），所以本批把跨层取消整个去掉（`Effect:remove()` 随之删）。
- 用户定：**逐目标（官方口径）** + **无懈是一次「使用」而不是「打出」** + **拆一支「对牌使用」（方案 B）** —— 见本变更对话记录；旧笔记里「整张作废」的口径作废。

## Goals / Non-Goals

**Goals:**

- 【无懈可击】能作为一次**使用**生效：锦囊对**某个目标**生效前，任何角色都可以「对那张牌使用」它来抵消；那张无懈自身也能被另一张抵消（分层）。
- 把「响应窗口不写在牌的钩子里」这条形状跑通一次，后面【八卦阵】那类窗口响应照抄。
- 顺手把阻止生效的机制换成正的（2026-09-24 用户定）：疑问式 `'效果-能否生效'`，**返回值即原因**；`Effect:remove()` 删掉；`UseCardToCard` 记下它的那次生效（`cardEffectToCard`）。

**Non-Goals:**

- 不做延时锦囊的无懈窗口（判定阶段）、《看破》那类「谁能响应」的技能干预、询问超时。
- 不做 UI / 协议层的「问谁、显示什么」（那是会话那批的事），也不把【闪】迁到「生效前」。

## Decisions

1. **插入点 = 内核那个「生效前」事件，由【无懈可击】自己的牌文件订阅**（`package/标准/卡牌/无懈可击.lua` 顶层写 `game:on('效果-能否生效', …)` —— 注意牌的 `: on(...)` 是**固定钩子集合**（`'进入区域'` / `'获取目标'` / `'结算前'` / `'生效'` / `'结算后'`），不含全局时机；牌文件里要订阅局的时机就写顶层 `game:on`）。理由：
   - 它逐目标、且在牌自己的效果之前，就是官方的「生效前」。筹码花在**「对牌使用」这一支**与**把阻止改成疑问式**上（见决策 2 与决策 3）。
   - **规则随牌走**：能抵消锦囊的只有【无懈可击】，所以「什么时候问、问谁、抵消掉什么」都写在它自己的文件里 —— 没装这张牌的规则集**不会**多问一圈（若写在 `@基础`，基础规则就得写死一个标准包的牌名，还在没那张牌时白问）；将来国战版【无懈可击・国】之类的变体各订各的即可。
   - 替代方案（已否决）：写在 `package/@基础/无懈可击.lua`（规则与牌分家、基础包点名标准包的牌）；**方案 A**：给内容侧一个「本次生效的对象」上下文、继续用 `askUseCard` 问（探针结论：`canUse` 表达不了「只在窗内可用」，A 得给钩子加一个全局上下文变量 —— 与「钩子按次给载荷」的既有形状相悖）；**方案 C**：复用 `askUseCard` + `noTarget()`（探针结论：这样【无懈可击】**会被出牌阶段正常提供**、变成能主动用的牌，偏了）。
2. **「对一张牌使用」自成一（内核新增，方案 B）**：新效果 `UseCardToCard`（一次使用、目标是牌）/ `CardEffectToCard`（对那张牌的一次生效），新入口 `useCardToCard` / `canUseToCard` / `askUseCardToCard`，新定义项（= 钩子）**`'对卡牌生效'`**。理由：
   - **合法性只在这里存在**：这类牌的「目标」是一张牌、且**由发起方给定**（内容侧枚举不出来），所以合法性不能是内容侧实现的 `'获取目标'`，而是**声明 `'对卡牌生效'` —— 声明即「它能被对一张牌使用」**；合法性里与目标无关那半（牌本身能不能用：在不在手里 / 是否已声明使用区域与次数）抽成 `checkCardItself` 与 `canUse` 共用，避免两套口径。
   - **不把「目标可以是一张牌」塞进 `UseCard` 的目标列表**：目标是**角色**还是**牌**是两种形状（字段类型、`'生效'` 载荷、目标合法性全都不同），混在一个 `targets` 里会让每条既有路径到处 `type` 判断；拆一支以后，「按载荷类型命名钩子载荷」的既有约定也照旧（`useCardToCard` / `cardEffectToCard`）。
   - 这条契约**内容侧可见**（第三方包要写无懈那类牌就得用它）⇒ 本批照常写 `core-play` 规格增量，不设 `skip_specs`。
3. **阻止生效用「问一句、用返回值回答」，不用 `remove()`**（用户 2026-09-24 定）：原来的写法是「窗口里拿到 `effect` 就 `remove()` 掉它」—— 但那个事件本来就是**在问**（“能不能生效”），拿删掉来回答既暴力，又逼出「取消只能自己发起」「里层想阻止外层只能去查状态」这些别扭。改成：`'效果-能否生效'`（疑问式名字，与 `'卡牌-能否使用'` 同一套规范），**回调返回非 nil 值即阻止**（返回值就是原因，只给 `false` 归一成一句通用原因），内核读到原因就不 `settle()`，这次生效以 `.err` = 原因 收尾（没有结果、**不算失败**、收尾照跑、不进错误处理器）。
   - 好处：① 无懈文件里再没有 `effect:remove()`；② 「阻止这一次生效」与「阻止外层」不再需要区分权限 —— 窗口只需管自己那一次；③ 返回值天然带原因（用例里读得到 `.err == '无懈可击'`）；④ 跨层取消这个坑直接消失（`Effect:remove()` 随之删掉）。
   - **取消（`remove()`）删了**（用户 2026-09-24 定）：内容侧要阻止就走返回值；内核自己要停掉一次结算改用 `task:cancel()`（`apply` 里那两处本来就是这么写的）。刪它而不是留着，是因为它唯一的语义（“跨效果取消”）已经证明既没用又危险，而“阻止自己”现在有更直白的返回值。
   - 这一层仍只认 `cardEffect`（锦囊 × 角色）与 `cardEffectToCard`（无懈 × 牌）两种 `kind`，`useCard` / `useCardToCard` 都不认（它们不是「生效前」，认了会把整张牌问一遍并与逐目标重复）。**嵌套因此天然来自事件本身**（用出去的无懈自己也是一种效果、也会被问一遍），不需要手写递归。
   - **「声明壳」为什么还在**：`'对卡牌生效'` 对【无懈可击】仍是空实现 —— 它的钩子跑在自己的效果里，阻止不了**外层**那张锦囊（能阻止的只有外层自己的那个问句）；所以“抵掉那张锦囊”靠外层的窗口返回原因。该目标被阻止 = 不跑它的 `'生效'` 钩子 = 官方「跳过生效时与生效后」；被抵消的牌**照常**进弃牌堆。
   - **不能改成阻止「那次使用」**（看似更省事的替代）：`UseCardToCard:settle()` 里才取牌，在「能否生效」就阻止会让那张无懈**留在手里**（违背「被抵消的牌照常进弃牌堆」与「此牌已使用」）；阻止 `CardEffectToCard` 正好在取牌之后。
   - **判决不用回传，回使用效果上记着的那次生效**（用户 2026-09-24 定，内核新增一行）：外层要知道「刚用出去的那张无懈有没有被抵消」，而那个事实就是**它那次「对牌生效」成不成** ⇒ `UseCardToCard` 在起 `CardEffectToCard` 时顺手记在自己身上（`use.cardEffectToCard`），内容侧直接读 `use.cardEffectToCard.err`（空 = 生效了 ⇒ 它把上面的牌抵掉了）。**本批不引入标记、也不翻 `childs`**。
   - **跨层阻止这条路已经整个去掉**（探针实测 2026-09-24）：从别的执行体里取消外层**不是空操作、但也没用** —— 外层任务当场以 `canceled` 收尾（`.err` 读得到、收尾也跑了）但**外层的执行体照旧跑完**⇒ 要阻止外层只能让它自己的窗口给原因。因此本批**删掉了 `Effect:remove()`**（全仓已无调用点；内核自己要停掉一次结算直接用 `task:cancel()`）。
4. **一圈 = 行动顺序一圈；「有人响应」不结束这一圈，「这张牌被抵消」才结束**（2026-09-24 用户改正）：从顺序锚点起依次问，每人一次机会；有人用了无懈但**那张无懈自己又被抵掉了** ⇒ 这张牌还没被抵消 ⇒ **接着问下一个人**（不是就此收场）。官方依据：① 3.2「生效前」的终止条件只有「此牌被抵消」（"生效前"终止 ⇒ 跳过生效时与生效后）；② 4.1 插入结算顺序「在 B 技能的使用结算完毕后，**继续进行 A 技能的使用结算**」⇒ 插入的无懈结完就继续那张牌的生效前；③ 4.1 同一时机多名角色「依次触发/决定」，且注意里写「先发动的技能的效果可能会导致此时机结束」⇒ 没结束就接着问；④ 旁证是濒死那一圈（3.14）：一张【桃】不结束一圈，救不回来就接着问下一个。被抵消的那张换成新目标后是**新的一层**（重新从锚点起问，先用过无懈的人对新目标也能再表态）。
5. **内容侧的形状**（`package/标准/卡牌/无懈可击.lua`）：

   ```lua
   -- 声明「对卡牌生效」= 它能被「对一张牌使用」（真抵消由下面那个窗口回报给内核）
   Card '无懈可击'
       : extends '锦囊牌'
       : on('对卡牌生效', function () end)

   --- 这次使用用出去的那张牌生效了吗（它那次「对牌生效」被阻止 / 不成立，就是没生效）
   ---@param use UseCardToCard
   ---@return boolean
   local function tookEffect(use)
       for _, child in ipairs(use.childs) do
           if child.kind == 'cardEffectToCard' then
               return child.err == nil
           end
       end
       return false
   end

   --- 问一圈：有没有人对这张牌使用【无懈可击】
   --- 一圈里每人只有一次机会；只有「这张牌被抵消」才终止这一圈 ⇒ 谁的无懈自己又被抵掉了，就接着问下一个人
   ---@param card Card # 要抵消的那张牌
   ---@return boolean # 这张牌有没有被抵消
   local function nullified(card)
       for player in game.desk:actionOrder(game.desk.alivePlayers) do
           local used = game:askUseCardToCard(player, card.name,
               { name = '无懈可击', target = card }).card
           if used then
               -- 用出去的那张无懈自己也会被问一遍：它生效了就抵掉了 card，没生效就接着问下一个人
               if tookEffect(game:useCardToCard(player, used, card)) then
                   return true
               end
           end
       end
       return false
   end

   --- 一次「生效前」：问一圈要不要抵消
   ---@param effect CardEffect|CardEffectToCard
   ---@return string? # 要抵消就给原因（这次生效被阻止）
   local function nullify(effect)
       if effect.card:isKind('锦囊') and nullified(effect.card) then
           return '无懈可击'
       end
   end

   --- 两种「生效」都在这里问：锦囊对某个角色的生效、以及无懈对一张牌的生效
   game:on('效果-能否生效', function (effect)
       if effect.kind == 'cardEffect' or effect.kind == 'cardEffectToCard' then
           ---@cast effect CardEffect|CardEffectToCard
           return nullify(effect)
       end
   end)
   ```

   层数为奇数 ⇒ 锦囊被抵消；偶数 ⇒ 锦囊照常生效。这条结论现在不是靠布尔翻出来的，而是**每一层都真的被阻止**（用例里断言了中间那张无懈的 `CardEffectToCard` 以 `err == '无懈可击'` 收尾）。
   - **官方是"嵌套"而不是"同一张牌收多张、按奇偶判定"**（已核对 §3.2 / §5.2）：【无懈可击】的**使用目标是一张牌**（"一张对一个目标生效前的锦囊牌"）⇒ 对已打出的无懈再打无懈时，目标是**那张无懈**，不是原锦囊；而且 §3.2 写明「若此牌被抵消 ⇒ 『生效前』终止、跳过『生效时』与『生效后』」⇒ **同一张锦囊不可能被连续无懈两次**（第一张生效后它的"生效前"就结束了）。所以每层是一个新的、针对上一张无懈的响应窗口，"奇偶"只是它的**结果**；事件递归天然保证"第二张只能针对上一张无懈"。
   - 缘由按惯例写**发起这次询问的那张牌的名字**（外层是锦囊名，内层是【无懈可击】）。
   - 代价（说清楚）：多了一支内核通道（`UseCardToCard` / `CardEffectToCard` / `'对卡牌生效'` / 三个入口），换来的是**这类牌真的走完整的「使用」结算**（进结算链、可被取消、可被再响应），而不是在窗口里塞一个旁路。
   - 答复方要知道"这次是冲谁来的"：看这次询问的父效果（`ask.parent`），就是那次 `CardEffect` —— 用例里的 `pendingEffect` 辅助函数就是这么读的；协议层同理。

## Risks / Trade-offs

- [`'效果-能否生效'` 也发给别的效果] → 只认 `cardEffect` / `cardEffectToCard` 两种 `kind`，再过 `isKind('锦囊')`；用例里补一条「非锦囊（【杀】）不触发询问」。
- [无懈"对牌使用"却不走 `'获取目标'`] → 合法性落在 `'对卡牌生效'` 这条声明上（`canUseToCard`），目标由发起方给定；用例里补一条「出牌阶段的候选里没有【无懈可击】、也不能主动用」。
- [一层被问两遍 / 层数算反] → 窗口**不认** `useCardToCard`，只认两种「生效」；嵌套只由事件产生，**不再自带递归**。这条踩过一次：两套都管时一次无懈会被问两次，表现为「无懈生效变成了偶数层」的结果。
- [“内层被抵消”怎么让外层知道] → 读那次使用的 `childs` 里 `cardEffectToCard` 的 `.err`（空 = 它生效了）；被阻止的效果也带着原因（`.err == '无懈可击'`），所以这个读法不需要额外标记。**不能**去阻止 `useCardToCard`（那张无懈会留在手里）。
- [递归层数不设上限] → 每层都要真用出一张【无懈可击】，受手牌与牌堆限制，实际层数极小；不另加上限（内核的效果嵌套上限仍在）。
- [「一圈」的终止条件] → 只有「这张牌被抵消」才停（官方 3.2 / 4.1，见决策 4）：一张没生效的无懈**不**能把这圈封掉；用例里拿四个人钉住它（第一个人用了无懈、第二个把那张无懈抵掉、第三个接着抵原锦囊 ⇒ 锦囊不生效）。同一层里同一个人不会被问两次，但换了层（有人用了无懈、又被无懈）会重新问到他。
- [询问的可靠性] → 一圈里每个存活角色都会收到一次询问（哪怕他手里没有【无懈可击】）：应答方给不出牌就是「没用」，不算失败；协议层想省掉空询问可以将来按「选项为空就不发」优化，本批不动。
- [【闪】仍写在【杀】自己的 `'生效'` 里，与无懈的落点不同] → 本批不迁移【闪】（那要动【杀】与相关用例）；在文档里标注两者目前的位置差异（【闪】的位置是"目标的行为"，无懈是"对那张牌的一次使用"）。
- [无懈算一次使用、会计进阶段次数] → 无懈没有声明限额 ⇒ 1000（事实上不限），与官方一致；不动。
