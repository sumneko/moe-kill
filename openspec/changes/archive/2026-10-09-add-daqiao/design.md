# Design

## Context

- 底本（`references/武将牌/标准包.md` 97–100 行）：【国色】「你可以将一张方块牌当【乐不思蜀】使用。」；【流离】「当你成为【杀】的目标时，你可以弃置一张牌并选择你攻击范围内为此【杀】合法目标（无距离限制）的一名角色：若如此做，该角色代替你成为此【杀】的目标。」
- 官方「转移」（`references/官方规则集/Chapter2/Section5.md` 75–77 行）：「在角色 A 成为一张牌的目标时将此牌转移给角色 B，即**取消此目标并生成一个与角色 B 具有对应关系的新的目标**并将此目标加入此牌的目标列表……**然后将所有还未生成过『成为目标时』这个时机的目标重新排序**。」
- 目标筛选现状：`canUse` 内部用局部函数 `collectLegalTargets` 逐候选过 `targets.filter` + 问候选者 `'卡牌-目标-能否指定'`；**给了目标时 `legal` 会被收窄**成「这次的目标里合法的那些」；`UseCard:settle()` 把 `canUse` 的返回**丢掉了**。
- 使用时机现状：`UseCard:settle()` 顺序 = 合并选项 → `canUse` 校验 → 记账 → 把牌挪进临时区 → `'卡牌-结算前'`（全局 / 使用者）→ **逐目标三份「指定目标后」** → 牌自己的 `'使用'` → **逐目标「生效」** → `'卡牌-结算后'`。（两轮都**现算** `desk:actionOrder(self.targets)`，而 `actionOrder` 建的是 `allowedSet` 快照。）

## Goals / Non-Goals

**Goals:**

- 大乔【流离】落地。
- 补上内核缺的一件：**改目标**（官方「转移」）。
- 顺带把「牌本体 / 目标」两件事拆开，并给「只要全量合法目标」开一个读取口。

**Non-Goals:**

- **【国色】本批不做**：它要「方块牌当【乐不思蜀】使用」，而延时锦囊的使用结算把牌放进**判定区** —— `Zone:accept` 会把虚拟牌**降级成实体子牌** ⇒ 判定阶段 `card:doEffect()` 跑的是**那张实体牌**的『生效』（方块【杀】会对判定者要闪/挨打）✗ 要做得先定「虚拟牌能不能进判定区」（与 2026-09-30 定的「虚拟牌进不了任何牌区」冲突，需单独拍）。
- **不做「已转移过」的标记**：官方没有任何禁止连锁转移的条文；每次转移都要弃一张牌（牌有限）+ 内核深度安全阀兜底 ⇒ 循环失控不了。
- 不改 `canUse` 的**返回值形状**（`Game.UsableTargets` 不加字段 —— 上一轮提过的 `candidates` 字段作废：它带着使用者的距离限制，交叉会漏人）。
- 不给 `canUse` 的 `target` 参数加谓词形态（它是**校验器**：给的目标**全部**必须合法，有一个不合法就整条 false ⇒ 表达不了「从名单里筛」）。
- 不给 `UseOptions` 加「跳过牌本体检查」的开关（本批不需要：真正要的是「只筛目标」这个口子）。

## Decisions

### D1. 「转移」= 换掉 `targets` 里那个元素 + **补发**三份「指定目标后」

- 官方原文就是「取消此目标 + 生成新目标 + 加入列表」= **替换**（不是新增、不是取消后重开）；后半句「将所有还未生成过『成为目标时』的目标重新排序」证明了**新目标要生成「成为目标时」** ⇒ 内核在 `replaceTarget` 里**立刻对新目标发一遍**（全局 → 使用者 → 新目标）。
- 这条**是「流离触发流离」的必要条件**：不补发，B（新目标）就收不到「成为目标」，他那份【流离】永远不发动 ⇒ 链式不成立（反向验证时正是红这两条）。
- 生效那轮 `settle` 现算 `actionOrder(self.targets)` ⇒ 被换掉的不生效、换上的生效；官方的「重新排序」在我们的座位序里天然成立（近似）。
- **「指定目标后」那一轮按原目标快照跑完**（`actionOrder` 的快照），新目标是补发的、不占原位置 —— 语义边界，写进文档。

### D2. 拿「全量合法目标」用新读取口 `game:getLegalTargets`，**不改 `canUse` 的返回值**

- 事实：`canUse` 给的名单**永远是「按使用者视角筛过的」**（【杀】的 filter 里 `user:isInRange(player, range, plan.useOptions)`）⇒ 拿它当基底会**漏掉「使用者够不着、但大乔够得着」的人** —— 而那正是流离的意义。
- **不能**用「重调一次 `canUse`」绕开：`canUse` 第一步 `checkCardItself` 要求「牌在使用者手上」，而流离发动时牌**已进临时区** ⇒ 实体牌必然返回「使用者手上没有这张牌」（只有虚拟牌跳过这三条）。
- **也不能**把「这次的候选名单」当 `canUse` 的第 3 参（那是「要校验的目标」，全部必须合法 ⇒ 有一个不合法就整条 false）。
- ⇒ 开一个**只做目标筛选**的读取口：跑 filter + 问候选者 `'卡牌-目标-能否指定'`，**不合并选项**（选项由调用方给：内容侧要叠加就 `table.copy(useCard.useOptions or {})` 改字段）、**不 fire `'卡牌-能否使用'`**（避免一次使用里把内容侧时机多问一遍）。`canUse` 与它共用 `collectLegalTargets`。

### D3. `canUse` 拆成两半（牌本体 / 目标）

- `checkCardItself`（已有）判「牌本身能不能用」；新抽 `checkTargets` 判「给的目标配不配」（数量区间 / 取小 / 子集 / 重复），`canUse` 只剩四步。
- 纯重构、行为等价（1013 全绿验证过），好处是 D2 的读取口与 `canUse` 的目标半天然是同一段。

### D4. 两句判据分开读（括号的位置决定落点）

| 底本片段 | 我们的落点 |
| --- | --- |
| 「**你攻击范围内**」 | 用**大乔自己**的攻击范围、**要算距离**：`owner:isInRange(player, owner:getAttr('攻击范围'))` |
| 「为此【杀】合法目标（**无距离限制**）」 | 判「是不是这张牌的合法目标」时**不判距离**：`getLegalTargets(user, card, options)`，`options.ignoreDistance = true` |

- 依据：若「无距离限制」修饰的是「你攻击范围内」，那这句几乎恒真（距离恒算 1）、白写；而修饰「合法目标」那半才有意义（【杀】的距离限制是**使用者视角**的，流离要的是「这张【杀】能不能落到他身上」）。
- `ignoreDistance` 的声明**搬出内核**（它只被 `@基础/距离.lua` 读）：内核只列自己要读的选项名，其余由读它的那个包声明 —— 与 `unnullifiable` 同一条口径。

### D5. 弃牌与转移**一次问完**

- 用 `askCardWithTarget`（一张牌 + 一个目标）一次拿到两样；**没答 = 不发动**（不问「发不发动」，照【张辽】口径「选不出就是不发动」）—— 避免「先弃了牌才发现没人可转」。
- 发动那一次套 `skill:cast`（归因）；候选为空就**连问都不问**。
