# Design

## Context

- 牌『被动』：进槽启用（跑一次、把返回的撤销函数收着）、离槽停用（撤销）；回调返回 disposer —— `game:on` 的返回正好是反注册函数。
- 目标数修正的收集点唯一：`Card:getTargetCount(user, targets)`（给了 targets 才收集；`(0,0)` 不收集）。方天返回就落在这里。
- 官方口径：「当你使用【杀】时，若此【杀】是你最后的手牌，你可以额外指定至多两个目标。」——「可以」= 放宽而非强制；「额外两个」= `+2` 增量（叠加式，与「加成」的既有口径一致）。

## Goals / Non-Goals

**Goals:**

- 方天画戟的技能：被动 + 目标数修正 `+2`，条件 = 使用者是装备主、牌名【杀】、此【杀】是最后手牌。
- 违规负例成套：数量超限（超声明 / 超合法数）、数量不足（不给目标）、目标不合法（含自己）、条件不满足（不是最后手牌 / 没装备 / 拆下后）、别的牌、别人用。

**Non-Goals:**

- 其余装备技能（各是一个功能点）。
- 装备区的协议层表达。

## Decisions

### D1. 技能形状 = 被动订阅 `'卡牌-目标数修正'`

```lua
: on('被动', function (card, zone)
    local owner = assert(zone.owner)
    return game:on('卡牌-目标数修正', function (check)
        if check.card.name ~= '杀' or check.user ~= owner then
            return
        end
        local hand = owner:getZone('手牌')
        if hand:count() == 1 and hand:list()[1] == check.card then
            return 2
        end
    end)
end)
```

### D2. 「最后手牌」的判定时点 = 校验时

`canUse`（含 `useCard` 的二次校验）发生在取牌之前 ⇒ 此刻【杀】还在手牌里，`hand:count() == 1 and list()[1] == 此杀` 就是「最后手牌」；`askUseCard` 的候选生成不传 targets ⇒ 不收集修正，不会误判。

### D3. 只认牌名「杀」与装备主

- 牌名直呼（标准包内部允许；机制侧不建按名分支）。
- `check.user ~= owner` ⇒ 别人用的【杀】不受影响；别的牌名（决斗等）也不受影响。

### D4. 用例面（含目标数量违规）

| 场景 | 期望 |
| --- | --- |
| 最后手牌 + 装备 ⇒ 两名 | 成立；区间 1..2（不超合法目标数） |
| 两名目标依次结算 | 一个目标的响应不影响另一个（迁移 `rule/slash` 的机制用例） |
| 三名目标（超合法数） | 拒「至多指定 2 个目标」 |
| 不给目标 | 拒「至少要指定 1 个目标」 |
| 含自己（不合法目标） | 拒「不能以这个角色为目标」 |
| 不是最后手牌 | 拒「至多指定 1 个目标」；一名照常 |
| 没装备 / 拆下后 | 拒「至多指定 1 个目标」 |
| 【决斗】（别的牌） | 拒「至多指定 1 个目标」 |
| 别人用【杀】 | 拒「至多指定 1 个目标」 |

## Risks / Trade-offs

- **[文案]** 「至多指定 N 个目标」里的 N 是当场算出的最终上限（含与合法目标数取小）—— 用例按它断言。
- **[回退]** 单文件、单钩子：撤掉 `'被动'` 订阅即回原状（机制对默认牌零影响）。
