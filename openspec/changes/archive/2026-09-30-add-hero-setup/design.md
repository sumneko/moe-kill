# Design

## 为什么落在内容侧（`@基础/武将.lua`）而不是内核

装配要写三样东西：`sex` / `kingdom`（字段）与**体力上限 / 体力**（**属性**）。属性名是内容侧定的（`@基础/体力.lua` 里 `define('体力上限', …)`），**内核写死属性名就破了「内核不预设属性名」这条硬约束**。

内容侧给内核类加方法是已有能力（`allow-package-class-edit`，2026-09-28）：`@基础/距离.lua` 的 `Player:distance`、`@基础/装备.lua` 的 `Player:equipCard`（后者还顺手管了体力之外的东西）—— 装配是同一类事（基础规则的默认层），照它们写即可。

于是分工是：**内核提供定义与查询**（`HeroDef` / `game:getHero`），**内容侧提供「装到角色身上」**。

## 一次 `setHero` 做什么

```lua
function M:setHero(hero)
    self.hero    = hero            -- 哪张武将
    self.sex     = hero:getSex()   -- 性别（官方：没有性别的角色不能判断别人与其性别是否相同）
    self.kingdom = hero:getKingdom()
    self:setAttr('体力上限', maxHp)  -- 覆写基础上限
    self:setAttr('体力', hp)        -- 初始体力值（官方：可以不为上限）
end
```

- **覆写而不是叠加**：武将给的是「基础值」，主公 +1 那类**加成**仍由身份场用 `addAttr`（增量）挂在后面 ⇒ **顺序 = 先选将、后开局**。反了的话 `setAttr` 会把加成冲掉 —— 这条不作为防御去挡（写清楚就行），但测试里正面钉住「先选将 → 开局 ⇒ 上限 = 武将上限 + 加成」。
- **体力的兜底链放在内容侧**（用户 2026-09-30 定）：内核只存**声明值**（公开字段 `maxHp` / `initialHp`、不再提供 `getHp()`），`getHp()` 的定义**挪到 `@基础/武将.lua`** —— **依次从「武将定义 → 规则数值 `默认体力` → 5」取值**（不给初始体力值就取上限）。于是 `setHero` 一行 `hero:getHp()` 拿到有效值，而内核完全不知道「默认体力」这个规则数值、也不硬编码 5。不判空（用户原话：「没必要判空」）。
- **不返回 disposer**：这是一次性「设置」（同 `setTag` / `setAttr`），不是可叠加的添加；换将 / 失去武将**现在没有需求**，真要做时按那时的口径（涉及「体力上限退回时体力怎么算」）另谈。

## 牌面数据的声明与读法都住内容侧

同一条理由推到势力、性别与体力（用户 2026-09-30 定）：内核只留「定义本身」（姓名 / 技能名 / 自带数据），**势力 / 性别 / 体力三样的链式写方法与读法全在 `@基础/武将.lua`**（`Class 'HeroDef'` 加私有字段 `kingdomName` / `sexName` / `maxHp` / `initialHp` 与方法 `kingdom` / `getKingdom` / `sex` / `getSex` / `hp` / `getHp`）。取值词（`'魏'` / `'男'`）本来就是牌面内容词，`默认体力` 与「与上限相同」也是规则口径 —— 内核不预设这些，也就不必为它们维护字段与类型。代价是内核套件（探针局不带 `@基础`）不再能声明 / 断言势力、性别与体力，这几样改由 `rule.hero` 盯。

## 体力在角色上的便捷读法

同一处（`@基础/武将.lua`）收口了**体力在角色上的读法**（用户 2026-09-30 定）：`player:getHp()` / `getMaxHp()` / `getLostHp()`。

- 前两个就是 `getAttr('体力')` / `getAttr('体力上限')` 的便捷写法 —— 属性名是内容侧的，读法也就收口在内容侧，调用点不必再拼字符串。
- `getLostHp()` 是**算出来的**（上限 − 当前），不存字段：官方叫「已损失体力值」，技能里「已受伤」的判据。抬上限后它自然跟着变大（用例钉住）。
- **能叠加的才返回 disposer**：这三个只读，不返回。
- **不动存量调用点**：既有代码里那批 `getAttr('体力')` 暂不替换（用户 2026-09-30 未提），要用时顺手换。

## 默认体力加兜底

`@基础/体力.lua` 的 `'游戏-开始'` 里加 `if not player.hero then …` —— 两个理由：

1. **顺序无关**：先选将（`setHero` 在开局前）不会被默认值冲掉；
2. **`默认体力` 的定位转正**：它从「所有人的上限」退成「**没选武将时的兜底**」—— 这正是 `sanguosha-rules` 里早就记下的那条（「等武将接管上限后，它就只剩兜底一个用途」）。

## 本批不做

- **技能挂载**：`setHero` 里留位置（将来的 `addSkill` 在那里逐个挂，并处理「主公技只给主公」）—— 技能系统是下一批。
- **选将流程**（谁拿到哪张武将、随机发牌、主公先选）：属装配方的编排（将来的会话 / 开局流程），本批只提供「把某张武将装给某人」这一个动作。
