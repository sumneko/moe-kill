# Design

## Context

- `canUse` 的目标部分现状（见 `server/core/game.lua`）：拿不到『获取目标』/ 合法集合为空 ⇒ 拒绝；调用方给了目标 ⇒ 必须 ⊆ 合法集合；**没有个数概念** —— 多目标【杀】因此一直能用（`rule.slash` 的「多目标依次结算」就是靠它跑的）。
- 将来装备技能的挂载点 = 上一批的『被动』：进槽启用、离槽停用；回调返回 disposer，而 `game:on(...)` 的返回值**正好是反注册函数**。
- 官方口径参照：底本「额定摸牌数」给出「基础值 + Δ修正」的模式（本项目表述为「定义上限 + 修正」）。
- 局级时机的 `fire` 是**快速返回**（第一个非 nil 返回值即停），**收集不了多个来源的修正**。

## Goals / Non-Goals

**Goals:**

- 一条可复用的「数量」约束：**区间（最少 / 最多）+ 可叠加修正（收集式）**，默认 `1, 1`；「额外指定目标」类技能与多目标锦囊都是它的用户。

**Non-Goals:**

- 「改为某值 / 无视上限」式替换效果（只做「区间 + 增量」，官方那套里更复杂的替换要用时再开）。
- 装备技能的落地（含【方天画戟】—— 机制备好后它待专门规划）与其余 9 张（各是一个功能点）。
- 协议层展示（询问选项里暂不携带「至多几个」）。

## Decisions

### D1. 数量模型 = 「区间（最少 / 最多）+ Σ增量」

- 声明：`CardDef:targetCount(min, max)`（**两个数字必给**；**不调用 = 默认 `1, 1`**；事实不限写 `1000` —— 与限额的「事实不限」同口径，比 nil 表达好写、好比较；`extends` 要带上它）。
- **「无目标」并入同一份配置**：`(0, 0)` 等价于原来的 `noTarget()`（后者退役）—— 一个概念管「能不能选、选几个」。
- 修正 = **整数增量、全部累加**（可正可负），**只作用在上限**；**最终上限 = min(上限 + Σ增量, 『获取目标』返回的合法目标数量)**（集合就那么大时，放宽也不能超）。
- 备选「取最大值」否决：官方文本是「**额外**指定」——追加语义；叠加式也与「加成叠加」的既有口径一致。

### D2. 修正通道 = 收集式触发（新原语 `collect`）

- `SimpleEvent:collect` / `Event:collect` / `game:collect`：跑**全部**回调、收集非 nil 返回值；执行顺序与报错隔离与 `fire` 一致。
- 为什么不用 `fire`：快速返回会被第一个说话者截断，而装备技能（运行期注册）永远排在加载期声明者之后 —— 恰恰轮不到它说话。
- 被否的备选：① 把修正塞进唯一「声明者」的定义里（装备技能不能改别的牌的定义）；② 在 Player 上挂「无条件修正」（「最后手牌」这类条件是每次使用的动态判断，挂不住）；③ 只扩展否决式 `'卡牌-能否使用'`（它只能拒、不能放宽）。

### D3. 时机 `'卡牌-目标数修正'`

- 载荷 `{ user, card, targets }`（与 `'卡牌-能否使用'` 同形）；**只对需要目标（上限 > 0）的牌、只在给了目标时**收集（上限 0 的牌不收集合法目标、也不收集修正；没给目标 = 不判个数）。
- `env-meta.lua` 补专用声明 + `string` 兜底（局级时机是开放集合）。

### D4. 校验位置与顺序

- `canUse` 里、**给了目标**时：先判个数（`少于最少` / `超过最终上限` —— 最终上限含与合法目标数量的取小），再判「⊆ 合法集合」；只判「能不能用」（没给目标）时个数不参与。
- 失败原因：「「X」至少要指定 N 个目标」/「「X」至多指定 M 个目标」（M = 最终上限的当场值）；`(0,0)` 的拒绝沿用「不需要指定目标」的说法。

### D5. 各牌的适配面

- **【杀】与单目标牌（借刀 / 顺手 / 过河 / 决斗 / 桃 / 无中 / 乐 / 闪电）什么都不用写** —— 默认 `1,1` 正是它们要的。
- **多目标锦囊**（南蛮 / 万箭 / 五谷 / 桃园）：`: targetCount(1, 1000)` —— 行为与现状一致（玩家仍可挑子集）；「官方是强制全体」另开（需要「必须全选」的表达）。
- **装备模板**：`noTarget()` → `: targetCount(0, 0)`；`noTarget()` / `isNoTarget()` 从 `CardDef` 删掉（判读点：`canUse`、`AskUseCard` 的选项生成）。
- `rule/slash` 的「多目标依次结算，一个目标的响应不影响另一个」—— **机制意图**（逐目标 + 响应互不影响）保留，由 `core.effect.play` 的逐目标一组继续覆盖；`rule/slash.lua` 换一条负例（没有放宽时 2 个目标被拒）。
- core 的探针里**多目标使用**的那些补 `: targetCount(1, 1000)`（跑失败清单定位）；`noTarget()` 写法换 `(0, 0)`。

### D7. 照搬件改动的记账

- `server/tools/simple-event.lua` 是上游照搬件；`collect` 的加入沿用 `fire`（快速返回）已有的先例 —— 记入 `infrastructure.md` 的「本项目对上游照搬件的改动点」。

## Risks / Trade-offs

- **[【杀】行为收紧]** 多目标【杀】从「默认可用」变「默认被拒」 → 适配面已核实：`rule/slash` 一条用例 + core 探针里多目标使用的少数几处（跑失败清单定位）；全量回归兜底。
- **[noTarget 退役]** 调用面很小（内容侧 1 处、内核 2 处判读、测试约 5 处） → 一次改干净；三种表现一一对应（给了目标即拒 / 零目标成立 / 不要求『获取目标』）。
- **[新原语先例少]** `collect` 目前只有一处使用 → 文档写清判据：**「多来源贡献 / 修正链」用 `collect`；「是非问 / 通知」用 `fire`**。
- **[选项不带数量提示]** 询问的 `targets` 仍是完整合法集合、个数约束在答复校验时才生效 → 已知缺口，留给会话 / 协议批次（Non-goal）。
- **[回退]** 单批自洽：内容侧只要把锦囊的声明与 `(0,0)` 恢复就是旧行为；内核机制（`collect` / `targetCount` / 修正时机）也可整体撤回（对默认牌零影响）。
