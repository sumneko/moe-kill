# 设计：诸葛连弩与「次数修正」

## D1. 落点 = `checkCardItself`（共用收口）

- `checkCardItself(game, user, card)` 是 `canUse` / `canUseToCard` 共用的「牌本体」校验，次数内建条目就在里面（`phase` 存在且属于使用者时判 `getUseCount < limit`）。
- 修正加在这**唯一一处**：`limit = def:getLimit(阶段名) + phase:getLimitDelta(名字) + Σ修正`。两条用牌路径同时享有、无别的读取点（选项与校验都走它，所以不像目标数那样需要 `Card` 上的读法封装）。

## D2. 事件：`'卡牌-次数修正'`（对仗「目标数修正」）

- 名字对仗 `'卡牌-目标数修正'`；载荷同形 `{ user, card }`；collect 语义（**每个来源各贡献一份**，判据同架构文档 §10：一个结论用 fire、各贡献一份用 collect）。
- 取值随状态**现问**（不是「阶段开始时一次性加账」）：装上立即生效、卸下立即消失 —— 这点用「拆下后限制立即回来」的用例守住。

## D3. 诸葛连弩的技能形状

- 『被动』+ 无条件（锁定技语义，与仁王盾同款）；`check.card.name == '杀'` 且 `check.user == owner` 才给 `+1000`。
- `+1000` 是既有口径（「+1000 相当于不限」），不做「无限」的特殊值。

## D4. 用例面

- 机制（`core.can-use`）：修正 Σ 正负都参与限额。
- 行为（`rule.equip`）：① 连出两张【杀】（第二张照常结算）② 只帮装备主（别人装着不帮自己）③ 拆下后限制立即回来。

## Risks

- 「阶段外不受次数限制」是既有口径 ⇒ 修正只在阶段内参与判定（与现状一致，不改）。
- `+1000` 不是真正无穷（实践足够；真要「无限」的语义词再另议）。
