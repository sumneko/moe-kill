# 玩家级时机表与效果判定的三段式

## Why

时机表现在只有全局一张（`game.events`）：订阅时没有「这是谁的技能」这一维 —— 技能挂在谁身上不是订阅信息的一部分。于是：

- 技能只能全局订阅 + 回调里自己认领（【仁王盾】写 `effect.target ~= owner` 就是在认领）；
- 每次「效果-能否生效」都会唤醒**所有**装备者的回调（别人的杀也过一遍他的函数）；
- 「技能挂在玩家身上、只响应与自己有关的」这件事现在**表达不出来**。

## What Changes

- **`Player` 加自己的时机表**：`player:on / fire / collect`，与 `game` 同形（同一个 `Event` 实现：注册顺序执行、疑问式名字看返回值、`on` 返回 disposer ⇒ 『被动』机制一行不用改）。
- **效果判定的三段式**：每个效果在自己结算之前，依次被问三次「能不能生效」：
  1. `game:fire('效果-能否生效')` —— 全局（第三方 / 规则，【无懈可击】现在的位置）；
  2. `effect.from?:fire('效果-来源-能否生效')` —— 来源；
  3. `effect.to?:fire('效果-目标-能否生效')` —— 承受者。

  任一给原因即**短路**（不再问后面的段）。
- **`Effect.from` / `Effect.to`**：沿用伤害已经用的名字（`Damage.from / Damage.to`、`Heal.to`）；`CardEffect` / `UseCard` / `UseCardToCard` / `CardEffectToCard` 用 `__getter` 转发（`from = user`、`to = target`）；基类默认都为空（无来源伤害、判定阶段自然跳过对应段）。
- **迁移【仁王盾】**：挂 `owner:on('效果-目标-能否生效')` —— 只有它主人被指定为目标时才被问，回调里不再认领目标。

## Non-goals

- 不重命名其他事件（`'回合-开始'` / `'摸牌-生效'` 等的「按玩家定向」将来另做）；
- 不给询问类效果（`Ask*`）单独定语义：它们的 `to`（被问者）照既有的字段读法会进目标段（见 design 的 D4）；
- 不处理重装（`resetContent`）清玩家事件表 —— 重装整块即将随 `add-worker-mode` 退役，不写一次性逻辑。
