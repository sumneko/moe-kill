# 变更：局终后原班人马重开一局

## 为什么

一局打完就没有下文了 —— 想再来一局只能**重启后端进程**。核实（2026-10-15）：`moe.room` 只有 `open` / `join` / `start`；座位占满后再 `join` 回「座位已经坐满」，`start` 里那句 `not game:getResult()` 守卫又挡着不重开。机器人冒烟跑完一局就停在那里，于是「连跑多局看内存 / 日志 / 时序」这类验证做不了 —— 而这正是接下来任何内核 / 内容 / 性能改动都想要的验证手段。

## 什么变了

- 新增**上行方法 `Game.Restart`**（无参数）：把已经终了的这一局放下，**原班人马 + 同配置同包**重开一局。
- 新增**下行通知 `Game.Restarted`**（params = 一份完整快照，形状与 `Game.Join` 的回包一致）：每个连接据此**整份重建**界面。
- 宿主侧 **`moe.room.restart()`**：从旧局读出「原班人马」（座位号 / 名字 / 连接）与配置（`seats` / `packages` / `sources`）⇒ 建新局 ⇒ 原班人马重坐（新 `Player` + 新 `ClientUser`，同一条连接）⇒ 广播座位表 + 给每个连接推一份新局快照。
- 前端：终局横幅旁加「**再来一局**」按钮；收到 `Game.Restarted` 按「重新入座」处理（清状态 + 应用快照）。
- 机器人（`?robot=`）：局终后**自动**触发一次重开（带小延时），于是能连跑多局。

## 口径（用户 2026-10-15 定）

- **原班人马重开**：座位号与名字都保持，**使用当前配置与包**。
- **任一条连接发一次就重开**（现在没有房间 / 房主概念，取最小形状）。
- **随机种子另取**（沿用配置但种子 +1 ⇒ 同样的包与人数、不同的牌）。
- **机器人局终后自动重开**。

## 非目标

- 不做房间 / 房主 / 投票那一套。
- 不做**局中**重开（必须已经终局；没终局就回错）。
- 不做「换配置重开」（配置一律沿用例；要换配置就重启进程，将来由 lobby 承担）。
- 不做旁观者、也不等断线的人回来（只服务当前还坐着的那些连接）。
