# 把「用过的牌进处理区」收进内核

## Why

「用过的牌在结算期间停在哪」现在是内容侧的一条订阅（`package/@基础/使用.lua`：订阅 `'卡牌-结算前'` → `game:moveCard(牌, 这次用牌的临时区)`），而它的另一半 ——「临时区剩下的牌送回弃牌堆」—— 早就收在内核（`Effect:bindFinish` 的默认收尾，2026-09-24 `kernel-base-zones` 定）。

同一个机制被切成两半，而且与「打出的牌」那条**不对称**：打出的牌由内核类自己安置（`AskPlayCard:onAnswered()` → `moveCard(牌, parent:getTempZone())`）。官方的「处理区」是通用机制（每次结算各自一块）—— 「进处理区」与「处理区剩下的回弃牌堆」是同一层；出口已在内核 ⇒ 入口也该在内核。

## What Changes

- `UseCard:settle` / `UseCardToCard:settle` 在**取出牌之后**自己把牌放进这次结算的临时区（仍走 `game:moveCard`，与原先内容侧那条逐字等价：有父效果、可取消、照旧进「效果-能否生效」窗口）。
- 删除 `package/@基础/使用.lua`（它只剩这一条订阅）。
- `'卡牌-结算前'` **保留**：角色从「让内容侧安置牌」变成**通知 / 干预点**（牌此刻已在临时区）—— 将来技能要用这个时点不必再动内核。
- **顺带修一处漏等待**（同日，用户发现）：两个 `settle` 里逐目标（对牌使用是一支）的 `effect:apply()` 改成 **`effect:apply():await()`** —— `apply()` 只驱动、不等，生效里一让出就会「前一个目标没结完就开下一个」、父结算提前收尾（对牌使用那一支还会让无懈窗口的 `reject` 落空）。
- 口径更正（文档同步）：不再写「牌的安置与去向由内容侧决定」；改成「**内核安置 + 内核默认收尾**」（去向的例外 —— 装备进装备区、延时锦囊进判定区 —— 仍由内容侧在牌的 `'使用'` 钩子里从临时区搬走）。

## Impact

- **行为不变**：用过的牌仍然是「原区 → 临时区 → 弃牌堆」，例外路径（装备 / 延时锦囊）依赖的是「牌此刻在临时区」，不依赖这一步由谁做。
- 受影响文件：`server/core/effect/use-card.lua`、`server/core/effect/use-card-to-card.lua`、`package/@基础/使用.lua`（删）、`server/test/core/effect/play.lua`（两条用例：探针局里没有 `@基础`，如今内核也会安置 ⇒ 断言改成「收尾后落在弃牌堆」）、技能文档（`architecture.md` / `code-style.md` / `progress.md` / `sanguosha-rules`）。
- **少一个覆盖口**：「mod 替换 `@基础/使用.lua` 改『用过的牌停哪』」不再可行 —— 这条属于机制而不是规则（mod 该改的是体力默认值 / 距离 / 摸牌数这类）。
- 验收基线 582 → **584**（新增两条 await 回归用例）。
