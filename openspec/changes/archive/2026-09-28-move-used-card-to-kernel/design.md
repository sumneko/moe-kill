# Design

## 1）落点与形状

```lua
-- UseCard:settle（UseCardToCard 同形）
zone:take(index)
self.game:moveCard(self.card, self:getTempZone())
self.game:fire('卡牌-结算前', self)
```

- **放在 `fire('卡牌-结算前')` 之前**：事件语义从「请你安置这张牌」变成「这次使用开始了（牌已在处理区）」—— 订阅者看到的是稳定状态（牌有落脚处），不用再自己搬。
- **仍走 `game:moveCard`**（不起 `zone:put` 快路径）：与原先内容侧那条**逐字等价** —— MoveCard 效果有父效果（这次用牌）、可取消、照旧进 `'效果-能否生效'` 窗口；用例里「记牌器只记根效果」「父效果链」那些断言不受影响。
- **只在取出牌之后**：`canUse` 不通过时 `reject` 发生在 `zone:take` 之前 ⇒ 牌留在原处、不触发 `'卡牌-结算前'`，与今天一致。

## 2）`'卡牌-结算前'` 保留（角色变化）

它现在是「使用结算开始时」的**通知点**（触发时牌已在临时区）。删掉省不了什么，代价却是以后再开要动内核；将来技能想干预这个时点用得着它。时机名与触发次数都不变（一次使用一次）。

## 3）为什么可以收（切分轴：固定 / 可配置）

- 「用过的牌进本次结算的处理区」**没有变体**：所有牌一律如此；装备 / 延时锦囊是**在「使用」钩子里从临时区搬走**的特例，不依赖这一步在内容侧。
- 与它成对的「处理区剩下的回弃牌堆」已在内核（`Effect:bindFinish`），两者同层。
- 与「打出的牌」对称：那条已经在内核（`AskPlayCard:onAnswered()`）。

## 4）不做

- 不把「装备进装备区 / 延时锦囊进判定区」收进内核：那是**规则**（有变体、是牌自己的效果），继续写在牌的 `'使用'` 钩子里。
- 不动 `Effect:bindFinish` 的默认收尾（已在内核）。

## 5）逐目标生效必须「等它结完」（同日补，用户发现）

两个 `settle` 里原本写的是 `effect:apply()` —— **只驱动、不等**（`apply()` = 建任务 + 一次 resume）。于是任何在生效里让出的写法（异步答复 / `sleep`）都会让「前一个目标还没结完就开始下一个」；更糟的是父结算**提前收尾**（`'卡牌-结算后'` 早发、临时区的牌已被送进弃牌堆）。对牌使用那一支更严重：无懈窗口里的询问让出时，`reject` 会落到**已经结完**的任务上（无懈抵不掉）。

改成 `effect:apply():await()`（`await` 幂等：没驱动过会先 `apply`）。两条回归用例 —— `core.effect.play`「使用：上一个生效结完（哪怕它让出）才轮到下一个」与 `core.effect.use-card-to-card`「对牌使用：窗口里让出时，父结算也等它结完」。

**对照实验**：把 `await` 撤掉重跑，两条都按预期失败（实际 `开始2开始3收尾` / `'卡牌-结算后'` 先于窗口原因）⇒ 用例真的抓得住这个 bug，不是摆设。
