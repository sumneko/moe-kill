# Design

## Context

- 官方（BWIKI 标准版）：【贯石斧】「当你使用的【杀】被【闪】抵消后，你可以弃置两张牌，令此【杀】依然造成伤害。」
- 官方两条裁定（规则集）：① `当角色用到一张装备牌提供的距离、攻击范围或技能时，不能以任何方式操作该装备牌`（判例 = 贯石斧）⇒ **斧子自己不能当弃牌**；② `没有「依次」这个关键词的操作均指 X 张……牌一次性同时操作`（陆逊【连营】判例）⇒ 两张**一次性同时弃**。
- 现状：【杀】用 `askPlayCard` 要【闪】，「被抵消」是内容侧约定（青龙靠『答复后』手筛近似，文档记着「真抵消等贯石斧批」）；FreeKill 用 `isCancellOut` 字段 + `CardEffectCancelledOut` 事件（管线宣布、斧翻回 `false`、杀复查）。
- 本批把「抵消」落成 ask 家族的一等对象（用户 2026-09-30 定形状）：**结果读 `.success`、子类自己发时机、驳回用返回值**。

## Goals / Non-Goals

**Goals**：「打出抵消」的通用形状（子类 + 两段时机 + `.success` 判读）；【贯石斧】本体与用例；青龙迁移。

**Non-Goals**：无懈那条路不报这个时机；「取消（不再是目标）」不碰；南蛮 / 万箭 / 决斗暂不迁（有消费者再迁）；多闪响应（【无双】）只保证模型接得上。

## Decisions

### D1. 子类语义（用户 2026-09-30 定）

- **打出 = 抵消名义成立**；没打出/被拒收 ⇒ 不成立（未答复写 `reject('没有打出')`；答错时保留既有原因「答复不在可选项里」）。
- 答复落定后发两段：全局 `'效果-被抵消'` → `parent.from` 的 `'效果-来源-被抵消'`（照「伤害-来源-开始」的先例；玩家份名字带「来源」—— 用户当天定的命名规则，同时记进 `architecture.md` §10）。
- **驳回 = 订阅者返回值即原因**（照「效果-能否生效」的家法：第一个非空返回值就停）；子类拿它 `cancel` 自己 —— Task 的 `cancel` 本就「优先级最高、结果已定也能强改」，正是「打完闪再翻回」的场景；代价：`.result` 被清（窗口内 `.card` 还读得到、事后读不到）。
- **判读统一走 `.success`**：打出且没人驳回 = 真；其余 = 假。

### D2. 【贯石斧】

- 订 `'效果-来源-被抵消'`，筛（`reason == '杀'` + 打出的牌是【闪】）。
- 候选 = 手牌 + 装备区、**去掉斧子自己**（官方裁定一）；**凑不出两张不问**（同麒麟弓「没坐骑不问」）；`askCard(owner, '贯石斧', { card = candidates, min = 2, max = 2 })` —— **给 = 发动、不给 = 不发动**（不另问「是否发动」）。
- 弃两张 = **一次 `moveCard` 批量**（官方裁定二）；`return '贯石斧'`。

### D3. 【青龙偃月刀】迁移

- 四条手筛 → `owner:on('效果-来源-被抵消')` + 两条筛（reason 杀 + 闪）；行为与用例不变。

### 用例面

| 场景 | 期望 |
| --- | --- |
| 内核：打出 / 没打出 / 驳回 / 两段 / 答错 | `.success` 与 `.err` 各就各位；驳回清 `.result`；没打出不发时机 |
| 杀 | 被闪 ⇒ 两段时机（全局 → 来源）、载荷 = 询问；不打闪不发 |
| 斧 | 正例（弃两张、掉血、进弃牌）/ 不弃 / 凑不出两张（去掉自身）/ 混弃（手牌 + 坐骑）/ 旁人 / 万箭 / 拆下 |
| 青龙 | 原 7 条照旧全过（迁移不改行为） |

## Risks / Trade-offs

- `cancel` 清 `.result`：事后读不到打出的牌 —— 文档写明，消费方都在窗口内动作。
- 独立 kind（`askOffsetCard`）：测试与 `env-meta` 载荷联合跟着改（机械改）。
- 「多张响应才算抵消」（【无双】）等武将系统：判定写在卡自己里，届时只改卡、消费方零改动。
