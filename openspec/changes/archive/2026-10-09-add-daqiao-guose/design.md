# 设计：大乔【国色】

## D1. 官方口径（底本原文，2026-10-09 查）

- `Chapter2/Section1.md`：**实体牌**是放置在某一个区域里的实际存在的游戏牌；**虚拟牌**是角色使用和打出的对象，「角色进行使用或打出结算，其实是对**牌的信息**而不是一张实体牌进行结算」，「多数情况下使用或打出牌是需要将若干张实体牌**置入处理区**的，可以理解为类似于是使用或打出此虚拟牌的**消耗**」。
- `Chapter2/Section5.md:317-321`（**转化**）：「在使用/打出一张牌（**虚拟牌**）时，若此牌对应的实体牌的数量为 1 且此牌与此牌对应的实体牌的**牌名，属性，花色，颜色，点数不一一对应**；或实体牌的数量大于 1，则称为其使用/打出了一张转化的牌。」
- `Chapter2/Section5.md:76`（转移规则末句）：「……最后若此牌为延时锦囊牌，系统会将此牌**对应的实体牌**置入 B 的判定区。」
- `Chapter2/Section6.md:13`（【闪电】例子）：「B 于其额外回合的判定阶段**开始【闪电】的使用流程**进行判定……系统将此【闪电】**对应的实体牌**置入 B 的下家 C 的判定区。」
- `Chapter2/Section8.md:39-42`（【巧变3】）：「将 A 的判定区里的【兵粮寸断】**对应的实体牌**置入……B 的判定区」。
- `Chapter2/Section5.md:27`（【红颜】）：「小乔的黑桃手牌、装备区里的黑桃牌和黑桃判定牌的花色均会受到【红颜】的影响视为红桃，但小乔**判定区**里的黑桃牌的花色不会受到影响。」

## D2. 结论：需要两条寿命，别混（本次只做第二条）

| 是什么 | 属于谁 | 寿命 | 例子 |
| ---- | ---- | ---- | ---- |
| **这次使用/打出的信息**（结算期读值） | 那张**虚拟牌**（`UseCard.card`） | 这一次使用 | 【红颜】的黑桃【杀】在整次使用里都视为红桃（`Ch2/S1:80` 的【奸雄】例子：曹操把实体牌拿走了，对下一个目标结算时此【杀】**仍是红桃**） |
| **实体牌 ↔ 虚拟牌的对应** | 那张**实体牌** | 它在某个区域里的这段时间 | 【国色】/延时锦囊：「判定区里那张实体牌代表【乐不思蜀】」（`Ch2/S5:76`「此牌对应的实体牌」） |

- 第一类**本次不做**。现状缺口：普通使用**不造虚拟牌**（`useCard.card` 就是那张实体牌）⇒ 实体牌进处理区 / 被拿走之后，结算期读值就不再可靠。真要做【红颜】那种效果得让「每次使用都有一张信息快照」—— 另开变更。
- 第二类是本次要做的：【国色】把方块牌置入判定区，判定期（官方口径里是**另一次「使用流程」**）那张实体牌要代表【乐不思蜀】。
- 反过来也成立：**判定期用「记在牌上」是贴官方的** —— 官方对这类关系的措辞就是「X **对应的实体牌**」，而不是「虚拟牌躺在判定区里」。

## D3. 形状（用户 2026-10-09 定）

**用户的口径**：① 「把牌置入判定区**后**添加 modifier，然后离开区域时撤销」；② 「加 `withZone`」；③ 「虚拟牌 `addModifier` 的时候额外转发一份给素材」（虚拟牌自己也挂）；④ 最后收敛成白名单：「**只有移动到判定区、从判定区移动到判定效果的临时区这 2 种情况维持 modifier，其他情况都移除**」。

- **`Card:withZone(disposer, keep?)`**：加回 2026-09-30 删掉的老形状，并**多一个可选判据** `keep(新位置)` —— 返回真就算「没离开」（省略 = 老语义「换区就撤」）；**多条绑定各判各的**（逐条存 `{ disposer, keep }`，不再用一个 `zoneGCHost` 容器）。
  - **④ 那条白名单落地后只剩前半条**：复核发现**判定期那张牌全程留在判定区**（判定阶段 `card:doEffect()` 跑完才送弃牌堆；`Judge:settle()` 进临时区的是**判定牌**）⇒「判定区 → 判定效果的临时区」这条**迁移不存在**，不需要 `game:getCurrentEffect()`、不需要给临时区打标记、不需要动 `doEffect`／`settle`。
  - 于是判据就是 **`function (zone) return zone?.name == '判定' end`（进的还是判定区就留）**：【巧变3】那类「把判定区里的牌挪到别人的判定区」身份跟着走；判完送弃牌 / 被拆 / 被顺 / 摘下没去处 ⇒ 撤。**判据能这么短是因为 `Zone` 记着自己的名字**（用户当天点出）：新增 `Zone.name` + `Zone:bindName`，`player:addZone` / `game:createZone` 自动登记 ⇒ 原来那个 `isJudgeZone(区)` 局部函数（要 `owner:getZone('判定') == zone` 绕一圈）整个删掉、写进闭包。
- **`Card:addModifier`**：虚拟牌上调用 ⇒ 自己挂一份 + 每张素材各挂一份（返回的撤销函数把这几份一起撤掉）。`Card:withZone` 在虚拟牌上同理转给素材。
  - 于是**内容侧完全不用碰 `physical`**，写法与普通牌一致。
- **顺序必须是「先置入、后挂」**：`withZone` 的语义是「离开**它当时所在的**那个区」⇒ 若先挂后搬，`moveCard` 那一下就把撤销触发了（用户第 ① 句正是这个意思）。
- **`bindZone` 里那句「只在真的换区时才算离开」按老形状保留**：今天 `Zone:accept` 不再支持「同区重排」，所以**没有能触发它的路径** —— 它是「离开**它当时所在的**那个区」这句话的表达，不是防御。

## D4. 落点

| 层 | 文件 | 做什么 |
| ---- | ---- | ---- |
| 内核 | `server/core/card.lua` | `withZone(disposer, keep?)` 加回（含 `zoneBinds` 逐条记录与 `bindZone` 的换区判据）；`addModifier` 在虚拟牌上自己也挂 + 转给素材 |
| 内核 | `server/core/zone.lua` | `takeIn` 去掉中间那次 `card:unbindZone()`（见 D7） |
| 内容 | `package/@基础/卡牌/锦囊牌.lua` | 延时锦囊模板的 `'使用'`：`moveCard` 之后 `card:withZone(card:addModifier { name = card.name }, function (zone) return zone?.name == '判定' end)` |
| 内核 | `server/core/zone.lua` / `player.lua` / `game.lua` | `Zone.name` + `Zone:bindName(名字)`；两个建区入口（`player:addZone` / `game:createZone`）自动登记 —— 区要能说出自己叫什么，内容侧才不用绕 `owner:getZone(...)` |
| 武将 | `package/标准/武将/大乔.lua` | `skills { '流离', '国色' }` + `Skill '国色' : viewAs('乐不思蜀', { condition = { suit = '方块', zone = rule.ownZones } })` |

- 普通（没转化过的）延时锦囊**也照挂**：名字相同、行为不变，写成一条路径、不分支。
- 【国色】素材取 `rule.ownZones`（手牌 + 装备子区）—— 与【武圣】【奇袭】【急救】同一口径（官方「一张方块牌」；`Ch2/S5:27` 的「你的牌」= 手牌区 + 装备区）。**素材要能来自装备区，就必须走虚拟牌**：虚拟牌过 `canUse` 时会跳过「声明的牌区」那条（【乐不思蜀】声明 `zone '手牌'`），普通牌会被挡掉。

## D5. 边界（曾以为是问题，现已解决）

- **转化后的【闪电】在判定区之间转移会掉身份** —— 白名单第一条（**进的还是判定区就留**）落地后**不会了**，用例「挪到别人的判定区，身份跟着走」钉着。
- 牌离开判定区之后（判完进弃牌堆 / 被拆 / 被顺），身份撤销、读出来回到原来那张牌 —— 与官方「判定区里的是实体牌、对应关系只在那段停留里成立」一致。

## D6. 被否掉的方案

- **让虚拟牌自己进判定区**（改「虚拟牌进不了牌区」）：与底本 D1 的定义冲突（虚拟牌是使用/打出的对象，不是放在区域里的牌），且牵动拆 / 顺、【闪电】转移、判定阶段收尾、`getZone` / 可见性一串。用户 2026-10-09 否。
- **不转发、内容侧自己遍历 `physical`**：能跑，但内容侧平白多一处知道 `physical`；用户选转发。
- **`addModifier` 只转发、自己不挂**：会让「读虚拟牌」与「读素材」不一致，用户否。
- **引入「判定区 → 判定效果的临时区」那一步**（用户最初提的第二个白名单情况）：复核发现现状**没有**这条迁移，判定期那张牌全程留在判定区 ⇒ 无需 `game:getCurrentEffect()`、临时区打标记、`doEffect` / `settle` 搬牌。（若将来真有那种迁移，再把 `to == judge.tempZone` 加进 `keep` 就行。）

## D7. `Zone:takeIn` 不再留「无主」中间态（为 D3 让路）

- 原顺序：逐张「`from:detach` → **`card:unbindZone()`** → 置入本区列表 → `card:bindZone(self)`」⇒ 一次搬牌在 `bindZone` 看来是**两次离区**（先变无主、再进新区），`keep(新位置)` 会读到空位置而误撤（实测：新写的判据用例直接红）。
- 改法：**去掉中间那次 `unbindZone()`**（一次搬动 = 一次归属变更）；真摘下（`Zone:remove` / `clear` / `draw`）仍然只 `unbindZone`，那才是「没去处」⇒ 判据收到空、照撤。
- 安全性：全量用例（含搬牌最重的 `core.move` / `rule.*`）改完仍 0 失败 ⇒ 这一层没有别的消费者。
