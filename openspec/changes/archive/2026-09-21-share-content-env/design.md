# Design

## D1 共享的是「一份环境」，不是「共享表 + `__index`」

`ctx.env` 在**一次装载**里只建一份（`makeEnv(ctx.injected)`），所有文件都用它：

- 内容侧写的全局落在**这一份表**里 ⇒ 后面的文件读得到（`function 帮手() end` / `帮手 = function () end` 都行）；
- 重装建新的 `ctx` ⇒ **新环境**，上一轮的全局自然消失（和规则表 / 规则数值同一生命周期，不需要额外清理）；
- 试跑那一趟同样只建一份（`probeEnv`）—— 语义与真跑一致，否则「文件 B 调用文件 A 定义的函数」在试跑里会假报错（试跑失败只记 `WARN`，但会误导）。

## D2 注入项「每个文件刷回」，不引入守卫

`game` / `Card` / `Depends` / `util` 在每次 `load` 之前从 `ctx.injected` 重新赋进环境。

为什么不用 `__newindex` 守：那需要把环境做成代理（真正的存储放另一张表），机制变重；而「刷回」是 3 行、语义直白，且效果一样 —— **别的包改坏了这几个名字也影响不到后面的文件**。代价只有一个：某个文件里写了 `game = ...`，它自己**这个文件后续**的语句会受影响（自己的锅，和以前一样）。

## D3 沙箱口径不变

共享的只是「**内容自己的全局命名空间**」，白名单仍是那 24 个基函数，**没有** `__index = _G`：

- `moe` / `require` / `io` / `os` 照旧拿不到（用户 2026-09-21 提醒过：`_G` 会把 `moe` 这个全局漏出去）；
- 所以「直接写全局函数」不会把沙箱打穿 —— 内容侧的全局只活在 `ctx.env` 里。

## D4 代价与遗留：顺序敏感、`util` 的归属

- **顺序敏感**：包 B 要用包 A 的函数，就要求 A 先加载 —— 这正好是 `Depends` 的用武之地（我们刚把「默认包」的多余 `Depends` 删了，但**这个**用途是真的）。
- **`util` 现在仍由内核注入**。它挪进包里技术上已经可行（`@基础/工具.lua` 写一个全局 `util`），但有两个后果要先认下来：
  1. `util` 从「内核保证」变成「**装了 `@基础` 才有**」（`Depends { '!基础' }` 的局就没有了）；
  2. 它的类型声明要从 `env-meta.lua`（内核的包作者契约）挪到 `package/@基础/meta.lua`（`---@type` 声明全局变量的类型）。
     好处是「内核不再认识内容侧需要什么工具」——与「内核零内容知识」这条一脉相承。**本批不做，等确认。**

## D5 为什么不做显式服务表

`game:provide(名字, 函数)` / `game:call(名字, ...)` 能做名字冲突检测、调用点显式 —— 但那是**一套新机制**（注册 / 覆盖 / 清理都要定规矩），而「同一个环境里的全局函数」已经满足需求（用户也直接说了「允许直接定义全局函数得了」）。真出现「需要有检查的共享函数」时再谈。
