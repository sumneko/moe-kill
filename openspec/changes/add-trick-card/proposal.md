# Proposal

## Why

牌表里已经有 **10 种即时锦囊（共 31 张，标准的第二大牌类）**，但**一张都没实现**：现在能用的只有【杀】【闪】【桃】三种基本牌。「锦囊」这个类别也还没人用过 —— 刚落的 `kind` 覆盖口径支持多分类，就是为了它（`{ '锦囊', '非延时锦囊' }`）。

而后面几批全都建在「锦囊能正常用出去」这条链上：**无懈可击**（响应的对象就是锦囊）、**延时锦囊**（置入判定区后走判定）、**借刀杀人 / 过河拆桥**（要选别人的牌）。先把第一张普通锦囊做出来，这条链才算开始。

**选【无中生有】当第一张**：

- 官方描述最短（「出牌阶段，对自己使用。摸两张牌。」），**零新内核能力** —— `useCard` / 逐目标生效 / 出牌阶段筛选项 / 用过的牌进 `处理` → `弃牌`，全是现成的。
- 它把「一张锦囊牌」的完整形状跑通：**分类**（`{ '锦囊', '非延时锦囊' }`）、**合法目标**（只有自己）、**生效**（摸牌）、**去向**（走基础规则的既有路径）。
- 目标是自己 ⇒ 不牵扯「选别人的牌」「响应窗口」这些还没做的能力，风险最低。

## What Changes

- **内容侧：`package/标准/卡牌/无中生有.lua`（新）**
  - 顶部写官方描述；`Card '无中生有' : extends '锦囊牌'`。
  - `'获取目标'`：返回 `{ 使用者自己 }`（官方「对自己使用」）。
  - `'生效'`：`game:draw(ctx.target, 2)`（摸两张）。
  - **不声明 `limit`**：锦囊按官方每回合不限次（没声明就是 1000 = 事实上不限）。
- **内容侧：顺手加一个「锦囊牌」模板**（`package/@基础/锦囊牌.lua`，与基本牌模板对称）：`kind { '锦囊', '非延时锦囊' }` + `zone '手牌'` —— 即时锦囊 `: extends '锦囊牌'` 就行；将来延时锦囊写 `: extends '锦囊牌' : kind { '锦囊', '延时锦囊' }`（分类覆盖）。
- **用例：`server/test/rule/trick.lua`（新）**
  - 用出去 ⇒ 摸到两张（手牌净 +1：那张锦囊用掉了，又摸 2 张）、抽牌堆少 2 张、用过的牌进 `弃牌`。
  - **只能以自己为目标**：给别的角色 ⇒ `canUse` 明确失败；不带目标 ⇒ 能用的牌的合法目标就是自己。
  - 分类是对的（`isKind('锦囊')` / `isKind('非延时锦囊')`）—— 顺带钉住内容侧真的用了新口径的列表写法。
- **明确不做**：无懈可击（它的窗口将来插在 `'卡牌-结算前'`：按 `isKind('锦囊')` 判断 + `reject` 取消整次生效，**与单张锦囊自己的定义无关**）、其它 9 种锦囊（各自另开）、延时锦囊与判定区、锦囊的可见性 / 前端表现。

## Capabilities

### New Capabilities

无（探索期不写规格：见 `openspec/config.yaml` 与 `AGENTS.md` 的「工作流」，本变更在 `.openspec.yaml` 里设 `skip_specs: true`，契约以用例为准）。

### Modified Capabilities

无（同上）。
