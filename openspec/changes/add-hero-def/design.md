# Design

## 本批只做定义

技能（`Skill` 定义 / `addSkill` 挂载 / 标签 / 是否发动的询问）与「武将装到玩家身上」（`setHero`、体力上限接管、势力与性别写入）**都留到下一批**。理由：定义是被它们依赖的载体，先把形状定下来，技能与装配才能照着写；而技能那一层的形状（具名定义 vs 武将上的钩子）用户 2026-09-30 明确「下一批」。

所以本批的 `: skills { … }` 只是**技能名列表**（数据），没有任何解析或校验 —— 下一批 `Skill '奸雄' : …` 落地后，装配时按名字去查。

## 字段口径（全部有底本）

| 字段 | 底本依据 | 说明 |
| --- | --- | --- |
| 姓名 | Chapter2/Section1「武将牌正面标识了……姓名」 | = 定义的名字（`Hero '曹操'`） |
| 性别 | Chapter2/Section2「分为男性、女性两种」 | `: sex '男'`；取值由内容侧定 |
| 势力 | Chapter2/Section2「分为魏、蜀、吴、群、西和神六种」 | `: kingdom '魏'`；标准包只用前四个 |
| 初始体力上限 | Chapter2/Section4「为武将牌上方所印的勾玉数」 | `: hp(4)` 的第一个参数 |
| 初始体力值 | Chapter2/Section4「为……所印的高亮的勾玉数。**所以会有初始体力值不为体力上限的情况**」 | `: hp(3, 1)` 的第二个参数，**省略 = 与上限相同** |
| 技能 | Chapter2/Section1「角色拥有其武将牌的所有技能作为其武将技能」 | `: skills { … }`（本批只是名字） |

`hp(最大, 初始?)` 这个方法名与两参数形状由用户 2026-09-30 定（读法是 `getHp()` 返回两个值）。**不给默认值、也不兜底**：没声明就是空，装配那批自己判（作者错误，不做防御 —— 见 `code-style.md` §9）。

## 写法与读法照 `CardDef`

- **写**是链式方法（`: kingdom '魏'` / `: hp(4)` / `: skills { … }`）；单参数的字面量**不带括号**（与 `: addKind '武器'` / `: kind { '基本', '锦囊' }` 一致），两个参数以上带括号（与 `: value('攻击范围', 3)` / `: limit('出牌', 1)` 一致）。
- **读**走方法（`getKingdom()` / `getSex()` / `getHp()` / `getSkills()` / `getValue()`）而不是直接读字段 —— 与 `CardDef`（`getZone` / `getKinds` / `getTargetCount` / `getLimit`）同一现状：定义的字段是**私有**的。
- 数据袋 `value / getValue` 与 `CardDef` 同形（内核只存不解释），给将来的「珠联璧合」这类牌面外的数据留口子。

## 与 `CardDef` / `BuffDef` 的关系：第三个定义命名空间

规则表从此有三张、**互不干扰**（同名不冲突）：

| 定义 | 声明入口 | 查询 | 进预解析的条目校验吗 |
| --- | --- | --- | --- |
| 卡牌 | `Card '杀'` | `game:getCard` | 进（用它查同包重名） |
| 状态 | `Buff '记录'` | `game:getBuff` | 不进（`Buff = function () end`） |
| 武将 | `Hero '曹操'` | `game:getHero` | 不进（同 `Buff`） |

武将不进条目校验的理由：同一包里「有一张叫 X 的牌」和「有一个叫 X 的武将」是**两回事**（官方里武将名与牌名本来就共享池子：刘备 / 曹操 这些名字不会出现在牌上，但 `Extends` 之类将来要按名字查，混在一起迟早出事），所以各查各的表。
