# Design

## Context

动机见 `proposal.md`。与做法相关的现状：

- 内核的类名与类型注解**同名**（`Class 'Moe.Game'` 对应 `---@class Moe.Game`），这个前缀来自「内核 vs 规则」分层时代（`Core.*` → `Moe.*`）；门面拍平后工程里只剩 `moe` 一个命名空间。
- 类型名进的是**全局类型空间**：`bee.lua` 的 meta 库、会话（`Server.*`）、测试（`Test.*`）都在同一空间里；规则包（含将来的第三方）会把这些类型写进自己的注解。
- 规则包文件里 `Card` 是**加载期环境函数**（`Card '杀'`），而 `Card` 也是牌实例的类型名。

## Goals / Non-Goals

**Goals:**

- 去掉类型名上的 `Moe.` 前缀，并保证运行时类名字符串与注解保持一致。
- 把新规则写进规格：不许用命名空间前缀，也不许换个别的前缀替代。

**Non-Goals:**

- 不改运行时门面（`moe.*` 照旧）。
- 不改会话与测试自己的类型命名空间（`Server.*` / `Test.*`）。
- 不引入替代前缀（`MK.` 之类）——「加前缀」这件事本身被否掉。

## Decisions

### D1 用同一条替换规则批量改名，不维护映射表

删掉字面量 `Moe.` 即可覆盖全部情况：`Moe.X` → `X`、`Moe.Loader.Y` → `Loader.Y`、`Class 'Moe.Game'` → `Class 'Game'`。注解名与类名字符串本来就同名，机械替换天然保持一致。

**备选**：维护「旧名 → 新名」表逐条替换（多余，且漏一条就出现半新半旧）；只改注解不改类名字符串（`New 'Moe.Card'` 与 `---@class Card` 脱节，LuaLS 失去关联）。

### D2 从属类型保留「类名.子名」

`Loader.Context` / `Game.EventCtx.卡牌` / `Player.CreateOptions`：去掉 `Moe.` 后保留各自所有者那一层 —— 既看得出归属，又不会把 `Context` / `CreateOptions` 这类泛词直接扔进全局类型空间。

**备选**：全拍平成 `Context` / `CreateOptions`（泛词抢名字、看不出归属）。

### D3 `Card` 的撞名靠问题面板确认，不提前回避

`Card` 作为类型名与「加载期环境函数 `Card`」共存：类型与值分属两个命名空间，LuaLS 应该能区分。实现后必须用问题面板确认 —— `Card '杀'` 与 `Card:on(...)` 的调用点不报错，同时 `---@param card Card` 这类注解正常解析。

**备选**：牌实例类型改叫 `CardInstance`（避开撞名，但与 `CardDef` 不对称、也不比 `Card` 清楚）；把环境函数改名（改的是规则包写法，本末倒置）。

## Risks / Trade-offs

- [第三方包作者写的注解会失效（**BREAKING**）] → 当前没有第三方；`env-meta.lua` 与文档一起改，将来写包文档时写明类型名。
- [约 350 处改名可能有漏网（探针字符串 / 文档 / 规格）] → 用同一条规则批量做，再 `grep -r 'Moe\.'`（区分大小写）复查到 0；规格里描述性提到类型名的需求用 MODIFIED 增量同步。
- [类型名变短后可能与将来的库撞名（`Event` / `Zone` / `Context`）] → 接受；真撞上时在那一处写全限定名，不回头加全局前缀。

## Open Questions

- 会话与测试的类型命名空间（`Server.*` / `Test.*`）要不要也拍平？留到它们定型时再定，本批不动。
