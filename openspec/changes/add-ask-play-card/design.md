# Design

## Context

`AskCard`（要一张牌）与 `AskUseCard`（要一次使用）已经拆开，「语义由类携带、缘由不透明」的口径立住了。剩下的缝隙是**打出**：它当初被表达成 `reason == '打出'`，并且由 `package/@基础/打出.lua` 订阅 `'卡牌-答复'` 来接管"答复的牌往哪去"。于是：

- `'打出'` 是唯一一个"动作类别"混进缘由的取值，而且它是**全局唯一读者**（内容侧靠魔法字符串判断）；
- 打出真正的语义差别（**牌当场交出去**、不跑 `canUse`、不记次数）没有任何类型上的落点。

## Goals / Non-Goals

**Goals**

- 把「打出」变成第三种询问类别：`AskPlayCard`，与 `AskUseCard` 一样只是 `AskCard` 的薄子类。
- 缘由彻底回到"谁发起的"这一种含义（惯例写牌名 / 阶段名）。
- 打出的牌的去向由内核类自己保证，内容侧（四张牌）完全不写 `moveCard`。

**Non-Goals**

- 不做 `game:respond` 之类的"打出动作"入口 —— 打出的表达仍是"一次询问被答复"，只是这次问的是 `AskPlayCard`。
- 不动 `'卡牌-答复'` / `'卡牌-答复后'` 两个时机（规则层仍能读到答复、做后续判断：【杀】就靠 `ask.card` 决定是否造成伤害）。
- 不做技能的"打出"（`askPlayCard` 的候选将来可由技能提供？留到技能那批再谈）。

## Decisions

### D1 三个类，各回答一种问题

| 类 | 问什么 | 差别 |
| --- | --- | --- |
| `AskCard` | 随便一张牌（选择） | 只要在候选里就行；拒收目标 |
| `AskUseCard` | 要一次「使用」 | 候选逐张跑 `canUse`；答复必须给目标 |
| `AskPlayCard` | 要一张「打出」的牌 | 与 `AskCard` 同形；**答复的牌当场交出去** |

判断"该用哪个类"不再看缘由字符串，而是看**这次问的是什么性质的东西**。缘由只用于日志与规则层区分"谁发起的"（写发起者名字：`'杀'` / `'出牌'` / `'濒死'`）。

### D2 基类多一个钩子 `onAnswered()`

`AskCard:settle()` 的次序定成：

```
收集候选 → '卡牌-询问'（等应答）→ 答复定下 → self:onAnswered() → '卡牌-答复' → '卡牌-答复后'
```

- `onAnswered` 是 `---@async` 的空基类钩子（子类可 `await` 挪牌）。
- 放在 `'卡牌-答复'` **之前**：规则层进答复时机时，牌已经在它该在的地方（账实一致），不必自己判断"这是不是打出的牌"。
- 没有答复就不会走到这里（`settle` 在没结果时提前返回）。

### D3 打出的牌进"发起那次结算的临时区"；没有父结算就不动

- 有父结算（正常情形：`askPlayCard` 在某个 `'生效'` 里被调用）⇒ `game:moveCard(牌, self.parent:getTempZone())`，父结算收尾时由 `@基础/收尾.lua` 统一送 `弃牌`。
- 没有父结算 ⇒ **不动那张牌**，交给内容侧 —— 理由：**内核零区域名**（`architecture.md` §12 定的口径）。旧实现（`@基础/打出.lua`）在无父结算时直接送 `'弃牌'`，那是**内容侧**知道区名，可以；同一个逻辑搬进内核类就不能再写死 `'弃牌'`。
- 实际调用点都在结算里，这条只在"内容侧在流程顶层直接问一张打出的牌"时才有意义。

### D4 `package/@基础/打出.lua` 删除

它的全部内容是"`reason == '打出'` ⇒ 挪进发起那次结算的临时区"，职责已由 D3 接走，留着就是第二处真相源（而且它认识 `'弃牌'`，会与 D3 的分支打架）。用户已明确同意删除。

### D5 用例怎么摆

- 类行为进 `server/test/core/effect/ask-play-card.lua`：`'卡牌-答复'` 回调里断言"牌已在父结算的临时区"（不能事后读，父结算收尾会把它送走）、没有父结算时牌不动、候选按条件筛且拒收目标、答复不在候选里就拒收且牌不动。
- `ask-card` 套件里原先两条 `'打出'` 用例（"缘由是打出 ⇒ 进弃牌"）**换成一条基类行为用例**：`AskCard` 自己不处置那张牌（答复后牌仍在手里、弃牌还是空的）。

## 可延后的问题

- `AskPlayCard` 要不要跑 `canUse`？现在不跑（打出的牌不看次数、不看 `'卡牌-能否使用'`）—— 等真出现"打出也要受某条限制"的技能时再说。
- 三个类的公共部分（条件筛选、选项、答复校验）都还在 `AskCard` 里；如果哪天子类只剩一行，再考虑合并 —— 现在分成三个文件是为了让"这次问的是什么"一眼可见。
