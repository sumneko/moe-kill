# Design

## 1）形状（2026-09-29 拟定，待用户过目）

```lua
---@class Buff
---@field name string # 内容侧起的名字（'防具无效' 这类）
---@field host Player # 挂在谁身上

player:addBuff(名字) -> Buff     -- 同名可并存（各自一个实例）
buff:attach(disposer)            -- 资源：随移除自动撤销
buff:on(时机, 回调)               -- 订阅：随移除自动注销（先只挂局级时机）
buff:remove()                    -- 幂等：撤销全部资源、注销全部订阅、从宿主摘掉
player:getBuffs() -> Buff[]      -- 快照（给查询与全量同步）
player:hasBuff(名字) -> boolean
```

## 2）为什么挂载点先只做 `Player`

第一个需求（青釭剑）挂在目标玩家身上；`Card` / `Zone` 的 buff 没有消费者（YAGNI）。宿主的存储是 `player.buffs`（引用在宿主身上 ⇒ 宿主没则 buff 自然没）。

## 3）为什么资源与订阅记在 buff 上，而不是创建时的环境

官方裁定（§1 司马懿条）：窗口以「这次【杀】使用开始」为准 —— 中途**剑被拿走 / 使用者失去这个技能**，还没结算的目标**照样无效**。⇒ 窗口不能由「剑的被动订阅」或剑自己持有，必须独立于来源 —— `attach` / `on` 记在 buff 上（而不是创建时的 disposer 栈），就是为了这条。

## 4）生命周期写法（内容侧，内核不预设）

青釭剑的用法（细节见 `add-qinggang-sword`）：创建时挂两条订阅 ——

- `'效果-收尾'`：`effect.useCard == 这次使用` 且 `effect.target == 我管的目标` ⇒ `buff:remove()`（官方：「此时青釭剑对司马懿的效果结束」）；
- `'卡牌-结算后'`：`useCard == 这次使用` ⇒ `buff:remove()`（兜底：这次使用整体收尾）。

⇒ 内核不提供「时长」参数，也不规定何时删：**buff 自己看表**（订阅随 `remove` 一起注销，不留尾巴）。

**依赖**：`'效果-收尾'` 原来只在「结完时自己建过临时区」的效果上发（2026-09-24 收紧）—— 按目标收尾要它无条件发。**那道闸门已于 2026-09-29 提前单独去掉**（每次结算结完都发；见 `architecture.md` §10）⇒ 这里照写即可，但**过滤条件要写全**（`effect.useCard == 这次使用` 且 `effect.target` 是我管的目标），且**别在收尾里起新结算** —— 收尾可重入，不筛会自激到爆栈。

## 5）不做的（YAGNI）

- `layers`：同名实例并存就够（窗口重叠时两个实例各持一层子区禁用，计数由 `Zone:disable` 自己配平）。
- 挂到卡 / 区上；`source` 字段（先不存；协议要展示来源时再加）。
