# Design

## Context

动机见 `proposal.md`。与做法相关的现状：

- 玩家（`Player`）目前只有「参与行动」标记（`setActing` / `isActing`），**没有存活概念**；伤害可以把体力打成负数，之后没有任何后续。
- 桌子（`Desk`）的座位列表是 getter 方法 `getPlayers()`；而局上「桌子 / 随机源」的口径已经是**公开字段**（`game.desk` / `game.random`，见 `core-game`）。
- 局的时机表 `game.events` 是**内容**：`Game:resetContent()`（每次加载规则集都会调）里会 `self.events:clear()`。`game:on(...)` 是**规则集加载期专用**的注册入口（非加载期报错）。

## Decisions

### D1 存活状态放在玩家上，死亡时机由玩家自己发

`player:setAlive(值)` 改状态，**从活变死**时发 `'玩家-死亡'`。理由：调用方（规则流程 / 内容包）在结算里拿到的是玩家，`player:setAlive(false)` 一句话就完成“置死 + 通知”，不必再记住“还得 fire 一次”。

**时机跟状态变化走**（重复置死不重复触发、复活后可再触发），而不是跟调用走 —— 否则「重入的置死」会让订阅者收到多次死亡，奖惩类逻辑就会重复执行。

### D2 玩家与桌子持有自己的局（`bindGame`）

玩家要发时机就必须知道局。两个触发点：**局建立时**（桌子转交给已入座的玩家）与**入座时**（桌上有局就一并绑定）。⇒ 装配方两种顺序都行：先建桌座人再建局、或先建局再入座。

**备选**：让调用方自己 `game:fire('玩家-死亡', player)`（把通知责任推给每一处调用点，容易漏）；或让玩家不持有局、由局反向持有全部玩家（引入“局的玩家名单”第二份真相）。

`Desk.game` / `Player.game` 这类字段跨文件写入会触发 LuaDoc 可见性检查（实测 `---@field package` 的可见范围就是**同一个文件**），所以跨模块的“交给局”走**方法**（`bindGame`），字段仍标 `private`。

### D3 两个列表字段**不缓存**

一开始的写法是「`__getter` 缓存 + 订阅 `'玩家-死亡'` 清缓存」，实测**行不通**：

1. 局的事件表是内容，`resetContent()` 每次加载都会 `events:clear()` ⇒ 内核挂上去的失效订阅**重装一次就静默消失**；
2. `game:on` 是加载期专用，内核侧根本订不进去（要用 `game.events:on`，但那正是会被清的那张表）。

即使绕过第 1 条，缓存还要在**入座 / 死亡 / 将来移出座位**多处记得失效 —— 而重建一张 4~10 元素的小表代价可忽略。⇒ **现算**，永远不过期，也没有“忘记失效”的坑。`desk:getPlayers()` 一并删掉（一个概念不要两套 API）。

**备选**：保留缓存 + 把失效订阅挂到专门的“内核事件”（要新造一套机制级事件通道，本批不值当）。

### D4 名字与形状

- `desk.players` / `desk.alivePlayers`（字段式读取，与 `game.desk` 同风格）。
- `player:isAlive()` / `player:setAlive(值)`（`setAlive` 是方法 —— 它要发时机，不是纯赋值）。
- 时机名 `'玩家-死亡'`：沿用「分类-动作」风格（`分类` = 玩家）；上下文直接就是 `Player` 实例（与 `'伤害-前'` 用 `Damage` 实例同一口径）。

### D5 「参与行动」改成由存活派生的只读属性

`player.acting` 用 `__getter` 现算，实现体**先只检查 `alive`**（活着就参与行动），原 `setActing` / `isActing` 删除。

- **为什么不继续做存储字段 + 让调用方置位**：那个字段现在的**唯一**用途就是“阵亡跳过”（三国杀里没有第二个持久来源），却额外要求调用方记得在置死时同步 —— 一处忘了就是“死人还能轮到”。派生之后不可能不同步。
- **为什么先只检查 `alive` 而不把“退出 / 旁观 / 未参与本局”也写进去**：那些情形内核还没见过真实形状（用户 2026-09-19 定：**遇到再说**）；getter 是唯一收窄点，将来加条件只动它一处。
- **连带**：`desk:getNext` 改读 `player.acting`；`Player` 的注解要写 `---@class Player: Class.Base`（`__getter` 声明在 `Class.Base` 上），getter 里走公开的 `self:isAlive()`（直接读 `alive` 会被 LuaDoc 判为跨作用域访问私有字段）。

## Risks / Trade-offs

- [`alive` 与 `acting` 重叠] → 已由 D5 解掉：`acting` 就是派生值，不存在两处不同步的可能。
- [每次读列表都建新表] → 座位数量级是 4~10，可忽略；真要优化也该是“让 `alivePlayers` 变成一次查询加过滤”，而不是缓存。
- [时机名是新的字符串常量，靠约定] → 与既有所有时机一样不预设不校验；类型面在 `env-meta.lua`（写错名字只是拿不到 `ctx` 类型，运行期不报）。

## Open Questions

- 死者的牌区怎么办（弃置全部手牌 / 装备）？濒死与死亡结算（求桃、奖惩、胜负）本批明确不做，等下一个功能点。
- `desk.players` 是否也需要“不参与行动者”的版本（如 `desk.actingPlayers`）？现在没有消费方，不加。
