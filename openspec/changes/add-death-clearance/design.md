# 设计：阵亡清算

## D1 落点

| 面 | 文件 | 改什么 |
| --- | --- | --- |
| 内容 | `package/@基础/阵亡.lua`（新） | 订阅 `'玩家-死亡'`：先停用死者所有技能的被动，再把所有牌区的牌一次送弃牌堆 |
| 内容 | `package/@基础/阶段/判定阶段.lua` | 撤掉「回合角色死了就停」的提前退出 |
| 用例 | `server/test/rule/death.lua`（新） | 5 条：三类牌区都清 / 没牌的死者不炸 / 死者的技能被禁用（探针技能记账）/ 对照（活着的会响应）/ 与奖惩共存 |
| 用例 | `server/test/rule/delayed-trick.lua`、`rule/hero-skill.lua` | 两条旧断言的前提变了（死者判定区不再留牌 / 死者手牌被清） |

## D2 顺序怎么保证

**不靠代码、靠加载顺序**：`@基础` 是默认包、排在清单项之前 ⇒ `'玩家-死亡'` 的处理器先注册、先跑；`身份场/奖惩.lua` 与 `胜负.lua` 依次在后。于是「清算 → 奖惩 → 胜负判定」是自然结果，不需要额外的阶段号。

> 代价：**顺序不可观测**（奖惩读的是凶手的手牌、清算是死者的牌，两者互不影响）⇒ 用例只钉结果，钉不住先后。真要钉，得给事件加阶段号，本批不做。

## D3 为什么先停技能

清算是「死者的牌离开牌区」⇒ 会发 `'卡牌-离开区域'`（还有「区主人那份」）。死者的技能此时**还挂在身上**（`setAlive(false)` 不摘技能），所以【枭姬】这类会照样响应 —— 违反官方「已死亡的角色不能发动技能」（`Ch1/S2:46`）。

做法取「**停用被动**」（`disablePassive()`，层数计数、订阅随容器释放）而不是「摘掉技能」（`remove()`）：他要复活（将来）或做死亡相关的展示时，技能定义还在。

## D4 反向验证（实现后填）

| 拆掉什么 | 结果 |
| --- | --- |
| 不先停用死者技能（`ipairs({})`） | **1 红**（「死者身上的技能被禁用」） |
| 只清手牌（不遍历所有牌区） | **3 红**（闪电那条 + 清算两条） |
| 不清牌（`if false`） | **5 红**（急救 / 闪电 / 清算 / 奖惩三条） |

> 注：「撤掉判定阶段的提前退出」这一条**反着也钉不住** —— 清算之后死者的判定区已经空了，那层提前退出变成不可达代码；它被撤掉的依据是「已无必要」，不是某条用例。
