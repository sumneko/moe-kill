# mount-hero-skills

## D1 重建「重算」而不是「挂一次」

`refreshSkills` 每次都从头算「该有哪些」再同步（挂缺的 + 摘多的），而不是「挂上就完事」。理由：**两个触发点会先后到达**（选将 → 分身份），而且武将也可能被换（将来的重选 / 【禅让】那类）。重算天然幂等。

**挂载顺序按武将声明顺序**（不是 `pairs` 顺序）—— 技能之间的时机回调顺序跟挂载顺序走，不能随机。

## D2 主公技「不挂」而不是「挂着停用」

官方（Chapter2/Section5）：「为主公，其**拥有**此技能；不为主公，其**没有**此技能」⇒ 非主公身上**不该有这个技能**（`hasSkill` 为假），不是「有但被动停用」。

另一条例外（同一节）：「若一名**不为主公**的角色**获得**一个带有此标签的技能，则其拥有此主公技」—— 那说的是技能系统的「获得」⇒ 过滤只作用在「**按武将挂**」这条路上，直接 `addSkill` 照旧不受影响。

## D3 已知边界：摘掉逻辑分不清来源

`refreshSkills` 会摘掉**任何**不在当前武将技能表里的技能。现在技能只有「武将自带」一个来源所以安全；将来有「临时获得技能」（【奇策】那类）时，得先给它们打标记再区分 —— 先记着。

## D4 内容侧没有 `error`

实现时第一版在 `@基础/武将.lua` 里写了 `error('没有叫「{}」的技能定义' % { name })` ⇒ 3 条用例当场红（`attempt to call a nil value (global 'error')`）。**内容侧的执行环境是白名单沙箱，不含 `error`** ⇒ 内容侧报错一律用 `assert(值, 消息)`（项目里一直的写法）。

## D5 【护驾】先建壳

`Hero '曹操' : skills { '奸雄', '护驾' }` 里【护驾】一直没有定义 —— 挂载一自动做它就报错。所以先建「只有名字 + `主公技` 标签」的最小定义（**不编描述**，等文本来源）；效果留空（挂上也没副作用）。
