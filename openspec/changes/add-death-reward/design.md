# Design

## Context

现状（见 `proposal.md` 的 Why）：

- **死亡链**：`Damage` 只触发三个时机、`@基础/伤害.lua` 在 `'伤害-生效'` 里 `addAttr('体力', -amount)` → `@基础/濒死.lua` 监听每个玩家的体力变化，从 >0 跨到 ≤0 时 `game:enterDying(player)`（**记账**，保存 disposer；体力回正就撤销）→ 当前效果结算收尾 `flushDying()` 才真正起 `Dying` → `Dying:settle()` 触发 `'濒死'` → 规则侧求桃、没人给就 `player:setAlive(false)`（触发 `'玩家-死亡'`）。
- **`'玩家-死亡'` 的上下文是 `Player` 本身**（不是表）；`身份场/胜负.lua` 就订阅它、直接判胜负。
- **`Draw`**：`settle()` 只触发 `'摸牌'`，`@基础/抽牌.lua` 负责取牌与洗回；**内核不看目标是否还活着**。
- **旧机制要拆掉的那部分**：`game.dyingPending` 记账、`game:flushDying()`、`Effect:apply()` 收尾的那次 flush 调用，以及 `@基础/濒死.lua` 里给每个玩家挂的体力变化监听（含 disposer 撤销）—— 本批全删（见 D6）。
- 包内文件加载顺序不显式保证 ⇒ 同一包里的先后靠 `Depends` 定序（`Depends { './奖惩' }` = 奖惩先加载、先注册）。

## Goals / Non-Goals

**Goals:**

- 「谁杀的」成为一条能查到的账（内核只**搬运**那次伤害实例，规则侧自己解释谁是凶手）。
- 濒死能区分**进入 / 离开**（救活也是规则事件）。
- **濒死时序改成早于 `'伤害-后'`**（用户 2026-09-22 核对后定）：`@基础/伤害.lua` 扣完血就判 ≤0 并进濒死，濒死**当场结算** ⇒「受到伤害后」类技能在濒死（含死亡 / 奖惩 / 胜负）之后才跑。
- 死亡奖惩落地：杀死反贼摸三张、主公杀忠臣弃所有手牌；奖惩跑在胜负判定之前。
- 对已阵亡的角色摸牌无效（内核拦），奖惩因此可以无条件照发。

**Non-Goals:**

- **装备区**（主公杀忠臣的「弃装备牌」）—— 等装备与距离修正那批。
- 武将技能、延时锦囊、判定。
- 「失去体力」类掉血来源（将来那些地方自己调 `enterDying`，不带伤害实例）。
- 不重构生死判定：`setAlive(false)` 仍由规则侧（`@基础/濒死.lua`）调。

## Decisions

### D1 检查点：`@基础/伤害.lua` 扣完血后，当场进濒死

- `@基础/伤害.lua` 的 `'伤害-生效'` 回调里：`damage.to:addAttr('体力', -damage.amount)` → **血量 ≤0 就 `game:enterDying(damage.to, damage)`**（把这次伤害实例一并交出去）。
- `game:enterDying(player, damage?)` 改成**当场结算**：`moe.dying.create { game, player, damage }` → 驱动 + 等（与其他 `game:` 入口同一形状），返回结完的 `Dying`。
- **为什么检查点放内容侧**（用户 2026-09-22 定）：内核**不认属性名**（既有约定），而「哪个属性是血量」只有规则侧知道；`伤害.lua` 就是扣血的那个地方，知道真相最直接。
- **为什么当场结算**（而不是等效果收尾）：濒死要早于 `'伤害-后'` —— 扣血 → 濒死（含判死 / 奖惩 / 胜负）→ 然后才 `'伤害-后'`。
- 备选（否）：内核判「血量 ≤0」（得先给内核一条拿血量的路子：属性系统加生命值标记 / 规则数值给属性名 / 硬编码 `'体力'`，用户 2026-09-22 选择把检查放内容侧）；仍旧监听属性变化 + 临时标签递伤害（用户明确说不用监听）。

### D2 濒死时机：`'濒死'` → `'濒死-进入'`，并新增 `'濒死-离开'`

- **BREAKING**：`'濒死'` 改名 `'濒死-进入'`（上下文仍是 `Dying` 实例）。
- **`'濒死-离开'`**：`Dying:settle()` 里触发 `'濒死-进入'` 之后，**结算收尾时 `player:isAlive()` 为真**就触发（没救活 ⇒ 不触发，走 `'玩家-死亡'`）。
- 为什么由内核发：内容包按约定**不主动 `fire` 时机**；内核只认「存活」这个它自己的概念，不碰体力。
- 备选（否）：内容侧自己 fire（破约定）；用「血量 > 0」作判据（内核不认识血量 —— D1 刚把它退给了内容侧）。

### D3 摸牌对已阵亡的角色无效（内核拦）

- `Draw`:settle()` 开头：目标已阵亡 ⇒ **直接完成**（不触发 `'摸牌'`、不取牌、不算失败、不报错）。
- 用途（用户 2026-09-22 定）：奖惩**照口径无条件执行**，死者的那一份由 `draw` 拦掉（同归于尽时不再写分支）。
- 备选（否）：在奖惩里判「凶手还活着吗」—— 把存活检查散进规则，且「给死人摸牌」本来也没有任何意义。

### D4 「凶手」记在死者身上的标签

- `@基础/濒死.lua` 在 `'濒死-进入'` 里：`player:setTag('凶手', ctx.damage and ctx.damage.from)`；在 `'濒死-离开'`（被救活）里 `removeTag`。
- 奖惩读死者的 `'凶手'` 标签（读不到 / 等于死者自己 ⇒ 没有凶手 ⇒ 不奖惩）。
- 为什么不让 `'玩家-死亡'` 的上下文带 `from`：它的上下文现在是 `Player` **本身**，要带就得把上下文改成表（更大的 BREAKING，且所有既有订阅者全要改）；标签还有个好处 ——「谁使他濒死」在**任何**时机都查得到。
- 口径：**自杀（凶手 = 死者）不触发奖惩**；「无来源伤害 / 失去体力」⇒ 标签为空 ⇒ 不奖惩（将来那些来源自己调 `enterDying`，不带伤害）。

### D5 奖惩：新文件 `package/身份场/奖惩.lua`

- 挂在 `'玩家-死亡'` 上，**必须排在胜负判定之前** ⇒ `package/身份场/胜负.lua` 顶部写 `Depends { './奖惩' }`（依赖先加载 ⇒ 钩子先注册 ⇒ 先执行）。
- **杀死反贼** ⇒ `game:draw(凶手, 3)`（凶手已阵亡 ⇒ 由 D3 拦掉）。
- **主公杀死忠臣** ⇒ 主公弃置**所有手牌**：`game:moveCard(手牌区里的全部牌, '弃牌')`（手牌空就不动）。装备牌等装备批次（Non-Goal）。
- 主公用 `game.desk:getPlayer(1)`（身份场口径：主公固定 1 号位）；身份读 `player:getTag('身份')`（身份场自己的标签）。
- 奖惩里**不判游戏结果**（`game:getResult()`）：顺序由注册顺序保证，胜负判定在它之后跑。

### D6 删掉旧的延迟机制与属性监听（用户 2026-09-22 定）

濒死既然当场结算，下面这些就都没用了，**同批删掉**：

- 内核：`game.dyingPending` 那本记账、`game:flushDying()`、`Effect:apply()` 收尾的那次 `flushDying()` 调用，以及 `enterDying` 返回 disposer 供撤销的写法（改成返回结完的 `Dying`）。
- 内容：`@基础/濒死.lua` 里「`'游戏-开始'` 时给每个玩家挂体力变化监听 + 保持 disposer、体力回正就撤销」那一整套。
- 理由：血量只由伤害（与治疗）改（用户口径），盯“谁改的”不如盯“扣血的那个地方”；去掉记账后濒死不再需要“等收尾”与“事后撤销”两个概念。

## Risks / Trade-offs

- [`'濒死'` 改名是 BREAKING，漏改就静默不触发] → 实现时 grep 全部订阅点（`@基础/濒死.lua`、两处用例、`env-meta.lua`、两份技能文档），`env-meta` 写错编辑期就报。
- [不再有临时标签 / 嵌套受伤串味的问题] → D1 改成当场进濒死，不再递标签；同一玩家嵌套受伤的技能还没出现（技能批次再谈）。
- [扣血、濒死、`'伤害-后'` 的先后现在完全由「同一个 `'伤害-生效'` 回调里扣血」这个位置定下；将来若做「改伤害值 / 防止伤害」类技能，它们得插在扣血**之前**] → 现在没有这类内容（伤害值就在 `Damage.amount` 里，没人改）；真要做时把「扣血」这一步的位置拿出来单独设计。
- [删掉属性监听后，非伤害的掉血（失去体力）不会再自动进濒死] → 写进 Non-Goals 当约定：那种来源将来自己调 `game:enterDying`。
- [奖惩改了手牌但游戏紧接着结束（主公杀忠臣后反贼全灭）] → 顺序天然：奖惩先跑完，胜负判定后跑；用例钉住「先摸牌、再结束」。
- [死者的 `'凶手'` 标签留在对象上] → 阵亡后没人再读（奖惩只读一次），无害；玩家对象随局生灭。
- [draw 拦死者可能掩盖调用方的错误（给死人摸牌本不该发生）] → 它是**明确口径**（奖惩照发），不是兜底：`Draw` 里就一条 `if not player:isAlive() then return end`，用例覆盖「死者不摸、不触发 `'摸牌'`」。

## Migration Plan

无（单进程、探索期、无外部消费者）：改完跑 `server/bin/moe-kill.exe --test` 全绿即可；不改 JSON-RPC，不回改 `openspec/specs/`。

## Open Questions

- `'凶手'` 这个标签名（内容侧约定）—— 将来若要让技能也读它，可以考虑改成更中性的名字（只动 `@基础/濒死.lua` 与奖惩两个文件）。
- 主公杀忠臣里「装备牌」的补做时机：等装备与距离修正那批落地后回头补一行（奖惩文件里会留一句说明）。
