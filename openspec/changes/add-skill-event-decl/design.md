# Design

## Context

现状（`server/core/skill.lua`）：

- `SkillDef:on(钩子名, 回调)` 的钩子集合是**封闭的两个**：`'被动'`（`Skill:applyPassive()` 启用时跑一次，回调收 `(skill, host)`，内容侧在那儿 `host:bindGC(…)` 挂订阅 / 建状态）与 `'使用'`（`Skill:use()` 主动发动）。内核读它的地方只有三处：`applyPassive` / `use` / `AskUseSkill` 的 `hasHandler('使用')`。
- `Skill:applyPassive()` 里**已经有一段**「照定义上的声明挂东西」的代码 —— `viewAsList`（`Card:applyPassive()` 同形）。
- `Skill:tryCast(body, use?)` = `confirm()` + `cast()`（2026-10-09 加的合并写法，动机就是「顺序写不反」）；`Cast` 是归因（`skill:cast` 里起的结算沿 `parent` 链追得到）。
- 技能订阅时机的两种写法现在都在用：多数 `owner:on(...)`（自己那份），【鬼才】是 `game:on('判定-前', …)`（全局那份）⇒ 新能力必须能表达这两者。
- 时机名是开放的（内核不预设）；**内核**时机的按名收窄住 `loader/env-meta.lua`，**内容侧**时机（伤害 / 治疗 / 判定）的收窄住 `package/@基础/meta.lua`。

## Goals / Non-Goals

**Goals:**

- 把「订阅时机」的两层壳（`on('被动')` + `host:bindGC`）从内容侧拿掉。
- 两种观察对象（自己 / 局）各有其名、不可混用。
- 存量行为零变化（迁移是逐字等价改写）。

**Non-Goals:**

- 不替内容侧决定「要不要发动」（条件与 `skill:tryCast(…)` / `card:cast(…)` 仍写在回调里）。
- ~~不动装备侧（`CardDef`，另批）~~ —— **2026-10-09 已纳入同一变更（D7）**。
- 不引入「锁定技自动不问」这类新口径。

## Decisions

### D1. `on` 不动，新方法叫 `event` / `globalEvent`

`on` 现在的语义 = 「**这个定义对象自己的事件**」（`game:on` 是局的事件、`SkillDef:on` 是技能自己的两个入口）。本变更要加的是「**订阅局 / 角色身上的时机**」—— 主语不同。同名会让读代码的人分不清（`on('使用')` 与 `on('卡牌-结算前')` 并排放在一个技能里尤其糊）。

- `SkillDef:on` 保持 `'被动'` / `'使用'`；
- 新方法 `event(name, handler)` 订 `owner`、`globalEvent(name, handler)` 订 `game`。

**`globalEvent` 单独成方法**（而不是 `{ global = true }` 选项）：少一件「记不记得传开关」的事，读起来也不必回头看参数（用户 2026-10-09 定）。

### D2. 只订阅 / 只转发（乙方案）—— **甲方案（自动问 + 套 `cast`）在迁移时被否**

内核在挂载时把声明包一层：

```lua
host:bindGC(owner:on(decl.name, function (...)
    return decl.handler(self, ...)   -- 第一参补技能自己；载荷与返回值都原样转
end))
```

**为什么不是甲**（先按甲实现的，迁移时才发现迁不动）：

- 13 处 `'被动'` 里，除【马术】【咆哮】（持续性修正，不是订阅）外**全都有条件前置**（「一张都拿不到就不问」/「只对【杀】」/「只在摸牌阶段」…），而甲把询问排在回调**之前** ⇒ 要么**无关触发也被问一次**（【铁骑】【克己】【裸衣】），要么多起一次**空 `Cast`**（`auto(true)` 那几个：空发动进归因链）—— 正是 2026-10-09 在 `viewAs` 上刚修掉的毛病（「拒绝 ⇒ 一次 `cast` 都不起」）。
- 要保留「先判条件再问」就得给 `event` 再加一格「条件」（同步、在询问之前跑），而那格与回调**同签名相邻** ⇒ 写反不报错。

⇒ 形状改回「只订阅」：条件与 `skill:tryCast(…)` 仍由回调自己写（与今天逐字一致），`event` 只负责「挂在哪、谁撤」。**收集式时机因此也能用**（返回值原样交给 `fire`）——【奇才】直接用 `event('卡牌-来源-使用选项', …)`。

顺带修掉一个真缺口：原包装只转一个 `payload`，而有的时机载荷是**多个参数**（`'卡牌-来源-指定目标后'` 的 `(useCard, target)`）⇒ 改成 `function (...) return decl.handler(self, ...) end`。

### D3. `event` 与 `'被动'` 共存；挂载顺序 = `'被动'` → `viewAs` → `event` / `globalEvent`

`'被动'` 与 viewAs 的既有位置**不动**（现有技能行为零变化），新声明追加在后面。

### D4. `auto` 不认「锁定技」标签

与今天 `Skill:confirm()` 完全一致 —— `auto` 是**玩家偏好**、「锁定技」只是**标签**、「是否强制发动」由技能自己写。现在没有「锁定技 + 普通时机订阅」的技能；真出现时再定要不要让内核认标签。

### D5. 类型面：先给内核常用几条 + `string` 兜底

时机名开放 ⇒ 精确收窄做不到（`viewAs` 那种靠 `ViewAs.Decl` 的做法不适用）。照 `Game.on` / `Player.on` 的既有配方：

- `event` 列几条**内核**时机：`'卡牌-结算前'` / `'卡牌-来源-使用选项'` / `'阶段-开始'` / `'效果-收尾'` / `'卡牌-来源-指定目标后'` / `'效果-目标-能否生效'`；
- `globalEvent` 列几条：`'游戏-开始'` / `'卡牌-结算前'` / `'效果-收尾'` / `'阶段-开始'` / `'卡牌-能否使用'`；
- 其余走 `fun(skill: Skill, ...: any)` 兜底。

**内容侧时机（伤害 / 治疗 16 条当事人份、`'判定-前'` / `'判定-后'`）的候选补进 `package/@基础/meta.lua` 的 `SkillDef` 块**（迁移那批已补；hover 实测 `damage.cardsInPlace` 收窄成 `Card[]`）。

### D6. 迁移范围：武将全迁，装备另批（→ 已并入同批，见 D7）

武将 11 处订阅全部迁（奸雄 / 集智 / 奇才 / 克己 / 铁骑 / 鬼才 / 反馈 / 刚烈 / 裸衣 / 洛神×2）；**【马术】【咆哮】保留 `'被动'`** —— 它们没有时机可订（`addAttr` / `addLimit` 是持续性修正）。装备侧 20 处（`CardDef:on`）等 `CardDef` 那批（用户 2026-10-09 定）。**同日该批就来了**（用户「提交，然后改卡牌」）—— 实数 7 处订阅 + 3 处持续性修正，见 D7。

### D7. 牌侧形状：与技能同形，唯一的差异在「主人」

`CardDef` 照样加 `event` / `globalEvent`（`event` 订**这张牌的主人** = 它所在区的 `owner`；**牌不在谁名下就跳过** —— 牌堆 / 弃牌堆里的牌照常启用被动、不报错），`Card:applyPassive()` 在跑完 `'被动'`、挂完 viewAs 之后照声明挂。

**回调第一参是这张牌**（照 `'被动'` 收 `(card, zone, host)` 的先例，也与 `viewAs` 的声明同形）⇒ 签名 `fun(card: Card, ...: any): any`。

**与技能的一处真差异**：技能实例自带 `owner`（`skill.owner`），**牌不自带主人** ⇒ 回调要主人的得自己取：

```lua
local zone  = assert(card:getZone())
local owner = assert(zone.owner)
```

订阅只挂在有主人的牌上（`applyPassive` 里那层 `if owner`）⇒ 这两个断言**恒真**，它们是**类型窄化**（`Zone?` / `Player?` ⇒ 非空，用法与 `Card:cast` 内部一致），不是在替谁兜错。**试过并否掉的两种**：① 内核把主人当第二参传 ⇒ 顶掉载荷位（技能那边载荷就是从第二参起的，两边会不同形）；② 给 `Card` 加一个读法 ⇒ 返回值仍是 `Player?`，窄化问题照旧。

**迁移口径**：装备 7 处订阅迁 `event`（青釭剑 / 雌雄双股剑 / 方天画戟 / 贯石斧 / 麒麟弓 / 青龙偃月刀 / 仁王盾）；**3 处保留 `'被动'`**（`武器牌` / `坐骑牌` 的 `addAttr`、【诸葛连弩】的 `addLimit`）—— 与技能那边保留【马术】【咆哮】同一条理由（持续性修正，不是订阅）。**类型面**照 D5 的配方同样补 `CardDef` 两块（内核候选 + `package/@基础/meta.lua` 的内容侧候选），另加 `'效果-来源-被抵消'`（载荷 `AskOffsetCard`，装备用它）。

## Risks / Trade-offs

- **同一个时机两种写法**：`'被动'` 里手写 `owner:on(…)` 与 `event(…)` 都能订阅 —— 前者留给「启用时做点什么」，后者是订阅的正道；文档要写清。
- **类型精度打折**（D5）：没列进候选表的时机，回调载荷是 `any`（内容侧按 §9.6 配方补候选即可）。
