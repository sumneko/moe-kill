# Proposal

## Why

用户已确定实施顺序并收窄了范围：**先把内核（core）做出来并单元测试，规则与 session 都排在后面**；并且明确要求「**目前的实现应该和游戏流程规则完全无关**」。

具体含义（用户拍板）：

- 内核只做**对象与容器**：玩家、桌子、房间、牌堆、可复现随机源。内核**不认识**"起手牌数""身份配置""谁先手""阶段顺序"这类规则。
- 规则的数值与时序**与内核分离**：例如起手牌数属于规则，不属于内核。
- **内核的每一项能力都要导出成可以直接调用的接口**；测试直接调这些接口，将来 session / Room 只是这些接口的**调用者**。
- 测试里的"发牌""开局"这类动作，由**测试自己组合内核接口完成**（例如连续调用 `player:addHandCard(drawPile:draw())`），内核不提供"发牌"这种高层动作。
- 内核命名统一为 **core**（原 `engine` 改名：`script/core/`、`moe.core`）。

现状：`script/engine/` 只有一个空表（`---@class Engine`）。本批把它改名为 `script/core/` 并填入内容；已归档的 `headless-server`（`script/server/`）与本批无关，内核 MUST NOT 依赖它。

## What Changes

- **改名**：`script/engine/` → `script/core/`，门面 `moe.engine` → `moe.core`（类型注解同步）。
- **对象模型**（`script/core/`）：
  - **玩家**：体力与体力上限（受 0 ~ 上限约束）、存活状态、手牌区 / 装备区 / 判定区、一个由调用方赋予的不透明标签。
  - **桌子**：座位与行动顺序的载体（入座、行动顺序遍历跳过已阵亡、相邻座位）、座位距离求值（沿两侧取较小值、最小为 1、修正参与求值）。
  - **房间**：一局的装配根（加入玩家、持有桌面与各牌堆、查询当前局面）；不同房间状态互不影响。
- **牌堆**：基类 + 抽牌堆 / 弃牌堆 / 处理区（放入、取出、洗牌、查看、计数）；对空牌堆取牌等非法操作明确失败。牌实例只有唯一标识与标签，**牌的定义属于配置，不在本批**。
- **随机源**：可实例化、可注入的伪随机源，不使用全局 `math.random` 状态；相同 seed 得到相同序列，多个实例互不干扰。

**明确移出本批**（都属于"游戏流程规则"，留给后续的规则层）：开局装配（身份分配 / 起手牌数 / 发牌 / 先手）、回合阶段推进、牌的效果与结算、技能、决策者接口。

## Capabilities

### New Capabilities

- `core-objects`: 玩家 / 桌子 / 房间的数据与查询行为（体力与上限、牌区、座位、行动顺序、座位距离）
- `core-piles`: 牌堆基类与抽牌堆 / 弃牌堆 / 处理区的行为（放入、取出、洗牌、查看、计数、牌的实例标识）
- `core-random`: 可实例化、可注入的伪随机源（确定性与实例间互不干扰）

### Modified Capabilities

（无。`openspec/specs/` 现有 `headless-server` 与 `async-io`，本批不修改它们。）

## Impact

- **新增**：`script/core/`（内核对象与容器）、`test/core/`（单元测试）。
- **改名**：`script/engine/` → `script/core/`；`script/moe-kill.lua` 的 `moe.engine` → `moe.core`。
- **文档**：`moe-kill-dev` 技能的分层图与目录职责表（`engine` → `core`，规则层另立）；`setup-backend-infra/design.md` 里"`script/engine/` 未来放纯规则引擎"一句已因改名过期，一并修正。
- **不改**：`script/server/`（Session 保留不动）、`script/async-io.lua`、协议层、前端。
- **后续顺序提醒**：规则层（开局装配 / 阶段流程 / 牌的效果 / 技能）与"内核与会话串起来"都在后面的批次；**卡牌开搞前先与用户预研**。
