# Design

## Context

- 现状（动机见 proposal.md）：`Effect:apply()` 是每次结算**唯一的驱动点**，它建一个协程、只 `resume` 一次，并且只认一种让出理由 `'cancelled'`（取消）；询问 `Ask` 当场取答案。
- **每个效果都有自己的协程**，这是取消的实现基础（取消一个效果 = 丢弃它的栈帧、外层继续）。本批不改这条。
- 现成的基础设施（复用，不重写）：`server/tools/await.lua`（`await.call` / `await.sleep` / `await.yield`，照搬 4.0.0）、`server/tools/event-loop.lua`（`start(options, errorHandler)`，options = `waiter` / `deadline` / `waker`）、`server/tools/timer.lua`（`wait` / `update` / `getNextDeadline`）、`moe.eventLoopOptions()`、`server/test.lua`（用例体本来就跑在 `moe.await.call` 起的协程里，事件循环由它启动 ⇒ **最外层已经可让出**）。
- 4.0.0 的参照做法：一个请求 = 一个协程；挂起时循环继续跑别的；**测试给事件循环一个假 sleeper**（`ls.timer.update(1000); thread.sleep(1)`）来推进虚拟时间，于是超时用例不必真等。
- 用户口径（2026-09-19）：「apply 直接改造成异步函数，把调用方挂起」「测试的时候套在协程里跑就行了，通过 event-loop 和假 sleeper 实现同步跑完」「实际运行你先不管」。

## Goals / Non-Goals

**Goals:**

- 一次结算能**真的挂起**：等答复期间把控制权交回最外层，答复或超时到达后从原处继续，结算栈与状态保持。
- 调用点的写法**与同步函数一致**（`local result = ask()`），挂起对内容侧与调用链不可见。
- 挂起期间**拒绝起新结算**（用户定）。
- 恢复两条路都要有：**答复**与**超时**（用户定本批一起做）。
- 测试侧能把「挂起 → 答复 → 继续」「挂起 → 超时 → 继续」整条链跑完，且超时用例**不必真等**（虚拟时间）。

**Non-Goals:**

- **生产侧的最外层**（会话怎么把询问报给前端、怎么收答复、超时从哪来）：本批不做（用户：「实际运行你先不管」）。
- 不引入 `ls.task` / `ls.progress` 式任务与进度体系（上一批已否 `ls.task`，见 `add-jink-response` 的 D6）。
- 不做「玩家操作窗口」式的完整语义（阶段、可撤回…）；本批只有"等一次答复"。
- 不改内容包写法（【杀】照旧调 `game:ask`）；不改取消的既有语义（挂起态被取消仍是"直接关闭"）。

## Decisions

### D1 挂起 = 把调用方一并挂起（用户定）

`Effect:apply()` 改造成**可挂起的异步函数**：结算需要等答复时，它把**调用它的执行体**一起挂起（沿调用链一路让出到最外层），答复 / 超时到达后从挂起处继续，`apply()` 到那时才返回。`game:play` / `game:damage` / `game:ask` / `UseCard:settle` / `CardEffect:settle` 随之都是可挂起入口（标 `---@async`）。

- **否掉**：`apply()` 返回 `'done' | 'suspended'` 状态码 —— 那会把"等"这件事推给每一层调用方（`game:play` → 会话 → 协议 → 前端），任何一层忘了传就静默错序。

### D2 让出协议：驱动点独占 resume，理由分派

保留「这次结算的驱动点独占 `coroutine.resume`」这条不变量。让出带**理由**：

| 理由 | 谁发出 | 谁处理 |
| --- | --- | --- |
| `'cancelled'`（载荷 = 是哪个效果） | 该效果自己（`remove()` 走 `__del` 的让出） | 它**自己的** `apply()`：关掉执行体、这次生效结束 |
| `'ask'`（载荷 = 这次 `Ask`） | 询问的结算体 | 原样上抛到最外层，由驱动器服务（见 D3/D4） |

取消**不需要转发**：`'cancelled'` 只可能由该效果自己让出，所以每个 `apply()` 只处理"载荷就是我自己"的那一个，别的原样上抛。别的未知理由 MUST 当场报错（免得有人偷 yield 却没人接）。

### D3 让出**原样上抛**，恢复打在最外层

`apply()` 的驱动循环做成**透明转发**：子执行体让出什么（理由 + 载荷），就由 `apply()` 原样交给它的调用方（`coroutine.yield(理由, 载荷)`），并把调用方恢复时给的值原样送进子执行体。

- 于是内层的「等答复」会**一路冒到最外层**；
- **恢复必须打在最外层的那个执行体上**，值再逐层下传回等待点 —— 这就是"调用点看起来像同步函数"的全部秘密。

**为什么不用 `moe.await.yield` / `await.sleep` 来做等待**：它们把"恢复"绑在**当前**协程上（`coroutine.running()`）。在嵌套的效果协程里调用时，恢复会打在内层协程上 —— 内层跑完就结束了，而外层仍停在转发那一行，整条链再也回不来（**搁浅**）。所以等待只能在**最外层**做，也就是 D4 的驱动器。**这条要写进代码风格约定**（「`await.*` 只能在最外层用；嵌套层要等就让它出上抛」）。

### D4 驱动器：本批只做测试侧

「驱动器」= 最外层的执行者，职责是**建流程协程、驱动它、服务它的让出**（伪代码）：

```lua
local co = coroutine.create(流程)
local args = {}
while true do
    local result = table.pack(coroutine.resume(co, table.unpack(args, 1, args.n)))
    if not result[1] then error(result[2]) end
    if coroutine.status(co) == 'dead' then break end
    args = serve(result[2], result[3])   -- 按让出理由服务，返回下次 resume 要送的值
end
```

- `serve('ask', ask)`：把询问交给回答者（D5），并给它一个「继续」入口；没人答复时按超时收尾（D6）。
- **本批只实现测试侧的驱动器**：它跑在 `moe.await.call` 起的协程里、由事件循环驱动（假 `waiter` 推进虚拟时间）。
- **生产侧的驱动器（会话）本批不做**（用户：「实际运行你先不管」）。

### D5 回答者的形状：`fun(ask, resume)`

驱动器把询问交给回答者，同时给出「继续」入口：

| 回答者怎么做 | 结果 |
| --- | --- |
| 返回前 `resume(答案)` | **当场答复**（不真挂起，调用链照常往下走） |
| 存起来稍后 `resume(答案)` | **挂起**，驱动器侧等（定时器 / 事件循环任务），到点时把值送回去 |
| `resume(nil)`（调了但没给答案） | 「**拿不出答案**」⇒ 明确失败（保留 `core-response` 既有口径） |
| 一直不调 | 还没答复 ⇒ 由**超时**收尾（D6） |

- 这样一来**不需要**"声明稍后答复"这种概念：`resume` 什么时候被调用就是全部信息，也不需要 `Ask:answer` 之外的第二套入口。
- 备选（**否掉**）：`Ask:answer(值)`（回答者持有询问对象再答复）—— 等价，但要多一个对象方法，且"拿不出答案"与"还没答复"的区分不如"调没调 `resume`"清楚。
- 现有脚本化回答者要跟着改成"在返回前调 `resume`"：只动 `server/test/rule/support.lua` 的辅助与几处内联回答者，**用例本身不动**。

### D6 超时由驱动器计时

- 时限挂在询问上、由**发起询问的一方**选定（`game:ask(to, question, options?)` 带 `timeout`；未给用约定值）。
- 驱动器在把询问交给回答者之后**同时**起一个定时器（`moe.timer.wait`）：到点仍未答复 ⇒ 送「没有答案」把链继续下去；询问以**没有答案**结束（与「被取消的询问」同一口径），发起方照常继续、不报错。
- 答复先到就撤销定时器；定时器先到就忽略后来的答复（迟到事件静默无害）。

### D7 挂起期间禁止起新结算

局上记住**当前挂起的询问**（最多一个），`game:play` / `game:damage` / `game:ask` 在挂起期间 MUST 明确失败。

- 理由：挂起时这次效果仍在栈顶，新结算会嵌在它下面；而且"游戏正挂着一件事"将来是会话要读的状态，明确失败比静默错序好。
- **否掉**：排队等答复后再跑（要引入队列与顺序语义）。

### D8 挂起态取消要连带收掉它下面挂着的子结算

取消一个**挂起中**的效果时，它下面可能还挂着子结算（子执行体停在自己的让出点，而它的驱动点正停在父执行体的转发那一行）。只关父执行体会让子执行体变成孤儿。

- 做法：沿**结算栈**自顶向下（从栈顶到该效果）依次关闭；栈本来就告诉了我们"谁嵌在谁里面"。
- 这条要在用例里钉住：取消一个"正在等答复、且自己底下还挂着一次结算"的效果，结算栈回到这次结算之前的样子、不留孤儿。

### D9 内容侧与既有用例的兼容

- 【杀】不动：`game:ask` 仍然"返回答案"，只是它**可能在返回前让出**。
- 回答者当场答复（现有测试全是这种）时**不真挂起** ⇒ 既有 292 个用例的行为不变（只有回答者辅助的写法改一处）。

### D10 事件循环接入点

- 内核**不主动驱动**事件循环：挂起只是把让出交上去，由最外层服务。
- 测试模式给事件循环注入**假 `waiter`**（照 4.0.0）：推进虚拟时间（`moe.timer.update(...)`）而不是真睡 ⇒ 超时用例秒过，且能跑到「挂起 → 定时器 → 继续」整条链。
- **否掉**：内核里直接登记到 `eventLoop`（内核不该知道事件循环，测试也不好换）。

## Risks / Trade-offs

- [让出穿过不可让出的 C 边界]（`include`、`table.sort` 比较器、C 上的 metamethod）→ 真踩到会以 `attempt to yield across a C-call boundary` 立刻暴露，不会静默；写进代码风格约定。
- [某一层忘了转发 ⇒ 搁浅] → 转发只在 `apply()` 一处实现（同一条循环），不在各子类；用例覆盖"挂起时控制权确实交到调用方"。
- [在嵌套深度用 `await.*` 会搁浅] → 写进代码风格约定（D3）；`await.*` 只给最外层用。
- [挂起态取消留下孤儿子结算] → D8 的"沿结算栈往下关" + 专门用例。
- [迟到事件]（结算已结束/已取消之后答复或超时回调才到）→ 驱动器的"继续"入口与超时回调都要先判断这次询问还在不在挂起；`await.*` 的恢复侧守卫是同一思路的现成例子。
- [没人答复 ⇒ 永久挂住] → 超时是询问的必备字段（有约定值）+ 用例覆盖。
- [漏标 `---@async`] → `.luarc.json` 已把 `await` 组设为 `None`（全项目关掉 `await-in-sync`），**不会有诊断提醒**；靠文档 + 用例覆盖。
- [有人绕过驱动点直接 resume 执行体] → 错误传播与取消会一起失效；写进代码风格约定（这条已存在，本批把"答复/超时也经驱动点送回去"写明）。

## Migration Plan

分三步落地（见 tasks.md）：① 内核（`Effect` 的转发循环 + `Ask` 挂起/答复/超时 + 局上"挂起中" + 挂起态取消的子链处理）；② 测试侧驱动器与假 `waiter`；③ 用例与文档。旧行为在"当场答复"路径下不变，不需要数据迁移；改动集中在三个内核文件 + 测试设施，回滚面小。

## Open Questions

- **OQ1（属于会话接线批次）**：生产侧驱动器长什么样 —— 会话怎么把询问报给前端、怎么把答复送回来、超时（含"该用规则数值吗"）从哪来。本批只保证内核与测试侧成立。
- **OQ2（可延后）**：超时的约定值取多少。
- **OQ3（可延后）**：除 `'ask'` 之外的让出理由（如"等待出牌窗口"）将来要不要，本批不预留。
