# Proposal

## Why

现在「询问」只能**当场取答案**（`game:ask` 同步返回），等于把「要一个决策」压成一次函数调用：将来决策要经协议往返（前端 / AI / 超时），必须有地方能**先挂起、等答复再继续**。

内核的底子已经具备：`Effect` 已是一个**独立的执行体**（这次结算唯一的驱动点）、已有让出协议（目前只认 `'cancelled'` 一种理由）、取消与退栈也都走这条通路 —— 缺的正是「挂起 → 恢复」这一段与它跟事件循环的接线。此时补，改动面最小：只有询问这一条路径需要挂起。

## What Changes

- **`Effect:apply()` 改造成可挂起的异步函数**（用户 2026-09-19 定）：结算需要等外部答复时，`apply()` **把调用方一并挂起**（沿调用链一路让出到最外层），答复到达后从原处继续。**BREAKING**（对内）：调用链不能再假定「`apply()` 返回即结算完成」，`game:play` / `game:damage` / `game:ask` / `UseCard:settle` / `CardEffect:settle` 随之都成为可挂起入口。
- **让出协议新增理由 `'ask'`**（payload = 这次 `Ask`），并**原样上抛到最外层**：由最外层的**驱动器**把询问连同「答复入口」一起交给回答者 —— 在返回前用它就是当场答复（不真挂起），留着稍后用就是挂起；没人答复则由**超时**收尾。答案再一路下传回等待点。
- **超时**（用户定，本批一起做）：挂起的询问到点仍未答复 ⇒ 以「没有答案」结束（与「被取消的询问」同一口径），发起方照常继续。
- **挂起期间禁止起新结算**（用户定）：`apply()` 未完成时，任何结算入口（`game:play` / `game:damage` / `game:ask`…）MUST **明确失败** —— 而不是把新结算嵌到挂起中的效果下面。
- **接入事件循环**：让出原样上抛到**最外层**，由那里的**驱动器**用 `moe.eventLoop` + `moe.timer` 服务（把询问交给回答者、计时超时、把结果送回去）；**本批只做测试侧的驱动器**，生产侧（会话怎么报给前端、怎么收答复、超时从哪来）**不做**（用户 2026-09-19：实际运行先不管）。
- **测试可注入假等待器**（照 LuaLS 4.0.0 的做法）：测试模式把事件循环的 `waiter` 换成**虚拟时间**推进（`moe.timer.update(...)`），于是超时用例不必真等，也能在无头环境跑到「挂起 → 定时器唤醒 → 继续」整条链。
- 本批**不做**协议 / 会话接线：不把「游戏挂起了」报给前端，也不从协议收答复（那是会话接线批次的事）。本批把「挂起」变成内核里真实存在、可被外部答复或被定时器唤醒的状态，并用无头测试证明它成立。

## Capabilities

### New Capabilities

（无 —— 挂起是既有能力的新增行为，不引入新概念、新对象。）

### Modified Capabilities

- `core-effect`: 执行体从「跑完才算完」变成「可让出、可挂起、可被恢复」；新增让出理由与恢复入口；挂起期间拒绝新结算。
- `core-play`: 使用入口成为可挂起入口（结算挂起时把控制权交回调用方，而不是假装已经结完）。
- `core-response`: 询问不再「当场必须拿到答案」，改成**可挂起等答复**；答复通道与超时的口径。

## Impact

- 内核：`server/core/effect.lua`（驱动循环 / 让出理由 / 恢复入口）、`server/core/ask.lua`（挂起与答复）、`server/core/game.lua`（结算入口的挂起、「挂起期间拒绝新结算」、超时登记）、`server/core/use-card.lua` 与 `server/core/damage.lua`（`settle` 可挂起）。
- 内容包：`package/标准/卡牌/杀.lua` 询问的**写法不变**，但调用链变成可挂起；不需要改包。
- 测试设施：`server/test.lua`（测试模式注入假 `waiter`）、`server/test/ltest.lua`（挂起相关的辅助，如需）、新增用例；复用 `moe.await` / `moe.timer` / `moe.eventLoop`，不改照搬来的工具。
- 文档：`moe-kill-dev`（挂起模型、测试假 `waiter` 写法）、`sanguosha-rules`（§7 响应：挂起与超时口径）。
