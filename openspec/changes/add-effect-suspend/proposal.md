# Proposal

## Why

现在「结算」一旦开始就必须跑完：`Effect:apply()` 只 `resume` 一次，并且只认一种让出理由（取消）。而「要一个外部决策」（玩家 / 前端 / AI 的响应）本质上是**等一会儿**，将来必然要能挂起等它。

内核的底子已经具备（每个效果是一个独立执行体、已有让出协议与取消、结算栈与错误口径都稳），缺的正是「挂起 → 恢复」这一段与它跟事件循环的接线。本批只做**抽象的等待能力**：让结算能挂起等一个外部输入、并且能被测通。`Ask`（询问）具体怎么用这套能力（答案从哪来、时限怎么定、回答者形状）**是下一步的事**，本批不动它。

## What Changes

- **`Effect:apply()` 改造成可挂起**（用户 2026-09-20 定）：结算要等外部输入时，让出会**把调用方一并挂起**（沿调用链一路让出到最外层），输入到达后从原处继续，`apply()` 到那时才返回。**BREAKING**（对内）：调用链不能再假定「`apply()` 返回即结算完成」，`game:play` / `game:damage` / `UseCard:settle` / `CardEffect:settle` 随之都是可挂起入口。
- **效果变成「可等待的任务」**（用户 2026-09-20 定）：效果有**完成信号** —— `settle()` 跑完 = 完成（可以有结果）、`remove()` / 超时 = 完成但没有结果、出错 = 失败；结果与失败分别记在 `.result` / `.err` 上。
  - `:apply()` 负责**驱动**这次结算（需要等外部输入时把调用链一起让出），`:wait()` 负责**等它结完**并返回**效果自己**（已经结完就立刻返回）；
  - **用牌 / 造成伤害这类入口自动「驱动 + 等」并返回效果实例** —— 调用方必须等（用户：「调用 damage 的那方必须要等」），这也是结算栈的要求；
  - 于是「等一个外部输入」不再是一种新原语，而是**造一个效果再等它**（例如将来的 `ask:wait()`），询问就是一类"完成时机由答复驱动的效果"；
  - 取消 / 超时 ⇒ 以「没有结果」完成、**不抛**；内核错误 ⇒ 照旧抛，同时记进 `.err`。
- **让出的转发与恢复**：每个效果的执行体把子执行体让出的（理由 + 载荷）**原样上抛**（`coroutine.yield(理由, 载荷)`），恢复打在最外层、值再逐层下传回等待点。
- **挂起期间禁止起新结算**（用户定）：`apply()` 尚未返回时，任何结算入口（用牌 / 造成伤害…）MUST 明确失败，而不是把新结算嵌到挂起中的效果下面。
- **挂起态的取消要连带收掉它下面的子结算**（沿结算栈自顶向下关闭），不留孤儿执行体。
- **驱动者（本批只做测试侧）**：最外层执行者负责服务让出 —— 把请求交给测试提供的服务函数，**"等多久"由它决定**；与事件循环 + **假等待器（虚拟时间）** 配合，使「挂起 → 稍后收到结果 → 继续」整条链在无头测试里同步跑完（照 LuaLS 4.0.0 的测试做法）。
- 本批**不做**：`Ask` 的挂起语义（用户还在想）、协议 / 会话接线、生产侧驱动者、超时（它是 `Ask` 那一层的事，跟着一起定）。

## Capabilities

### New Capabilities

（无 —— 是既有能力的新增行为，不引入新概念、新对象。）

### Modified Capabilities

- `core-effect`: 执行体从「跑完才算完」变成「可让出、可挂起、可被恢复」；效果成为**可等待的任务**（完成信号 + `result` / `err`，`apply` 驱动、`wait` 等它结完）；让出的转发/恢复；挂起期间拒绝新结算；挂起态取消要连带收掉子结算。
- `core-play`: 使用入口成为可挂起入口（结算挂起时把控制权交回调用方，而不是假装已经结完）。

## Impact

- 内核：`server/core/effect.lua`（转发循环、`Effect:wait`、取消让出带自身载荷、挂起态取消的子链处理）、`server/core/game.lua`（挂起登记 + 挂起期间拒绝新结算）、`server/core/use-card.lua` 与 `server/core/damage.lua`（`settle` 标 `---@async`）。
- **不动** `server/core/ask.lua`：`Ask` 照旧当场取答案（它现在就能工作；将来它的挂起语义长在这套机制之上，另开变更）。
- 测试设施：`server/test.lua`（测试模式注入假等待器）、测试侧驱动者、新增用例；不加新依赖（复用 `moe.await` / `moe.timer` / `moe.eventLoop`）。
- 文档：`moe-kill-dev` 的 `references/architecture.md`（挂起模型）与 `references/code-style.md`（`await.*` 只能在最外层用；让出必须原样转发）。
