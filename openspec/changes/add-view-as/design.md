# Design

## 形状：窗口制（乙），不是选项制（甲）

「产出一张虚拟牌」有两种落法，2026-09-30 讨论后定**乙**：

| | 甲：选项制 | 乙：窗口制（本变更） |
| --- | --- | --- |
| 交互 | 一次询问，候选 `[实体闪, 闪（八卦阵）]` | 先试声明（要不要发动、判定），不成再问实体牌 |
| 判黑之后 | 该选项作废 ⇒ 要回到选择（询问要支持「重开」） | 自然退回「照常要实体牌」 |
| ask 的形状 | 要改（单轮 → 多轮） | 不动 |
| 与官方流程 | 一步选完 | 一致（先声明发动、再判定） |

理由：① 不动 ask 的单轮语义；② 官方口径「判黑后还能打实体闪」自动成立；③ 贴官方交互顺序；④ 现有【八卦阵】已经在这条路上，改动收敛。

**推论：声明对象不持虚拟牌实例。** 不进候选就不需要一个稳定实例；真正交出去的那张由**内核照声明的牌名造**（`createVirtualCard`）。将来若表现层要展示「可视为的牌」，再加。

## 依次尝试，不是「让玩家挑一个」

多个声明都能替代时，**按声明顺序逐个试**（用户 2026-09-30 定）：

- 试 = 调它的 `'发动'`；返回真 ⇒ 内核照声明的牌名造一张虚拟牌、当答复落定、不再往下试；返回空 / 假（不发动 / 裁决失败）⇒ 试下一个；
- 试用顺序 = **声明创建的顺序**（= 装备 / 技能生效顺序）；「武将技能 ＞ 装备技能」这类优先级**以后再显式提供**（届时给声明加一个字段 + 排序规则，不靠时机名先后）；
- 一圈试完 ⇒ 照常 `fire('卡牌-询问')` 要实体牌。

## 匹配规则：只看牌名

声明的牌名对上这次要的牌名才试 —— 依据是询问条件里的 `names`（`AskCard.NormalizedCondition`）：

- 条件**没给 `names`**（= 要什么都行）⇒ 也试；
- 声明牌**不参与**其余条件（`zone` / `card` / `min` / `max`），也**不走 `checkAnswer`** —— 它本来就不在任何牌区里，它的合法性由 `'发动'` 钩子自己负责（引擎给的是"这次要不要视为成立"这一条）。
- 落点只在**打出族**（`AskPlayCard:beforeAsk`，`AskOffsetCard` 继承）。`askCard`（如【五谷丰登】挑亮出的牌）**不试声明**。将来【丈八蛇矛】/【武神】要参与「出牌阶段主动使用」时，再考虑 `AskUseCard` 那一侧（那属于**候选侧**的支持，不是声明族的事）。

## 命名

- `player:addViewAs(name)` —— 对齐 `addBuff`（返回实例、对象上 `:remove()` 撤销、可叠多个）；`declare*` 在项目里留给**加载期声明内容定义**（`game:declareCard`），运行期挂状态不叫它。
- 类名 `ViewAs`（与 FreeKill 的 `view_as` 对得上）。

## 不做（本批）

- **素材**（丈八蛇矛的两张手牌 / 武圣的一张红桃）—— 在 `'发动'` 钩子里自己 `askCard`，需要时再加「可选性」钩子（同步、不进尝试列表），或把 `'发动'` 的返回值扩成「素材」；
- **`'获取目标'`**（产出的【杀】指定谁）—— 丈八批再谈；
- **候选侧**（让声明出现在 `askUseCard` 的 `options` 里）；
- **优先级字段**（先用创建顺序）。
