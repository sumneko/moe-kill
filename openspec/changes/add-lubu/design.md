# 设计：【无双】

## D1 形状：订阅挂在「这次使用」上

```
指定目标后（来源 / 目标两个入口，按牌名与角色方向分流）
  ⇒ useCard:bindGC(game:on('卡牌-答复后', 处理))     -- 寿命 = 这次使用
      处理：ask.responseOptions?.responseTo == useCard 且 ask.to == 那个角色
            ⇒ game:askPlayCard(他, ask.reason, { name = 牌名 })
                 拿到 ⇒ 什么都不做（这次响应成立）
                 拿不到 ⇒ ask:cancel('无双')
```

三个选择各自的理由：

1. **宿主是 `useCard` 而不是技能**（用户提的）：`Effect : GCHost` ⇒ `useCard:bindGC(...)` 现成可用（青釭剑就是这么写的）。挂在技能身上（= `'被动'` 回调给的 `host`，`Skill:removePassive()` 一 `Delete` 全撤）时，中途失去技能就中断；挂在这次使用上则与技能存活无关 ⇒ 满足官方 `Ch1/S2:139`（吕布被【断肠】掉光技能、轮到 A 时【无双1】照旧执行）。
2. **时机是 `'卡牌-答复后'`**（不是 `'效果-来源-被响应'`）：`ask:cancel` 会把这次询问的结算当场停住（`Task:cancel` 在自己就是执行体时让出、不再唤醒）⇒ 在答复后吊销，「被响应」那两段时机**根本不发** ⇒ 青龙偃月刀 / 贯石斧不会被误触发（否则它们会按「此【杀】已被抵消」发动，而官方口径下还差一张【闪】）。
3. **追的那张不带 `responseTo`**：它不是一次**新的响应**（两张【闪】合起来抵消一次【杀】）⇒ 订阅的过滤条件天然排除它、不递归；牌照常进临时区、照常记打出账、八卦阵 / 龙胆 / 丈八蛇矛照样能顶上。

## D2 挂几份、要不要状态

**一份订阅管一个角色**，每个目标各挂一份（`'卡牌-来源-指定目标后'` 是逐目标发的）⇒ 多目标【杀】各判各的、**不需要任何「已经多要过」的标记**；【决斗】来回多轮时，对方每轮的响应都是一次新的 `askPlayCard`（带 `responseTo`）⇒ 那份订阅每轮各触发一次，也不需要「本轮已经加过」的状态。

## D3 官方口径（底本）

- `武将牌/标准包.md:121`：【无双】全文（两条 + 「连**续**」这个关键词）。
- `Ch2/S5:99`（张角例）：两张【闪】是**两次独立的「使用」**（第一张的结算跑完、第二张响应时能**再次**发动【雷击】）⇒ 实现必须是「**追一次询问**」，不能是「一次询问要两张」。同时说明「第一张出了、第二张拿不出」时第一张照常消耗（我们的落法：那张照常进弃牌堆、伤害照常结算）。
- `Ch1/S2:46`（神吕布例）：负担在**对方**身上（【无双2】没发动时 B 只需一张）⇒ 吕布自己始终只出一张。
- `Ch1/S2:139`（蔡文姬例）：要求写下来之后**不因中途失去技能消失** ⇒ D1 的宿主选择。
- 对照 `Ch2/S5`「没有『依次』这个关键词的操作均指 X 张……一次性同时操作」（贯石斧弃两张）——【无双】写「连续」⇒ 逐个来。

## D5 被否 / 推迟的方案

- **`useCard:setResponseCount(谁, 牌名, 张数)` + 牌自己读**（「记录式」）：零寿命管理，但要给内核加规则字段，且拦不住「以后再来个『要额外弃一张才能闪』」（用户 2026-10-09 否决）。
- **把「一次响应」做成内核概念（`count` 参数 / `AskOffsetCard` 留着）**：同一个理由，已随 `merge-offset-into-response` 一并收掉。
- **`useCard:on(时机, 处理)` 之类的糖**：推迟到形状稳定之后再谈（用户定「先按现有接口实现」）。
- **隐式作用域**（执行时机回调期间自动把注册的东西绑到这次使用）：省一行，但要给每个「返回 disposer」的 API 加钩子、并引入隐式状态 ⇒ 不做。

## D6 反向验证（实测）

- 去掉 `ask:cancel` ⇒ **4 条红**（四条「拿不出第二张 ⇒ 挨 1 点」）。
- 去掉「只针对对方」的筛选（`ask.to ~= other`）⇒ **1 条红** —— 而且第一次跑时是 **0 红**：那两条【决斗】用例里对方只出一张就卡住了、**吕布根本没轮到** ⇒ 假绿 ⇒ 为此补了「两边都有牌时吕布自己只要一张」那条用例 ✓
- 去掉 `useCard:bindGC(...)`（裸 `game:on`）⇒ **0 条红**（因为过滤条件带这次使用的对象，行为不变，只是处理器常驻 = 泄漏）⇒ 记为**已知覆盖缺口**：要钉住它得加「一局打完局上处理器数不涨」这类断言。

## D7 落地时顺带修的一处内核：空答复不算一次响应

一次**响应**的答复若是**空表**（玩家主动「不出」），`AskCard` 把「空答复 = 取消、不算失败」当合法结局 ⇒ 那次响应会被当成**成立**（【杀】被白抵消、不掉血）。修法：`AskPlayCard:beforeResolve` 在**定结果之前**作废它（`responseTo` 有值时 `value.card` 为空就返回 `nil`）⇒ `settleAnswer` 返回假 ⇒ `settle` 记 `reject('没有打出')`、**「被响应」时机也不发**。

- 为什么不用 `settle` 里那句 `reject`：那时任务已经 `resolve` 过，`Task:reject` 对已 resolve 的任务是空操作（只有 `cancel` 能改），实测也踩到了。
- 只管**响应**（带 `responseTo`）：普通「要一张打出的牌」的「空答复 = 取消」口径不动。
- 用例：「无双：目标答复空表（主动不出）⇒ 不追第二张」（顺带钉住【杀】照常造成伤害）。
- ⚠️ 这是**先于本批就存在**的缺口（`AskOffsetCard` 时代一样），不是本批引入的；发现它的是【无双】的用例。
- **后续**：这处 `beforeResolve` 特殊处理已在下一批（`ask-cancel-as-failure`）收编进 `AskCard` 基类（「空答复 = 取消」），本文件保留当时的形状记录。

## D8 归因：追的那张算【无双】的一次发动

用户 2026-10-09 提「每次 `askPlayCard` 要 `cast` 一下」⇒ 用 **`skill:cast(function () … end)`** 包住**追的那张询问与随后的 `ask:cancel`**：否则它的 `parent` 是【杀】那次要【闪】的询问 —— 只说明时序、不说明「这是谁做的」；包了以后 `parent` 链上就查得到【无双】。

- **订阅本身不包**：`useCard:bindGC(game:on(…))` 是**持续性**（活到这次使用结束），按既有口径（`architecture.md` 的 `Cast` 行「两类不套」）不套；套的是**时机到了之后做的这件事**。
- **`ask:cancel` 留在 cast 体内**（与包之前行为一致）：`Task:cancel` 从别的协程调不返回（不 yield），收口照跑 —— 四条「拿不出第二张 ⇒ 挨 1 点」的用例照旧绿。
- **不是根、不进记牌器**：cast 在时机回调里起 ⇒ 有 `parent` ⇒ 符合既有口径。
- **用例**：在「只出一张【闪】⇒ 追问一张，拿不出就挨 1 点」上加两条断言（追的那张的 `parent.source` = 【无双】、`0 == #lt.errors`）。
- **反向验证**：去掉 `skill:cast` ⇒ **恰好 1 红**（那条归因断言）。
