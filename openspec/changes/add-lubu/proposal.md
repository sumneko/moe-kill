# 变更：【吕布】【无双】

## 需求

落地标准包吕布：「**群 · 男 · 体力上限 4**」，唯一技能【无双】：

> **无双**：锁定技，当你使用【杀】指定目标后，其使用【闪】抵消此【杀】的方式改为需**连续使用两张【闪】**；当你使用【决斗】指定目标后，或当你成为【决斗】的目标后，你令其打出【杀】响应此【决斗】的方式改为需**连续打出两张【杀】**。

## 为什么现在能做

「响应」概念刚在 `merge-offset-into-response` 里收成一个（`askPlayCard` + 带 `responseTo` + 两段「被响应」时机 + `ask:cancel` 驳回），于是「一次响应要两张牌」能用**通用机制**表达，不必给内核加一条「响应张数」字段。

## 做什么

1. **内容**：`package/标准/武将/吕布.lua`（新）—— `Skill '无双'`（`tags '锁定技'`）订两个时机，把一份**挂在这次使用上**的订阅写下来：
   - `'卡牌-来源-指定目标后'`（我用牌）：【杀】⇒ 给该目标、要两张【闪】；【决斗】⇒ 给该目标（= 对方）、要两张【杀】；
   - `'卡牌-目标-指定目标后'`（我成为目标）：【决斗】⇒ 给使用者（= 对方）、要两张【杀】。
   - 订阅本体订 `'卡牌-答复后'`：认出「这次响应冲那次使用去的、且是那个人的」⇒ `game:askPlayCard(他, 缘由, { name = 那个牌名 })` 追一张；**追不到 ⇒ `ask:cancel('无双')`**（吊销这次响应）。
2. **不加内核 API**：只用手上有的东西（`useCard:bindGC` / `game:on` / `askPlayCard` / `ask:cancel` / `responseOptions.responseTo`）。
3. **用例**：`server/test/rule/hero-skill.lua` 加一组（见 tasks）。
4. **文档**：`sanguosha-rules` §9.32 加【无双】（含官方裁定 `Ch1/S2:139`）＋「挂谁 = 活多久」的口径；`architecture.md` 补那段对照表；`progress.md` 基线 / 24 将。
5. **顺带修一处内核**（写用例时发现的**既有缺口**）：一次**响应**的空答复（主动不出）以前算「响应成立」⇒【杀】会被白抵消；现在 `AskPlayCard:beforeResolve` 在定结果之前作废它（见 design D7）。

## 不做什么

- **不给内核加「响应张数」之类的规则字段**（曾考虑 `useCard:setResponseCount`）：那等于每条新规则都开一个口子（「多弃一张才能闪」…还得再来一个），而且内核要替内容解释语义 —— 用户 2026-10-09 否决。
- **不做「糖」**（`useCard:on(时机, 处理)` 之类）：先按现有接口把功能跑通，形状稳定了再说（用户 2026-10-09 定）。
- **不实现【断肠】那类「失去技能」的技能**（蔡文姬不在标准包）：只按官方 `Ch1/S2:139` 的口径保证「已写下的要求不因中途失去技能而中断」，并用测试钉住。

## 验收

`server/bin/moe-kill.exe --test` 全绿；问题面板 information 及以上 0；吕布端到端可跑：【杀】的目标要连出两张【闪】（只出一张 ⇒ 挨 1 点且那张照常进弃牌堆；出齐 ⇒ 只发一次「被响应」时机）、【决斗】里「对方」每轮要连出两张【杀】（吕布自己仍只要一张）、中途失去技能要求照旧。
