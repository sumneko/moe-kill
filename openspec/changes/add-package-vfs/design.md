# Design

## Context

- 现状（动机见 `proposal.md` 的 Why）：清单项与依赖项都在**单一根目录**下解析 —— `server/rule/init.lua` 的 `loadItem` 依次尝试「文件 → `名字 + '.lua'` → 目录」，`loadDirectory` 递归列举 `.lua`。默认根 = `<仓库根>/game`（该目录**尚未创建**，所以改名没有历史包袱）。
- 用户 2026-09-19 定的方向：分包机制与扩展路径**不是同一个功能** —— 先把多个扩展路径合并成一个**虚拟文件系统**，再在它之上做依赖与分包（`add-package-routing`）。
- 已核对（无需改动）：`make/bootstrap.lua`、`.luarc.json`、`.gitignore` 里都**没有** `game/` 引用（规则集不进 `package.path`）。
- 约束：`server/rule/` 是用 `require` 加载的**不可重载**模块，状态挂在门面表 `M` 上；只用 `bee.filesystem`，不引入新依赖。

## Goals / Non-Goals

**Goals:**

- 来源列表 → 一棵逻辑目录树（后者覆盖前者、文件级、目录内容并集），不缓存。
- 加载器的清单项与依赖项一律按**逻辑路径**解析，读文件与列目录都走这一层。
- 依赖支持相对路径。
- `game/` → `package/` 改名落地（含默认来源与文案）。

**Non-Goals:**

- 包 / 名字路由（`标准.杀`、同包重名报错、裸名路由）→ 后续变更 `add-package-routing`。
- 除结尾 `/*` 之外的任何通配语法（不做 glob）。
- 来源列表的持久化与配置来源（谁提供来源、要不要落协议方法）——本变更只提供接口。
- 缓存与文件监视：明确不做缓存。

## Decisions

### D1 来源语法：`X` 与 `X/*` 是两种**角色**，不是通配匹配

- `X` = 该目录本身是一个来源（逻辑第一层 = 它的目录名）；`X/*` = X 是**容器**，其下每个子目录各是一个来源，容器名不进逻辑路径。
- 不用通配库实现：`*` 在这里表达的是「这一层是容器」这个**结构语义**，而不是匹配任意名字。用 glob 会让 `X/*.lua`、`X/*/y` 之类写法意外生效，语义反而模糊 —— 所以只允许结尾 `/*`，其余写法直接报错。
- 两种写法归一为「**逻辑路径第一层恒为来源目录名**」。这样「同一个逻辑包」天然对齐（`./package/标准/…` 与 `D:/某合集/标准/…` 是同一个逻辑包），覆盖规则才成立。
- 基准 = **仓库根**，所以默认来源是 `{ './package/*' }`（项目自己的包容器）。

### D2 合并规则：文件级、后者胜、目录并集

- 逻辑树按「逻辑路径 → 物理文件」**扁平化**：同一个键被后面的来源覆盖；实现上不必真的建树 —— 来源展开成若干 `(逻辑包目录名, 物理目录)`，遍历时按顺序写入一张表，表天然「后写覆盖先写」。
- 目录列举是**合并**而非整目录替换：`标准/卡牌/` 下两个来源的文件取并集，同名文件按覆盖规则取后者。
- 判定顺序（文件 → 补 `.lua` 的文件 → 目录）对**整棵树**一致，不按来源分别判定；避免「A 有 `标准/杀.lua`、B 有 `标准/杀/` 目录」这类歧义按来源漂移。
- **不缓存**：每次 `load` 当场重建（用户明确要求「不缓存，load 的时候当场合并读取」）。代价是每次加载多若干次 stat，换来运行期换包立刻生效。

### D3 分层：本变更只回答「路径 → 文件」

- 本变更**不知道**「包名 / 条目名」这回事，只回答「这个逻辑路径在磁盘上是哪个文件、这个逻辑目录下有哪些文件」。
- 下一个变更在这之上回答「这个名字归属哪个包、裸名路由到谁、同包重名怎么办」。
- 拆开的好处：内容语义与路径机制各自独立演进；也符合用户「两者不是同一个功能」的判断。

### D4 相对路径依赖

- 以 `.` / `..` 开头的依赖项以**声明它的文件所在目录**为基准拼接；其余（如 `基础规则`、`标准/卡牌/杀`）仍按逻辑根。
- 不改成「依赖项一律相对当前文件」：那会推翻既有写法（`depends { '基础规则' }`），而 `.`/`..` 前缀能让意图一眼可见。
- 归一化在**逻辑路径**层面做（`a/../b` → `b`），这样同一文件的不同写法会归一到同一个键，去重集合（「同一轮只执行一次」）才有效。

### D5 实现落点与接口

- 新文件 `server/rule/vfs.lua`：`Vfs.create(sources) -> vfs`；`vfs:exists(logical)` / `vfs:read(logical)` / `vfs:listFiles(logical)`（递归、只取 `.lua`、按路径排序）/ `vfs:resolve(logical) -> 物理路径?`。来源展开与非法写法校验都在 `create` 里做（失败即报错）。
- `server/rule/init.lua`：`loadItem` 的判定改在 vfs 上做，`loadDirectory` 改成 `vfs:listFiles`；新增 `M.setRoots(sources)`、`M.setRoot(root)` 保留为单来源简写（测试与旧的调用方都在用）。`load(清单, 根?)` 的返回值（实际执行的文件列表、按执行完成顺序）不变。

### D6 改名范围

- 改：默认来源、主规格 `rule-loading` / `chinese-identifier` 的 Purpose 文案（`## Purpose` 不能由 delta 改，直接改主规格文件）、技能文档里的目录表与示例。
- **不改**协议域前缀（`game/submitDecision`、测试里的 `game/start`）：那是「游戏操作」的域，与目录无关。
- `package/` 与 Lua 标准库同名：目录名不进 `package.path`，规则集执行环境也不注入 `package`，无冲突；文档留一句提醒。

## Risks / Trade-offs

- [两套排序方向相反：「来源合并」是后者胜，「包路由」是清单先者胜] → 在 `architecture.md` 第 9 节做一张**对照表**并列写死，避免以后自己看反。
- [来源路径写错（盘符、尾斜杠、大小写）导致静默取到错误内容] → 来源路径不存在直接报错；逻辑路径不做大小写折叠，交给文件系统语义。
- [不缓存 ⇒ 每次加载全量重扫，包多时开销上升] → 当前规模（十几个包、几百文件）可忽略；真出现性能问题再加缓存与失效策略，本变更明确不做。
- [相对路径归一化写错会让同一文件被当成两个文件（重复执行）] → 用例覆盖「同一文件两种写法只执行一次」。

## Migration Plan

- 纯增量 + 一处改名：`game/` 尚未创建，改名只动代码里的默认值与文档；`server/rule/vfs.lua` 是新增文件。
- 回滚 = 删掉 `server/rule/vfs.lua`，把 `server/rule/init.lua` 的默认根与 `loadItem` / `loadDirectory` 还原到单根版本。

## Open Questions

- 来源列表的来源（谁提供、要不要落配置文件 / 协议方法）—— 等真有第二个来源时再定，本变更只提供 `setRoots` 接口。
