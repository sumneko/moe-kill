# Design

## Context

- 现状：内核有 `Card` / `Zone` / `OrderedZone` / `Attributes` / `Random` / `Event` / `Desk` / `Player`；规则门面持有规则表、规则数值与四个"内核能力工厂"（`createAttributeSystem` / `createCard` / `createZone` / `createOrderedZone`）。
- 直接后果：牌与牌区虽然是**运行期**的东西，却挂在**加载期**的规则门面上；抽牌堆作为规则数值（`rule:setValue('牌堆', deck)`）存放 —— 一局游戏没有"场地"这个概念，公共资源没有归属。
- 用户口径（2026-09-19）：给出场地的形状 —— `ctx.room:createZone('抽牌堆', true)`、`ctx.room:createCard(name)`、`牌区:shuffle()`（洗牌不再传随机源）。

## Goals / Non-Goals

**Goals:**

- 一局的公共资源（桌子、随机源、公共牌区、牌工厂）有一个明确的归属：**场地**。
- 规则包写起来是"让场地建个抽牌堆、往里放牌、洗一下"，不再手工拼零件。
- 洗牌的随机源来自场地，规则包不必自己传递它。

**Non-Goals:**

- **不做**场地接管开局装配（建桌子 / 建玩家 / 属性实例仍由调用方组合内核接口完成；将来的 Room 内封装会话是另一批事）。
- **不做**会话 / 挂起 / 事件流接入场地。
- **不做**牌区移除接口（现在没有消费者；按需再加）。

## Decisions

### D1 场地是内核对象（`Core.Room`），只管容器与工厂

- 持有：一张 `Core.Desk` + 一个 `Core.Random`；登记的牌区（名字 → 牌区）；建牌工厂。
- 不认识任何具体牌区名（`'抽牌堆'` 是规则包给的名字），也不含游戏流程 —— 与内核"不预设区域名 / 不放流程"的既有口径一致。
- 落地为 `server/core/room.lua`，挂 `moe.core.room`（`Core.Room`），依赖方向仍是"外层调内层"。

### D2 公共牌区挂场地，玩家牌区仍挂玩家

- 分工：**属于某个玩家的位置**（手牌区 / 装备区 / 判定区）用 `player:addZone(名字)`；**公共区域**（抽牌堆 / 弃牌堆 / 处理区）用 `room:createZone(名字, 有序?)`。
- 这样"这是谁的牌区"从**归属**上就分清了，不需要内核用参数去描述。

### D3 牌 / 牌区搬到场地，属性系统留在 `rule`

- 分界线是**加载期 vs 运行期**：
  - 属性系统是**内容定义**（有哪些属性、上下限多少），必须在**加载期**就建好、给装配方拿去给玩家造实例 ⇒ 留在 `rule:createAttributeSystem()`（那时场地还不存在）。
  - 牌与牌区是**运行期资源**，必然属于某一局 ⇒ 从 `rule` 上撤掉，改由场地创建。
- 于是 `rule` 上只剩「加载期能力」（规则表 / 规则数值 / 属性系统工厂），`room` 上是「一局的资源」。

### D4 有序牌区可以绑定随机源 ⇒ `shuffle()` 可省略参数

- 用户的形状是 `抽牌堆:shuffle()`，说明"牌区自己知道该用哪个随机源" ⇒ 场地创建有序牌区时把**自己的随机源绑给它**（`core.orderedZone.create(random?)`）。
- 独立创建的有序牌区（测试、别的用途）仍可 `:shuffle(random)`；两者都没有时明确报错。
- 顺手去掉 `OrderedZone:shuffle` 里 `Type(random) ~= 'Core.Random'` 的运行时类型判定 —— 与"运行时不做类型判定"的既有约定一致，而且它对 `Core.Random` 的子类会误判。

### D5 游戏时机的上下文带上场地

- `ctx = { desk, random, room }`：`room` 是本批新增；`desk` / `random` **暂时保留**，让已有的包（体力设置、身份分配）不用改一遍 —— 等真有理由收窄（比如 `room` 覆盖了它们的能力）再另开变更。
- `room` 的字段声明写进 `server/rule/env-meta.lua` 的 `Rule.EventCtx.游戏开始`，包作者在编辑器里就能拿到 `ctx.room` 的类型。

### D6 抽牌堆只在场地里

- 牌堆不再进规则数值（`rule:setValue('牌堆', ...)` 取消）——它是一局的资源，不是配置。
- 取回方式是 `room:getZone('抽牌堆')`（按名字），装配方与将来的流程代码都走这条路。

## Risks / Trade-offs

- [场地容易变成"什么都往里塞"的垃圾桶] → 只在「桌子 / 随机源 / 公共牌区 / 建牌」四件事内生长；要加新职责先问"它是公共资源吗、还是某个玩家的、还是流程的"。
- [牌区名字写死在规则包里（`'抽牌堆'`）] → 名字是**内容**，内核不预设；将来要有多个抽牌堆（例：军争的额外堆）也只是多建一个，不需要改内核。
- [D5 保留 `ctx.desk` / `ctx.random` 有点冗余] → 有意为之的过渡：先让场地落地，收窄上下文另开变更（那时一并改包与测试）。
- [绑定随机源让牌区有了"隐式依赖"] → 绑定发生在**场地创建它**时，来源明确（场地的随机源）；没绑定的仍然可以显式传参。

## Migration Plan

- 数据：`package/@基础/牌堆.lua` 改为场地版；牌堆的读取点从 `rule:getValue('牌堆')` 改成 `room:getZone('抽牌堆')`。
- 门面：去掉 `createCard` / `createZone` / `createOrderedZone`（保留 `createAttributeSystem`）。
- 回滚：把三个工厂加回门面、包改回 `rule:*` 写法即可；内核侧 `Core.Room` 可以直接不使用。

## Open Questions

- 场地要不要承担"开局装配"（建桌子、按人数建玩家、发起始手牌）—— 等**发牌**这个功能点落地时一起看，那时才知道装配需要多少参数。
