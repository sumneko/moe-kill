# Tasks

## 1. 内核：效果协程化与取消

- [x] 1.1 `server/core/effect.lua`：`apply()` 改为协程驱动（协程体内「记父 → 压栈 → fire「即将生效」→ 执行结算」，退栈仍交给 `<close>`；外层循环 `coroutine.resume` 并按让出原因分派，结束时收尾）。验证：现有 `server/test/core/effect.lua`、`damage.lua`、`play.lua` 全绿
- [x] 1.2 `Effect:remove()`：按驱动协程状态三态分派（运行态 `yield('cancelled')`、挂起态 `coroutine.close`、已结束报错）。验证：新增用例 —— 取消后不产生效果、取消只作用于这一个效果、取消不影响外层、对已结束的效果取消报错、取消后结算栈恢复原状
- [x] 1.3 `apply()` 里统一 `fire('即将生效', 效果实例)`（子类不得各自触发）。验证：无订阅者时照常生效；订阅者拿到的上下文就是这个效果实例、且此刻它在栈顶
- [x] 1.4 驱动点错误处理：`resume` 失败时 `error(debug.traceback(co, err), 0)` 原样上抛。验证：既有"断言抛错"用例照旧通过，且新增用例证明错误信息里带出错位置（而不是只有一句话）
- [x] 1.5 结算栈恢复的四种情形复核（正常结束 / 取消 / 抛错 / 校验失败）。验证：`core-effect` 的退栈场景全部有用例覆盖，且栈长度回到结算前

## 2. 内核：询问与打出
