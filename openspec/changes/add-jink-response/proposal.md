# Proposal

## Why

当前「把一张牌用出去」是一次性同步走完的：校验 → 取牌 → 跑「使用」回调 → 触发收尾时机。于是只有一张牌的规则能这么写（在回调里直接造成伤害），**做不到**「每个目标先问一句『打出闪吗』」—— 内核既没有"中途向某人要一个决策"的能力，也没有"问完之后可以否决这次生效"的能力。

三国杀的绝大多数机制都建立在这两件事上（闪的响应、无懈可击、濒死求桃、判定改判、技能询问……），所以先把内核的「挂起 + 取消」补上，后续内容才有地基。而"能挂起"同时引入了一种新的失败模式（挂住的结算可能永远没人答复），必须连同取消、超时、错误收口一起解决。

## What Changes

- **内核：效果改为协程驱动**。`Effect:apply()` 变成「在一个协程里跑自己的结算，并作为该效果**唯一的驱动点**」：压栈、触发「即将生效」、执行结算、退栈都在协程体内，结算栈的恢复仍靠 `<close>`（取消时同样成立）。**BREAKING**（内容包看得见的结算模型变化）。
- **内核：新增「即将生效」时机与取消**。任何效果在**执行自己的结算之前**触发「即将生效」（上下文 = 这个效果）；效果提供 `:remove()`，**作用域是这一个效果**：取消后不执行它的结算，结算栈不留帧。取消分两种情形都应成立 —— 取消者在该效果的调用链里（运行态）与从外部关闭一个挂起的结算（挂起态）。
- **内核：用牌结算改为「按行动顺序逐目标生效」**。`UseCard` 不再"跑一遍回调 + 一次收尾"，而是对每个目标各结算一次「生效」（每个目标的生效是独立效果，父效果 = 这次用牌），全部目标处理完才触发收尾时机。**BREAKING**（替换现有「使用」回调的语义）。目标集合在结算开始前确定；"作废尚未结算的目标"这类特例（如国战方天画戟）本批不做，等真遇到再定。
- **内核：新增「询问」与「打出」**。`Ask`（询问）把"要一个决策"表达成一个**可挂起的效果**：答案存在它自己身上，父效果记下"谁在问"，可被取消、可超时。「打出」是与「使用」并列的动作：把牌从持有者手上取出，但**不产生它自己的效果**、不进用牌结算。
- **内核：错误收口**。内容包代码（时机订阅者、牌的内容回调）出错一律隔离 + 统一错误报告（沿用 `game-events` 既有口径，不打断其余回调）；内核契约违反照旧向外传播，协程化后由驱动点原样重抛（含完整协程堆栈）。
- **内容包（标准）**：【杀】改成"每个目标生效前询问该目标打出一张【闪】，打出则该目标这次不生效"；新增【闪】。
- **测试可见性（工具）**：测试模式下错误一律"记账"，用例结束时账非空即判该用例失败；同时给断言框架一个**显式声明"预期有错误"**的入口，供现有故意报错的用例（重载失败、没有牌表）使用。
- **本批不做**：无懈可击（嵌套取消）、濒死与死亡的插入结算、判定、八卦阵/龙胆这类"同一响应窗口里的多个候选技能"、前端与会话接线（本批询问的答案由测试脚本注入，同步返回）。

## Capabilities

### New Capabilities

- `core-response`: 「询问」与「打出」这条内核机制 —— 把要决策表达成一个可挂起的效果（答案回传、父效果可溯）、取消与超时的兜底、以及"打出"作为与"使用"并列的动作。
- `standard-cards`: 标准包牌面的响应规则 —— 【杀】逐目标询问【闪】、打出则该目标这次生效被取消，以及【闪】本身的声明。

### Modified Capabilities

- `core-effect`: 效果改为协程驱动（唯一的驱动点、取消与结算栈恢复的关系），并新增「即将生效」时机与 `:remove()`。
- `core-play`: 结算从"执行声明的结算回调 + 收尾时机"改为"按行动顺序对每个目标各结算一次生效，全部完成后收尾"。

## Impact

- **内核**：`server/core/effect.lua`（协程驱动、`remove()`、「即将生效」）、`server/core/use-card.lua`（逐目标生效）、`server/core/game.lua`（驱动与查询入口）、`server/core/loader/env-meta.lua`（新时机与询问/打出的类型面）；新增 `server/core/ask.lua`。
- **规则包**：`package/标准/卡牌/杀.lua`（改为逐目标询问）、新增 `package/标准/卡牌/闪.lua`。
- **测试**：`server/test/core/effect.lua`、`play.lua`、`damage.lua` 与规则用例调整；新增取消（运行态 / 挂起态）、挂起往返、超时、错误收口的用例。
- **工具**：`server/test/ltest.lua`（错误记账 + 预期错误入口）、`server/moe-kill.lua`（测试模式下把 error / fatal 记进账 —— 复用初始化日志时的 print 钩子）。承载测试框架规格的能力 `headless-test` 目前还在进行中的 `setup-backend-infra` 里尚未归档，所以这一部分本轮只改工具、不产出规格增量；等它归档后再补规格。
- **文档**：`moe-kill-dev` 技能（挂起模型与错误口径）、`sanguosha-rules` §7（结算时序：逐目标「即将生效」）。
- **风险**：`Effect` 的驱动方式与结算流程都变了，既有 273 个用例里所有断言"结算中抛错"的用例都要复核；内容包的「使用」回调语义被替换，属破坏性变更（当前只有【杀】一处使用者）。
