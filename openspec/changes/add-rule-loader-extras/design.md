# Design

## Context

- 现状（`server/rule/init.lua`）：`rule.depends { ... }` 在执行到那一行时同步加载；去重与防环靠 `ctx.loaded` / `ctx.loading`。加载是**顺序**的，所以"互斥/重名"这类冲突只能跑到才发现（前面的文件已经执行、已经写进规则表）。
- 用户口径（2026-09-19）：互斥写成 `rule.depends { '!国战' }`；预解析**只用于执行前的校验 + 包元信息**，**不做**依赖优先排序；试跑可以用 `sumneko/utility/without-check-nil`。
- 已查清：`utility/without-check-nil.lua` 的实现是 `debug.setmetatable(nil, mt)`（给 **`nil` 本身**装元表，nil 上的算术 / 拼接 / 索引 / 调用 / 比较都不崩），对外 `m.enable()` / `m.disable()`；`disable()` 只在元表仍是它的那份时才恢复。⇒ 试跑时不必造"万能对象"，文件里 `rule.getCard('杀'):on(...)` 这类链式调用落到 `nil` 也不会炸。
- 约束：`server/rule/` 是 `require` 加载的不可重载模块；规则集执行环境只注入 `rule` + 标准库白名单；来源合并**不缓存**（每次 `load` 重新枚举）。

## Goals / Non-Goals

**Goals:**

- 互斥声明可用，且**任何清单顺序**下都能拦住。
- 执行前就能报出互斥冲突与同包重复条目（不留"跑了一半才炸"的状态）。
- 包元信息（依赖 / 互斥 / 条目 / 来源）可只读查询，供排查与将来的前端展示。

**Non-Goals:**

- **不做**依赖优先排序（依赖仍在执行到那一行时同步加载）。
- **不做**预解析结果缓存（`load` 每次重扫，符合"运行期换包立刻生效"）。
- 元信息**不含**时机注册、规则数值等运行时状态（只含加载期声明）。
- 不做"试跑沙箱"（不隔离 `io` / `os` —— 规则集本来就拿不到它们；试跑用的是与真实执行**同一套**注入面）。

## Decisions

### D1 互斥项 = 依赖项的兄弟写法

- `!` 前缀只是**项**的写法差异，解析（相对路径、`.lua` 补全、目录展开）与依赖项完全共用一套代码。
- 判定"已加载"：在已枚举 / 已加载的逻辑路径集合里，找有没有 `项 == p` 或 `项 .. '/'` 是 `p` 的前缀。
- 报错信息给出两个逻辑路径：**声明者**（哪个文件写了 `!X`）与**被排斥的项**。

### D2 校验时机：执行前一次 + 结束前兜一次

- **执行前**：预解析结果已知全部声明，直接比对"本轮会加载的集合" ⇒ 冲突在第一个文件执行之前就报出来（满足"不留半成品状态"）。
- **结束前兜底**：试跑失败的文件（见 D4）可能藏着声明 ⇒ 执行完后再比对一次 `ctx.loaded`。
- 之所以两处都做：前者给"早"，后者给"全"；单独任一个都有洞。

### D3 试跑：stub 环境 + `without-check-nil` 包起来的 `pcall`

- 环境：`probeEnv = { rule = stub }` + 标准库白名单（与真实执行同一套白名单）；`stub` 上只有 `depends` 是真函数（记录依赖 / 互斥项，并顺带记录 `rule.card` 的裸名清单 —— 见 D5），其余字段落到 `nil`。
- 试跑窗口：`withoutCheckNil.enable()` → `pcall(chunk)` → `withoutCheckNil.disable()`，用 `<close>` 保证即使中途抛错也一定会 `disable()`（它是进程全局的改动，绝不能漏关）。
- 试跑失败 ⇒ 记警告（`log.warn`）并继续；该文件的元信息标记为"试跑失败"（元信息里可查，便于排查）。

### D4 迭代展开：预解析与依赖展开互为因果

- 枚举清单项 ⇒ 得到一批文件 ⇒ 试跑 ⇒ 可能发现新的依赖项 ⇒ 再枚举 ⇒ 再试跑，直到不动点（用"已试跑过的逻辑路径"集合防环）。
- 上限保护：同一个逻辑路径只试跑一次；依赖成环由现有去重集合兜住（不新增机制）。

### D5 条目清单也是"提取"，不是"执行"

- 试跑的 stub 记录 `rule.card(名字)` 的调用（名字 + 顺序）⇒ 于是**同包重复条目**能在执行前发现（D2 的前置条件）。
- stub 不创建任何真实 `Rule.Card`（不写 `M.cards`），所以同包重名不会在试跑阶段被误报为"真实重复"（真实报错仍由执行期负责，两处错误信息格式保持一致）。

### D6 元信息形状（只读）

```
meta[包名] = {
    依赖 = { '基础/回合流程', ... },     -- 顺序即声明顺序
    互斥 = { '国战', ... },
    条目 = { '杀', '闪', ... },          -- 声明顺序
    文件 = { { 逻辑路径 = '标准/卡牌/杀.lua', 来源 = 'D:/.../标准/卡牌/杀.lua', 试跑 = 'ok'|'失败' }, ... },
}
```

- 查询接口只返回**快照**（拷贝一份），调用方改不动内部状态。
- 元信息随每次 `load` 重建（与规则表同生命周期）。

## Risks / Trade-offs

- [`debug.setmetatable(nil, mt)` 是**进程全局**的改动] → 用 `<close>` 包住必须 `disable()`；并且只在试跑那一刻开启（其余时间保持关闭）。用例覆盖"试跑失败后 `nil` 的元表已恢复"。
- [试跑会**执行**规则集代码（哪怕在 stub 下）⇒ 文件里的重活会跑两遍] → 约定规则集文件顶部只做声明；真出现性能问题再考虑"只解析源码不执行"的替代路线（届时另开变更）。
- [预解析结果与真实执行可能不一致（同一文件两次行为不同）] → 元信息是**预告**；真实语义仍以执行为准 —— 冲突以"执行前 + 结束前"两次校验共同保证，不依赖单次预告。
- [互斥判定用前缀匹配，`国战` 与 `国战外传` 会误判] → 前缀匹配必须带上分隔符（`项 .. '/'`），并对"项本身就是文件"的情况判等；用例钉住。
- [元信息暴露包内细节] → 只读快照 + 不含运行时状态；将来要暴露给前端再定协议形状。

## Migration Plan

- 纯新增：新增 `server/rule/preparse.lua`、照搬一个 `tools/without-check-nil.lua`、门面新增校验与查询。回滚 = 删掉这些并在 `load` 里去掉预解析步骤。
- 兼容性：既有 `depends` 语义（顺序、去重、防环）不变；不写 `!` 声明的规则集行为完全不变。

## Open Questions

- 预解析要不要在**多来源**下比较"同名来源的差异"（例如后来源覆盖了前来源，元信息里哪一份算）—— 目前只记录**生效来源**，够用；等真有多来源内容时再看。
