# Design

## 1）形状

- 四个**普通** `Zone`，名字 = 分类名：`武器` / `防具` / `进攻马` / `防御马` —— 一件装备进哪个子区由它的**分类**决定（与现在的槽位匹配同一份数据，不另写一份「槽位名」）。
- **创建归内容侧**（2026-09-29 用户拍板）：`@基础/装备.lua` 在 `'游戏-开始'` 里对每个玩家 `addZone(名字)`（返回撤销函数，与「可叠加操作返回撤销函数」的约定一致）。内核不认识这四个名字。
- 内核的基础牌区清单回到四个：局上 `抽牌` / `弃牌`，玩家 `手牌` / `判定`；`env-meta.lua` 顶部注释与 `architecture.md` 第 12 节同步。

## 2）「一个子区只能有一张」落在内容帮助 `equipCard(玩家, 牌)`

理由：同种装备互斥是**装备区的放置规则**（官方「将牌置入装备区」要求对应子区空着），不是牌区的通用能力 —— `SlotZone:accept` 当初把它做进收牌里，才造出那个特殊形状。

```lua
-- 分类 → 子区名；把这张装备放进它该去的子区
-- 同子区已有牌 ⇒ 先把旧的送弃牌堆，再放新的
```

- 顺序：先弃旧、再放新 —— 旧牌的 `'离开区域'` 先发、新牌的 `'进入区域'` 后发（与现在「旧牌排在最前」的次序一致）。
- 分类不认识 / 找不到对应子区 ⇒ 不装（牌随结算收尾进弃牌堆；沿用现在「找不到槽位就不装」的口径，不报错）。
- 「子区可能不存在」是编程错误（内容自己建的）⇒ 帮助函数里的 `assert` 口径：触发 = 这局打不下去。

## 3）装备模板的启停判定（内容做，2026-09-29 用户拍板）

```lua
: on('进入区域', function (card, zone)
    if isEquipZoneOf(card, zone) then card:enablePassive() end
end)
: on('离开区域', function (card, zone)
    if isEquipZoneOf(card, zone) then card:disablePassive() end
end)
```

`isEquipZoneOf(牌, 区)`：区有主，且 `区.owner:getZone(分类名)` 就是它 —— 用帮助函数（分类 → 名字）+ 区对象同一性判，**不加内核字段**（不给 `Zone` 添 `name`）。「进错子区不启用被动」这条保证保留（用例保留）。

## 4）删掉的口径（要一起改的断言）

- `Zone:accept` 的第三参数与它的失败原因（`'这个牌区不是槽位区'` / `'槽位区必须指名收进哪个槽位'` / `'一个槽位只能收一张牌'` / `'这个牌区没有「X」这个槽位'`）全部消失；`core.zone` / `core.move` / `core.game` / `core.card-def` 的对应用例删除或改写。
- `SlotZone:accept` 的「换下来的牌进弃牌堆」「弃牌堆被禁用 ⇒ 换不进去」一起消失（前者由 `equipCard` 承担；禁用的那半已由 `rework-zone-disable` 去掉）。
- 槽位名的另一处使用者 `slotNameOf`（`Zone` 里按 `kind == 'slotZone'` 判）随类一起删。
- `zone.kind` 少了 `'slotZone'` 一种取值；`moe.slotZone` 门面删除。
