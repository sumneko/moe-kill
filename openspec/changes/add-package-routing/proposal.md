# Proposal

## Why

规则集按包组织之后（`package/标准`、`package/军争`、`package/一将成名`），必须回答一个 A 阶段刻意不回答的问题：**多个包定义同一个名字时，用这个名字的人拿到哪一条**。没有明确的名字路由，包与包之间会互相覆盖（用户自定义扩展尤其容易撞名），而且撞名时既无法察觉也无法指定。

## What Changes

- 引入**包**的概念：包 = 来源逻辑路径的**第一层目录**（目录名即包名）；规则集文件 MUST 位于包目录下，**根下散落文件报错**；包名与条目名 MUST NOT 含 `.`。
- **定义归属**：包内文件用定义入口声明条目时，完整名（`包名.名字`）由**加载器拼接**，文件里只写裸名。
- **同包唯一**：同一个包里重复声明同名条目 ⇒ **报错**（并指出两处来源）；**跨包同名合法并存**。给已存在条目**追加回调**改用查询入口（`rule.getCard`），不再靠再次声明。
- **名字路由**：裸名 SHALL 带作用域 —— **包内**（加载过程中的规则集代码）的裸名**优先取本包**，本包没有才 fallback 到默认路由；默认路由按包的**加载顺序**（清单顺序）取**第一个**定义该名字的包；限定名 `军争.杀` 精确取到指定包，不受优先级影响。两者解析结果是**同一个对象**。
- 定义对象带上 **来源信息**：裸名、包名、完整名、声明它的文件（逻辑路径），供报错与排查。

## Capabilities

### New Capabilities

- `package-routing`: 包的定义与边界、定义归属与同包唯一、名字路由（裸名 / 限定名）、条目携带来源信息。

### Modified Capabilities

- `rule-loading`: 「规则定义入口」不再允许"同名重复取得即同一条"，改为「只在加载过程中可用、名字不含 `.`、同包重复声明报错」；查询入口负责跨文件追加回调。

## Impact

- `server/rule/init.lua`：规则表由「名字 → 定义」改为「包 → 名字 → 定义」+ 包顺序表；`rule.card` / `rule.getCard` 的语义与校验调整。
- `Rule.Card` 元数据字段增加（裸名 / 包名 / 完整名 / 声明文件）。
- 既有测试 `server/test/rule/init.lua` 需要适配（定义与查询按包进行；同包重复声明从合法变为报错）。
- 技能文档：`moe-kill-dev/references/architecture.md` 第 9 节补「包与名字路由」；`sanguosha-rules` 的规则集侧写法补包与限定名。
- **前置**：本变更依赖 `add-package-vfs`（虚拟文件系统与逻辑路径）先落地。
