# Design

## Context

- 底本：「摸牌阶段，你可以**改为**获得**至多两名**其他角色的**各一张手牌**。」
- 摸牌阶段业务（`package/@基础/阶段/摸牌阶段.lua`）：`'阶段-生效'` 里 `phase.player:draw(phase.player:getAttr('摸牌数'))`；`摸牌数` 是玩家属性（`min = 0`），技能在 **`'阶段-开始'`** 改它、`phase:bindGC` 挂到阶段上（【裸衣】的既有用法）。时机顺序：`'阶段-开始'`（全局 → 当事人）→ `'阶段-生效'`（全局 → 当事人）。
- `AskPlayer` 现状：`condition.players`（候选）+ 单名答复；`AskCard` 已有 `min` / `max` 与 `moe.askCard.checkTargets`（个数 / 归属 / 重复）。

## Goals / Non-Goals

**Goals:**

- 张辽整将落地，**不新增机制**（只把 `AskPlayer` 的个数区间补齐 —— 那是与 `AskCard` 对齐的既有形状）。
- 把两条写法记下来：「**改为**」（属性归零）与「**盲取别人的手牌**」（局随机源）。

**Non-Goals:**

- 不引入「跳过 / 替换阶段业务」的新 API（见 D2）。
- 不改摸牌阶段、不动协议层。

## Decisions

### D1. 「改为」= 把本阶段摸牌数减 1000（用户定）

```lua
phase:bindGC(skill.owner:addAttr('摸牌数', -1000))
```

- 属性下界是 0 ⇒ 减一个大数就是**事实归零**；这与项目里「`1000` = 事实上不限」（【诸葛连弩】/【咆哮】的 `addLimit('杀', '出牌', 1000)`）是同一个惯例，用户 2026-10-09 点名用 `-1000`。
- 修正挂在**本阶段**上（`phase:bindGC`）⇒ 阶段一离开自动撤、不需要「恢复摸牌数」。
- **为什么不在「阶段-生效」里拦**：摸牌业务订的是**全局**那份 `'阶段-生效'`，技能若订当事人份就排在它**之后**；而「`'阶段-开始'` 改参数、`'阶段-生效'` 跑业务」正是上次为【裸衣】分出来的口子 ⇒ 用它。

### D2. 不引入「阶段业务可跳过」的新 API

更"准"的做法是给 `Phase` 一个「本阶段业务不跑」的表达。但：① 现在只有这一个消费者；② 它要追加定义「多个技能各自想跳过时怎么合并」「跳过之后阶段还算不算进行」等口径；③ 属性那条路已在【裸衣】上验证过。⇒ 记成待办（真出现第二个消费者再评估）。

### D3. `AskPlayer` 的 `min` / `max`（用户定）

- 条件加 `min?` / `max?`（**`min` 省略 = 1、`max` 省略 = `min`** —— 不写就是 1/1（与从前逐字一致 ⇒ 既有调用点零改动）、`{ min = 0 }` 则是 0/0）。
- **候选字段改名并扩成四态**（用户同日定）：`players` → **`player`**，类型 **`Player|Player[]|true|fun(player: Player): boolean`** —— 一名 / 一批 / **`true` = 不做限制**（`options = nil`，与「不给条件」同一分支）/ **谓词**（在**存活角色**（`desk.alivePlayers`）里筛，筛出来的名单挂在 `ask.options` 上）。**读写分家**：条件的字段是 `player`、**答复的读法不变**（`.players` / `.player`）。谓词在 `collectOptions()` 里现算（内核没有 `table.filter` ⇒ 手写循环）。
- **答复 `Player|Player[]`**（照 `AskCard.Answer.targets` 的既有形状：单值也收下、归一成列表）。
- 校验**复用 `moe.askCard.checkTargets`**（个数 / 在候选名单里 / 不重复）⇒ 文案随之与 `AskCardWithTarget` / `AskUseSkill` 统一：**`答复不在可选角色里` → `答复的目标不在可选项里`**（既有用例的那一条期望已同步改）。
- 读法：`.players`（恒列表，没答 = 空表）+ `.player`（= `players[1]`，既有调用点照旧）。**没答复 = 空答复、不算失败**（与 `AskCard` 的「允许取消」同一口径）；**`min = 0` 时空表合法**。
- ⚠️ **类型面坑**：`__getter` 只给运行时实现，**类型面要靠类声明上的 `---@field`**（我一度把 `---@field player? Player` 删成 `result?` ⇒ test / 内容侧一片 `undefined-field`）；改回来后再 **`lua.startServer` 重启 Lua 服务器**诊断才刷新（否则面板里留着旧缓存）。

### D4. 张辽的询问与候选

- 候选 = `desk.alivePlayers` 里「不是自己」且「**手牌非空**」的（空手牌的目标拿不到东西、自己不能拿）。
- **候选为空 ⇒ 不问也不发动**（照「不满足条件就不问」的既有口径）——否则会白弃一次摸牌。
- 一次选 0~2 名：`{ players = victims, min = 0, max = 2 }`。
- **不问「发不发动」—— 选 0 名就是不发动**（用户 2026-10-09 定，本轮改的）：询问直接放在时机里，**拿到人再 `skill:cast(…)`** ⇒ 不发动（空表 / 没表态）**照常摸牌**，而且**连一次空 `cast` 都不起**（照「拒绝 ⇒ 不起 `cast`」的既有口径；【青龙偃月刀】是同一形状的首例）。
  - 第一版曾用 `tryCast`（先问一句 `askChoice`、同意才清零摸牌数），那会得到「选 0 名 = 白弃摸牌」的语义 —— 用户否掉。
  - ⇒ **「能用一次询问表达表态时就不另问 `confirm`」** 这条口径写进了 `sanguosha-rules` §9.15。
- **盲取**：`hand:list()[game.random:nextInt(1, hand:count())]` —— 手牌区是**无序区**（没有"顶"）、牌面不能暴露给玩家 ⇒ 只能随机取；用**局随机源** ⇒ 整局可复现（项目一贯要求）。
- 发动要问吗：**不问**（用户 2026-10-09 定）—— 一次询问已经表达表态（选空 / 不表态 = 不发动、照常摸牌），照【青龙偃月刀】的形状。

## Risks / Trade-offs

- **「减 1000」依赖「摸牌数」这个属性**：它由内容侧定义（`@基础/阶段/摸牌阶段.lua`），技能与阶段同属内容侧 ⇒ 可接受；若将来属性改名，这里跟着改。
- **`AskPlayer` 答复形状变化**（一次可多名）是**对外契约**面的变化（协议层要认列表）⇒ 已在 `architecture.md` §12 / `sanguosha-rules` §9.25 写清；`openspec/specs/` 冻结不追。
- **测试脚本要按 `ask.kind` 分辨**：`tryCast` 先问一句 `askChoice`（`reason` 与技能同名）⇒ 只按 `reason` 匹配的脚本会把「选人的名单」回给确认问题（踩过，两条用例红）。
