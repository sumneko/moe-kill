# Design

## Context

（动机见 `proposal.md` 的 Why。）

现状：

- `Effect.tempZone` 是**普通字段**，`getTempZone()` 懒建在**自己**身上 ⇒ 每个效果各自一块。
- 于是「用这次结算的暂存区」只能人工点名：`@基础/使用.lua` 写 `useCard:getTempZone()`、`@基础/判定.lua` 写 `judge:getTempZone()`、`@基础/收尾.lua` 读 `effect.tempZone` 清牌；`AskPlayCard:onAnswered()` 写 `self.parent:getTempZone()`。
- 父子链是**层层**的：`AskPlayCard → CardEffect(某个目标) → UseCard`；`CardEffect → UseCard`；`Damage` 等过程效果也可能夹在中间。今天 `AskPlayCard` 因此把打出的【闪】放进**它父亲**（通常是 `CardEffect`）新建的区里。
- `'效果-收尾'` 每个效果结完都发一次（`bindFinish`）；内容侧靠「没建过区 ⇒ `effect.tempZone` 为空」天然只清一次。
- 已记的口径：`sanguosha-rules` §10 —— 打出的牌 / 判定牌都在**一次结算**结束时进弃牌堆（【五谷丰登】「使用结算结束后」、【杀】「按行动顺序对每个目标依次结算」、判定自成一次结算）；`progress.md` §3「效果分主要 / 次要」里已定的一条 —— 判据不该是「每个效果」，而是「开结算的那个效果」。

## Goals / Non-Goals

**Goals:**

- 子效果要这次结算的暂存区时不必手写 `parent`：`self:getTempZone()` 就是对的。
- 「谁负责清」由内核定，且**不加标记字段** —— 归属靠重写方法表达。
- 现存四处调用点（用掉的牌 / 判定牌 / 亮出的牌 / 打出的牌）的**入弃牌堆时机逐条不变**。

**Non-Goals:**

- 不做「效果分主要 / 次要」的其余部分：严格模式（次要效果调 `getTempZone()` 报错）、「往上找最近的主要效果」的通用回溯读法、记牌器是否只记主要效果。
- 不给 `Damage` / `Heal` / `Draw` / `Dying` / `MoveCard` / `Ask*` 加重写 —— 它们在结算里是过程，用外面那次结算的区。
- 不引入 timeout、不改任何时机名。

## Decisions

### 1）继承靠**方法委托**，不是遍历字段

基类 `getTempZone()`：

1. `self.tempZone` 有 ⇒ 用它（自己就是归属者，或当初就地建过）；
2. 否则 `self.parent` 有 ⇒ `return self.parent:getTempZone()`；
3. 都没有 ⇒ 就地建（最外层那次结算就是自己）。

**为什么**：只有经由方法，子类的重写才会在链条上生效（嵌套结算要能**截断**继承）。备选是内核自己沿 `parent` 遍历 raw 字段 —— 那样「自己开结算」的效果就失效了。

### 2）归属 = **重写**：`UseCard` / `CardEffect` / `Judge` 自建

三者重写为一行 `return self:createTempZone()`（不向父层取）。判据是官方口径的**结算单位**：

| 效果 | 为什么它是一次结算 | 谁依赖它 |
| --- | --- | --- |
| `UseCard` | 【五谷丰登】「**使用结算结束后**，剩余的牌置入弃牌堆」 | 亮出的牌、用掉的牌 |
| `CardEffect` | 【杀】「按行动顺序对**每个目标依次结算**」；规则集 3.14 的「响应完毕后」 | 打出的【闪】/【杀】 |
| `Judge` | 判定自成一次结算 | 判定牌、改判换下的牌 |

**为什么不让所有效果都自建**（= 今天的样子）：那正是子效果只能手写 `parent` 的根源。
**为什么不给结算边界加类上标记**：用户 2026-09-24 定 —— 重写方法够用，不必新增字段。

### 3）`tempZone` 保持普通字段（**不做 `__getter`**）

读它就是「**自己建的那块**」（没建过为空），存在的意义正是**绕过** `getTempZone()` —— 不建、也不向上取。于是：

- 内核判「谁是归属者」读它；
- `@基础/收尾.lua` 读它（可看到的就是「自己那块」）；
- 归属不需要额外标记：`self.tempZone ~= nil` 就等于「我是归属者」。

**备选**（已否）：把 `tempZone` 做成递归 getter —— 内层子效果的收尾会读到**共享的那块**，就会提前清牌（【五谷丰登】第一个目标生效结束就把剩余亮出的牌送进弃牌堆，后面目标无牌可选）。

### 4）`'效果-收尾'` 只发给**归属者**

`bindFinish()` 里把触发条件收紧成「任务结完时 `self.tempZone` 非空」（在**完成点上**判，因为区常常是结算中途才建的）。语义变成「**这次结算的临时区该清了**」。

**为什么**：`tempZone` 不再天然为空之后，「谁清」必须由内核表达，否则子效果的收尾要么清错（getter 版）、要么内容侧得写晦涩的归属判断。

**备选**：
- 内容侧判归属（`not effect.parent or effect.parent.tempZone ~= zone`）：内核不动，但把内核的归属语义漏给每个内容包。
- 保持「每个效果都发」：会导致内层子效果也去清共享区（`收尾.lua` 读到的若是继承值就提前清）。

### 5）`AskPlayCard:onAnswered()` 改用 `self:getTempZone()`

答复的牌进**最近的归属者**那块。当前四个用牌点（【杀】【万箭齐发】【南蛮入侵】【决斗】）的父链是 `AskPlayCard → CardEffect` ⇒ 落点与今天（在 `CardEffect` 上建区）**完全相同**；`MoveCard` 等过程效果不会再被误当成归属者。**没有外层结算（`parent` 为空）时仍然不动那张牌** —— 这条现有口径（用例已断言）保留：一次孤立的询问不是一个「会消耗这张牌」的结算，去向交给内容侧。

### 6）基类加一行辅助 `createTempZone()`

「自己那块，没有才建」，供三处重写与基类第 3 步共用。**备选**：三段内联重复的懒建（6 行 ×3）。

## Risks / Trade-offs

- [`'效果-收尾'` 触发条件是对外可见的变化] → 现在唯一的订阅者是 `@基础/收尾.lua`（它对没建区的效果本来就是空操作）⇒ 行为无变化；补文档（`architecture.md` §10 / §12、`env-meta.lua` 附近）与用例断言「子效果不发收尾」，第三方包照文档写即可。
- [效果在 `apply()` 之前就调 `getTempZone()` 会被当成最外层] → 与今天行为一致，现存调用点都发生在结算内；按项目约定不过度防御。
- [归属粒度可能随规则口径修订（`CardEffect` 算不算一次结算）] → 口径变了只改**重写清单**（一处一行），机制不动。
