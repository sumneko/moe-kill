# guard-card-in-place

## D1 判据：牌有没有离开「结算开始时它所在的地方」

- 快照时机 = `Damage:settle()` **开头**（不是 `__init`）：`apply()` 是平栈驱动、起执行体不内联，构造到结算之间有一个调度空档，结算开头取才是「伤害开始时它在哪」。
- **不看它在谁手里**，只看「有没有动过」。好处：【闪电】那种「造成伤害时牌本来就在判定区（有归属）」照常工作 —— 对一个已经在别人手上的对象，那是「牌本来就该在那」，不是「被抢」。
- 代价（明确接受）：如果发起方给的牌**在伤害结算之前**就已经在别人手上，这条挡不住。正常流程走不到（用牌时牌已进临时区），按「不过度防御」放过。

## D2 虚拟牌：位置看素材，自己不注销

- 「搬虚拟牌 = 搬它的素材」是 2026-09-30（`add-zhangba-spear`）定的；那条语义下「核虚拟牌还在不在」也该核**素材** ⇒ `cardsInPlace` 顺着 **`Card.physical`**（新加的 getter：普通牌就是它自己、虚拟牌是它的素材）逐张对照，**还在原处的收进结果**（只有一部分还在时就只有那几张 —— 「能拿几张拿几张」，官方 `min{其能获得的<牌>数, X}`）。
- 原来 `Zone:accept` 收到虚拟牌会 `Delete(card)`，而 `useCard.card` / `damage.card` 还拿着它 ⇒ 外面在用已注销对象（`IsValid` = false，只是字段还在才没炸）。去掉 `Delete` 后虚拟牌不绑任何区（`getZone()` 恒为空）、生命周期交给 GC。
- **`accept` 里那段特判也随之消失**（用户 2026-09-30 追加）：既然「实体牌」有了统一读法 `Card.physical`，「虚拟牌 ⇒ 改收子牌、普通牌 ⇒ 收自己」就是同一件事 ⇒ 循环体只剩两行（`local physical = card.physical` + `table.move(…)`）。代价是普通牌每次搬多建一个单元素表（可忽略）。
- 查过 `Card` 没有 `__del` ⇒ 那行 `Delete` 对它只是个「已注销」标记，去掉没有别的账要还。

## D3 否掉的方案

- **「虚拟牌可以进（临时）区」**（用户提的思路）：临时区不是终点 —— `Effect:bindFinish` 的默认收尾是 `弃牌:accept(zone:list())`，所以「只放宽临时区」站不住；要放宽就得连弃牌堆一起放宽，而弃牌堆会洗回牌堆（`@基础/抽牌.lua` 的洗回）⇒ 虚拟牌会被当成实体牌洗回牌堆。
- **内容侧自己逐张核 `subcards`**：技能侧要认识虚拟牌，把机制细节抄进每个获得类技能。
- **`game:moveCard` 加「期望来源区」参数**：把「该不该拿」混进「怎么搬」，而且不解决虚拟牌的判据。
- **判据改成「牌不在任何角色手里」**：会误挡【闪电】这类「造成伤害时牌本来就在某人区域里」的情况。

## D4 为什么一张都拿不到时连问都不问

官方字面是「可以发动」，发动后按 `min{能获得的牌数, X}` 执行 = 拿到 0 张。但**一张都拿不到**时这个技能没有可执行的效果，弹一次窗纯骚扰；且目前没有任何机制关心「你发动过技能」（要靠它联动时可以再谈）。用户 2026-09-30 定：**不问**。

`cardsInPlace` 返回的是**列表**而不是布尔，所以「只有一部分还在」走得通：照问、拿到能拿的那几张（用户 2026-09-30 提议）。
