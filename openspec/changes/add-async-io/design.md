# Design

## Context

`backend-runtime` 提供了单线程事件循环 + 协程 await；`headless-server` 提供了会话外壳。事件循环的空闲策略是从 LuaLS 4.0.0 照搬的：`getIdleTime()` 小于 1 秒就**完全不睡**，靠 `markBusy()` 表达"忙"。这套设计的前提是「阻塞 IO 丢到工作线程，用 channel 回传，忙等能更快看到回传」。

本工程既没有工作线程也没有 channel，文件读写全是同步 `io.open`，所以那个前提不成立 —— 忙等只剩副作用：`bin/moe-kill.exe --test` 从 0.07 秒涨到约 1.4 秒（事件循环迭代 61 万次），服务模式空转时白烧 CPU。

bee.lua 现在自带 `bee.async`（跨平台异步 I/O）。**本机实测**（用本工程 exe 直接跑）：

- `bee.async.create(64)` 可用，Windows 走 IOCP；
- `asfd:wait(200)` 精确阻塞 200 毫秒并返回 0 个完成事件 —— 可直接替代 `thread.sleep`，且能被 I/O 完成事件提前唤醒；
- `asfd:associate_file(io.open 得到的文件)` + `submit_file_read` 成功，完成事件 `op = OP_FILE_READ`、`status = SUCCESS`、数据正确；
- `asfd:submit_poll(fd, udata)` 文档明确说明可用于监听 `channel:fd()`（收到通知后调用方自行 `channel:pop()`）。

结论：**等待与唤醒都可以交给内核**，忙等可以整体删除。

## Goals / Non-Goals

**Goals:**

- 事件循环空闲时阻塞等待，不再空转轮询；定时任务仍按时执行、停止仍能交回控制权。
- 用统一的异步 I/O 实例提供：异步文件读写、完成事件分发、外部事件源（通道 / socket）的唤醒接线。
- 把这套等待机制的接线留在上层（`script/moe-kill.lua`），`tools/` 不反向依赖上层模块。

**Non-Goals:**

- 不引入工作线程 / 子线程，不改线程模型。
- 不做网络传输层与 socket 业务逻辑（只做"能被唤醒"的接线）。
- 不改同步文件工具（`tools/fs-utility.lua` 保持原样），异步读写是**新增**能力。
- 不改外壳（`script/server/`）、协议、规则。

## Decisions

### D1 等待策略：删掉忙等启发式，等待时长由「下一个到期时间」决定

- 删除 `busyTime` / `markBusy` / `getIdleTime`，以及 `runDelayQueue` 返回值驱动的"忙"标记。
- 循环每轮：跑任务 → 跑延迟队列 → 计算等待时长 → 等待。
- 等待时长 = `min(下一个定时任务到期时间, 分片上限 1 秒)`；没有任何定时任务时按 1 秒分片等待。
- 备选与取舍：保留"忙就不睡"（现状）——否决，它就是空转的来源；改用固定的 1 毫秒轮询——否决，只是把空转放慢，仍是轮询。

### D2 等待与唤醒通过注入实现，`tools/` 保持无上层依赖

`eventLoop.start` 的入参从 `sleeper` 改为可选的注入项：

| 注入项 | 语义 | 默认值 |
| --- | --- | --- |
| `waiter(seconds)` | 阻塞等待：睡满 `seconds`，或被 I/O 完成事件提前唤醒 | `thread.sleep` |
| `deadline()` | 距离下一个定时任务到期还有多少秒（没有则 `nil`） | 返回 `nil`（即按分片等待） |

默认值让 `tools/event-loop.lua` 单独也能跑（不依赖 `moe`）。真正的等待由 `script/moe-kill.lua` 注入为「`bee.async` 实例的 `wait`」+「`moe.timer` 的下一个到期时间」。

- 理由：依赖方向保持自上而下，工具层不知道谁是定时器、谁是 I/O。
- 备选与取舍：让 `event-loop.lua` 直接 `require 'tools.timer'` 与 `bee.async`——否决，会把工具层绑死在具体实现上，也让"等待"无法在测试里替换。

### D3 定时器新增「下一个到期时间」查询

`tools/timer.lua` 增加一个查询：返回**距离最近一个定时任务到期还有多少秒**（没有定时任务时返回 `nil`）。实现上遍历定时器分桶（毫秒为键）取最小的、尚未过去的桶，与当前时间求差。

- 理由：循环只有知道"最近什么时候有事"，才能算出一个既准确又不需要空转的等待时长。
- 代价与约定：等待时长必须**向上取整并留 1 毫秒余量**（分桶是毫秒粒度），避免醒来时目标时间还没到而多空转一轮。
- 备选与取舍：维护最小堆——当前定时器数量是个位数（60 秒内存日志 + 测试），遍历足够；将来定时器多了再换。

### D4 异步 I/O 模块 `script/async-io.lua`（本工程自有，不放 `tools/`）

职责：

1. **实例**：持有 `bee.async` 实例（创建失败即报错，不静默降级）。
2. **等待**：`wait(seconds)` 阻塞到超时或有完成事件。
3. **分发**：`poll()` 取出已完成事件，按提交时登记的 `udata` 把结果交回挂起的发起方；完成事件的用户数据原样返回，因此直接以登记表项作为 `udata`。
4. **提交**：
   - 异步文件读 / 写（对协程是"挂起直到完成"的异步函数，失败以错误形式抛出）；
   - 文件读的长度先由同步 stat 取得（读整个文件，一次提交；大文件分批留给将来）；
   - 外部事件源：按 fd 提交 poll，完成时回调取走数据（通道由调用方 `pop`）。
5. **保险**：同一笔操作重复完成、或完成事件到达时发起方已不在等待，按"已结算"忽略（复用 `moe.await.yield` 的一次性语义），并记录一条可排查的日志，不静默丢弃。

放在 `script/` 下而不是 `tools/`：`tools/` 是照搬区，本工程自有能力不往里塞。

### D5 接线与测试入口

- `script/moe-kill.lua`：挂 `moe.asyncIO`；把 `waiter` / `deadline` 注入事件循环；把 `asyncIO.poll` 挂成高优先级任务（每轮先分发完成事件，再跑其它任务）。
- `test.lua`：删除 `sleeper` 里 `moe.timer.update(1000)` 的**虚拟时间兜底**（那是为了掩盖忙等而"提前"触发定时器）。测试里的等待改回真实时间（毫秒级），不去动定时器实现。
- `test/smoke/eventloop.lua`：依赖 `getIdleTime` 的用例（"空闲时间随真实时间推进"）随启发式一起删除；"不空转"的替代用例放到 `test/async/`。

### D6 等待分片上限取 1 秒

没有任何定时任务时按 1 秒分片等待：每分钟 60 次唤醒，CPU 可忽略，且保证"停止请求最迟一个分片内生效"。

- 备选与取舍：做一个自唤醒通道（`submit_poll` 监听自建 channel）实现即时停止——否决，本次没有这个需求，加进来只是多一条没人用的路径；等网络层真的需要即时唤醒时再做。

## Risks / Trade-offs

- **[等待时长算短了导致空转]** → D3 的向上取整 + 1 毫秒余量；测试里用"空闲 200 毫秒内迭代次数远低于空转"的断言把它钉住。
- **[`bee.async` 在某些构建/平台缺失]** → 实测可用；实例创建失败时**启动报错**而不是静默降级，避免变成"看起来能用但不会唤醒"。
- **[与上游 `tools/` 分叉]** → 在 `moe-kill-dev` 技能里登记「本工程对 `tools/` 的改动清单」（改了什么、为什么），将来从上游同步时逐条比对。
- **[等待期间定时器不更新]** → 定时器更新（`moe.timer.update`）本来就是循环的高优先级任务，等待只睡到"下一个到期时间"，醒来立刻执行，不会漏触发。
- **[异步文件句柄被就地替换为 IOCP 关联句柄]** → 异步路径用完后必须 `close`，且同一句柄不混用同步读写；写进 `async-io` 的使用说明。
- **[事件循环停止语义变化]** → 停止仍由循环内任务请求（与 `headless-server` 的 D6 一致：主循环归入口所有）。

## Migration Plan

纯增量 + 两处工具改动：新增 `script/async-io.lua`、`test/async/`；修改 `tools/event-loop.lua`、`tools/timer.lua`、`script/moe-kill.lua`、`test.lua`、`test/smoke/eventloop.lua`。回滚 = 还原这几处并删除新增文件（无数据迁移、无对外接口兼容问题）。

## Open Questions

- 异步文件读当前只做"整文件读"（长度来自同步 stat）。将来若需要边读边处理大文件，是否补 `offset` / 分批读取的公开接口？
- 同步文件工具（`tools/fs-utility.lua`）是否要在某个时间点也切到异步路径？本次不动，等真正出现"读大文件卡住循环"的场景再决定。
- 外部事件源接线目前只做"能注册、能唤醒"；将来网络层还需要"注册 / 注销 / 连接关闭"的完整生命周期，届时在同一个模块上扩展。
