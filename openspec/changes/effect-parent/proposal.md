# 效果记录父效果

## Why

结算栈已经能查「现在在结算什么」，但**效果实例本身不带这条线**：一次伤害结算完就退栈了，事后（或在 `伤害-后` 之后的时机里）拿到那个 `Damage`，无法知道它是"哪一次用牌（或哪一次技能）结算里发生的"。将来做连锁、写日志、AI 复盘、以及按"起因"汇总结算都会需要这条线。

嵌套在规格里本来就有定义（先进后出的结算栈），父效果就是**结算那一刻的栈顶** —— 但它没有被记下来。

## What Changes

- `Effect` 增加 **`parent`** 字段：这一个效果是**在哪一个效果的结算里**被结算的（没有就是「不存在」）。
- 赋值放在 **`Effect:apply()` 里、压栈之前**（一行）：此刻栈顶正是外层效果。于是**所有效果子类自动具备**这条线，不需要各自处理。
- 父效果是**结算上的嵌套关系**，与「伤害来源」（`Damage.from`）**不是一回事**：前者是"谁在结算时把我造出来的"，后者是"这一下算谁的"。两者都要留。
- 机制入口不变：`game:damage` / `game:play` 照旧（它们造出的效果自己会带上父），**不新增也不删除 API**。

## Non-Goals

- **不把 `damage` 挪到 `Effect` 上**：那会让"父"来自**接收者**而不是栈，接收者可能不在栈上（造好没结算 / 已经结算完），要额外校验；且根效果（身份场开局扣体力、调试用伤害）就没法造伤害了，留着 `game:damage` 又变成两套 API。
- **不记「子效果列表」**：没有消费方，且要跟着栈维护；沿 `parent` 往上走即可还原整条链。
- 不引入"效果优先级 / 时间戳 / 结算编号"之类的额外元信息。
