# Design

## Context

动机见 `proposal.md`。与做法相关的现状：

- 伤害现在是一个方法（`game:damage(from, to, amount)`）+ 一个匿名表上下文（`{ from, to, amount }`），类型 `Game.EventCtx.伤害` 只是给这个表起名（纯类型文件 `loader/env-meta.lua` 里声明）。
- 内核的既有形状是「类 + `create` 工厂 + 门面 `moe.xxx`」（`moe.card` / `moe.zone` / `moe.orderedZone` / `moe.player` / `moe.game`）；把某个概念立成对象要与它一致。
- 有先例把「自己所属的环境」绑在实例上：`OrderedZone` 绑定随机源（洗牌可省参数）；也有先例只把环境当参数传（`Zone:shuffle(random)`）。
- 时机上下文约定「只读」，要改行为走**接口**而不是改上下文字段（见 `game-events` 的能力口径）。

## Goals / Non-Goals

**Goals:**

- 「这次伤害」是一个有类型、有行为的实例，能在时机之间传递（前后两个时机拿到同一个对象）。
- 保留现有的调用写法：规则包 `game:damage(使用者, 目标, 1)` 与现有用例**不用改**。

**Non-Goals:**

- 伤害值修改、伤害防止、属性伤害（火 / 雷）、多目标伤害的"一次伤害打多人"语义 —— 等有技能 / 军争内容时再定。
- 不让伤害实例承担"结算栈 / 濒死插入"的职责（那是下一批的事）。

## Decisions

### D1 伤害实例持有它所属的局，`:apply()` 不收参数

`moe.damage.create { game = game, from = ..., to = ..., amount = 1 }:apply()`。伤害总是"某一局里的一次伤害"，把局绑在实例上（同 `OrderedZone` 绑随机源），于是结算不需要再传环境，`game:damage(...)` 也只是「建实例 + `:apply()`」的一句便利wrapper。

**备选**：`create { from, to, amount }` + `:apply(game)`（实例保持纯数据，但包作者每次要自己传局，且"这次伤害属于哪一局"变成调用点的隐含知识）；`game` 由外部注入到字段（隐式、易忘）。

### D2 时机上下文就是实例本身

「伤害-前」/「伤害-后」的 `ctx` 直接是这个 `Damage` 实例：`ctx.from` / `ctx.to` / `ctx.amount` 的读法不变，类型从 `Game.EventCtx.伤害` 变成 `Damage`（纯类型改名 + 类替换）。

**备选**：包一层 `{ damage = 实例 }` —— 只有等"伤害时机还要带别的参数"时才有价值，现在纯属多余一层。

### D3 字段可读，改值留给将来的接口方法

`game` / `from` / `to` / `amount` 做成**可读字段**（与 `Game.desk` / `Game.random` 同类），沿用"上下文只读"的现状；将来"改伤害值"要加的是接口（`setAmount` / `addAmount` 之类）或专门的时机，而不是让包作者直接写 `ctx.amount = ...`。

**备选**：现在就加 `setAmount` 之类的写接口 —— 没有消费者，提前拍口径（违反"按功能点推进、最小可用形状"）。

### D4 `game:damage` 保留为便利入口

它是"造成一次伤害"的最短写法，规则包与测试都在用；语义上等于「建实例 + 结算」，不引入第二条语义。

**备选**：删掉它、只留 `moe.damage.create(...):apply()` —— 包作者每次要写两截，且规则包里"造成伤害"这件事变得不那么直白。

## Risks / Trade-offs

- [实例持有局 ⇒ 伤害不能脱离局存在] → 它本来就是"这一局里的一次伤害"；测试里建实例也必须先有局。
- [局 ↔ 伤害 循环引用] → 伤害是短命对象（结算完就没人引用），内核不做缓存或登记，不需要特殊处理。
- [将来要支持"一次伤害打多个目标"时字段 `to` 可能要变成列表] → 届时要么新增字段、要么把多目标拆成多次伤害（三国杀多数效果就是逐个目标分别结算），本批不预设。
- [把 `Game.EventCtx.伤害` 换成 `Damage` 会让已经写下的包注解失效] → 当前只有本仓库的包，且它们不写类型注解，代价为零。

## Open Questions

- 「伤害」的**属性**（无属性 / 火 / 雷）要不要成为实例上的一个字段？等做军争或属性伤害相关技能时再定。
- 伤害实例是否需要一个"来源为空"的表达（无来源伤害，如闪电、体力流失）？等真有这种效果时再定；本批要求来源必填。
