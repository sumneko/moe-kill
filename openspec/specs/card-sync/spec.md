# card-sync Specification

## Purpose
后端向客户端同步「盘面」的契约：场上每个牌区里有哪些牌、牌面是什么、牌从哪儿到了哪儿。客户端据此渲染牌桌、播移动动画，并在此基础上接收询问（候选、答复、目标）。卡牌视图是**不可变实例 + 三种通知**（出现 / 消失 / 原地更新），加一条只为动画而发的移动预通知。

## Requirements

### Requirement: 卡牌实例与视图 id

每个连接 SHALL 各有一份「这个客户端当前看见的卡牌视图」，视图里每张牌 SHALL 带一个**视图 id**（由这个连接自己发，同一连接内唯一；牌离开区域后这个 id 作废）。

系统 MUST NOT 要求不同连接上代表同一张实体牌的 id 相同，也 MUST NOT 要求同一张实体牌先后两次待在区里时 id 相同。

#### Scenario: 离开再进入会换一个新 id

- **WHEN** 一张牌离开牌区后又被放回牌区
- **THEN** 在这个连接看来，它第二次的视图 id 与第一次不同

#### Scenario: 离开牌区后旧 id 作废

- **WHEN** 一张牌被移出牌区（例如用掉之后暂不在任何区里）
- **THEN** 这个连接不能再拿它的旧 id 指认任何牌

### Requirement: 看不见内容的牌不可被追踪

对某个连接而言，**内容不可见的区**里的牌 SHALL 不可被追踪：客户端 MUST NOT 能据 id 判断「这个区里的哪一张牌」与被移到别处的那一张是同一张。

具体地：牌**进入**这样的区时 SHALL 拿到一个全新的 id（给这个连接看的那个号必须是它没用过的）；同时后端 SHALL 把这个新号与**同一区域里另一张同样看不见内容的牌**所占的号**对调**（可能抽到它自己 = 不对调）—— 于是客户端那里的 id 集合一个都不变，换的只是「哪个 id 属于哪张真牌」，而服务端内部这张新牌背上的是旧号 ⇒ 之后**移除**、**移动**报出去的 id 都认不出是哪一张。

#### Scenario: 暗牌绕一圈回来也对不上

- **WHEN** 一张牌被移进某个对该连接不可见的区，之后又被移到别处
- **THEN** 客户端无法据 id 判断这两次是同一张牌

#### Scenario: 摸牌不泄露

- **WHEN** 一名玩家摸牌（从抽牌堆进他的手牌，两边对别人都是暗的）
- **THEN** 客户端只知道「抽牌堆少了一张、他的手牌多了一张」，无从追踪是哪一张

### Requirement: 开局与重连的全量卡牌

开局（以及将来的重连）时，后端 SHALL 把当前所有牌区里的牌**全量**发给客户端（含抽牌堆里的牌），使客户端不必依赖任何增量历史。

发出去的内容 SHALL 按收件人视角裁剪（见「按收件人视角裁剪」）。

#### Scenario: 开局收到全场牌

- **WHEN** 一局开始并完成装配
- **THEN** 客户端收到全部牌区里的牌，各区的牌数与本方视角看到的张数一致

#### Scenario: 背面牌只有身份没有牌面

- **WHEN** 客户端收到一张它看不见的牌（别人的手牌、抽牌堆里的牌）
- **THEN** 它拿得到这张牌的视图 id 与所在区域，但拿不到牌名、花色与点数

### Requirement: 出现、消失与原地更新

卡牌视图的变化 SHALL 用三种通知表达：

- 牌进入牌区 ⇒ SHALL 发 `Card.Create`（带上新的视图 id）；
- 牌离开牌区 ⇒ SHALL 发 `Card.Remove`（按视图 id 列出）；
- 牌**仍待在同一区域**但内容变了（比如被转化为别的牌、或从不透明变为可见）⇒ SHALL 发 `Card.Update`（**视图 id 不变**）。

把一张牌「这个连接上一次收到的内容」与「现在的内容」逐字段比较后**完全一致**时，MUST NOT 发出任何通知。

#### Scenario: 新出现的牌收到创建通知

- **WHEN** 一张牌被放进某个牌区
- **THEN** 客户端收到一条创建通知，其中带这张牌的新视图 id、它所在的区域与（看得见的）牌面

#### Scenario: 消失的牌收到移除通知

- **WHEN** 一张牌离开牌区
- **THEN** 客户端收到一条移除通知，其中列出它的视图 id

#### Scenario: 转化牌原地更新

- **WHEN** 一张牌待在同一个区域里被转化为另一种牌（例如方块牌被当作【乐不思蜀】）
- **THEN** 客户端收到一条原地更新，视图 id 不变，内容带上转化后的牌面

#### Scenario: 没有变化就不发通知

- **WHEN** 一张牌被标脏，但它的视图 id、区域与可见的内容与上一次同步出去的一模一样
- **THEN** 客户端收不到任何通知

### Requirement: 换区走移除 + 创建并更换 id

牌从一个区域变到**另一个**区域时，MUST NOT 用原地更新表达：后端 SHALL 为它分配**新的视图 id**，并以「移除旧 id + 创建新 id」表达这次变化。

「是不是换了区」SHALL 按**协议区域**判断（见「协议区域」）：协议区域相同的两次变化 MUST 视为没换区。

#### Scenario: 手牌到弃牌堆换新 id

- **WHEN** 一张手牌被弃置进弃牌堆
- **THEN** 客户端收到一条移除通知（旧视图 id）与一条创建通知（新视图 id、位于弃牌堆）

#### Scenario: 临时区之间互移不算换区

- **WHEN** 一张牌从一块临时区被挪到另一块临时区（两块都没有名字与归属）
- **THEN** 它的视图 id 不变，也不产生移除与创建通知

### Requirement: 移动动画的预通知

每次搬牌时，若牌的**协议区域**与搬之前不同，后端 SHALL **当场**发出一条移动通知（带来源区域、目标区域，以及每张牌搬之前的视图 id），供客户端播移动动画。

移动通知 MUST 早于对应的移除通知到达客户端。

协议区域没有变化时（例如临时区之间互移）MUST NOT 发出移动通知。

#### Scenario: 手牌到弃牌堆会先发移动通知

- **WHEN** 一张手牌被移动到弃牌堆
- **THEN** 客户端先收到移动通知（来源是那个玩家的手牌区、目标是弃牌堆），之后才收到移除与创建通知

#### Scenario: 临时区之间互移不发移动通知

- **WHEN** 一张牌在一块临时区与另一块临时区之间移动
- **THEN** 客户端收不到移动通知

### Requirement: 协议区域

下发里的区域 SHALL 由「玩家 + 区名」两部分构成：有归属的区 SHALL 带该玩家的标识，公共区 MUST NOT 带玩家标识。

既没有名字、也没有归属的区（临时区）MUST 一律表示成**同一个空区域** —— 客户端无法据协议区分不同的临时区。

#### Scenario: 玩家的手牌区

- **WHEN** 一张牌位于某个玩家的手牌里
- **THEN** 它的区域带着那个玩家的标识与「手牌」这个名字

#### Scenario: 公共区

- **WHEN** 一张牌位于抽牌堆或弃牌堆
- **THEN** 它的区域只有名字（`抽牌` / `弃牌`），没有玩家标识

#### Scenario: 临时区一律等价

- **WHEN** 两张牌分别位于两块不同的临时区
- **THEN** 它们在协议里的区域表示完全相同

### Requirement: 按收件人视角裁剪

每次下发 SHALL 按**收件人**裁剪内容：收件人看不见的牌 MUST 省掉牌面（牌名 / 花色 / 点数），只保留视图 id 与所在区域。

可叠加的可见性（区域自身的可见性与这一次移动的可见性）SHALL 由后端消费，MUST NOT 原样下发给客户端。

#### Scenario: 自己的手牌看得见

- **WHEN** 后端把某个玩家的手牌同步给**这个玩家自己**
- **THEN** 每张牌都带着牌面

#### Scenario: 别人的手牌只有背面

- **WHEN** 后端把某个玩家的手牌同步给**其他玩家**
- **THEN** 那些牌只有视图 id 与所在区域，没有牌面；牌的张数仍然是可见的

### Requirement: 合并下发

`Card.Remove` / `Card.Create` / `Card.Update` SHALL 攒到一次调度末尾合并发出：同一笔调度里对同一张牌的多次变化 MUST 只发最终结果，一批牌的变化 SHALL 合成同一条通知。

移动通知 MUST 例外，当场发出。

#### Scenario: 一笔调度里改两次只发一次

- **WHEN** 同一笔调度里一张牌被连续改了两次
- **THEN** 客户端只收到一条通知，内容是改完之后的状态

#### Scenario: 同一笔里的多张牌合成一条

- **WHEN** 同一笔调度里有三张牌分别被移到同一个牌区
- **THEN** 客户端收到的创建通知里带着这三张牌

### Requirement: 牌面分两层下发

`Proto.Card.template` SHALL 是**牌自己那份**牌面（不随「转化」变化），`Proto.Card.modifier` SHALL 是**所有「转化」叠出来的那一份**；没挂转化时 MUST NOT 带 `modifier`。

合并（后挂的覆盖先挂的）MUST 由后端做，客户端只负责把两份叠起来。

#### Scenario: 挂上转化只动 modifier

- **WHEN** 一张看得见的牌被挂上「转化」
- **THEN** 客户端收到 `Card.Update`：`template` 与之前一致，`modifier` 给出转化后的值

#### Scenario: 没转化就不带 modifier

- **WHEN** 一张没有「转化」的牌被下发
- **THEN** 通知里只有 `template`，没有 `modifier`
