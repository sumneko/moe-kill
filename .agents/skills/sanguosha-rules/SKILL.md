# 三国杀规则（项目口径）

本文件是规则侧的事实来源，供实现与评审使用。**口径状态：预研，未最终确认**（见文末「待确认口径」）。
任何实现若与「待确认口径」冲突，先问用户，不要自行选定规则版本。

## 1. 模式与身份配置

本工程先做**身份场**（单机，AI 补齐人数），暂不做国战 / 3v3 / 斗地主等其它模式。

| 人数 | 主公 | 忠臣 | 反贼 | 内奸 |
| --- | --- | --- | --- | --- |
| 4 | 1 | 1 | 1 | 1 |
| 5 | 1 | 1 | 2 | 1 |
| 6 | 1 | 1 | 3 | 1 |
| 7 | 1 | 2 | 3 | 1 |
| 8 | 1 | 2 | 4 | 1 |
| 9 | 1 | 3 | 4 | 1 |
| 10 | 1 | 3 | 5 | 1 |

- 先手（第一回合）由主公开始；身份牌除主公外均隐藏。
- 体力上限：主公在标准规则下**体力上限 +1**（人数相关变体另计）。

**已实现口径（`package/身份场/`）**：

- 配置表先做 **4~8 人**（上表前五行，`package/身份场/配置.lua` 以 `game:setValue('身份配置', ...)` 落进**规则数值**，所以后续包可覆盖）；9 / 10 人表等真要用时再补。
- **主公固定坐 1 号位**（简化假设），于是「按座位号递增」的行动顺序天然让主公首回合先手 —— 不需要给内核加「起始行动者」的概念。
- 身份写进玩家的**不透明标签**（`player:setTag('身份', ...)`）：内核只记录、不解释取值。
- 主公 +1 走**改体力上限**（`attrs:add('体力上限', 加成)`，加成取规则数值 `主公体力上限加成`），**不是**直接改体力值；因为基础包先把体力与上限都写成了默认值，身份场只需再“抬”一次，体力自然跟上。
- **规则数值里的 `默认体力` 是「无武将时的开局体力初值」**（`package/@基础/配置.lua` 里为 5）：它同时被用作战玩家的 `体力上限`，也是「主公 +1」的**基数**，所以现在必须留着（用户 2026-09-19 确认）；等**武将**接管上限后，它就只剩“武将没写时的兜底”一个用途，可以退休。
- **体力属性的边界（已实现）**：`体力` 下界为负（`-999999`，濒死结算要用）、上界写**字符串引用** `'体力上限'` ⇒ 写值会**钳到当前上限**；`体力上限` 自带 `0..999999`。抬上限**不会**自动加体力（所以主公那句「上限与体力各 +1」仍必要）。

## 2. 胜负与奖惩

- 主公 + 忠臣：消灭所有反贼与内奸。
- 反贼：杀死主公（主公死亡时若反贼已全灭，仍由反贼胜）。
- 内奸：成为最后的存活者，且必须与主公单挑后杀死主公；内奸与反贼同归于尽时反贼胜。
- 奖惩：
  - 任意角色杀死反贼 → 摸 3 张牌。
  - 主公杀死忠臣 → 主公弃置其所有手牌与装备牌。

## 3. 回合流程

```
准备阶段 → 判定阶段 → 摸牌阶段 → 出牌阶段 → 弃牌阶段 → 结束阶段
```

| 阶段 | 内容 |
| --- | --- |
| 准备阶段 | 回合开始时点的技能结算 |
| 判定阶段 | 逆序结算判定区内的延时锦囊（后入先出） |
| 摸牌阶段 | 默认摸 2 张 |
| 出牌阶段 | 使用牌；默认「杀」限一次 |
| 弃牌阶段 | 手牌数须降至当前体力值 |
| 结束阶段 | 回合结束时的技能结算 |

每个阶段本身也是**时机**（有「阶段开始时 / 结束时」的触发点），技能可挂在阶段前后。

- **已实现（2026-09-21）**：回合流程在 `package/@基础/回合.lua`，加载期登记（`game:registerFlow`）、由装配侧 `game:runFlow()` 启动。六阶段依次走完，各触发 `'阶段-开始'` / `'阶段-结束'`（上下文 = 回合角色 + 阶段名），整段被 `'回合-开始'` / `'回合-结束'`（上下文 = 回合角色）包住；首回合主公（1 号位）、阵亡者跳过、只剩一个存活角色时流程结束。
  - **摸牌阶段**：摸 2 张（`抽牌` → 该玩家的 `手牌`）；抽牌不够时把 `弃牌` 洗混当新抽牌堆（用局上的随机源 ⇒ 同种子可复现）。
  - **出牌阶段**：循环询问回合角色（决策询问，缘由 `'出牌'`）—— 答复「用哪张牌 + 哪些目标」就用牌并继续问，答复为空就结束阶段。**不限次数、不限张数**（本批不做）。
  - **弃牌阶段**：手牌数须降到**当前体力值**（询问，缘由 `'弃牌'`；弃不够或没答复 ⇒ 明确失败）；手牌没超就不问、不挪牌。
  - **本批不做**：判定区的结算（判定阶段只触发时机）、装备与距离修正、濒死与胜负判定、出牌次数限制、延时锦囊与技能。

## 5. 距离与攻击范围

- **座位距离**：沿桌面两个方向取较小值，最小为 1。
- **距离修正**：目标装备 +1 马 → 距离 +1；自己装备 -1 马 → 距离 -1；结算后距离仍**最小为 1**。
- **攻击范围**：默认 1，由武器决定；与「距离」是两个独立概念。
- 距离与范围是**动态计算**（技能、装备均可改），必须作为求值函数而非缓存字段。
- **已实现（内核）**：`desk:getDistance(from, to)` 当场求值（只由两个座位号与座位总数决定、最小 1、不缓存成字段）；**修正来源（装备 ±1 马、技能）还没接**，接的时候只改求值路径，不动调用形状。
- **已实现（基础规则）**：属性 `攻击范围` 默认 1（`package/@基础/攻击范围.lua` 开局写给每个玩家）；「够不够得着」由**内容包**把距离与它组合得出（见 §9.2 的「杀」）—— 内核不作任何具体判定。武器改范围只需修正这个属性，调用形状不变。

## 6. 「使用」与「打出」

这两个是不同的动作，不能合并实现：

- **使用**：出牌阶段主动使用牌（杀、锦囊、装备……）。
- **打出**：为响应而使用（闪响应杀、杀响应决斗/南蛮/万箭、桃用于濒死救援）。
- 打出**不触发**「使用时」的技能；结算时机的差异是技能系统的关键区分点。
- **已实现（部分）**：**使用**这条链路跑通了（`game:useCard(使用者, 牌, 目标们)`）；**响应**用"要一张牌"表达 —— `game:askCard(被问者, 缘由, 要什么牌)`（返回**询问实例**，出来的牌读 `.result` / `.card`；应答方挂在局上的 `'卡牌-询问'` 时机里，**答复后规则层在 `'卡牌-答复'` / `'卡牌-答复后'` 里按缘由接手那张牌的去向**）。**内核里没有「打出」这个动作**（用户 2026-09-20 定）：为响应而用掉一张牌 = 一次以 `'打出'` 为缘由的询问被答复 ⇒ 基础规则把它送进弃牌。具体见 §7 与 §9.2。【闪】已落地（响应）。

## 7. 结算时序与插入

- 锦囊结算：先检查目标合法性，再**从使用者的下家开始按行动顺序逐个结算目标**。
- **无懈可击**可在任意锦囊生效前使用，且可被另一张无懈可击抵消（可嵌套）。
- **濒死**：体力降至 ≤ 0 时插入濒死结算，**从濒死者开始**按行动顺序询问是否使用桃（本项目口径，用户 2026-09-21 定；与「从当前回合角色开始」那种说法不同，见 §10）。
- **死亡**：濒死结算失败后死亡，插入死亡结算 → 奖惩 → 胜负判定 → 可能立即结束游戏。
- 以上都要求引擎能**嵌套结算**：结算过程中可以起新的结算，处理完再回到原处继续。
- **已实现（部分）**：用牌与伤害都是**效果对象**（`UseCard : Effect` / `Damage : Effect`），每个效果由**自己的任务**驱动 —— `Effect:apply()` 是驱动点（「记父（当前正在结算的那个）→ 触发 `'即将生效'` → 自己结算」），`Effect:await()` 等它结完、`result` / `err` 就在效果上；局上留一个**只增的记牌器**（`game:getEffect()` = 最近发起过的根效果、`game:getEffects()` = 按发起顺序的快照 —— 记的是**发起过什么**，不是"正在结算什么"，内层效果不单独记），嵌套深度上限 100 层（`Effect.deep`），**失败不抛给调用方**（记 `.err`）；`Effect.parent` 就是**外层效果**（根效果为空），沿着它往上走能还原整条结算链 —— 注意它是**结算嵌套**、"这一下算谁的"归伤害自己的 `from`（两者可不同）。**伤害与回复的结算只发事件、自己不动体力**（2026-09-21 定）：`Damage:settle()` = `'伤害-前'` → `'伤害-生效'` → `'伤害-后'`（`Heal` 对称，三个时机的上下文都是这次伤害 / 回复的实例），**扣血在基础规则的 `@基础/伤害.lua`（`'伤害-生效'` 里）、回血在 `@基础/回复.lua`** —— 于是内核不认识任何属性名，将来**护甲 / 改伤害值 / 回复加成**都挂这两个文件；
  - **逐目标生效**：用牌的结算 = 「校验 → 取出牌 → 触发 `'卡牌-结算前'`（基础规则这时把牌放进 `处理`）→ **按行动顺序**（从使用者下家开始）对每个目标各结算一次**生效**（`CardEffect`，父效果 = 这次用牌）→ 全部处理完后触发 `'卡牌-结算后'`（基础规则把牌送进 `弃牌`）」。每个生效都是独立效果 ⇒ 有自己的「即将生效」、能被**单独取消**；前一个生效连同它引发的插入结算全部结束之后，才轮到下一个目标。
  - **取消**：效果执行自己的结算**之前**触发一次 `'即将生效'`（上下文 = 该效果实例，此刻它正是最近发起过的那个），订阅者调 `效果:remove()` 即**取消这一次生效**（不再结算、不算失败）；**作用域只到这一个效果** —— 不影响外层、也不影响同一张牌对其余目标的生效，且**只能由正在运行的那个效果自己发起**（在别处拿到实例再取消是空操作）。【闪】就是长在这个时机上。
  - **响应**：要一张牌用 `game:askCard(被问者, 缘由, 要什么牌)` —— 询问走局上的 **`'卡牌-询问'` 时机**，应答方（无头测试注入的脚本、将来的匹配系统或前端）拿到询问后调 `ask:answer(那张牌)`，**给出的牌读 `ask.result` / `ask.card`**（没人答上 / 被取消 ⇒ 不存在）。**缘由**（如 `'打出'`）是内核不解释的字符串：询问结束后还会连着触发 **`'卡牌-答复'`** 与 **`'卡牌-答复后'`**（**有答复才触发**；没人应答不触发 —— 表达"问了没人答"是另一个事件，将来加），基础规则在它们里按缘由接手 —— `'打出'` ⇒ `'卡牌-答复'` 先进 `处理`、`'卡牌-答复后'` 再进 `弃牌`；**结果在应答的那一刻就定下了，所以这个时机里 `ctx.card` 读得到给出的牌**。所以**业务层（内容包）不用自己挪牌**；**内核里没有「打出」动作**（没有 `game:respond`、也没有 `'卡牌-打出后'` 时机）—— "打出"只是内容侧对 `'打出'` 这个缘由的解释。
- **还没做**：无懈可击的嵌套响应、奖惩与胜负判定、装备与判定、改伤害值 / 防止伤害 / 属性伤害、【杀】的使用次数限制；**询问的异步答复与超时**（本批是当场取答案）。
- **【2026-09-21 已落地】濒死与【桃】**：体力从 >0 跨到 ≤0 ⇒ **濒死结算**（`Dying : Effect`，由基础规则在 `'濒死'` 时机里求桃）；结算完仍 ≤0 ⇒ `setAlive(false)`（触发 `'玩家-死亡'`）。**内核只提供 Dying 与「记账」入口**（`game:enterDying(player)`）—— 谁该进濒死、怎么救、什么时候判死**全部在规则里**（`package/@基础/濒死.lua`）；【桃】两种用法（出牌阶段对自己 / 濒死时对濒死角色）写在 `package/标准/卡牌/桃.lua`。详见 §9.4。
- **【2026-09-20 已落地】牌的自动去向**：`game:askCard(被问者, 缘由, 要什么牌)` 的第二个参数是**缘由**（如 `'打出'` / `'使用'`；内核**不解释**取值），询问结束后局上触发 **`'卡牌-答复'`**，**基础规则据 `ctx.reason == '打出' and ctx.card` 让那张牌经 `处理` 进 `弃牌`** ⇒ **业务层完全不写 `moveCard`**（【杀】的响应只读 `ask.result`、按结果决定是否受伤）。
- **【2026-09-20 已落地】`moveCard` 提成效果**：`MoveCard : Effect`（`kind` = `moveCard`），**一次结算挪一批牌**（不再逐张 `Zone:move`）⇒ 有父效果、可被取消、失败记 `.err`（与伤害 / 用牌同一形状）。
- **已定：两套去向，都是内容包说了算**（用户 2026-09-20）——**用过的牌**：`'卡牌-结算前'` 进 `处理`、`'卡牌-结算后'` 进 `弃牌`（`package/@基础/使用.lua`）；**打出的牌**：`'卡牌-答复'` 进 `处理`、`'卡牌-答复后'` 进 `弃牌`（`package/@基础/打出.lua`）。两个时机本身就是**连着触发**的（事件连着来，别指望中间有停顿）。**没有归属的牌也能挪**，所以两处都用 `game:moveCard(牌, 区名)`。
  - **已落地的死亡最小形状**：`player:isAlive()` / `player:setAlive(false)`，从活变死时触发 **`'玩家-死亡'`**（上下文 = 这个玩家）；`desk.alivePlayers` 直接读“还活着的角色”；「参与行动」（`player.acting`）也已改成**由存活派生**（活着就参与，阵亡即退出行动顺序）。**濒死流程已落地**（见 §9.4），奖惩与胜负判定还没做 —— 所以现在人真的会死，但死了之后除了这个时机不会发生别的。

## 8. 时机系统（实现要点）

- 所有可变行为收敛为「时机（时机名 + 相关对象）→ 查询可触发技能 → 依序执行 → 可能请求玩家决策」。
- 技能分：触发技（被动，挂时机）、主动技（出牌阶段主动发动）、锁定技（必发，不可放弃）。
- **技能可以在任意时机插入**，因此引擎必须能在结算中途**停下来等人输入再继续**：遇到需要玩家决策的点就让出，等输入回来接着跑，而不是一路跑到底的函数调用。
- **建议：时机名用 `分类-动作` 风格**（`'游戏-开始'`、`'回合-开始'`、`'判定-前'`、`'伤害-后'`…）—— 前一段是分类、后一段是动作，便于把事件表按分类聚合；与“集中定义成一张枚举表”的初衷一致，但**不预设、不校验**（时机名仍是任意字符串，写法规约而已）。
- **落定机制（已实现）**：规则集用 `game:on(时机名, function (ctx) ... end)` 注册、装配 / 流程代码用 `game:fire(时机名, ctx)` 触发（时机名**不预设**，注册顺序即执行顺序，注册随清空重装清空）。上下文**只装该时机的参数**（`'游戏-开始'` 没有参数 ⇒ 传空表），环境对象就是注入的 `game`（这一局的桌子 / 随机源 / 牌区都从它取）；每个时机的 `ctx` 类型写在 `server/core/loader/env-meta.lua`（纯类型文件，按事件名收窄字段类型；详见 `moe-kill-dev` 的 `references/architecture.md` 第 10 节）。
- `ctx` 约定**只读**；加载期的回调**报错被隔离**（只记日志、不影响其它回调），所以“规则包出错”的可见信号是**状态没写**（如没写出牌堆），装配方要在 `fire` 之后断言必需状态。
- 要"覆盖"别人的效果就改**状态**（写标签 / 改属性 / 加标记），不做"回调返回值改事件载荷"那一套。

## 9. 对实现的结构性约束

1. 引擎是**纯逻辑**，不依赖 IO / jsonrpc；随机数必须可注入（固定 seed 可复现整局）。**内核（`server/core/`）不含任何游戏流程，也不预设区域名与属性名**——手牌区/装备区/体力 这些都在 `package/` 规则集里定义。
2. 决策点统一走「请求输入 → 挂起 → 恢复」，**挂起的持有者是流程内部**（`server/session/` 的会话外壳只当容器；在流程里封装它是后续批次），无头测试与前端走同一条路径（只是输入来源不同）。**整个游戏都在协程里跑**（用户 2026-09-21 确认）：装配方在协程里开局、触发 `'游戏-开始'`、启动流程，所以内容侧的时机钩子可以直接 `await`（放置走 `game:moveCard`、询问、用牌都是 await 点）。
3. 一次操作产生的表现需求（动画/音效）由后端输出为**事件流**，前端只消费，不反推状态。
4. 前端不参与任何规则判断：目标合法性、距离、可用牌列表**全部由后端计算并下发**。
5. 规则集**不参与开发期热重载**：`package/` 由自建装载器**读文件执行**（不走 `require` / `include`），所以改卡牌 / 技能代码要生效，得走**业务侧清空重装**（`moe.loader.install(game, { packages = 清单 })` 重新跑）或重启进程；**装载器与局这两份代码本身**（`server/core/loader/` 与 `server/core/game.lua`）与其它内核模块一样可热重载，已建好的局在重载后照常可用。因此：需要跨重载存活的数据（如牌的唯一 ID）必须挂在**内核的类表 / 门面表**上，不要指望规则集文件里的 `local`。
6. **「规则集重载」是游戏业务功能，与开发期「热重载」是两个不同的东西**（用户 2026-09-19 明确要求）：前者是**运行期**重新装置 / 切换**这一局的**规则集（清空规则表 + 重新加载，触发者在业务侧），后者是**开发期**改代码不重启（触发者在开发者）。两者定位、生命周期与影响范围不同，**不要互相替代或混为一谈**（`moe.reload` 是后者，见 `moe-kill-dev` 的 `references/architecture.md` 第 8 节与第 9 节）。

### 9.1 规则集侧写法（已落地）

```lua
Depends { '../基础' }   -- 写在文件顶部：执行到该行时同步把依赖加载完

game:setValues { 默认体力 = 5 }               -- 规则数值：可被后续包覆盖的配置

local attributeSystem = game:getAttributeSystem()      -- 属性系统由这一局持有（包在加载期 define）
attributeSystem:define('体力上限', { min = 0, max = 999999 })
attributeSystem:define('体力', { min = -999999, max = '体力上限' })   -- 体力可为负、写值钳到上限

game:on('游戏-开始', function ()          -- 挂时机（分类-动作）：这个时机没有事件参数，上下文是空表
    local deck = game:createZone('抽牌', true)   -- 公共牌区挂局上（第二个参数 = 需要有顺序能力）
    deck:put(game:createCard('杀'))                 -- 牌由局建（牌名进不透明标签）
    deck:shuffle()                                 -- 有序牌区洗牌不用再传随机源
end)

local slash = Card '杀'
    : on('生效', function (ctx) end)    -- 钩子是固定集合（见 §9.2）：'获取目标' / '生效'
```

- 入口：**装载器 `moe.loader`**（`server/core/loader/`）+ **局 `moe.game`**（`server/core/game.lua`）：`moe.game.create { desk, random, sources?, packages }` 建**一局**并把规则装好（**建局即装**，清单省略就只装默认加载的包），重装走 `moe.loader.install(game, { packages = 清单 })`（省略参数就复用局上记的来源与清单）；内容放在项目根 `package/` 下、**按包组织**（`package/标准/…`、`package/军争/…`）。
- **来源与合并**：可配置多个来源（`moe.loader.install(game, { sources = { './package/*', 'D:/某合集/*' } })`）；来源里**后面的覆盖前面的**，同一逻辑路径只执行最后一个来源的那个文件（用户自定义包就是靠这个替换标准包的文件）。逻辑路径第一层恒为包目录名。
- **清单项是逻辑路径**（如 `标准/卡牌/杀`）：先按文件解释（`.lua` 可省），不存在再按目录解释（递归、只取 `.lua`）；清单是唯一入口（加进去即生效，移除即失效）。
- **依赖用路径写、写在文件顶部**，并**支持相对路径**：`Depends { './卡牌/杀' }`、`Depends { '../../基础规则/回合流程' }`。- **互斥**：`Depends { '!国战' }` 表示本轮不能加载该项（模式之间互斥靠它）；项与依赖项同一套路径解析（含相对路径），没被加载就不报错，冲突时在**执行任何文件之前**报错。- **包与名字路由**：包名 = 逻辑路径第一层目录；`package/军争/卡牌/火杀.lua` 里写 `Card '火杀'` 登记为 `军争.火杀`。**同包内不许重复声明**（两处建同名条目直接报错），跨包同名合法并存。
- **默认加载标记**：包目录名以 `@` 开头（`package/@基础`）⇒ 该包自动加载（清单不用写它，且排在最前），引用时**一律写不带 `@` 的名字**：`Depends { '../基础' }`、限定名 `基础.杀`、`game:getPackageMeta('基础')`。
- **裸名带包内作用域**：包内写裸名**先取本包**，本包没有才按清单顺序取第一个定义它的包；**引用他包的同名条目必须写限定名**（军争里想用标准版「杀」要写 `标准.杀`）。包外（游戏运行期）的裸名直接按清单顺序取先加载的包。
- **跨文件给同一条定义追加回调**：先 `Depends { '../卡牌/杀' }` 保证顺序，再 `game:getCard('杀'):on(...)` —— **不能用 `Card` 再声明一次**。
- 条目带 `name` / `package` / `fullName` / `source`（声明它的文件），报错与排查时直接用。
- **挂时机**：`game:on('游戏-开始', function (ctx) ... end)` —— 注册顺序即执行顺序（后注册的后执行，写下的状态覆盖先前的，所以“覆盖别人的默认值”也靠它——例：身份场把主公体力上限抬 1）；订阅随每次装载清空（`game:on` 不限于加载期，但内核 / 装配的长期簿记别挂它上面）；**内容包不要主动 `game:fire`**（触发是装配 / 流程代码的事）。
- **规则数值**：`game:setValue(名字, 值)` / `game:setValues { ... }` 落默认值，读用 `game:getValue(名字)`（没设置得到 `nil`，自己写 `or 默认`）；**挂在局上一张表、按加载顺序后者覆盖前者**（这就是后续包改默认值的正道），与规则表同生命周期。**不要往里存函数**：行为写时机注册。
- **注入面是 `game`（这一局）与 `Card` / `Depends`（加载期环境函数，大写）、`util`（收窄的纯函数工具集，小写）**：内核门面 `moe`（含 `moe.core` 这类写法）、`require` / `io` / `os` 都拿不到。包需要的内核资源全从 `game` 取：**属性系统**用 `game:getAttributeSystem()`，**这一局的牌 / 牌区 / 桌子 / 随机源**用 `game:createCard(name)` / `game:createZone(名字, 有序?)` / `game.desk` / `game.random`（**只认字段，没有 getter**）。
- **工具集只给纯函数**：`util.filter(列表, 判定)` / `util.map(列表, 变换)` / `util.contains(列表, 值)` —— 它是 `server/core/loader/env-util.lua` 里**收窄**的一份，不是内核工具库本体（`moe.util` 里还有 `saveFile` / `defer` 这类副作用，拿不到）；清单与签名以那个文件为准。
- **接口面在哪（包作者视角）**：`server/core/loader/env-meta.lua` 是纯类型文件，声明了注入的 `game` / `Card` / `Depends` 与每个时机的 `ctx` 类型 —— 新增时机要顺手补一条。**不提供可单独分发的 meta**（引用链横跨 `Game` / `Moe` / `moe` / `bee`，单独导出不完整）：第三方开发者**直接打开本工程**写包，包目录写进来源清单即可。
- **不要为空值防御**：注入的 `game` 按约定一定在（它就是这一局）；只有**真的会缺**的才 `error` —— 例如清单里可能没有内容包（⇒ 没牌表）、人数不在身份配置表里。详见 `moe-kill-dev` 的 `references/code-style.md` 第 9 节。
- **属性定义只能在加载期写**：属性系统由**这一局**持有（一局一份，清空重装时重置），属性库把定义编译成生成函数、**编译后不允许再 `define`**（会在运行期报 `Cannot define new attributes after compilation`）⇒ `define` 写在包文件顶层，别写进「游戏-开始」回调。玩家侧读写用 `player:setAttr / getAttr / addAttr`（等价于 `player:getAttributes():set/get/add`）。
- **公共牌区与玩家牌区的分工**：抽牌 / 弃牌 / 处理这类**公共区域**用 `game:createZone(名字, 有序?)`（按名字登记，之后 `game:getZone(名字)` 取回）；手牌 / 装备 / 判定这类**属于某个玩家**的牌区用 `player:addZone(名字)`。
- 文件里**不需要 `require`**：装载器注入 `game` / `Card` / `Depends` / `util` + 一份标准库白名单（`require` / `io` / `os` 一律没有）。
- **中文标识符只留给难翻译的内容名**（技能名 / 卡牌名 / 身份名，以及规则数值的键与属性名），**字段名 / 局部变量 / 函数名一律英文**（如 `local slash = Card '杀'`）；中文标识符本身是构建期给 Lua 打的补丁（见 `moe-kill-dev` 的 `references/infrastructure.md`），关键字与 ASCII 标识符行为不变。
- 重装 = **清空局上的内容 + 重新加载**（不做按名单卸载，桌子 / 随机源 / 牌区不被清掉）；同一份清单重复加载会**重新执行**所有文件。加载、依赖、定义入口的细节见 `moe-kill-dev` 的 `references/architecture.md` 第 9 节，契约见 `server/test/rule/` 下的规则侧套件（规格快照已冻结）。

### 9.2 第一张牌：「杀」与响应（已落地）

```lua
-- package/标准/卡牌/杀.lua
-- 【杀】（标准版）
-- 出牌阶段，对你攻击范围内的一名其他角色使用：该角色需打出一张【闪】来抵消，否则受到你造成的 1 点伤害。

Card '杀'
    : on('获取目标', function (ctx)              -- 合法目标由牌自己声明：内核不作任何具体判定
        local desk  = game.desk
        local range = ctx.user:getAttr('攻击范围')
        return util.filter(desk.alivePlayers, function (player)
            return player ~= ctx.user
               and desk:getDistance(ctx.user, player) <= range
        end)                                 -- 空列表 = 现在用不了
    end)
    : on('生效', function (ctx)                  -- 每个目标各跑一次
        local target = ctx.target
        local card   = game:askCard(target, '打出', { name = '闪' }).result    -- 要一张牌：缘由「打出」，出来的牌读 .result
        if card then                                                    -- 基础规则已按缘由让这张牌经处理进弃牌（'卡牌-答复'）
            return                                                      -- 有闪就不受伤
        end
        game:damage(ctx.user, target, 1)     -- 伤害入口：写体力 + 触发伤害前 / 后时机
    end)
```

- **流程怎么被启动**（2026-09-21 落地）：回合流程是**内容**（`package/@基础/回合.lua` 在加载期 `game:registerFlow(function () ... end)`），由**装配侧**用 `game:runFlow()` 启动（无头测试 / 将来的房间 / 会话）—— 返回的是**任务**（`moe.task`）：可 `await` 等这局跑完、`.result` / `.err` 读结果与失败、`cancel()` 停掉；**流程不是效果**（不进记牌器 —— 它跑得比谁都长，进了就把真结算全挤成子效果）。内容包拿不到 `moe`，自己起不了协程，所以“谁启动”必须由装配侧来。
- **用牌入口**：`game:useCard(使用者, 牌, 目标们)` —— 机制自己在**使用者名下牌区**里找到这张牌（内核不预设「手牌」这类区域名），**校验全部通过才取出**并结算；校验不通过时报错且牌留在原处。
- **目标口径（fail-closed）**：调用方给出的目标必须是牌声明的**合法目标列表的非空子集**（`{}` 也不行）；牌**没声明 `'获取目标'` 钩子 / 钩子没返回列表 / 列表为空** ⇒ 这张牌**现在用不了**（明确失败、牌留在原处），漏写钩子 MUST NOT 被当成「谁都能打」；同一张牌声明多个钩子时取**交集**（每个声明只能收窄）。
- **内容侧事件名（牌的钩子）**：`'获取目标'`（返回合法目标列表 `Player[]`）与 `'生效'`（对**每个目标**各调一次，按目标在行动顺序上先后；同一张牌为同一目标声明多个钩子时按声明顺序执行），`'生效'` 的上下文是**对该目标的那一次生效**（`CardEffect`，字段 `user` / `card` / `target`）。钩子是**固定集合**（与启用的包无关、没有扩展需求）：清单以 `server/core/loader/env-meta.lua` 为准，拼错在编辑期就报 —— 新加钩子要同步补进那里。
- **响应（打出）**：【杀】的每个目标在生效时问一次「要一张【闪】」（`game:askCard(target, '打出', { name = '闪' })` —— **缘由**告诉规则层"这次要的牌是打出去的"，要什么牌由内容侧定）；拿到了就结束这次生效，没人答上（`ask.result` 为空）则照常造成伤害。**应答方不在内核里**：谁收到询问、怎么给出牌，由挂在局上 `'卡牌-询问'` 时机的那些订阅者决定（测试是脚本，将来是匹配系统 / 前端）。
- **牌的去向**：内容包**不写 `moveCard`** —— 基础规则分在两个文件里：`使用.lua`（`'卡牌-结算前'` → `处理`、`'卡牌-结算后'` → `弃牌`，用过的牌）、`打出.lua`（`'卡牌-答复'` → `处理`、`'卡牌-答复后'` → `弃牌`，缘由是「打出」的答复）。
- **区域名是内容侧约定**：`手牌`（玩家侧）与 `抽牌` / `弃牌` / `处理`（局侧）都由 `@基础` 建；内核只按名字登记牌区。**区名不带尾巴**（不写「抽牌堆 / 弃牌堆 / 处理区」这类最后那个字，用户 2026-09-20 定）。
- **本批不做**：目标数量（至多 / 至少 N 个）、**「出牌阶段限一次」这类次数限制**（回合流程已落地，但【杀】本批不限次数）、濒死与死亡、装备、判定、无懈可击、八卦阵 / 龙肝这类"同一响应窗口里的多个候选技能"。

### 9.4 濒死与【桃】（已落地）

```lua
-- package/@基础/濒死.lua
game:on('游戏-开始', function ()
    for _, player in ipairs(game.desk.players) do
        local attributes = player:getAttributes()
        local pending    = nil
        attributes:onChange('体力', function (_, value, last)   -- 回调签名：(instance, newValue, oldValue)
            if player:isAlive() and value <= 0 and last > 0 then
                pending = game:enterDying(player)                -- 记账：等这次结算收尾才起濒死
            elseif pending and value > 0 then
                pending()                                        -- 又回正了 ⇒ 撤销
                pending = nil
            end
        end)
    end
end)

game:on('濒死', function (dying)                                 -- 求桃从这里开始
    local player  = dying.player
    local current = player
    while player:getAttr('体力') < 1 do
        local card = game:askCard(current, '使用', { name = '桃' }).result
        if card then
            game:useCard(current, card, { player })              -- 缘由 '使用' ⇒ 基础规则不动它，正好交给 useCard
        else
            current = assert(game.desk:getNext(current))         -- 按行动顺序问下一位
            if current == player then
                break                                            -- 一圈问完没人给
            end
        end
    end
    if player:getAttr('体力') < 1 then
        player:setAlive(false)                                   -- 真死（触发 '玩家-死亡'）
    end
end)
```

```lua
-- package/标准/卡牌/桃.lua
-- 【桃】（标准版）
-- 出牌阶段，对自己使用：回复 1 点体力；或令一名处于濒死状态的角色回复 1 点体力。
Card '桃'
    : on('获取目标', function (ctx) ... end)   -- 已受伤（未满）的自己 + 体力 ≤0 的存活角色
    : on('生效', function (ctx) game:heal(ctx.target, 1) end)
```

- **内核只提供两样**：`Dying : Effect`（`settle()` 只触发 `'濒死'`）与 `game:enterDying(player)`（记账 + 返回撤销；不在结算里时当场起）。**判死阈值（≥1）与求桃都在规则里** —— 内核不认识生命值属性。
- **濒死插在哪一刻**：`Effect:apply()` 里结算体跑完之后（`game:flushDying()`）⇒ **「受到伤害后」类技能（郭嘉遗计 / 曹操奸雄）先跑、濒死随后**；逐目标结算时天然逐目标处理。
- **【桃】两种用法都是「使用」**（官方描述：出牌阶段对自己 / 濒死时令濒死角色回复）⇒ 求桃拿到牌后直接 `game:useCard`，桃的效果与去向都只写一处。
- **求桃的一圈**：从濒死者开始、`desk:getNext` 绕一圈（自动跳过阵亡者）；同一个人可以连给多张（1 点不够就继续问）；体力 ≥1 立刻停。
- **回复**：`Heal : Effect` + `game:heal(目标, 点数)`，与伤害对称（只发 `'回复-前'` / `'回复-生效'` / `'回复-后'`，加体力写在 `@基础/回复.lua`）。
- **还没做**：死亡奖惩与胜负判定（人死后除了 `'玩家-死亡'` 没有别的后果）、濒死中连锁的特殊处理。

### 9.5 常用动作：抽牌（以及"动作该怎么给大家用"）

```lua
-- 任何包、任何地方：让某个人摸 3 张
game:draw(player, 3)
```

- **内核只发时机**：`Draw : Effect`（`kind` = `draw`，字段 `player` / `count`）在 `settle()` 里只触发 **`'摸牌'`**；**真取牌写在 `package/@基础/抽牌.lua`**（`@基础` 是默认加载包 ⇒ 任何局都有它）：从 `抽牌` **逐张**取顶 → 牌堆不够时把 `弃牌` 全部洗回（`moveCard` + `shuffle`，用局上的随机源）→ **整批**一次 `game:moveCard` 进该玩家的 `手牌`；牌堆与弃牌都空时能摸多少算多少（不报错）。
- **摸牌阶段用的是同一个入口**（`package/@基础/回合.lua` 里 `game:draw(player, 2)`）⇒ 常用动作**只有一份实现**，其它包（【无中生有】、将来的【遗计】）也写 `game:draw(player, n)`。
- **约定（用户 2026-09-21 定）**：凡「抽牌 / 弃置 / 获得 / 判定」这类会被多处复用的动作 —— ① 内核给**一个效果 + 一个入口**（可 await、进效果链、失败读 `.err`）；② 语义（区名、洗回、阈值、顺序）写在 `@基础` 的**同名文件**里，通常就是订阅该动作的那个时机；③ **不预造"动作注册表"**，要替换整个动作时再单独谈（覆盖手段目前是"改状态 + 注册顺序"）。
