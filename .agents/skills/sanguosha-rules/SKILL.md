# 三国杀规则（项目口径）

本文件是规则侧的事实来源，供实现与评审使用。**口径状态：预研，未最终确认**（见文末「待确认口径」）。
任何实现若与「待确认口径」冲突，先问用户，不要自行选定规则版本。

## 1. 模式与身份配置

本工程先做**身份场**（单机，AI 补齐人数），暂不做国战 / 3v3 / 斗地主等其它模式。

| 人数 | 主公 | 忠臣 | 反贼 | 内奸 |
| --- | --- | --- | --- | --- |
| 4 | 1 | 1 | 1 | 1 |
| 5 | 1 | 1 | 2 | 1 |
| 6 | 1 | 1 | 3 | 1 |
| 7 | 1 | 2 | 3 | 1 |
| 8 | 1 | 2 | 4 | 1 |
| 9 | 1 | 3 | 4 | 1 |
| 10 | 1 | 3 | 5 | 1 |

- 先手（第一回合）由主公开始；身份牌除主公外均隐藏。
- 体力上限：主公在标准规则下**体力上限 +1**（人数相关变体另计）。

## 2. 胜负与奖惩

- 主公 + 忠臣：消灭所有反贼与内奸。
- 反贼：杀死主公（主公死亡时若反贼已全灭，仍由反贼胜）。
- 内奸：成为最后的存活者，且必须与主公单挑后杀死主公；内奸与反贼同归于尽时反贼胜。
- 奖惩：
  - 任意角色杀死反贼 → 摸 3 张牌。
  - 主公杀死忠臣 → 主公弃置其所有手牌与装备牌。

## 3. 回合流程

```
准备阶段 → 判定阶段 → 摸牌阶段 → 出牌阶段 → 弃牌阶段 → 结束阶段
```

| 阶段 | 内容 |
| --- | --- |
| 准备阶段 | 回合开始时点的技能结算 |
| 判定阶段 | 逆序结算判定区内的延时锦囊（后入先出） |
| 摸牌阶段 | 默认摸 2 张 |
| 出牌阶段 | 使用牌；默认「杀」限一次 |
| 弃牌阶段 | 手牌数须降至当前体力值 |
| 结束阶段 | 回合结束时的技能结算 |

每个阶段本身也是**时机**（有「阶段开始时 / 结束时」的触发点），技能可挂在阶段前后。

## 4. 牌的分类

| 类别 | 代表牌 | 说明 |
| --- | --- | --- |
| 基本牌 | 杀、闪、桃 | 军争篇另有 酒、火杀、雷杀 |
| 锦囊（即时） | 过河拆桥、顺手牵羊、无中生有、决斗、借刀杀人、桃园结义、南蛮入侵、万箭齐发、五谷丰登、无懈可击 | 立即结算 |
| 锦囊（延时） | 乐不思蜀、兵粮寸断、闪电 | 置入目标判定区，其判定阶段结算 |
| 装备 | 武器、防具、+1 马、-1 马 | 装备区各槽位各一 |

## 5. 距离与攻击范围

- **座位距离**：沿桌面两个方向取较小值，最小为 1。
- **距离修正**：目标装备 +1 马 → 距离 +1；自己装备 -1 马 → 距离 -1；结算后距离仍**最小为 1**。
- **攻击范围**：默认 1，由武器决定；与「距离」是两个独立概念。
- 距离与范围是**动态计算**（技能、装备均可改），必须作为求值函数而非缓存字段。

## 6. 「使用」与「打出」

这两个是不同的动作，不能合并实现：

- **使用**：出牌阶段主动使用牌（杀、锦囊、装备……）。
- **打出**：为响应而使用（闪响应杀、杀响应决斗/南蛮/万箭、桃用于濒死救援）。
- 打出**不触发**「使用时」的技能；结算时机的差异是技能系统的关键区分点。

## 7. 结算时序与插入

- 锦囊结算：先检查目标合法性，再**从使用者的下家开始按行动顺序逐个结算目标**。
- **无懈可击**可在任意锦囊生效前使用，且可被另一张无懈可击抵消（可嵌套）。
- **濒死**：体力降至 ≤ 0 时立即插入濒死结算，从当前回合角色开始按行动顺序询问是否使用桃。
- **死亡**：濒死结算失败后死亡，插入死亡结算 → 奖惩 → 胜负判定 → 可能立即结束游戏。
- 以上都要求引擎具备**结算栈**：结算过程中可以压入新的结算，处理完再回到原处继续。

## 8. 时机系统（实现要点）

- 所有可变行为收敛为「时机（时机名 + 相关对象）→ 查询可触发技能 → 依序执行 → 可能请求玩家决策」。
- 技能分：触发技（被动，挂时机）、主动技（出牌阶段主动发动）、锁定技（必发，不可放弃）。
- **技能可以在任意时机插入**，因此引擎必须支持**挂起 / 恢复**：遇到需要玩家决策的点就让出，等输入后再继续，而不是一路跑到底的函数调用。
- 建议：时机名集中定义成一张表（类似 `phase.before` / `damage.after` 的枚举），技能只注册到时机名，不硬编码在流程代码里。
- **落地机制（已实现）**：规则集用 `rule:on(时机名, function (ctx) ... end)` 注册、`rule:fire(时机名, ctx)` 触发（时机名**不预设**，注册顺序即执行顺序，注册随清空重载清空；详见 `moe-kill-dev` 的 `references/architecture.md` 第 10 节）。
- 要"覆盖"别人的效果就改**状态**（写标签 / 改属性 / 加标记），不做"回调返回值改事件载荷"那一套。

## 9. 对实现的结构性约束

1. 引擎是**纯逻辑**，不依赖 IO / jsonrpc；随机数必须可注入（固定 seed 可复现整局）。**内核（`server/core/`）不含任何游戏流程，也不预设区域名与属性名**——手牌区/装备区/体力 这些都在 `package/` 规则集里定义。
2. 决策点统一走「请求输入 → 挂起 → 恢复」，**挂起的持有者是 Room 内部**（`server/session/` 的会话外壳只当容器；Room 内封装它是后续批次），无头测试与前端走同一条路径（只是输入来源不同）。
3. 一次操作产生的表现需求（动画/音效）由后端输出为**事件流**，前端只消费，不反推状态。
4. 前端不参与任何规则判断：目标合法性、距离、可用牌列表**全部由后端计算并下发**。
5. 规则集**不参与开发期热重载**：`package/` 由自建加载器**读文件执行**（不走 `require` / `include`），所以改卡牌 / 技能代码要生效，得走**业务侧清空重载**（`moe.rule.load` 重新跑清单）或重启进程。因此：需要跨重载存活的数据（如牌的唯一 ID）必须挂在**内核的类表 / 门面表**上，不要指望规则集文件里的 `local`。
6. **「规则集重载」是游戏业务功能，与开发期「热重载」是两个不同的东西**（用户 2026-09-19 明确要求）：前者是**运行期**重新装置/切换规则集（清空规则表 + 重新加载，触发者在业务侧），后者是**开发期**改代码不重启（触发者在开发者）。两者定位、生命周期与影响范围不同，**不要互相替代或混为一谈**（`moe.reload` 是后者，见 `moe-kill-dev` 的 `references/architecture.md` 第 8 节与第 9 节）。

### 9.1 规则集侧写法（已落地）

```lua
rule.depends { './基础规则/回合流程' }   -- 写在文件顶部：执行到该行时同步把依赖加载完

local 杀 = rule.card '杀'
    :on('使用', function () end)    -- 事件名与签名做「杀」时再定
```

- 入口：门面 `moe.rule`（`server/rule/`）；内容放在项目根 `package/` 下、**按包组织**（`package/标准/…`、`package/军争/…`）。
- **来源与合并**：可配置多个来源（`moe.rule.setRoots { './package/*', 'D:/某合集/*' }`）；来源里**后面的覆盖前面的**，同一逻辑路径只执行最后一个来源的那个文件（用户自定义包就是靠这个替换标准包的文件）。逻辑路径第一层恒为包目录名。
- **清单项是逻辑路径**（如 `标准/卡牌/杀`）：先按文件解释（`.lua` 可省），不存在再按目录解释（递归、只取 `.lua`）；清单是唯一入口（加进去即生效，移除即失效）。
- **依赖用路径写、写在文件顶部**，并**支持相对路径**：`rule.depends { './卡牌/杀' }`、`rule.depends { '../../基础规则/回合流程' }`。- **互斥**：`rule.depends { '!国战' }` 表示本轮不能加载该项（模式之间互斥靠它）；项与依赖项同一套路径解析（含相对路径），没被加载就不报错，冲突时在**执行任何文件之前**报错。- **包与名字路由**：包名 = 逻辑路径第一层目录；`package/军争/卡牌/火杀.lua` 里写 `rule.card '火杀'` 登记为 `军争.火杀`。**同包内不许重复声明**（两处建同名条目直接报错），跨包同名合法并存。
- **裸名带包内作用域**：包内写裸名**先取本包**，本包没有才按清单顺序取第一个定义它的包；**引用他包的同名条目必须写限定名**（军争里想用标准版「杀」要写 `标准.杀`）。包外（游戏运行期）的裸名直接按清单顺序取先加载的包。
- **跨文件给同一条定义追加回调**：先 `rule.depends { '../卡牌/杀' }` 保证顺序，再 `rule.getCard('杀'):on(...)` —— **不能用 `rule.card` 再声明一次**。
- 条目带 `name` / `package` / `fullName` / `source`（声明它的文件），报错与排查时直接用。
- **挂时机**：`rule:on('游戏开始', function (ctx) ... end)` —— 只在加载期可注册，注册顺序即执行顺序（后注册的后执行，写下的状态覆盖先前的）；**内容包不要主动 `rule:fire`**（触发是装配 / 流程代码的事）。
- 文件里**不需要 `require`**：加载器注入 `rule` + 一份标准库白名单（`require` / `io` / `os` 一律没有）。
- **可以用中文标识符**（如 `local 杀 = ...`、`local function 造成伤害(目标)`），这是构建期给 Lua 打的补丁（见 `moe-kill-dev` 的 `references/infrastructure.md`）；关键字与 ASCII 标识符行为不变。
- 重载 = **清空规则表 + 重新加载**（不做按名单卸载）；同一份清单重复加载会**重新执行**所有文件。加载、依赖、定义入口的细节见 `moe-kill-dev` 的 `references/architecture.md` 第 9 节，规格见 `openspec/specs/rule-loading/spec.md`。
