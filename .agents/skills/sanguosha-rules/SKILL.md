# 三国杀规则（项目口径）

本文件是规则侧的事实来源，供实现与评审使用。**口径状态：预研，未最终确认**（见文末「待确认口径」）。
任何实现若与「待确认口径」冲突，先问用户，不要自行选定规则版本。

## 1. 模式与身份配置

本工程先做**身份场**（单机，AI 补齐人数），暂不做国战 / 3v3 / 斗地主等其它模式。

| 人数 | 主公 | 忠臣 | 反贼 | 内奸 |
| --- | --- | --- | --- | --- |
| 4 | 1 | 1 | 1 | 1 |
| 5 | 1 | 1 | 2 | 1 |
| 6 | 1 | 1 | 3 | 1 |
| 7 | 1 | 2 | 3 | 1 |
| 8 | 1 | 2 | 4 | 1 |
| 9 | 1 | 3 | 4 | 1 |
| 10 | 1 | 3 | 5 | 1 |

- 先手（第一回合）由主公开始；身份牌除主公外均隐藏。
- 体力上限：主公在标准规则下**体力上限 +1**（人数相关变体另计）。

**已实现口径（`package/身份场/`）**：

- 配置表先做 **4~8 人**（上表前五行，`package/身份场/配置.lua` 以 `game:setValue('身份配置', ...)` 落进**规则数值**，所以后续包可覆盖）；9 / 10 人表等真要用时再补。
- **主公固定坐 1 号位**（简化假设），于是「按座位号递增」的行动顺序天然让主公首回合先手 —— 不需要给内核加「起始行动者」的概念。
- 身份写进玩家的**不透明标签**（`player:setTag('身份', ...)`）：内核只记录、不解释取值。
- 主公 +1 走**改体力上限**（`attrs:add('体力上限', 加成)`，加成取规则数值 `主公体力上限加成`），**不是**直接改体力值；因为基础包先把体力与上限都写成了默认值，身份场只需再“抬”一次，体力自然跟上。
- **规则数值里的 `默认体力` 是「无武将时的开局体力初值」**（`package/@基础/配置.lua` 里为 5）：它同时被用作战玩家的 `体力上限`，也是「主公 +1」的**基数**，所以现在必须留着（用户 2026-09-19 确认）；等**武将**接管上限后，它就只剩“武将没写时的兜底”一个用途，可以退休。
- **体力属性的边界（已实现）**：`体力` 下界为负（`-999999`，濒死结算要用）、上界写**字符串引用** `'体力上限'` ⇒ 写值会**钳到当前上限**；`体力上限` 自带 `0..999999`。抬上限**不会**自动加体力（所以主公那句「上限与体力各 +1」仍必要）。

## 2. 胜负与奖惩

- 主公 + 忠臣：消灭所有反贼与内奸。
- 反贼：杀死主公（主公死亡时若反贼已全灭，仍由反贼胜）。
- 内奸：成为最后的存活者，且必须与主公单挑后杀死主公；内奸与反贼同归于尽时反贼胜。
- 平局：**牌堆与弃牌堆都没有牌时，游戏平局**（用户 2026-09-23 定；官方口径）。
- 奖惩：
  - 任意角色杀死反贼 → 摸 3 张牌。
  - 主公杀死忠臣 → 主公弃置其所有手牌与装备牌。

**已实现**：胜负判定的判据写在 `package/身份场/胜负.lua`（订阅 `'玩家-死亡'` → `game:endGame { side, reason }`），详见 §9.6；**奖惩已落地**（`package/身份场/奖惩.lua`，靠 `Depends` 排在胜负判定**之前**，见 §9.7）—— 手牌与装备区的牌一起弃（装备批次落地后已能弃）。**平局也已落地**（牌堆耗尽 ⇒ 洗不回来，见 §9.6）。

## 3. 回合流程

```
准备阶段 → 判定阶段 → 摸牌阶段 → 出牌阶段 → 弃牌阶段 → 结束阶段
```

| 阶段 | 内容 |
| --- | --- |
| 准备阶段 | 回合开始时点的技能结算 |
| 判定阶段 | 逆序结算判定区内的延时锦囊（后入先出） |
| 摸牌阶段 | 默认摸 2 张 |
| 出牌阶段 | 使用牌；默认「杀」限一次 |
| 弃牌阶段 | 手牌数须降至当前体力值 |
| 结束阶段 | 回合结束时的技能结算 |

每个阶段本身也是**时机**（有「阶段开始时 / 结束时」的触发点），技能可挂在阶段前后。

- **已实现（2026-09-21；阶段收进内核 2026-09-22）**：回合流程在 `package/@基础/回合.lua`，加载期登记（`game:registerFlow`）、由装配侧 `game:runFlow()` 启动。六阶段依次走完：每个阶段用 `local _ <close> = game:enterPhase(回合角色, 阶段名)` 进、作用域结束自动出，进出各触发 `'阶段-开始'` / `'阶段-结束'`（**载荷 = 阶段实例**：`phase.player` / `phase.name`）；整段被 `'回合-开始'` / `'回合-结束'`（上下文 = 回合角色）包住；首回合主公（1 号位）、阵亡者跳过、只剩一个存活角色时流程结束。
  - **摸牌阶段**：摸 2 张（`抽牌` → 该玩家的 `手牌`）；抽牌不够时把 `弃牌` 洗混当新抽牌堆（用局上的随机源 ⇒ 同种子可复现）。
  - **出牌阶段**：向回合角色**要一张牌**（`game:askUseCard(回合角色, '出牌', { zone = '手牌' })` —— **要的是「使用」就调 `askUseCard`**（「使用」的语义由类型携带，不再靠缘由字符串）：内核逐张跑 `canUse` 把用不了的牌挡在候选项外、并给选项带上可用目标；`{ zone = '手牌' }` 再把候选限在手牌里。**筛到什么、为什么筛都在内核，业务层不手写候选**）—— 答复里带「用哪张 + 打给谁」（`ask.card` / `ask.targets`）就用牌并继续问，答不上 / 答复不在选项里就结束阶段。**默认「杀」每出牌阶段限一次**：限额写在**牌自己的定义**上（`Card '杀' : limit('出牌', 1)`），次数记在**阶段实例**上，判定是 **`game:canUse` 的内建条目**（用满就直接用不了、**不问内容侧**；不在自己的阶段里既不计数也不受限）。别的牌没声明限额 = 1000 次（事实上不限）。
    - 两种放宽口径都走阶段实例的接口：“此【杀】不计入次数” = `game.phase:addUseCount('杀', -1)`；“可以多用一次 / 本阶段无限次” = `addLimit('杀', 1)` / `addLimit('杀', 1000)`。
  - **弃牌阶段**：手牌数须降到**当前体力值**（询问，缘由 `'弃牌'`；弃不够或没答复 ⇒ 明确失败）；手牌没超就不问、不挪牌。
  - **本批不做**：判定区的结算（判定阶段只触发时机；**判定动作本身已落地**，见 §9.8）、装备与距离修正、濒死与胜负判定、出牌次数限制、延时锦囊与技能。

## 5. 距离与攻击范围

- **座位距离**：沿桌面两个方向取较小值，最小为 1。
- **距离修正**：目标装备 +1 马 → 距离 +1；自己装备 -1 马 → 距离 -1；结算后距离仍**最小为 1**。
- **攻击范围**：默认 1，由武器决定；与「距离」是两个独立概念。
- 距离与范围是**动态计算**（技能、装备均可改），必须作为求值函数而非缓存字段。
- **已实现（内核）**：`desk:getDistance(from, to)` 当场求值（只由两个座位号与座位总数决定、最小 1、不缓存成字段）—— **它只算座位距离，修正不由它管**。
- **已实现（基础规则，2026-09-24）**：修正走**属性**、求值在**内容侧** —— `进攻修正`（自己到别人，进攻马 `-1`）/ `防御修正`（别人到自己，防御马 `+1`）默认 0，装备牌**进槽时由类别基类的 `'进入区域'` 钩子**用 `player:addAttr` 加（它返回撤销函数）、**牌离开装备区自动撤**（`Card:withZone`，见 §9.11）；基础规则 `package/@基础/距离.lua` 的 `distance(from, to)` 把这三段加起来：座位距离 + 自己的 `进攻修正` + 对方的 `防御修正`，结算后仍**最小 1**（`杀` / `顺手牵羊` / `借刀杀人` 都用它）。技能改距离时同样加 `进攻修正`（如【马术】）。
- **已实现（基础规则）**：属性 `攻击范围` 默认 1（`package/@基础/攻击范围.lua` 开局写给每个玩家），武器的加成也走 `player:addAttr`、撤销同样随牌走；「够不够得着」由**内容包**把距离与它组合得出（见 §9.2 的「杀」）—— 内核不作任何具体判定。

## 6. 「使用」与「打出」

这两个是不同的动作，不能合并实现：

- **使用**：出牌阶段主动使用牌（杀、锦囊、装备……）。
- **打出**：为响应而使用（闪响应杀、杀响应决斗/南蛮/万箭、桃用于濒死救援）。
- 打出**不触发**「使用时」的技能；结算时机的差异是技能系统的关键区分点。
- **已实现（部分）**：**使用**这条链路跑通了（`game:useCard(使用者, 牌, 目标)` —— 目标可以是单个也可以是列表，**用不了就 `reject` 进 `.err`、牌还留在原处**）；**响应**用“要一张牌”表达 —— `game:askCard(被问者, 缘由, 条件?)`（要一次**使用**就换 `game:askUseCard`、要一张**打出**的牌就换 `game:askPlayCard`）（返回**询问实例**，应答方读 `ask.options` 拿到可选项、答复读 `.card` / `.targets`，**答复必须在选项里**否则拒收；条件里三个字段 `name` / `zone` / `card` 都是筛选条件（`askUseCard` 多一条 `target`），详见 `moe-kill-dev` 的 `references/architecture.md` 第 12 节；应答方挂在局上的 `'卡牌-询问'` 时机里）。**「打出」不是内核动作、而是询问的一个类别**：`askPlayCard` 的候选按条件筛、答复只有牌，**牌当场交出去**（进发起那次结算的临时处理区 ⇒ 收尾时进 `弃牌`）。具体见 §7 与 §9.2。【闪】已落地（响应）。

## 7. 结算时序与插入

- 锦囊结算：先检查目标合法性，再**从顺序锚点起按行动顺序逐个结算目标**（官方口径；锚点 = 当前回合角色，回合结束后是上一个回合角色，见 §9.4；使用者自己也在目标里时他就是第一个结算的）。
- **无懈可击**可在任意锦囊生效前使用，且可被另一张无懈可击抵消（可嵌套）。
- **濒死**：体力降至 ≤ 0 时插入濒死结算，**从顺序锚点开始**按逆时针方向绕一圈询问是否使用桃（**官方口径**，2026-09-23 改正；旧口径「从濒死者开始」已废）—— 回合内锚点就是当前回合角色，**回合结束后是上一个回合角色**（`game.turnPlayer or game.lastTurnPlayer`）。
- **死亡**：濒死结算失败后死亡，插入死亡结算 → 奖惩 → 胜负判定 → 可能立即结束游戏。**奖惩（§9.7）与胜负判定 / 结束（§9.6）都已落地**（`package/身份场/奖惩.lua` / `胜负.lua` + `game:endGame`）。
- 以上都要求引擎能**嵌套结算**：结算过程中可以起新的结算，处理完再回到原处继续。
- **已实现（部分）**：用牌与伤害都是**效果对象**（`UseCard : Effect` / `Damage : Effect`），每个效果由**自己的任务**驱动 —— `Effect:apply()` 是驱动点（「记父（当前正在结算的那个）→ 触发 `'即将生效'` → 自己结算」），`Effect:await()` 等它结完、`result` / `err` 就在效果上；局上留一个**只增的记牌器**（`game:getEffect()` = 最近发起过的根效果、`game:getEffects()` = 按发起顺序的快照 —— 记的是**发起过什么**，不是"正在结算什么"，内层效果不单独记），嵌套深度上限 **150 层**（`Effect.MAX_DEPTH`）—— 超了**不报错**：那一层以「取消」收尾（不算失败）+ 记一条 `warn`（实测再深（≈225）进程会直接没，所以阈值只能在安全区；"无限"的正解是回合时限 / 玩家停手），**失败不抛给调用方**（记 `.err`）；`Effect.parent` 就是**外层效果**（根效果为空），沿着它往上走能还原整条结算链 —— 注意它是**结算嵌套**、"这一下算谁的"归伤害自己的 `from`（两者可不同）。**伤害与回复的结算只发事件、自己不动体力**（2026-09-21 定）：`Damage:settle()` = `'伤害-前'` → `'伤害-生效'` → `'伤害-后'`（`Heal` 对称，三个时机的上下文都是这次伤害 / 回复的实例），**扣血在基础规则的 `@基础/伤害.lua`（`'伤害-生效'` 里）、回血在 `@基础/回复.lua`** —— 于是内核不认识任何属性名，将来**护甲 / 改伤害值 / 回复加成**都挂这两个文件；
  - **逐目标生效**：用牌的结算 = 「校验 → 取出牌 → 触发 `'卡牌-结算前'`（基础规则这时把牌放进这次用牌的临时区）→ **按行动顺序**（`desk:actionOrder(目标)`：从顺序锚点起绕一圈，轮回到自己就结束）对每个目标各结算一次**生效**（`CardEffect`，父效果 = 这次用牌；**钩子拿到 `(cardEffect, useCard)` 两个参数**）→ 全部处理完后触发 `'卡牌-结算后'`」。每个生效都是独立效果 ⇒ 有自己的「即将生效」、能被**单独取消**；前一个生效连同它引发的插入结算全部结束之后，才轮到下一个目标。
  - **取消**：效果执行自己的结算**之前**触发一次 `'即将生效'`（上下文 = 该效果实例，此刻它正是最近发起过的那个），订阅者调 `效果:remove()` 即**取消这一次生效**（不再结算、不算失败）；**作用域只到这一个效果** —— 不影响外层、也不影响同一张牌对其余目标的生效，且**只能由正在运行的那个效果自己发起**（在别处拿到实例再取消是空操作）。【闪】就是长在这个时机上。
  - **响应**：要一张牌用 `game:askCard(被问者, 缘由, 条件?)`（要一次使用用 `game:askUseCard(...)`）—— 询问走局上的 **`'卡牌-询问'` 时机**，应答方（无头测试注入的脚本、将来的匹配系统或前端）先读 `ask.options`（可选项：牌 + 这张牌的可用目标）再调 `ask:answer{ card = 那张牌 }`（要一次使用这类还要 `targets` —— 给单个或一张列表都行，**答复里的 `targets` 恒为列表**），**答复读 `ask.card` / `ask.targets`**（没人答上 / 被取消 / **答复不在选项里** ⇒ 不存在）。**缘由**（如 `'杀'` / `'出牌'` / `'濒死'`）是**内核不解释**的值，惯例是写**发起这次询问的牌名 / 阶段名**（与 `reason` 一样不参与判断）；**要的是「使用」还是「一张牌」由类表达**（`AskCard` / `AskUseCard` / `AskPlayCard`）；**条件**（第三个参数）描述"要什么样的牌"—— 四个字段 `name?` / `zone?` / `card?` / `target?` 都是**筛选条件**（数组 = 满足其一、单值 = 归一化、不填 = 无要求；候选默认来自被问者的牌区，`zone` / `card` 给了就换成那里）：**内核在询问前把 `ask.options` 算好**；**业务层不自己拼候选**，**不给条件 = 不做限制**。询问结束后还会连着触发 **`'卡牌-答复'`** 与 **`'卡牌-答复后'`**（**有答复才触发**；没人应答不触发 —— 表达"问了没人答"是另一个事件，将来加），基础规则在它们里按缘由接手 —— `'打出'` ⇒ 牌进**发起那次结算的临时区**，它的收尾送 `弃牌`；**结果在应答的那一刻就定下了，所以这个时机里 `askCard.card` 读得到给出的牌**。所以**业务层（内容包）不用自己挪牌**；**内核里没有「打出」动作**（没有 `game:respond`、也没有 `'卡牌-打出后'` 时机）—— "打出"只是内容侧对 `'打出'` 这个缘由的解释。
- **还没做**：无懈可击的嵌套响应、**判定区与延时锦囊**（判定动作本身已落地，见 §9.8）、**最后一种普通锦囊【无懈可击】**（其余 9 种已落地，见 §9.10，【借刀杀人】也在其中）、**防具**与**装备自带的技能**（武器 / 坐骑的「加成」已落地，见 §9.11）、改伤害值 / 防止伤害 / 属性伤害；**询问的异步答复与超时**（本批是当场取答案）。
- **【2026-09-21 已落地；2026-09-22 改成当场结 + 判死归内核】濒死与【桃】**：体力降到 ≤0 ⇒ **濒死结算**（`Dying : Effect`）—— 检查点在 `@基础/伤害.lua`（扣完血判 ≤0 就 `game:enterDying(受害者, 这次伤害)`），规则侧在 **`'濒死-进入'`** 里求桃；**没人把体力回正 ⇒ 内核在收尾时 `setAlive(false)`**（「濒死效果负责杀死玩家」），回血方（`@基础/回复.lua`）在体力 > 0 时喊 `dying:leave()`。**时序：濒死早于 `'伤害-后'`**（扣血 → 濒死（含判死 / 奖惩 / 胜负）→ 才轮到 `'伤害-后'`）；**内核只搬伤害**（不知道血量属性，也不再记 `'凶手'` 标签 —— 凶手读 `game:getDying(死者).damage.from`）；【桃】两种用法（出牌阶段对自己 / 濒死时对濒死角色）写在 `package/标准/卡牌/桃.lua`。详见 §9.4。
- **【2026-09-20 已落地】牌的自动去向**：`game:askCard(被问者, 缘由, 条件)` 的第二、三个参数分别是**缘由**与**条件**（要什么样的牌，内核据此算 `ask.options`）；**缘由完全不解释**（只原样带给规则层）⇒ 询问结束后局上触发 **`'卡牌-答复'`**。**打出的牌不用业务层操心**（2026-09-23 起）：`game:askPlayCard` 在答复定下的那一刻就把那张牌放进**发起那次结算的临时处理区**（收尾时进 `弃牌`）⇒ **业务层完全不写 `moveCard`**（【杀】的响应只读 `ask.card`、按结果决定是否受伤）。

  - **已落地的死亡最小形状**：`player:isAlive()` / `player:setAlive(false)`，从活变死时触发 **`'玩家-死亡'`**（上下文 = 这个玩家）；`desk.alivePlayers` 直接读“还活着的角色”；「参与行动」（`player.acting`）也已改成**由存活派生**（活着就参与，阵亡即退出行动顺序）。**濒死（§9.4）、死亡奖惩（§9.7）与胜负判定（§9.6）都已落地** —— 人死后依次发生：`'玩家-死亡'` → 奖惩（先注册）→ 胜负判定（后注册，可能直接把游戏判结束）；已阵亡的角色**摸不到牌**（`Draw` 直接完成）。

## 8. 时机系统（实现要点）

- 所有可变行为收敛为「时机（时机名 + 相关对象）→ 查询可触发技能 → 依序执行 → 可能请求玩家决策」。
- 技能分：触发技（被动，挂时机）、主动技（出牌阶段主动发动）、锁定技（必发，不可放弃）。
- **技能可以在任意时机插入**，因此引擎必须能在结算中途**停下来等人输入再继续**：遇到需要玩家决策的点就让出，等输入回来接着跑，而不是一路跑到底的函数调用。
- **建议：时机名用 `分类-动作` 风格**（`'游戏-开始'`、`'回合-开始'`、`'判定-前'`、`'伤害-后'`…）—— 前一段是分类、后一段是动作，便于把事件表按分类聚合；与“集中定义成一张枚举表”的初衷一致，但**不预设、不校验**（时机名仍是任意字符串，写法规约而已）。
- **落定机制（已实现）**：规则集用 `game:on(时机名, 回调)` 注册、装配 / 流程代码用 `game:fire(时机名, 载荷)` 触发（时机名**不预设**，注册顺序即执行顺序，注册随清空重装清空）。上下文**只装该时机的参数**（`'游戏-开始'` 没有参数 ⇒ 传空表），环境对象就是注入的 `game`（这一局的桌子 / 随机源 / 牌区都从它取）；**回调的载荷参数按它的具体类型取名**（`damage` / `askCard` / `phase` / `target` 这类，**别叫 `ctx`** —— 清单见 `moe-kill-dev` 的 `code-style.md` 第 8 节），每个时机的载荷类型写在 `server/core/loader/env-meta.lua`（纯类型文件，按事件名收窄字段类型；详见 `references/architecture.md` 第 10 节）。
- 载荷约定**只读**；加载期的回调**报错被隔离**（只记日志、不影响其它回调），所以“规则包出错”的可见信号是**状态没写**（如没写出牌堆），装配方要在 `fire` 之后断言必需状态。
- 要"覆盖"别人的效果就改**状态**（写标签 / 改属性 / 加标记），不做"回调返回值改事件载荷"那一套。

## 9. 对实现的结构性约束

1. 引擎是**纯逻辑**，不依赖 IO / jsonrpc；随机数必须可注入（固定 seed 可复现整局）。**内核（`server/core/`）不含任何游戏流程，也不预设区域名与属性名**——手牌区/装备区/体力 这些都在 `package/` 规则集里定义。
2. 决策点统一走「请求输入 → 挂起 → 恢复」，**挂起的持有者是流程内部**（`server/session/` 的会话外壳只当容器；在流程里封装它是后续批次），无头测试与前端走同一条路径（只是输入来源不同）。**整个游戏都在协程里跑**（用户 2026-09-21 确认）：装配方在协程里开局、触发 `'游戏-开始'`、启动流程，所以内容侧的时机钩子可以直接 `await`（放置走 `game:moveCard`、询问、用牌都是 await 点）。
3. 一次操作产生的表现需求（动画/音效）由后端输出为**事件流**，前端只消费，不反推状态。
4. 前端不参与任何规则判断：目标合法性、距离、可用牌列表**全部由后端计算并下发**。
5. 规则集**不参与开发期热重载**：`package/` 由自建装载器**读文件执行**（不走 `require` / `include`），所以改卡牌 / 技能代码要生效，得走**业务侧清空重装**（`moe.loader.install(game, { packages = 清单 })` 重新跑）或重启进程；**装载器与局这两份代码本身**（`server/core/loader/` 与 `server/core/game.lua`）与其它内核模块一样可热重载，已建好的局在重载后照常可用。因此：需要跨重载存活的数据必须挂在**跨重载仍是同一份的载体**上（这一局的数据挂局实例 `game`，如号源 `game:nextId()`；内核级、跨局的才挂门面表 `moe`），不要指望规则集文件里的 `local`。
6. **「规则集重载」是游戏业务功能，与开发期「热重载」是两个不同的东西**（用户 2026-09-19 明确要求）：前者是**运行期**重新装置 / 切换**这一局的**规则集（清空规则表 + 重新加载，触发者在业务侧），后者是**开发期**改代码不重启（触发者在开发者）。两者定位、生命周期与影响范围不同，**不要互相替代或混为一谈**（`moe.reload` 是后者，见 `moe-kill-dev` 的 `references/architecture.md` 第 8 节与第 9 节）。

### 9.1 规则集侧写法（已落地）

```lua
-- 默认包（`@基础`）由加载器自动装、且排在清单项之前 ⇒ **不必为它写 Depends**；
-- 只有依赖非默认包时才在文件顶部写，如 `Depends { '标准/卡牌/杀' }`

game:setValues { 默认体力 = 5 }               -- 规则数值：可被后续包覆盖的配置

local attributeSystem = game:getAttributeSystem()      -- 属性系统由这一局持有（包在加载期 define）
attributeSystem:define('体力上限', { min = 0, max = 999999 })
attributeSystem:define('体力', { min = -999999, max = '体力上限' })   -- 体力可为负、写值钳到上限

game:on('游戏-开始', function ()          -- 挂时机（分类-动作）：这个时机没有事件参数，上下文是空表
    local deck = game:createZone('抽牌', true)   -- 公共牌区挂局上（第二个参数 = 需要有顺序能力）
    deck:put(game:createCard('杀'))                 -- 牌由局建（牌名进不透明标签）
    deck:shuffle()                                 -- 有序牌区洗牌不用再传随机源
end)

local slash = Card '杀'
    : on('生效', function (cardEffect) end)    -- 钩子是固定集合（见 §9.2）：'进入区域' / '获取目标' / '结算前' / '生效' / '结算后'
```

- 入口：**装载器 `moe.loader`**（`server/core/loader/`）+ **局 `moe.game`**（`server/core/game.lua`）：`moe.game.create { seats, random, sources?, packages }` 建**一局**并把规则装好（**建局即装**，`seats` = 座位数、桌子由局自己建；清单省略就只装默认加载的包），重装走 `moe.loader.install(game, { packages = 清单 })`（省略参数就复用局上记的来源与清单）；内容放在项目根 `package/` 下、**按包组织**（`package/标准/…`、`package/军争/…`）。
- **来源与合并**：可配置多个来源（`moe.loader.install(game, { sources = { './package/*', 'D:/某合集/*' } })`）；来源里**后面的覆盖前面的**，同一逻辑路径只执行最后一个来源的那个文件（用户自定义包就是靠这个替换标准包的文件）。逻辑路径第一层恒为包目录名。
- **清单项是逻辑路径**（如 `标准/卡牌/杀`）：先按文件解释（`.lua` 可省），不存在再按目录解释（递归、只取 `.lua`）；清单是唯一入口（加进去即生效，移除即失效）。
- **依赖用路径写、写在文件顶部**，并**支持相对路径**：`Depends { './卡牌/杀' }`、`Depends { '../../基础规则/回合流程' }`。**默认包（`@` 开头，如 `@基础`）不必写** —— 加载器自动把它排在清单项之前（用户 2026-09-21 指出）。- **互斥**：`Depends { '!国战' }` 表示本轮不能加载该项（模式之间互斥靠它）；项与依赖项同一套路径解析（含相对路径），没被加载就不报错，冲突时在**执行任何文件之前**报错。- **包与名字路由**：包名 = 逻辑路径第一层目录；`package/军争/卡牌/火杀.lua` 里写 `Card '火杀'` 登记为 `军争.火杀`。**同包内不许重复声明**（两处建同名条目直接报错），跨包同名合法并存。
- **默认加载标记**：包目录名以 `@` 开头（`package/@基础`）⇒ 该包自动加载（清单不用写它，且排在最前），引用时**一律写不带 `@` 的名字**：限定名 `基础.杀`、`game:getPackageMeta('基础')`。
- **裸名带包内作用域**：包内写裸名**先取本包**，本包没有才按清单顺序取第一个定义它的包；**引用他包的同名条目必须写限定名**（军争里想用标准版「杀」要写 `标准.杀`）。包外（游戏运行期）的裸名直接按清单顺序取先加载的包。
- **跨文件给同一条定义追加回调**：先 `Depends { '../卡牌/杀' }` 保证顺序，再 `game:getCard('杀'):on(...)` —— **不能用 `Card` 再声明一次**。
- 条目带 `name` / `package` / `fullName` / `source`（声明它的文件），报错与排查时直接用。
- **挂时机**：`game:on('游戏-开始', function (event) ... end)` —— 注册顺序即执行顺序（后注册的后执行，写下的状态覆盖先前的，所以“覆盖别人的默认值”也靠它——例：身份场把主公体力上限抬 1）；订阅随每次装载清空（`game:on` 不限于加载期，但内核 / 装配的长期簿记别挂它上面）；**内容包不要主动 `game:fire`**（触发是装配 / 流程代码的事）。
- **规则数值**：`game:setValue(名字, 值)` / `game:setValues { ... }` 落默认值，读用 `game:getValue(名字)`（没设置得到 `nil`，自己写 `or 默认`）；**挂在局上一张表、按加载顺序后者覆盖前者**（这就是后续包改默认值的正道），与规则表同生命周期。**不要往里存函数**：行为写时机注册。
- **注入面是 `game`（这一局）与 `Card` / `Depends`（加载期环境函数，大写）**：内核门面 `moe`（含 `moe.core` 这类写法）、`require` / `io` / `os` 都拿不到。包需要的内核资源全从 `game` 取：**属性系统**用 `game:getAttributeSystem()`，**这一局的牌 / 牌区 / 桌子 / 随机源**用 `game:createCard(name)` / `game:createZone(名字, 有序?)` / `game.desk` / `game.random`（**只认字段，没有 getter**）。
- **工具集是对（内容侧）标准库的扩充**（用户 2026-09-21 定，不是内核注入的 —— 工具集与游戏规则无关）：默认包 `@tools` 往内容侧的 `table` 上加四个函数 —— `table.filter(列表, 判定)` / `table.map(列表, 变换)`（回调收 `(值, 下标)`）/ `table.contains(列表, 值)` / `table.without(列表, 值)`（去掉这个值的所有出现，**返回新列表**），清单以 `package/@tools/table.lua` 为准。**没装 `@tools` 的局仍然有 `table`，只是没有这三个函数**；助手写在沙箱里（`io` / `os` / `moe` 都够不着）⇒ 想写带副作用的助手也写不出来。
- **内容侧的标准库是副本**（用户 2026-09-21 定）：`table` / `string` / `math` / `utf8` 在每轮装载时各浅拷贝一份 ⇒ 内容侧给它们加函数 / 改函数**只影响内容侧**、内核不受影响，重装换新副本。**泛型要标在实体函数上**（`---@generic T` + `function table.filter(…)`）—— LuaLS 不支持 `---@field f fun<T>(…)`，写进 `meta.lua` 反而会把泛型压平。
- **包之间共享函数：直接写全局函数**（用户 2026-09-21 定）—— 整轮装载**共用一份书写环境**，所以 `function 是否受伤(player) ... end` 写在哪个文件里，后面的文件（含别的包）就能直接调。注意三点：**顺序敏感**（要用别人的函数就要求它先加载，可以用 `Depends` 定序）、**注入的 `game` / `Card` / `Depends` 每个文件加载前会刷回**（别拿它们当全局变量用；`table` 是内容侧的副本、没有这层保护）、**重装换新环境**（上一轮的全局与扩充自然消失）。沙箱没变：仍然看不到 `moe` / `require` / `io` / `os`。
- **接口面在哪（包作者视角）**：`server/core/loader/env-meta.lua` 是内核的纯类型文件，声明了注入的 `game` / `Card` / `Depends` 与每个时机的**载荷类型** —— 新增时机要顺手补一条；**包自己的概念**（身份、规则数值、自有标签）写在**包目录下的 `meta.lua`**（纯 LuaDoc，固定叫 `meta`）：

```lua
-- package/身份场/meta.lua：纯类型声明（不是规则内容，装载器照常当普通文件执行，里面只有注释）
---@meta
---@alias 身份场.身份 '主公'|'忠臣'|'反贼'|'内奸'
---@class Player: Class.Base                     -- 基类要写全
---@field getTag fun(self: Player, key: '身份'): 身份场.身份
---@field getTag fun(self: Player, key: string): any   -- 兜底必须自己再写一遍（否则会把内核签名吃掉）
```

  于是 `player:getTag('身份')` 收窄成四种身份的联合类型（拼错取值编辑期就报），`game:getValue('身份配置')` 也有了结构。**不提供可单独分发的 meta**（引用链横跨 `Game` / `Moe` / `moe` / `bee`，单独导出不完整）：第三方开发者**直接打开本工程**写包，包目录写进来源清单即可。
- **不要为空值防御**：注入的 `game` 按约定一定在（它就是这一局）；只有**真的会缺**的才 `error` —— 例如清单里可能没有内容包（⇒ 没牌表）、人数不在身份配置表里。详见 `moe-kill-dev` 的 `references/code-style.md` 第 9 节。
- **属性定义只能在加载期写**：属性系统由**这一局**持有（一局一份，清空重装时重置），属性库把定义编译成生成函数、**编译后不允许再 `define`**（会在运行期报 `Cannot define new attributes after compilation`）⇒ `define` 写在包文件顶层，别写进「游戏-开始」回调。玩家侧读写用 `player:setAttr / getAttr / addAttr`（前两个等价于 `getAttributes():set/get`；**`addAttr` 是 `getAttributes():addModifier` 的直接转发** —— 同样做增减，只是多返回一个「精确减掉这次加量」的撤销函数，不理它当单向增减用也没问题）。
- **牌区的建法**：**五个基础区由内核建好**（局上 `抽牌` / `弃牌`，玩家身上 `手牌` / `装备` / `判定`）—— 内容侧**直接取、不得重建**（`game:getZone('弃牌')` / `player:getZone('装备')`）；要加**自己**的区才用 `game:createZone(名字, 有序?)`（按名字登记、之后 `game:getZone(名字)` 取回）或 `player:addZone(名字)`，要顺序能力就传 `moe.orderedZone.create(局)` / 第二参数 `true`，要槽位就 `moe.slotZone.create(局)`（见 §9.11）。**自造牌区要带上局**（`moe.zone.create(局)` 之类 —— 牌区自己记着局，进区的牌才能按定义发 `'进入区域'`）。
- 文件里**不需要 `require`**：装载器注入 `game` / `Card` / `Depends` + 一份标准库白名单（`require` / `io` / `os` 一律没有；`table` / `string` / `math` / `utf8` 是内容侧的**副本**）；工具函数是默认包 `@tools` 给那份 `table` 加的。
- **中文标识符只留给难翻译的内容名**（技能名 / 卡牌名 / 身份名，以及规则数值的键与属性名），**字段名 / 局部变量 / 函数名一律英文**（如 `local slash = Card '杀'`）；中文标识符本身是构建期给 Lua 打的补丁（见 `moe-kill-dev` 的 `references/infrastructure.md`），关键字与 ASCII 标识符行为不变。
- 重装 = **清空局上的内容 + 重新加载**（不做按名单卸载，桌子 / 随机源 / 牌区不被清掉）；同一份清单重复加载会**重新执行**所有文件。加载、依赖、定义入口的细节见 `moe-kill-dev` 的 `references/architecture.md` 第 9 节，契约见 `server/test/rule/` 下的规则侧套件（规格快照已冻结）。

### 9.2 第一张牌：「杀」与响应（已落地）

```lua
-- package/标准/卡牌/杀.lua
-- 【杀】（标准版）
-- 出牌阶段，对你攻击范围内的一名其他角色使用：该角色需打出一张【闪】来抵消，否则受到你造成的 1 点伤害。

Card '杀'
    : extends '基本牌'                            -- 公共模板（@基础/卡牌/基本牌.lua）：分类「基本」+ 只能从手牌用
    : limit('出牌', 1)                            -- 每出牌阶段限一次：限额写在定义上（不写就是 1000 = 不限）
    : on('获取目标', function (target)         -- 合法目标由牌自己声明：内核不作任何具体判定
        local desk  = game.desk
        local range = target.user:getAttr('攻击范围')
        return table.filter(desk.alivePlayers, function (player)
            return player ~= target.user
               and desk:getDistance(target.user, player) <= range
        end)                                 -- 空列表 = 现在用不了
    end)
    : on('生效', function (cardEffect)         -- 每个目标各跑一次
        local target = cardEffect.target
        local card   = game:askPlayCard(target, '杀', { name = '闪' }).card  -- 要一张打出的牌：缘由 = 发起询问的牌名，条件「名字是闪」
        if card then                                                    -- 答复的牌已当场交进发起那次结算的临时区（收尾进弃牌）
            return                                                      -- 有闪就不受伤
        end
        game:damage(cardEffect.user, target, 1) -- 伤害入口：写体力 + 触发伤害前 / 后时机
    end)
```

- **流程怎么被启动**（2026-09-21 落地）：回合流程是**内容**（`package/@基础/回合.lua` 在加载期 `game:registerFlow(function () ... end)`），由**装配侧**用 `game:runFlow()` 启动（无头测试 / 将来的房间 / 会话）—— 返回的是**任务**（`moe.task`）：可 `await` 等这局跑完、`.result` / `.err` 读结果与失败、`cancel()` 停掉；**流程不是效果**（不进记牌器 —— 它跑得比谁都长，进了就把真结算全挤成子效果）。内容包拿不到 `moe`，自己起不了协程，所以“谁启动”必须由装配侧来。
- **定义上的三件套**（2026-09-22 落地；分类口径 2026-09-23 改成覆盖）：`kind`（**分类**，内核只记录、不解释；取值省略「牌」字 —— 基本 / 锦囊 / 装备。**一次调用就把分类定下来**：要多个就给一张列表 `: kind { '锦囊', '延时锦囊' }`，**重复调以后写的为准**（不再累加）；**要「在基类分类之上再补一条」就用 `addKind`**（2026-09-24 补上 —— 它只往里加、已有的不动，`kind` 则是覆盖）、`zone`（**必须从哪个牌区用**，由 `canUse` 的内建条目判：不声明 = 使用者的任一牌区都行）、`extends`（把基类定义的**钩子与字段抄**过来：基类的钩子跑在前面、**分类拄过来也是覆盖**（基类没声明分类就不动子定义自己的）、抄完即与基类脱钩）。公共模板写在默认包里（`package/@基础/卡牌/` 下的 `基本牌.lua` 就一句 `Card '基本牌' : kind '基本' : zone '手牌'`，它不在牌表里、不会被真的造出来），具体牌 `: extends '基本牌'` 继承即可。**类基类文件的加载顺序要自己声明**（同一目录按名字排序，`武器牌.lua` 排在 `装备牌.lua` 前面 ⇒ 写 `Depends { './装备牌' }`）。
- **用牌入口**：`game:useCard(使用者, 牌, 目标们)` —— 机制自己在**使用者名下牌区**里找到这张牌（内核不预设「手牌」这类区域名），**校验全部通过才取出**并结算；校验不通过（内建条目（含**次数**）或内容侧的 `'卡牌-能否使用'`）⇒ 这次生效**以「不成立」收尾**（`.err` = 原因、**不报错、不取牌、不记账**）；过了就由内核在阶段上记一次。筛选与二次校验共用同一个 `game:canUse`（见 `moe-kill-dev` 的 `architecture.md` §12）。
- **目标口径（fail-closed）**：调用方给出的目标必须是牌声明的**合法目标列表的非空子集**（`{}` 也不行）；牌**没声明 `'获取目标'` 钩子 / 钩子没返回列表 / 列表为空** ⇒ 这张牌**现在用不了**（明确失败、牌留在原处），漏写钩子 MUST NOT 被当成「谁都能打」；同一张牌声明多个钩子时取**交集**（每个声明只能收窄）。
- **内容侧事件名（牌的钩子）**：`'获取目标'`（返回合法目标列表 `Player[]`）与 `'生效'`（对**每个目标**各调一次，按目标在行动顺序上先后；同一张牌为同一目标声明多个钩子时按声明顺序执行）；另有**各只跑一次**的 `'结算前'` / `'结算后'`（载荷 = 这次用牌的效果实例，分别在使用结算开始时 / 全部生效之后；夹在全局 `'卡牌-结算前'` / `'卡牌-结算后'` 内侧），以及 **`'进入区域'`**（载荷 `(card, zone, slot)`：牌**落进某个牌区之后**由那个区发 —— 玩家身上三个区与公共区（抽牌 / 弃牌 / 临时区）都发，`slot` 只有进槽位区时才有；不是「使用」的一环，装备的加成靠它加 —— 见 §9.11）。`'生效'` 的钩子拿**两个参数** `(cardEffect, useCard)`：前者是对该目标的那一次生效（`CardEffect`，字段 `user` / `card` / `target`），后者是**这次用牌**（要临时区直接 `useCard:getTempZone()`）。钩子是**固定集合**（与启用的包无关、没有扩展需求）：清单以 `server/core/loader/env-meta.lua` 为准，拼错在编辑期就报 —— 新加钩子要同步补进那里。钩子里的 `card` **能直接读自己的分类与数据**（`card:isKind('武器')` / `card:getValue('攻击范围')` / `card.fullName` —— 牌自己记着局，见 §9.11）。
- **响应（打出）**：【杀】的每个目标在生效时问一次「要一张【闪】」（`game:askPlayCard(target, '杀', { name = '闪' })` —— 类告诉内核“这次要的是**打出去的**牌”，**条件**说“名字是闪”）；拿到了就结束这次生效，没人答上 / 答的不是选项里的牌（`ask.card` 为空）则照常造成伤害。**应答方不在内核里**：谁收到询问、怎么给出牌，由挂在局上 `'卡牌-询问'` 时机的那些订阅者决定（测试是脚本，将来是匹配系统 / 前端），**它们读 `ask.options` 拿可选项**（内核已经按条件算好了）。
- **牌的去向**：内容包**不写 `moveCard`** —— 用过的牌由 `@基础/使用.lua` 在 `'卡牌-结算前'` 放进**这次用牌的临时区**；打出的牌由 `AskPlayCard` 在答复定下时放进**发起那次结算的临时区** —— 两处都只写「放进哪块临时区」，**去向由内核一处收尾**（效果结完时把临时区剩下的牌送 `弃牌`，2026-09-24 起；见 `moe-kill-dev` 的 `references/architecture.md` 第 12 节）。
- **区域名：五个基础区由内核建**（2026-09-24 起）—— 局上 `抽牌` / `弃牌`、玩家身上 `手牌` / `装备` / `判定`；内容侧直接取（`game:getZone('弃牌')` / `player:getZone('手牌')`），**不得重建同名区**；要加自己的区才用 `game:createZone` / `player:addZone`。**区名不带尾巴**（不写「抽牌堆 / 弃牌堆」这类最后那个字，用户 2026-09-20 定）。
- **本批不做**：目标数量（至多 / 至少 N 个）、濒死与死亡、装备、判定、无懈可击、八卦阵 / 龙肝这类"同一响应窗口里的多个候选技能"。

### 9.4 濒死与【桃】（已落地）

```lua
-- package/@基础/伤害.lua：扣完血判一下就进濒死（内部转交给内核，早于 '伤害-后'）
game:on('伤害-生效', function (damage)
    local to = damage.to
    to:addAttr('体力', -damage.amount)
    if to:getAttr('体力') <= 0 then
        game:enterDying(to, damage)                             -- 当场结算；damage 一并交出去
    end
end)

-- package/@基础/濒死.lua：只管一件事 —— 从濒死者开始绕圈求桃（判死不在这里）
game:on('濒死-进入', function (dying)                             -- 上下文 = Dying 实例
    local player  = dying.player
    local start   = assert(game.turnPlayer or game.lastTurnPlayer)   -- 顺序锚点：回合内是当前回合角色，回合结束后是上一个
    local current = start
    while player:getAttr('体力') < 1 do
        local card = game:askUseCard(current, '濒死', { name = '桃', target = player }).card  -- 条件：名字是桃、要能用在濒死者身上
        if card then
            game:useCard(current, card, { player })              -- 缘由 '使用' ⇒ 基础规则不动它，正好交给 useCard
        else
            current = assert(game.desk:getNext(current))         -- 按行动顺序问下一位
            if current == start then
                break                                            -- 一圈问完没人给
            end
        end
    end
end)

-- package/@基础/回复.lua：体力回正 ⇒ 由回血方喊“脱离”（当场发 '濒死-离开'）
game:on('回复-生效', function (heal)
    local to = heal.to
    to:addAttr('体力', heal.amount)
    local dying = game:getDying(to)
    if dying and to:getAttr('体力') > 0 then
        dying:leave()
    end
end)
```

```lua
-- package/标准/卡牌/桃.lua
-- 【桃】（标准版）
-- 出牌阶段，对自己使用：回复 1 点体力；或令一名处于濒死状态的角色回复 1 点体力。
Card '桃'
    : on('获取目标', function (target) ... end)   -- 已受伤（未满）的自己 + 体力 ≤0 的存活角色
    : on('生效', function (cardEffect) game:heal(cardEffect.target, 1) end)
```

- **内核提供三样**：`Dying : Effect`（携带把它打到濒死的**最后一次**伤害；`settle()` = 触发 `'濒死-进入'` → **没人喊 `leave()` 就没收成功 ⇒ 内核 `setAlive(false)`**；`leave()` 幂等、**当场**发 `'濒死-离开'`）、`game:enterDying(玩家, 伤害?)`（**当场**结算）与 `game:getDying(玩家)`（查某人当前那次濒死）。**“血量 ≤0 算濒死”在规则里**（`@基础/伤害.lua` 判），**“结完没脱离就死”在内核**（只看 `left` 标记，不看血量）—— 口径上仍是「濒死效果负责杀死玩家」。
- **一个角色同时只有一个濒死状态**：已在濒死中又被打到（或再进）⇒ `enterDying` 返回**现有实例**并把它 `damage` 换成后一次（致死伤害 = 最后一次打他那一击，凶手也按这次算），**不重开结算**；`leave()` 过的旧实例不算「正在濒死」，再进就是新的一次。
- **濒死插在哪一刻**：由**调用点**决定 —— 现在是 `@基础/伤害.lua` 扣完血判 ≤0 那一下，所以**濒死排在 `'伤害-后'` 之前**（扣血 → 濒死（含判死 / 奖惩 / 胜负）→ `'伤害-后'`）。旧的「属性监听 + 记账 + 结算收尾 flush + 撤销」写法已删。
- **【桃】两种用法都是「使用」**（官方描述：出牌阶段对自己 / 濒死时令濒死角色回复）⇒ 求桃拿到牌后直接 `game:useCard`，桃的效果与去向都只写一处。
- **求桃的一圈**（官方口径，2026-09-23 改正）：**从顺序锚点起**绕一圈（到锚点的上家为止，`desk:getNext` 自动跳过阵亡者）；回正之前**一直问同一个人**（同一个人可以连给多张，也就是官方那个「新的『处于濒死状态时』从上次响应者 B 起到当前回合角色的上家」而不回头问前面的人）；体力 ≥1 立刻停。**锚点 = `game.turnPlayer or game.lastTurnPlayer`**（回合内是当前回合角色；**回合结束后是上一个回合角色** —— 官方『一名角色的回合结束后……若该角色存活，从其开始』）；两者都没有（还没人开过回合）才报错。
- **回复**：`Heal : Effect` + `game:heal(目标, 点数)`，与伤害对称（只发 `'回复-前'` / `'回复-生效'` / `'回复-后'`，加体力写在 `@基础/回复.lua`）。
- **还没做**：濒死中连锁的特殊处理（如“濒死中再次进入濒死”的复杂插入——现在就是换致死伤害、返回同一实例）。（死亡奖惩见 §9.7。）

### 9.5 常用动作：抽牌（以及"动作该怎么给大家用"）

```lua
-- 任何包、任何地方：让某个人摸 3 张
game:draw(player, 3)
```

- **内核只发时机**：`Draw : Effect`（`kind` = `draw`，字段 `player` / `count`）在 `settle()` 里只触发 **`'摸牌'`**；**真取牌写在 `package/@基础/抽牌.lua`**（`@基础` 是默认加载包 ⇒ 任何局都有它）：`game:getZone('抽牌'):draw(count)`（**内核牌区接口**，见 §9.8）→ **整批**一次 `game:moveCard` 进该玩家的 `手牌`；牌堆不够时由牌区上挂的不足回调把 `弃牌` 全部洗回（`@基础/牌堆.lua` 一处），两张堆都空时能摸多少算多少（不报错）。
- **摸牌阶段用的是同一个入口**（`package/@基础/回合.lua` 里 `game:draw(player, 2)`）⇒ 常用动作**只有一份实现**，其它包（【无中生有】、将来的【遗计】）也写 `game:draw(player, n)`。
- **已阵亡的不摸**：`Draw:settle()` 开头就查存活，已阵亡 ⇒ 直接完成（不触发 `'摸牌'`、不取牌、不算失败）—— 奖惩因此可以照口径无条件调用（用户 2026-09-22 定）。
- **约定（用户 2026-09-21 定）**：凡「抽牌 / 弃置 / 获得 / 判定」这类会被多处复用的动作 —— ① 内核给**一个效果 + 一个入口**（可 await、进效果链、失败读 `.err`）；② 语义（洗回规则、阈值、顺序）写在 `@基础` 的**同名文件**里，通常就是订阅该动作的那个时机；**「抽 N 张牌」这类跨动作复用的写法已收成内核的 `game:drawCards`**（去向省略 = 手牌，给了就是「抽到处理区」）（2026-09-24 落地）；③ **不预造"动作注册表"**，要替换整个动作时再单独谈（覆盖手段目前是"改状态 + 注册顺序"）。

### 9.6 游戏结束（胜负判定已落地）

```lua
-- package/身份场/胜负.lua（判据在内容）
game:on('玩家-死亡', function ()
    if game:getResult() then return end
    ...
    game:endGame { side = '反贼', reason = '主公阵亡' }
end)
```

- **信号在内核、判据在内容**：内核只给 `game:endGame(result)`（幂等）/ `game:getResult()` 与 **`'游戏-结束'`** 时机；结果类型 `Game.Result` = `{ side, reason }` —— `side` 取官方术语 `'主公方'` / `'反贼'` / `'内奸'` / **`'平局'`**，`reason` 是给人看的中文短句（前端可直接显示）。
- **判据（`package/身份场/胜负.lua`）**：① **主公阵亡** ⇒ 此刻只剩一个存活者且是**内奸**则内奸胜，否则**反贼胜**（含「反贼已全灭」与「内外同归于尽」两种情形，官方都算反贼胜）；② **主公活着**且存活者里已无反贼与内奸 ⇒ **主公方胜**。
- **平局的判据在基础规则里**（2026-09-23 落地）：**牌堆与弃牌堆都没牌** ⇒ `package/@基础/牌堆.lua` 挂在抽牌区上的「不足回调」洗不回来，就地 `game:endGame { side = '平局', reason = '牌堆与弃牌堆都没有牌' }` —— 平局与身份无关；一处覆盖摸牌 / 判定 / 将来任何取顶动作。发现即结束 ⇒ **这一次取牌里已经取到的牌不会再挪给谁**（见下面「结束后不再起新的结算」那条）。
- **流程会被就地收掉**：`endGame` 记下结果 → 触发 `'游戏-结束'` → `Task:cancel()` 掉这一局的流程任务（挂起中的流程协程被关掉）⇒ **回合不再转**。流程以「取消」收尾**不算失败**，是不是正常终局看 `game:getResult()`。
- **结束后不再起新的结算**：`Effect:apply()` 开头查一次结果 —— 已结束 ⇒ 这次生效以「取消」收尾（所以多目标【杀】打死主公后不会再打下一个目标、结束后也不会再起新的濒死）；**已经跑着的结算不打断**（记牌器只增，没法猜「谁还在跑」）。
- **还没做**：**再开一局**（用户 2026-09-21 定：将来做法是**重新建一个 `Game` 实例**，不是重置当前局）。

### 9.7 死亡奖惩（已落地，2026-09-22）

```lua
-- package/身份场/奖惩.lua（注册在 '玩家-死亡' 上；胜负.lua 靠 Depends { './奖惩' } 排它后面）
game:on('玩家-死亡', function (player)
    local dying  = game:getDying(player)                            -- 死亡时机里那次濒死的账还在
    local damage = dying and dying.damage                           -- 致死伤害 = 最后一次打他那一击
    local killer = damage and damage.from
    if not killer or killer == player then return end               -- 无凶手 / 自杀 ⇒ 不奖惩
    if player:getTag('身份') == '反贼' then
        game:draw(killer, 3)                                        -- 已阵亡的凶手由 Draw 自己拦
    elseif player:getTag('身份') == '忠臣' and killer == game.desk:getPlayer(1) then
        game:moveCard(killer:getZone('手牌'):list(), '弃牌')          -- 主公杀忠臣：弃所有手牌
    end
end)
```

- **顺序**：官方是「死亡 → 奖惩 → 胜负判定」—— 两者都挂在 `'玩家-死亡'` 上，**先注册的先跑**，所以 `package/身份场/胜负.lua` 顶部写 `Depends { './奖惩' }`（依赖先加载、先注册）。用例钉住了“反贼是最后一个死的”那种情形：奖励的那 3 张必须真的摸到（若胜负先跑，`game:draw` 会因为游戏已结束被取消）。
- **凶手从哪来**：读 `'玩家-死亡'` 时死者的那次濒死 —— `game:getDying(死者).damage.from`（内核不认识“凶手”，只把致死伤害搬在 `Dying` 上，**不额外记标签**）。“无来源伤害 / 失去体力” ⇒ `damage` 为空 ⇒ 不奖惩；自杀（凶手 = 死者）也不奖惩。**注意读的时机**：只在 `'玩家-死亡'`（同步、还在濒死收尾之前）读得到；内核在 `'玩家-死亡'` 发完之后才清账。
- **已阵亡的凶手照发**（用户 2026-09-22 定）：奖励照调 `game:draw`，死者那份由内核的 `Draw` 拦掉（而不是在奖惩里写分支）。
- **还没做**：主公杀忠臣的「**装备牌**」—— 装备区还不存在（等装备与距离修正那批），现在只弃手牌；奖惩文件顶部留了说明。

### 9.8 判定（动作已落地，2026-09-23）

```lua
-- 任何包、任何地方：让某个人判定（缘由内核不解释）
local judge = game:judge(player, '八卦阵')
-- 判定结果就是判出的那张牌
local card = judge.card
```

- **形状：亮牌 → 改判 → 结果已定**（三个时机由**内核按次序**发出，不靠注册顺序）：

| 时机 | 谁用 | 做什么 |
| ---- | ---- | ---- |
| `'判定-亮牌'` | `@基础/判定.lua` | 从抽牌堆顶翻一张放进 `judge.card`（牌先进**这次判定的临时区**，收尾时统一送 `弃牌`） |
| `'判定-前'` | 技能（将来的【鬼才】） | **改判窗口**：`judge:replace(新牌)` 换掉当前判定牌（新牌也进临时区，被换下的记进 `judge.replaced`；**窗口外调直接报错**） |
| `'判定-后'` | 内容侧（现在没人用） | 结果已定；牌的去向由**收尾**统一处置（`@基础/收尾.lua` 送 `弃牌`） |

- **结果 = 那张判定牌**：内核**不认识花色 / 点数**（也不预设它们），调用方拿到牌后自己解释（【乐不思蜀】看是否红桃、【闪电】看是否黑桃 2~9）—— **牌面（花色 / 点数）已落地**（§9.9）：读 `judge.card.suit` / `judge.card.point`。
- **判定牌来自抽牌堆顶**：随机性由「开局洗牌 + 不足时洗回」承担（局上的随机源可注入 seed ⇒ 整局可复现），没有单独的“判定随机源”。
- **改判是同一趟里依次换**：先注册的看到旧牌、后注册的看到换过的牌；**不是**「换一次就重新发一轮」（那需要终止条件，且有死循环风险）。
- **取顶 / 洗回是牌区接口**（与摸牌共用）：`OrderedZone:draw(n)`（从区顶取 n 张，不够就少给、不报错）+ `OrderedZone:setShortageHandler(fn)`（取空了调一次这个回调补牌；`@基础/牌堆.lua` 挂的是「弃牌全部洗回抽牌 + `shuffle()`」）。
- **还没做**：判定区（玩家的延时锦囊位）与延时锦囊的逆序结算（**回合流程里的判定阶段仍然只进 / 出**）、技能的改判实现（牌面已落地，见 §9.9）。

### 9.9 牌面：花色与点数（已落地，2026-09-23）

```lua
local card = game:createCard('杀', '黑桃', 7)   -- 建牌时把牌面给进去
card.suit    -- '黑桃'（花色）
card.point   -- 7（点数）
```

- **口径**：花色取值 `'黑桃'` / `'红桃'` / `'梅花'` / `'方块'`；点数取数字 **`1..13`**（A=1 … K=13，官方记法只是展示层的事）。判定要判区间（如【闪电】看是否黑桃 2~9）、拼点要比大小，数字最省事。
- **颜色（红 / 黑）不存**：由花色推得（内容侧一个映射就够）。
- **内核只存不解释**（用户 2026-09-23 定）：`Card` 多两个字段 `suit` / `point`，`game:createCard(名字, 花色, 点数)`（后两个可选）；**内核不校验取值、不换算**，两个字段**直接读**（不另给 getter，项目规则见 `moe-kill-dev` 的 `references/code-style.md` 第 11 节）。
- **牌表是逐张的**（`package/标准/牌表.lua`）：`{ name = '杀', suit = '黑桃', point = 7 }` 一张一条，`@基础/牌堆.lua` 建牌时把牌面传下去。**张数与牌面还是草稿，待按官方标准版核对**（延时锦囊还不在表里）。
- **判定怎么用**：`game:judge(玩家, 缘由)` 翻出的那张牌就带着牌面（§9.8），调用方直接读 `judge.card.suit` / `judge.card.point`。

-- package/标准/卡牌/无中生有.lua
Card '无中生有'

```lua
-- package/标准/卡牌/南蛮入侵.lua（万箭齐发同形，只把条件里的「杀」换成「闪」）
Card '南蛮入侵'
    : extends '锦囊牌'
    : on('获取目标', function (target)
        return table.filter(game.desk.alivePlayers, function (player)
            return player ~= target.user        -- 所有其他角色
        end)
    end)
    : on('生效', function (cardEffect)         -- 每个目标各跑一次
        local target = cardEffect.target
        if game:askPlayCard(target, '南蛮入侵', { name = '杀' }).card then
            return                             -- 打出了就不受伤
        end
        game:damage(cardEffect.user, target, 1)
    end)
```

- **多目标 + 响应**：【南蛮入侵】与【万箭齐发】只需要「`'获取目标'` 给所有其他角色」+「`'生效'` 里问那张牌」—— 逐目标结算、行动顺序、响应询问、伤害都是现成的（与【杀】的【闪】响应同一个写法）。
- **【桃园结义】（2026-09-23）**：官方「使用目标：所有角色」+「目标角色回复 1 点体力」+ **◆对未受伤的角色无效** ⇒ `'获取目标'` 给 `game.desk.alivePlayers`（**含自己**），`'生效'` 里 `game:heal(cardEffect.target, 1)` —— **“未受伤无效”落到效果上**（满体力者回复 0 点，`Heal` 受体力上限钳制），没有另做「使用结算开始时检测此牌对目标的有效性」那套机制；目标照官方给“所有角色”，不预先排除满血者。
- **【五谷丰登】（2026-09-23）**：官方「使用目标：所有角色；**指定目标后**你亮出牌堆顶的 X 张（X = 目标数）；目标角色获得这些牌中（剩余）的一张；**使用结算结束后**，剩余的牌置入弃牌堆」⇒`'结算前'` 用 `game:drawCards(useCard.user, #useCard.targets, useCard:getTempZone())` 亮出（牌直接进**这次用牌自带的临时处理区** ⇒ 牌有位置、账实一致；`'生效'` 里 `useCard:getTempZone():list()`（生效钩子的第二个参数就是这次用牌）就是「剩余」）；`'生效'` 里 `game:askCard(target, '五谷丰登', { card = 剩余 })`（**候选就是给定的一批牌**，不看被问者的牌区）⇒ `game:moveCard(选中, 目标的手牌区对象)`（**必须用目标自己的区对象**，区名会解析到当前回合角色身上）；**没有 `'结算后'` 钩子** —— 剩余由**内核的默认收尾**统一送 `弃牌`（效果结完时把临时区剩下的牌送 `弃牌`，2026-09-24 起）。**“没人答” = 不获得**（那张牌留在剩余里一起进弃牌）；逐目标顺序就是**顺序锚点起的行动顺序** —— 使用者是当前回合角色时他第一个选（官方 3.2 的案例）。
- **【决斗】（2026-09-23）**：官方「**由目标角色开始**，其与你轮流打出【杀】，直到其中一名未打出；然后未打出的角色受到**另一名角色造成的** 1 点伤害」⇒ `'生效'` 里这两个角色在循环里互换，每轮 `game:askPlayCard(当前, '决斗', { name = '杀' })`，谁没打出来谁吃 `game:damage(另一方, 他, 1)`；打出的【杀】由 `AskPlayCard` 放进发起那次结算的临时区、收尾时进 `弃牌`（内容侧不写 `moveCard`）。两人来回打很多张也只是**同一次用牌结算**里的多轮询问（不是嵌套结算），手牌有限 ⇒ 必然结束。
- **锦囊与基本牌共用同一套用牌链**（§6 / §9.2）：`'获取目标'` 给合法目标 → `canUse` 校验 → `'卡牌-结算前'` 进这次用牌的临时区 → 按行动顺序逐目标 `'生效'` → 收尾统一送 `弃牌`。**这两批锦囊大部分没有新内核机制**（多目标、逐目标生效、筛选与次数都现成）；只有【五谷丰登】要几个**通用**口子：牌自己的 `'结算前'` / `'结算后'` 钩子、`AskCard.Condition.card`（候选就是给定的一批牌）、以及 `Effect` 的**临时处理区 + 收尾时机**（`getTempZone()` / `'效果-收尾'` —— 结算期间暂存一批牌的标准做法，判定与打出的牌也已迁过来）。
- **分类**：即时锦囊是 `{ '锦囊', '非延时锦囊' }`（模板里就写好了）；**延时锦囊**将来写 `: extends '锦囊牌' : kind { '锦囊', '延时锦囊' }`（分类**覆盖**，把原有的 `非延时锦囊` 替掉）。
- **不限次**：锦囊按官方每回合不限次 ⇒ 不写 `: limit(...)`（兜底 1000 = 事实上不限）。
- **【过河拆桥】（2026-09-23）**：官方「使用目标：一名区域里有牌的其他角色；作用效果：你弃置其区域里的一张牌」⇒ `'获取目标'` 排掉**身上一张牌都没有**的角色（局部 `hasCard` 遍历 `player:getZones()`）；`'生效'` 把**目标身上有牌的区**交给询问（`game:askCard(user, '过河拆桥', { zone = 那些区 })` ⇒ 那些区里的牌**逐张**都是候选），挑中哪张就 `game:moveCard(牌, '弃牌')`。
- **【顺手牵羊】（2026-09-23）**：与【过河拆桥】同一套「从别人的区域里拿一张」，只差两处：目标要距离 **1 以内**（用基础规则的 `distance(user, player) <= 1`，不是 `desk:getDistance`）；拿到的东西 `game:moveCard(牌, user:getZone('手牌'))` 进**自己的**手牌。
- **【借刀杀人】（2026-09-24）**：官方「出牌阶段，对装备区里有武器牌的一名其他角色使用。你指定其攻击范围内的一名其他角色：该角色需对其使用一张【杀】，否则将其装备区里的武器牌交给你」⇒ ① `'获取目标'` = 其他角色 + **装备区里有武器牌**（按分类 `isKind('武器')` 认，不认槽位名）+ **其攻击范围内还有别的存活角色**；② `'生效'` 里用**通用 `Ask`** 让**使用者**指定一名角色（问法 `{ candidates = 他能打到的人 }` 由内容侧自己解释，答复不在候选里就按「没指定」处理，**不报错**）；③ 拿 `askUseCard(被借刀者, '借刀杀人', { name = '杀', target = 被指定的角色 })` —— 答复由现成的 `AskUseCard` 校验（次数用满 / 目标不在范围内 ⇒ 选项为空 ⇒ 用不出来），用出来了就 `game:useCard`；④ 没用出来 ⇒ 武器牌 `game:moveCard(武器, 使用者:getZone('手牌'))`（官方「交给你」= 进手牌）。**被指定的那名角色不是这张牌的目标**（不进 `targets`，不触发「成为目标」类技能、也不进多目标结算顺序）；**换装后修正自动撤**（武器离开装备区 ⇒ 攻击范围回落），无需写「卸下」。
- **「区域里有牌」与区名**（2026-09-23，2026-09-24 扩充）：玩家的区域有三个 —— `手牌` / `装备` / `判定`（**判定阶段还没做**，它现在只是个空区）；`装备` 区已能装牌（见 §9.11）。
- **服务器侧不看明暗**（2026-09-23 用户定）：不可见是**与客户端通讯时**的隐瞑 ⇒ 内核 / 规则层一律看得见所有牌（这两张牌因此**逐张**给候选、应答方直接挑）；`手牌` 仍标着 `setVisible(false)`，那是**协议层遮蔽**要读的声明（将来客户端把该区域的牌换成「未知卡牌」，选完服务器映射回来或丢弃重抽）。
- **用过的牌的去向**不用自己写：基础规则已经把 `'使用'` 的牌放进临时区、收尾时送 `弃牌`（§9.2 的「两套去向」）。
- **无懈可击将来插在哪**（本批不做）：官方是「任意锦囊**生效前**」，所以插入点是**基础规则**在 `'卡牌-结算前'` 里按 `isKind('锦囊')` 判断、再问一圈有没有人打【无懈可击】，被打出就把这次用牌 `reject` 掉（整张牌作废）—— **与单张锦囊自己的定义无关**，现在做的牌一行不用改。

### 9.11 装备（武器 + 坐骑 + 槽位区；已落地 8 武器 / 6 坐骑，2026-09-24）

装备的加成由**类别基类自己的 `'进入区域'` 钩子**写进属性 —— **进来时加、离开时由 `Card:withZone` 自动撤**，没有「装上 / 卸下」这对函数。

```lua
-- package/@基础/卡牌/装备牌.lua（模板：不在牌表里、不会被造出来）
-- 只管「结算后进装备区」：按分类找槽位 ⇒ putInto(槽位名, 牌)
-- （装备区的四条槽位由 @基础/装备.lua 在「游戏-开始」里遍历玩家的装备区设置）
Card '装备牌'
    : kind '装备'
    : noTarget()                      -- 官方装备牌不指定目标
    : zone '手牌'
    : on('结算后', function (useCard)
        -- 拿分类去装备区声明的槽位里找自己那条
    end)

-- package/@基础/卡牌/武器牌.lua（类别定义：进武器槽时把攻击范围加成写进持有者的属性）
Depends { './装备牌' }                -- 同类文件按名字排序，必须显式声明先加载
Card '武器牌'
    : extends '装备牌'
    : addKind '武器'
    : on('进入区域', function (card, zone, slot)
        if slot ~= '武器' then
            return
        end
        card:withZone(zone.owner:addAttr('攻击范围', card:getValue('攻击范围')))
    end)

-- package/@基础/卡牌/坐骑牌.lua（两种马功能一模一样 ⇒ 先把共性写在坐骑牌上，再各给一个定义）
Depends { './装备牌' }
Card '坐骑牌'
    : extends '装备牌'
    : addKind '坐骑'
    : on('进入区域', function (card, zone, slot) end)   -- 按槽位名（进攻马 / 防御马）决定改哪条修正

Card '进攻马'
    : extends '坐骑牌'
    : addKind '进攻马'
    : value('距离修正', -1)           -- 两种马的修正逐张都一样 ⇒ 写在马定义上

Card '防御马'
    : extends '坐骑牌'
    : addKind '防御马'
    : value('距离修正', 1)

-- package/标准/卡牌/麒麟弓.lua（攻击范围 5；牌上写的就是描述里的值，与默认 1 的差值由武器牌钩子去减）
Card '麒麟弓'
    : extends '武器牌'
    : value('攻击范围', 4)

-- package/标准/卡牌/赤兔.lua（进攻马 -1；具体马连数据都不用写）
Card '赤兔'
    : extends '进攻马'
```

- **用牌链一行不改**：装备牌与其它牌共用同一条链（`canUse` → 取牌 → `'卡牌-结算前'` 进临时区 → 逐目标生效（空转）→ **牌自己的 `'结算后'`** → 收尾），区别只在「**不指定目标**」这一个声明上。
- **槽位由区自己管**：装备区是**槽位区**（四条槽位：`武器` / `防具` / `进攻马` / `防御马`，由基础规则在 `'游戏-开始'` 里给每个玩家的装备区设），`zone:putInto(槽位名, 牌)` 放进槽位，**同槽已有的牌由内核同步置入弃牌堆**（官方：同一槽位的旧装备置入弃牌堆）。
- **加成一进槽就写、离开自动撤**：牌进装备区时，牌区发 **`'进入区域'`** 钩子（载荷 `(card, zone, slot)`）—— 类别基类在这里按 `slot` 认自己那条槽、把这张牌的数据用 `player:addAttr` 写进属性；**撤销挂在牌上**（`card:withZone`）⇒ 牌一离开装备区（拆 / 抢 / 换装 / 死亡弃牌）修正自动撤，**一条「卸下」都不用写**，也没有集中式的 `equip` 函数。
- **分类既说「是什么」也给出去哪个槽**：`{ '装备', '武器' }` / `{ '装备', '防具' }` / `{ '装备', '坐骑', '进攻马' }` / `{ '装备', '坐骑', '防御马' }` —— 技能判「你装备了坐骑」看 `'坐骑'`，槽位匹配看 `'进攻马'`（拿区声明的名字去分类里查，**顺序无关**）；**不另写一份「槽位名」数据**。分类写法：**每个具体类别一个定义**，具体牌只 `: extends` 一个并写自己的数据 —— 类别定义负责「带分类」（`武器牌` ⇒ `'武器'`；两种马各一个定义：`进攻马` / `防御马` 分别 `extends '坐骑牌'` 再 `addKind` 自己那条），**不要**在具体牌上写 `kind`（那是覆盖，会把基类带的分类清掉）；要追加分类用 `addKind`（只往里加）。
- **数据只给数值**（`CardDef:value`，内核只存不解释）：武器写 `攻击范围` —— **就是描述里的那个值**（麒麟弓 ⇒ `5`），差值由武器牌的钩子减（`range - 1`，因为属性「攻击范围」的初值是 1）；坐骑的 `距离修正` 也与描述一致（进攻马 `-1` / 防御马 `1`）且逐张都一样 ⇒ 写在 **`进攻马` / `防御马` 两个定义**上，具体马只 `: extends` 其中一个；攻击范围与距离的读法见 §5。
- **本批未做**：**防具**（八卦阵 / 仁王盾 —— 要「替换 / 追加一次响应」的新能力）；**装备自带的技能**（诸葛连弩的无限【杀】、雌雄双股剑、青龙偃月刀、丈八蛇矛、贯石斧、方天画戟、麒麟弓、青紅剑 —— 各自是一个技能功能点）；装备区的**协议层表达**（明牌 / 前端展示）。牌的**定义与数据已经在了**，补技能时只往那张牌的定义里加钩子。
- **牌名的待核对**：牌表草稿里的「**青紅剑**」（官方标准版作「青釭剑」）—— 本批按牌表现有写法定义，核对后一起改。
