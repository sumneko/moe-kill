## 1. 模式与身份配置

本工程先做**身份场**（单机，AI 补齐人数），暂不做国战 / 3v3 / 斗地主等其它模式。

| 人数 | 主公 | 忠臣 | 反贼 | 内奸 |
| --- | --- | --- | --- | --- |
| 4 | 1 | 1 | 1 | 1 |
| 5 | 1 | 1 | 2 | 1 |
| 6 | 1 | 1 | 3 | 1 |
| 7 | 1 | 2 | 3 | 1 |
| 8 | 1 | 2 | 4 | 1 |
| 9 | 1 | 3 | 4 | 1 |
| 10 | 1 | 3 | 5 | 1 |

- 先手（第一回合）由主公开始；身份牌除主公外均隐藏。
- 体力上限：主公在标准规则下**体力上限 +1**（人数相关变体另计）。

**已实现口径（`package/身份场/`）**：

- 配置表先做 **4~8 人**（上表前五行，`package/身份场/配置.lua` 以 `game:setValue('身份配置', ...)` 落进**规则数值**，所以后续包可覆盖）；9 / 10 人表等真要用时再补。
- **主公固定坐 1 号位**（简化假设），于是「按座位号递增」的行动顺序天然让主公首回合先手 —— 不需要给内核加「起始行动者」的概念。
- 身份写进玩家的**正式字段 `player.identity`**（内容侧 `package/身份场/身份.lua` 的 `setIdentity(name)` 写入，读法直接读字段；2026-09-30 前是标签）：内核只记录、不解释取值。
- 主公 +1 走**加体力上限与体力**（`lord:addAttr('体力上限', bonus)` 与 `lord:addAttr('体力', bonus)`，加成取规则数值 `主公额外体力`，两处都是增量、各返回撤销函数）；因为基础包先把体力与上限都写成了默认值，身份场只需再“抬”一次。
- **规则数值里的 `默认体力` 是「无武将时的开局体力初值」**（`package/@基础/配置.lua` 里为 5）：**2026-09-30 起它只给「还没选武将」的角色**（`@基础/体力.lua` 在 `'游戏-开始'` 里判 `player.hero`；武将的上限与体力由 `@基础/武将.lua` 的 `setHero` 写）—— 这就是当初说的「武将没写时的兜底」；主公 +1 仍是**加成**（`addAttr`），叠在武将上限之上。
- **体力属性的边界（已实现）**：`体力` 下界为负（`-999999`，濒死结算要用）、上界写**字符串引用** `'体力上限'` ⇒ 写值会**钳到当前上限**；`体力上限` 自带 `0..999999`。抬上限**不会**自动加体力（所以主公那句「上限与体力各 +1」仍必要）。

## 2. 胜负与奖惩

- 主公 + 忠臣：消灭所有反贼与内奸。
- 反贼：杀死主公（主公死亡时若反贼已全灭，仍由反贼胜）。
- 内奸：成为最后的存活者，且必须与主公单挑后杀死主公；内奸与反贼同归于尽时反贼胜。
- 平局：**牌堆与弃牌堆都没有牌时，游戏平局**（用户 2026-09-23 定；官方口径）。
- 奖惩：
  - 任意角色杀死反贼 → 摸 3 张牌。
  - 主公杀死忠臣 → 主公弃置其所有手牌与装备牌。

**已实现**：胜负判定的判据写在 `package/身份场/胜负.lua`（订阅 `'玩家-死亡'` → `game:endGame { side, reason }`），详见 §9.6；**奖惩已落地**（`package/身份场/奖惩.lua`，靠 `Depends` 排在胜负判定**之前**，见 §9.7）—— 手牌与装备区的牌一起弃（装备批次落地后已能弃）。**平局也已落地**（牌堆耗尽 ⇒ 洗不回来，见 §9.6）。

## 3. 回合流程

```
准备阶段 → 判定阶段 → 摸牌阶段 → 出牌阶段 → 弃牌阶段 → 结束阶段
```

| 阶段 | 内容 |
| --- | --- |
| 准备阶段 | 回合开始时点的技能结算 |
| 判定阶段 | 逆序结算判定区内的延时锦囊（后入先出） |
| 摸牌阶段 | 默认摸 2 张 |
| 出牌阶段 | 使用牌；默认「杀」限一次 |
| 弃牌阶段 | 手牌数须降至当前体力值 |
| 结束阶段 | 回合结束时的技能结算 |

每个阶段本身也是**时机**（有「阶段开始时 / 结束时」的触发点），技能可挂在阶段前后。

- **已实现（2026-09-21；阶段收进内核 2026-09-22）**：回合流程在 `package/@基础/回合.lua`，加载期登记（`game:registerFlow`）、由装配侧 `game:runFlow()` 启动。六阶段依次走完：每个阶段用 `local _ <close> = game:enterPhase(回合角色, 阶段名)` 进、作用域结束自动出，**进发两个时机** —— `'阶段-开始'`（**只通知**：技能在这里改「摸牌数」这类参数）与 `'阶段-生效'`（**这个阶段的业务**，2026-10-09 加，见下）、出发 `'阶段-结束'`（**载荷 = 阶段实例**：`phase.player` / `phase.name`；2026-09-29 起**全局一份 + 对当事人再发一份** —— 技能直接挂 `player:on('阶段-开始', …)`，不用自己认领）；整段被 `'回合-开始'` / `'回合-结束'`（上下文 = 回合角色）包住；首回合主公（1 号位）、阵亡者跳过、只剩一个存活角色时流程结束。（2026-09-28 改造：`runTurn` 建一个 **`Turn`（回合）对象**挂在 `player.turn` 上（跳过阶段记在它身上、回合结束就没了）；**各阶段业务住 `@基础/阶段/` 一个阶段一个文件**（判定 / 摸牌 / 出牌 / 弃牌），各自订阅 **`'阶段-生效'`**（2026-10-09 从「开始」挪过来 —— 「开始」留给技能改参数）。）
  - **摸牌阶段**：摸「**摸牌数**」张（**玩家属性**，默认 2、开局写入；`抽牌` → 该玩家的 `手牌`）—— 技能可以在 `'阶段-开始'` 里 `addAttr('摸牌数', …)` 改它（修正挂到**本阶段**上就行，阶段一离开自动撤）；抽牌不够时把 `弃牌` 洗混当新抽牌堆（用局上的随机源 ⇒ 同种子可复现）。
  - **出牌阶段**：向回合角色**要一张牌**（`game:askUseCard(回合角色, '出牌', { zone = '手牌' })` —— **要的是「使用」就调 `askUseCard`**（「使用」的语义由类型携带，不再靠缘由字符串）：内核逐张跑 `canUse` 把用不了的牌挡在候选项外、并给选项带上可用目标；`{ zone = '手牌' }` 再把候选限在手牌里。**筛到什么、为什么筛都在内核，业务层不手写候选**）—— 答复到手内核就直接把它用出去（`ask.useCard` 读得到那次使用），答不上 / 答复不在选项里就没有那次使用、结束阶段。**默认「杀」每出牌阶段限一次**：限额写在**牌自己的定义**上（`Card '杀' : limit('出牌', 1)`），次数记在**阶段实例**上，判定是 **`game:canUse` 的内建条目**（用满就直接用不了、**不问内容侧**；不在自己的阶段里既不计数也不受限）。别的牌没声明限额 = 1000 次（事实上不限）。
    - 两种放宽口径：“此【杀】不计入次数” = `game.phase:addUseCount('杀', -1)`（记在**阶段实例**上）；“可以多用一次 / 本阶段无限次” = `player:addLimit('杀', '出牌', 1)` / `player:addLimit('杀', '出牌', 1000)`（**修正挂在玩家身上**、随装备 / 技能撤销，2026-09-30 起）。
  - **弃牌阶段**：手牌数须降到**当前体力值**（询问，缘由 `'弃牌'`；**答得不对（没答 / 张数不对）就由服务器替他弃**——手牌从前往后数，2026-09-28）；手牌没超就不问、不挪牌。
  - **后续批次已补齐**：判定阶段的结算（延时锦囊，2026-09-28，见 §9.12）、装备与距离修正（§9.11）、濒死与胜负判定（§9.4 / §9.6）、出牌次数限制、**武将定义与装配**（§9.14，2026-09-30）；**还没做**：武将技能（`Skill` 定义 / `addSkill` 挂载 / 标签）与选将流程。

## 5. 距离与攻击范围

- **座位距离**：沿桌面两个方向取较小值，最小为 1。
- **距离修正**：目标装备 +1 马 → 距离 +1；自己装备 -1 马 → 距离 -1；结算后距离仍**最小为 1**。
- **攻击范围**：默认 1，由武器决定；与「距离」是两个独立概念。
- 距离与范围是**动态计算**（技能、装备均可改），必须作为求值函数而非缓存字段。
- **已实现（内核）**：`desk:getDistance(from, to)` 当场求值（只由两个座位号与座位总数决定、最小 1、不缓存成字段）—— **它只算座位距离，修正不由它管**。
- **已实现（基础规则，2026-09-24）**：修正走**属性**、求值在**内容侧** —— `进攻修正`（自己到别人，进攻马 `-1`）/ `防御修正`（别人到自己，防御马 `+1`）默认 0，装备牌**进槽时由类别基类的 `'卡牌-进入区域'` 钩子**用 `player:addAttr` 加（它返回撤销函数、由被动的容器管着）、**牌离开装备区自动撤**（`'被动'` 钩子把修正挂进内核给的 `GCHost`，见 §9.11）；基础规则 `package/@基础/距离.lua` 的 `distance(from, to)` 把这三段加起来：座位距离 + 自己的 `进攻修正` + 对方的 `防御修正`，结算后仍**最小 1**（`杀` / `顺手牵羊` / `借刀杀人` 都用它）。技能改距离时同样加 `进攻修正`（如【马术】）。
- **已实现（基础规则）**：属性 `攻击范围` 默认 1（`package/@基础/攻击范围.lua` 开局写给每个玩家），武器的加成也走 `player:addAttr`、撤销同样随牌走；「够不够得着」由**内容包**把距离与它组合得出（见 §9.2 的「杀」）—— 内核不作任何具体判定。

## 6. 「使用」与「打出」

这两个是不同的动作，不能合并实现：

- **使用**：出牌阶段主动使用牌（杀、锦囊、装备……）。
- **打出**：为响应而使用（闪响应杀、杀响应决斗/南蛮/万箭、桃用于濒死救援）。
- 打出**不触发**「使用时」的技能；结算时机的差异是技能系统的关键区分点。
- **已实现（部分）**：**使用**这条链路跑通了（`game:useCard(使用者, 牌, 目标)` —— 目标可以是单个也可以是列表，**用不了就 `reject` 进 `.err`、牌还留在原处**）；**响应**用“要一张牌”表达 —— `game:askCard(被问者, 缘由, 条件?)`（要一次**使用**就换 `game:askUseCard`、要一张**打出**的牌就换 `game:askPlayCard`、要**角色**就换 `game:askPlayer`（**一名或几名**，`min` / `max` 给个数区间 —— 2026-10-09 补））（返回**询问实例**，应答方读 `ask.options` 拿到可选项、答复读 `.card` / `.targets` / `.players`，**答复必须在选项里**否则拒收；条件里三个字段 `name` / `zone` / `card` 都是筛选条件（`askUseCard` 多一条 `target`），详见 `moe-kill-dev` 的 `references/architecture.md` 第 12 节；应答方挂在局上的 `'卡牌-询问'` 时机里）。**「打出」不是内核动作、而是询问的一个类别**：`askPlayCard` 的候选按条件筛、答复只有牌，**牌当场交出去**（进发起那次结算的临时处理区 ⇒ 收尾时进 `弃牌`）。具体见 §7 与 §9.2。【闪】已落地（响应）。

## 7. 结算时序与插入

- 锦囊结算：先检查目标合法性，再**从顺序锚点起按行动顺序逐个结算目标**（官方口径；锚点 = 当前回合角色，回合结束后是上一个回合角色，见 §9.4；使用者自己也在目标里时他就是第一个结算的）。
- **无懈可击**可在任意锦囊生效前使用，且可被另一张无懈可击抵消（可嵌套）。
- **濒死**：体力降至 ≤ 0 时插入濒死结算，**从顺序锚点开始**按逆时针方向绕一圈询问是否使用桃（**官方口径**，2026-09-23 改正；旧口径「从濒死者开始」已废）—— 回合内锚点就是当前回合角色，**回合结束后是上一个回合角色**（`game.turnPlayer or game.lastTurnPlayer`）。
- **死亡**：濒死结算失败后死亡，插入死亡结算 → 奖惩 → 胜负判定 → 可能立即结束游戏。**奖惩（§9.7）与胜负判定 / 结束（§9.6）都已落地**（`package/身份场/奖惩.lua` / `胜负.lua` + `game:endGame`）。
- 以上都要求引擎能**嵌套结算**：结算过程中可以起新的结算，处理完再回到原处继续。
- **已实现（部分）**：用牌与伤害都是**效果对象**（`UseCard : Effect` / `Damage : Effect`），每个效果由**自己的任务**驱动 —— `Effect:apply()` 是驱动点（「记父（当前正在结算的那个）→ **依次**问 `'效果-能否生效'`（全局）/ `'效果-来源-能否生效'`（来源）/ `'效果-目标-能否生效'`（目标）（**返回值即阻止的原因**，谁先给就停）→ 自己结算」），`Effect:await()` 等它结完、`result` / `err` 就在效果上；局上留一个**只增的记牌器**（`game:getEffect()` = 最近发起过的根效果、`game:getEffects()` = 按发起顺序的快照 —— 记的是**发起过什么**，不是"正在结算什么"，内层效果不单独记），嵌套上限两根轴：**深度 150 层**（`Effect.MAX_DEPTH`）与**一次结算挂的子结算 1000 个**（`Effect.MAX_CHILDS`）—— 超了**不报错**：那一层**不结算、也不发收尾**、以「取消」收尾（不算失败）+ 记一条 `warn`（实测再深（≈225）进程会直接没，所以阈值只能在安全区；"无限"的正解是回合时限 / 玩家停手），**失败不抛给调用方**（记 `.err`）；`Effect.parent` 就是**外层效果**（根效果为空），沿着它往上走能还原整条结算链 —— 注意它是**结算嵌套**、"这一下算谁的"归伤害自己的 `from`（两者可不同）。**伤害与回复的规则就在自己的结算里**（2026-09-21 定「只发事件、自己不动体力」；2026-09-28 起 `Damage` / `Heal` 搬进 `@基础`，三个时机也一并去掉；**2026-10-09 起时机重新长回来，改成「四个阶段各三份」**）：`Damage:settle()` 直接 `to:addAttr('体力', -amount)`、≤0 就 `to:enterDying(self)`；`Heal:settle()` 直接加体力、体力回正就喊 `dying:leave()` —— 内核不认识任何属性名。**「失去体力」不是伤害**（底本 Chapter2/Section5：「失去体力与受到伤害是不同的事件」，它没有来源、因它死亡不奖惩）⇒ 走独立的效果 `LoseHp`（一个时机都不发），见 §9.17。**伤害与治疗的四个阶段（2026-10-09 用户定，每个阶段各发三份：全局 → 来源 → 目标，没来源就不发来源那份）**：**开始**（`'伤害-开始'` / `'治疗-开始'`，仅通知、别改值）→ **生效前**（`'伤害-生效前'` / `'治疗-生效前'`，**改值的口子** = 官方「造成/受到伤害时」、【麒麟弓】与【救援】挂这里）→ 生效（扣 / 加体力；**濒死夹在这里**）→ **生效后**（`'伤害-生效后'` / `'治疗-生效后'`，= 官方「受到伤害后」，【奸雄】【反馈】【刚烈】挂 `'伤害-目标-生效后'`）→ **结束**（`'伤害-结束'` / `'治疗-结束'`，所有插入结算跑完之后的收尾通知）。名字里的方向词照「对当事人再发一份」规则：`'伤害-来源-X'` / `'伤害-目标-X'`；发时机的帮手是 `Damage:fireStage(阶段名)` / `Heal:fireStage(阶段名)`；
  - **逐目标生效**：用牌的结算 = 「校验 → 取出牌 → **内核把牌放进这次用牌的临时区** → 触发 `'卡牌-结算前'` → **牌自己的 `'使用'` 钩子**（一次用牌一次；声明 `: skipEffect()` 的牌到此为止、不发起生效）→ 逐条生成「成为目标时」（先按行动顺序整份排好，逐条发三份；本条时机里被追加过就把还没轮到的那批重排一次）→ **按行动顺序**（`desk:actionOrder(最终目标列表)`：从顺序锚点起绕一圈；**同一个角色出现两次就结算两次**，2026-10-09 起）对每个目标各结算一次**生效**（`CardEffect`，父效果 = 这次用牌；**钩子拿到 `(cardEffect, useCard)` 两个参数**）→ 触发 `'卡牌-结算后'`」。每个生效都是独立效果 ⇒ 有自己的「能否生效」、能被**单独阻止**；前一个生效连同它引发的插入结算全部结束之后，才轮到下一个目标。
  - **阻止**（2026-09-24 定，取代原来的“窗口里 `remove()`”；2026-09-29 起**三段式**）：效果执行自己的结算**之前**被**依次**问三次「能不能生效」—— ① 全局 `'效果-能否生效'`（【无懈可击】在这段，上下文 = 该效果实例）→ ② 来源 `effect.from` 身上的 `'效果-来源-能否生效'` → ③ 承受者 `effect.to` 身上的 `'效果-目标-能否生效'`（**技能挂在主人身上、只在这一段醒来** —— 装备 / 技能的自然落点就是它主人的时机表，【仁王盾】挂这里）；**订阅者返回非 nil 值即阻止**（返回值就是原因，只给 `false` 归一成一句通用原因），**谁先给原因就停在谁那儿**（不再问后面的段）⇒ 这次生效不结算、没有结果、`.err` = 原因、**不算失败**、收尾照跑；**作用域只到这一个效果** —— 不影响外层、也不影响同一张牌对其余目标的生效。**【无懈可击】的「抵消」落在第一段**（写在**它自己的牌文件**里，见 §9.10）；而【闪】**不在这里** —— 它写在【杀】自己的 `'生效'` 钩子里（2026-09-30 起走 `askPlayCard` 带 `responseTo` 的「响应」两段时机与 `.success`，2026-10-09 收口，见 §9.11【贯石斧】），两者位置不同。**没有 `remove()` 了**（2026-09-24 删）：内容侧要阻止一律返回原因；内核自己要停结算直接用 `task:cancel()`。
  - **响应**：要一张牌用 `game:askCard(被问者, 缘由, 条件?)`（要一次使用用 `game:askUseCard(...)`、要角色用 `game:askPlayer(...)`（一名或几名，`min` / `max`）—— 后者候选名单由内核摆好、答复必须在名单里）—— 询问走局上的 **`'卡牌-询问'` 时机**，应答方（无头测试注入的脚本、将来的匹配系统或前端）先读 `ask.options`（可选项：牌 + 这张牌的可用目标）再**返回**答复 `{ card = 那张牌 }`（要一次使用这类还要 `targets` —— 给单个或一张列表都行，**答复里的 `targets` 恒为列表**；返回空 = 不表态）。**第一个给出答复的胜出、后面的订阅者不再调**（2026-09-30 起；`ask:answer(...)` 已退休）。**答复读 `ask.card` / `ask.targets`**（没人答上 / 被取消 / **答复不在选项里** ⇒ 不存在）。**缘由**（如 `'杀'` / `'出牌'` / `'濒死'`）是**内核不解释**的值，惯例是写**发起这次询问的牌名 / 阶段名**（与 `reason` 一样不参与判断）；**要的是「使用」还是「一张牌」由类表达**（`AskCard` / `AskUseCard` / `AskPlayCard`）；**条件**（第三个参数）描述"要什么样的牌"—— 四个字段 `name?` / `zone?` / `card?` / `target?` 都是**筛选条件**（数组 = 满足其一、单值 = 归一化、不填 = 无要求；候选默认来自被问者的牌区，`zone` / `card` 给了就换成那里）：**内核在询问前把 `ask.options` 算好**；**业务层不自己拼候选**，**不给条件 = 不做限制**。询问结束后还会连着触发 **`'卡牌-答复'`** 与 **`'卡牌-答复后'`**（**有答复才触发**；没人应答不触发 —— 表达"问了没人答"是另一个事件，将来加），基础规则在它们里按缘由接手 —— `'打出'` ⇒ 牌进**发起那次结算的临时区**，它的收尾送 `弃牌`；**结果在应答的那一刻就定下了，所以这个时机里 `askCard.card` 读得到给出的牌**。所以**业务层（内容包）不用自己挪牌**；**内核里没有「打出」动作**（没有 `game:respond`、也没有 `'卡牌-打出后'` 时机）—— "打出"只是内容侧对 `'打出'` 这个缘由的解释。
- **还没做**：**判定区与延时锦囊**（判定动作本身已落地，见 §9.8）、**防具的技能**（八卦阵 —— **牌定义与分类已补齐**，缺的是「替换 / 追加一次响应」那条能力，见 §9.11；【仁王盾】已完成）、**装备自带的技能**（武器 / 坐骑的「加成」已落地，见 §9.11）、改伤害值 / 防止伤害 / 属性伤害；**询问的异步答复与超时**（本批是当场取答案）。
- **【2026-09-21 已落地；2026-09-22 改成当场结 + 判死归规则；2026-09-28 起 `Dying` 整体住 `@基础/濒死.lua`】濒死与【桃】**：体力降到 ≤0 ⇒ **濒死结算**（`Dying : Effect`）—— 检查点在 `@基础/伤害.lua`（扣完血判 ≤0 就 `受害者:enterDying(这次伤害)`），**求桃写在 `Dying:settle()` 里**（不是时机，2026-09-28 起）；**没人把体力回正 ⇒ `Dying` 自己 `setAlive(false)`**（「濒死效果负责杀死玩家」），回血方（`@基础/回复.lua`）在体力 > 0 时喊 `dying:leave()`。**时序：濒死就在那次伤害结算里、判死早于 `'伤害-生效后'`**（扣血 → 濒死（含判死 / 奖惩 / 胜负）→ `'伤害-生效后'` → `'伤害-结束'`）；**凶手读 `死者.dying.damage.from`**（不再记 `'凶手'` 标签）；【桃】两种用法（出牌阶段对自己 / 濒死时对濒死角色）写在 `package/标准/卡牌/桃.lua`。详见 §9.4。
- **【2026-09-20 已落地】牌的自动去向**：`game:askCard(被问者, 缘由, 条件)` 的第二、三个参数分别是**缘由**与**条件**（要什么样的牌，内核据此算 `ask.options`）；**缘由完全不解释**（只原样带给规则层）⇒ 询问结束后局上触发 **`'卡牌-答复'`**。**打出的牌不用业务层操心**（2026-09-23 起）：`game:askPlayCard` 在答复定下的那一刻就把那张牌放进**发起那次结算的临时处理区**（收尾时进 `弃牌`）⇒ **业务层完全不写 `moveCard`**（【杀】的响应只读 `ask.card`、按结果决定是否受伤）。

## 8. 时机系统（实现要点）

- 所有可变行为收敛为「时机（时机名 + 相关对象）→ 查询可触发技能 → 依序执行 → 可能请求玩家决策」。
- 技能分：触发技（被动，挂时机）、主动技（出牌阶段主动发动）、锁定技（必发，不可放弃）。
- **技能可以在任意时机插入**，因此引擎必须能在结算中途**停下来等人输入再继续**：遇到需要玩家决策的点就让出，等输入回来接着跑，而不是一路跑到底的函数调用。
- **建议：时机名用 `分类-动作` 风格**（`'游戏-开始'`、`'回合-开始'`、`'判定-前'`、`'伤害-后'`…）—— 前一段是分类、后一段是动作，便于把事件表按分类聚合；与“集中定义成一张枚举表”的初衷一致，但**不预设、不校验**（时机名仍是任意字符串，写法规约而已）。
- **落定机制（已实现）**：规则集用 `game:on(时机名, 回调)` 注册、装配 / 流程代码用 `game:fire(时机名, 载荷)` 触发（时机名**不预设**，注册顺序即执行顺序，注册随清空重装清空）。上下文**只装该时机的参数**（`'游戏-开始'` 没有参数 ⇒ 传空表），环境对象就是注入的 `game`（这一局的桌子 / 随机源 / 牌区都从它取）；**回调的载荷参数按它的具体类型取名**（`damage` / `askCard` / `phase` / `target` 这类，**别叫 `ctx`** —— 清单见 `moe-kill-dev` 的 `code-style.md` 第 8 节），每个时机的载荷类型写在 `server/core/loader/env-meta.lua`（纯类型文件，按事件名收窄字段类型；详见 `references/architecture.md` 第 10 节）。
- 载荷约定**只读**；加载期的回调**报错被隔离**（只记日志、不影响其它回调），所以“规则包出错”的可见信号是**状态没写**（如没写出牌堆），装配方要在 `fire` 之后断言必需状态。
- 要"覆盖"别人的效果就改**状态**（写标签 / 改属性 / 加标记），不做"回调返回值改事件载荷"那一套。

## 9. 对实现的结构性约束

1. 引擎是**纯逻辑**，不依赖 IO / jsonrpc；随机数必须可注入（固定 seed 可复现整局）。**内核（`server/core/`）不含任何游戏流程，也不预设区域名与属性名**——手牌区/装备区/体力 这些都在 `package/` 规则集里定义。
2. 决策点统一走「请求输入 → 挂起 → 恢复」，**挂起的持有者是流程内部**（`server/session/` 的会话外壳只当容器；在流程里封装它是后续批次），无头测试与前端走同一条路径（只是输入来源不同）。**整个游戏都在协程里跑**（用户 2026-09-21 确认）：装配方在协程里开局、触发 `'游戏-开始'`、启动流程，所以内容侧的时机钩子可以直接 `await`（放置走 `game:moveCard`、询问、用牌都是 await 点）。
3. 一次操作产生的表现需求（动画/音效）由后端输出为**事件流**，前端只消费，不反推状态。
4. 前端不参与任何规则判断：目标合法性、距离、可用牌列表**全部由后端计算并下发**。
5. 规则集**不参与开发期热重载**：`package/` 由自建装载器**读文件执行**（不走 `require` / `include`），所以改卡牌 / 技能代码要生效，得走**业务侧清空重装**（`moe.loader.install(game, { packages = 清单 })` 重新跑）或重启进程；**装载器与局这两份代码本身**（`server/core/loader/` 与 `server/core/game.lua`）与其它内核模块一样可热重载，已建好的局在重载后照常可用。因此：需要跨重载存活的数据必须挂在**跨重载仍是同一份的载体**上（这一局的数据挂局实例 `game`，如号源 `game:nextId()`；内核级、跨局的才挂门面表 `moe`），不要指望规则集文件里的 `local`。
6. **「规则集重载」是游戏业务功能，与开发期「热重载」是两个不同的东西**（用户 2026-09-19 明确要求）：前者是**运行期**重新装置 / 切换**这一局的**规则集（清空规则表 + 重新加载，触发者在业务侧），后者是**开发期**改代码不重启（触发者在开发者）。两者定位、生命周期与影响范围不同，**不要互相替代或混为一谈**（`moe.reload` 是后者，见 `moe-kill-dev` 的 `references/architecture.md` 第 8 节与第 9 节）。

### 9.1 规则集侧写法（已落地）

```lua

game:setValues { 默认体力 = 5 }               -- 规则数值：可被后续包覆盖的配置

local attributeSystem = game:getAttributeSystem()      -- 属性系统由这一局持有（包在加载期 define）
attributeSystem:define('体力上限', { min = 0, max = 999999 })
attributeSystem:define('体力', { min = -999999, max = '体力上限' })   -- 体力可为负、写值钳到上限

game:on('游戏-开始', function ()          -- 挂时机（分类-动作）：这个时机没有事件参数，上下文是空表
    local deck = game:createZone('抽牌', true)   -- 公共牌区挂局上（第二个参数 = 需要有顺序能力）
    deck:accept(game:createCard('杀'))                 -- 牌由局建（牌名交给内容定义）
    deck:shuffle()                                 -- 有序牌区洗牌不用再传随机源
end)

local slash = Card '杀'
    : on('生效', function (cardEffect) end)    -- 钩子是固定集合（见 §9.2）：'卡牌-进入区域' / '卡牌-离开区域' / '使用' / '生效' / '被动'（目标声明走 `targets` / `cardTargets` 条件，不再是钩子）
```

- 入口：**装载器 `moe.loader`**（`server/core/loader/`）+ **局 `moe.game`**（`server/core/game.lua`）：`moe.game.create { seats, random, sources?, packages }` 建**一局**并把规则装好（**建局即装**，`seats` = 座位数、桌子由局自己建；清单省略就只装默认加载的包），重装走 `moe.loader.install(game, { packages = 清单 })`（省略参数就复用局上记的来源与清单）；内容放在项目根 `package/` 下、**按包组织**（`package/标准/…`、`package/军争/…`）。
- **来源与合并**：可配置多个来源（`moe.loader.install(game, { sources = { './package/*', 'D:/某合集/*' } })`）；来源里**后面的覆盖前面的**，同一逻辑路径只执行最后一个来源的那个文件（用户自定义包就是靠这个替换标准包的文件）。逻辑路径第一层恒为包目录名。
- **清单项是逻辑路径**（如 `标准/卡牌/杀`）：先按文件解释（`.lua` 可省），不存在再按目录解释（递归、只取 `.lua`）；清单是唯一入口（加进去即生效，移除即失效）。
- **依赖用路径写、写在文件顶部**，并**支持相对路径**：`Depends { './卡牌/杀' }`、`Depends { '../../基础规则/回合流程' }`。**默认包（`@` 开头，如 `@基础`）不必写** —— 加载器自动把它排在清单项之前（用户 2026-09-21 指出）。- **互斥**：`Depends { '!国战' }` 表示本轮不能加载该项（模式之间互斥靠它）；项与依赖项同一套路径解析（含相对路径），没被加载就不报错，冲突时在**执行任何文件之前**报错。- **包与名字路由**：包名 = 逻辑路径第一层目录；`package/军争/卡牌/火杀.lua` 里写 `Card '火杀'` 登记为 `军争.火杀`。**同包内不许重复声明**（两处建同名条目直接报错），跨包同名合法并存。
- **默认加载标记**：包目录名以 `@` 开头（`package/@基础`）⇒ 该包自动加载（清单不用写它，且排在最前），引用时**一律写不带 `@` 的名字**：限定名 `基础.杀`、`game:getPackageMeta('基础')`。
- **裸名带包内作用域**：包内写裸名**先取本包**，本包没有才按清单顺序取第一个定义它的包；**引用他包的同名条目必须写限定名**（军争里想用标准版「杀」要写 `标准.杀`）。包外（游戏运行期）的裸名直接按清单顺序取先加载的包。
- **跨文件给同一条定义追加回调**：先 `Depends { '../卡牌/杀' }` 保证顺序，再 `game:getCard('杀'):on(...)` —— **不能用 `Card` 再声明一次**。
- 条目带 `name` / `package` / `fullName` / `source`（声明它的文件），报错与排查时直接用。
- **挂时机**：`game:on('游戏-开始', function (event) ... end)` —— 注册顺序即执行顺序（后注册的后执行，写下的状态覆盖先前的，所以“覆盖别人的默认值”也靠它——例：身份场把主公体力上限抬 1）；订阅随每次装载清空（`game:on` 不限于加载期，但内核 / 装配的长期簿记别挂它上面）；**内容包不要主动 `game:fire`**（触发是装配 / 流程代码的事）。
- **规则数值**：`game:setValue(名字, 值)` / `game:setValues { ... }` 落默认值，读用 `game:getValue(名字)`（没设置得到 `nil`，自己写 `or 默认`）；**挂在局上一张表、按加载顺序后者覆盖前者**（这就是后续包改默认值的正道），与规则表同生命周期。**不要往里存函数**：行为写时机注册。
- **注入面是 `game`（这一局）、`rule`（装载器每轮建的共享袋）、`Class` / `New`（内核类那两个全局）与 `Card` / `Depends`（加载期环境函数，大写）**：内核门面 `moe`（含 `moe.core` 这类写法）、`require` / `io` / `os` 都拿不到。包需要的内核资源全从 `game` 取：**属性系统**用 `game:getAttributeSystem()`，**这一局的牌 / 牌区 / 桌子 / 随机源**用 `game:createCard(name)` / `game:createZone(名字, 有序?)` / `game.desk` / `game.random`（**只认字段，没有 getter**）。
- **工具集是对（内容侧）标准库的扩充**（用户 2026-09-21 定，不是内核注入的 —— 工具集与游戏规则无关）：默认包 `@tools` 往内容侧的 `table` 上加六个函数 —— `table.filter(列表, 判定)` / `table.map(列表, 变换)`（回调收 `(值, 下标)`）/ `table.contains(列表, 值)` / `table.without(列表, 值)`（去掉这个值的所有出现，**返回新列表**）/ `table.mergeArray(列表, ...)`（依次接在后面，**改第一个表**）/ `table.copy(表)`（`pairs` 浅拷贝，改它不影响原表），清单以 `package/@tools/table.lua` 为准。**没装 `@tools` 的局仍然有 `table`，只是没有这几个函数**；助手写在沙箱里（`io` / `os` / `moe` 都够不着）⇒ 想写带副作用的助手也写不出来。另有一个没有标准库可挂的助手 **`util.defer(回调)`**（`package/@tools/util.lua`）：拿一个 `<close>` 收尾对象，作用域一结束（正常 / 出错 / 提前 return 都算）就跑回调 —— 判定里那个改判窗口守卫就用它（用户 2026-09-28 定）。
- **内容侧的标准库是副本**（用户 2026-09-21 定）：`table` / `string` / `math` / `utf8` 在每轮装载时各浅拷贝一份 ⇒ 内容侧给它们加函数 / 改函数**只影响内容侧**、内核不受影响，重装换新副本。**泛型要标在实体函数上**（`---@generic T` + `function table.filter(…)`）—— LuaLS 不支持 `---@field f fun<T>(…)`，写进 `meta.lua` 反而会把泛型压平。
- **包之间共享函数：直接写全局函数**（用户 2026-09-21 定）—— 整轮装载**共用一份书写环境**，所以 `function 是否受伤(player) ... end` 写在哪个文件里，后面的文件（含别的包）就能直接调。注意三点：**顺序敏感**（要用别人的函数就要求它先加载，可以用 `Depends` 定序）、**注入的 `game` / `Card` / `Depends` / `Class` / `New` / `rule` 每个文件加载前会刷回**（别拿它们当全局变量用；`table` 是内容侧的副本、没有这层保护）、**重装换新环境**（上一轮的全局与扩充自然消失）。沙箱没变：仍然看不到 `moe` / `require` / `io` / `os`。
- **接口面在哪（包作者视角）**：`server/core/loader/env-meta.lua` 是内核的纯类型文件，声明了注入的 `game` / `Card` / `Depends` / `Class` / `New` / `rule` 与每个时机的**载荷类型** —— 新增时机要顺手补一条；**包自己的概念**（身份、规则数值、自有标签）写在**包目录下的 `meta.lua`**（纯 LuaDoc，固定叫 `meta`）：

```lua
-- package/身份场/meta.lua：纯类型声明（不是规则内容，装载器照常当普通文件执行，里面只有注释）
---@meta
---@alias 身份场.身份 '主公'|'忠臣'|'反贼'|'内奸'
---@class Player: Class.Base                          -- 基类要写全
---@field identity? 身份场.身份                          -- 内容侧 身份.lua 写入的字段
---@class Game
---@field getValue fun(self: Game, name: '身份配置'): table<integer, 身份场.身份配置项[]>
---@field getValue fun(self: Game, name: string): any   -- 兜底必须自己再写一遍（否则会把内核签名吃掉）
```

  于是 `player.identity` 在编辑期就是那四种身份的联合类型（拼错取值就报），`game:getValue('身份配置')` 也有了结构。**不提供可单独分发的 meta**（引用链横跨 `Game` / `Moe` / `moe` / `bee`，单独导出不完整）：第三方开发者**直接打开本工程**写包，包目录写进来源清单即可。
- **不要为空值防御**：注入的 `game` 按约定一定在（它就是这一局）；只有**真的会缺**的才 `error` —— 例如清单里可能没有内容包（⇒ 没牌表）、人数不在身份配置表里。详见 `moe-kill-dev` 的 `references/code-style.md` 第 9 节。
- **属性定义只能在加载期写**：属性系统由**这一局**持有（一局一份，清空重装时重置），属性库把定义编译成生成函数、**编译后不允许再 `define`**（会在运行期报 `Cannot define new attributes after compilation`）⇒ `define` 写在包文件顶层，别写进「游戏-开始」回调。玩家侧读写用 `player:setAttr / getAttr / addAttr`（前两个等价于 `getAttributes():set/get`；**`addAttr` 是 `getAttributes():addModifier` 的直接转发** —— 同样做增减，只是多返回一个「精确减掉这次加量」的撤销函数，不理它当单向增减用也没问题）。
- **牌区的建法**：**四个基础区由内核建好**（局上 `抽牌` / `弃牌`，玩家身上 `手牌` / `判定`）—— 内容侧**直接取、不得重建**（`game:getZone('弃牌')` / `player:getZone('手牌')`）；要加**自己**的区才用 `game:createZone(名字, 有序?)`（按名字登记、之后 `game:getZone(名字)` 取回）或 `player:addZone(名字)`，要顺序能力就传 `moe.orderedZone.create(局)` / 第二参数 `true` —— **装备的四个子区就是这么建的**（见 §9.11）。**自造牌区要带上局**（`moe.zone.create(局)` 之类 —— 牌区自己记着局，进区的牌才能按定义发 `'卡牌-进入区域'`）。
- 文件里**不需要 `require`**：注入 `game` / `Card` / `Depends` / `Class` / `New` / `rule` + 一份标准库白名单（`require` / `io` / `os` 一律没有；`table` / `string` / `math` / `utf8` 是内容侧的**副本**）；工具函数是默认包 `@tools` 给那份 `table` 加的。
- **中文标识符只留给难翻译的内容名**（技能名 / 卡牌名 / 身份名，以及规则数值的键与属性名），**字段名 / 局部变量 / 函数名一律英文**（如 `local slash = Card '杀'`）；中文标识符本身是构建期给 Lua 打的补丁（见 `moe-kill-dev` 的 `references/infrastructure.md`），关键字与 ASCII 标识符行为不变。
- 重装 = **清空局上的内容 + 重新加载**（不做按名单卸载，桌子 / 随机源 / 牌区不被清掉）；同一份清单重复加载会**重新执行**所有文件。加载、依赖、定义入口的细节见 `moe-kill-dev` 的 `references/architecture.md` 第 9 节，契约见 `server/test/rule/` 下的规则侧套件（规格快照已冻结）。

### 9.2 第一张牌：「杀」与响应（已落地）

```lua
-- package/标准/卡牌/杀.lua
-- 【杀】（标准版）
-- 出牌阶段，对你攻击范围内的一名其他角色使用：该角色需打出一张【闪】来抵消，否则受到你造成的 1 点伤害。

Card '杀'
    : extends '基本牌'                            -- 公共模板（@基础/卡牌/基本牌.lua）：分类「基本」+ 只能从手牌用
    : limit('出牌', 1)                            -- 每出牌阶段限一次：限额写在定义上（不写就是 1000 = 不限）
    : targets {                                  -- 目标条件：个数区间 + 逐角色谓词（不声明整条 = 这张牌没有「对角色使用」这一支）
        filter = function (player, plan)          -- 合法目标由牌自己当场判：内核不作任何具体判定
            return player ~= plan.user            -- 射程给 nil = 自己的攻击范围（要显式射程就写第 2 参）
               and plan.user:isInRange(player, nil, plan.useOptions)
        end,                                     -- 没人过 = 空列表 = 现在用不了
    }
    : on('生效', function (cardEffect)         -- 每个目标各跑一次
        local target = cardEffect.target
        local card   = game:askPlayCard(target, '杀', { name = '闪' }).card  -- 要一张打出的牌：缘由 = 发起询问的牌名，条件「名字是闪」
        if card then                                                    -- 答复的牌已当场交进发起那次结算的临时区（收尾进弃牌）
            return                                                      -- 有闪就不受伤
        end
        game:damage(cardEffect.user, target, 1, cardEffect.card) -- 伤害入口：扣体力、≤0 进濒死
    end)
```

- **流程怎么被启动**（2026-09-21 落地）：回合流程是**内容**（`package/@基础/回合.lua` 在加载期 `game:registerFlow(function () ... end)`），由**装配侧**用 `game:runFlow()` 启动（无头测试 / 将来的房间 / 会话）—— 返回的是**任务**（`moe.task`）：可 `await` 等这局跑完、`.result` / `.err` 读结果与失败、`cancel()` 停掉；**流程不是效果**（不进记牌器 —— 它跑得比谁都长，进了就把真结算全挤成子效果）。内容包拿不到 `moe`，自己起不了协程，所以“谁启动”必须由装配侧来。
- **定义上的三件套**（2026-09-22 落地；分类口径 2026-09-23 改成覆盖）：`kind`（**分类**，内核只记录、不解释；取值省略「牌」字 —— 基本 / 锦囊 / 装备。**一次调用就把分类定下来**：要多个就给一张列表 `: kind { '锦囊', '延时锦囊' }`，**重复调以后写的为准**（不再累加）；**要「在基类分类之上再补一条」就用 `addKind`**（2026-09-24 补上 —— 它只往里加、已有的不动，`kind` 则是覆盖）、`zone`（**必须从哪个牌区用**，由 `canUse` 的内建条目判：不声明 = 使用者的任一牌区都行）、`extends`（把基类定义的**钩子与字段抄**过来：基类的钩子跑在前面、**分类拄过来也是覆盖**（基类没声明分类就不动子定义自己的）、抄完即与基类脱钩）。公共模板写在默认包里（`package/@基础/卡牌/` 下的 `基本牌.lua` 就一句 `Card '基本牌' : kind '基本' : zone '手牌'`，它不在牌表里、不会被真的造出来），具体牌 `: extends '基本牌'` 继承即可。**类基类文件的加载顺序要自己声明**（同一目录按名字排序，`武器牌.lua` 排在 `装备牌.lua` 前面 ⇒ 写 `Depends { './装备牌' }`）。
- **用牌入口**：`game:useCard(使用者, 牌, 目标们)` —— 机制自己在**使用者名下牌区**里找到这张牌（内核不预设「手牌」这类区域名），**校验全部通过才取出**并结算；校验不通过（内建条目（含**次数**）或内容侧的 `'卡牌-能否使用'`）⇒ 这次生效**以「不成立」收尾**（`.err` = 原因、**不报错、不取牌、不记账**）；过了就由内核在阶段上记一次。筛选与二次校验共用同一个 `game:canUse`（见 `moe-kill-dev` 的 `architecture.md` §12）。
- **目标口径（fail-closed + 数量区间）**：每张牌在定义上用 `CardDef:targets { min?, max?, filter? }` 声明**目标条件** —— `filter` = 逐角色谓词 `fun(player, plan): boolean`（不写 = 全部存活角色；`plan` = `{ user, card, targets?, useOptions? }`），`min` 省略 = 1、`max` 省略 = `min`，**不声明整条 = 这张牌没有「对角色使用」这一支**（【闪】这类就靠它主动用不出去）。给了目标时：个数先看区间 —— 少于 `min` ⇒ 拒（`{}` 也在内），多于**最终上限** ⇒ 拒，最终上限 = `min(max + extraTargets, 合法目标数)`（**额外目标数与合法目标数取较小值**）；`{ min = 0, max = 0 }`（装备牌这类）反过来 —— **给了非空目标就是不成立**。过了数量再看**子集**：必须是内核逐角色过 filter 筛出的**合法目标列表**的子集；牌**没声明目标条件 / 没有角色过得了 filter** ⇒ 这张牌**现在用不了**（明确失败、牌留在原处），不声明 MUST NOT 被当成「谁都能打」（`{ 0, 0 }` 的牌不走这条路）；多次声明同一张牌时 filter **叠加**（逐条都要过）、`min` / `max` **后者覆盖前者**（`extends` 也按这条：基类的 filter 在前、抄给子类后子类再声明就叠在它上面；深拷贝、兄弟子类互不影响）。**候选者自己也能否决**（2026-10-09 加）：逐候选过完 `filter` 之后内核还会**问候选者自己一句 `'卡牌-目标-能否指定'`**（返回非空 = 不能指定他，【谦逊】用它）—— 「不能被选择为目标」的写法在这里，**不要塞进 `filter`**（那是发起方视角的判据，写进去等于牌自己在替别人做主）。**只要那份全量名单**另有读取口 **`game:getLegalTargets(使用者, 牌, 选项?)`**（只筛目标、不判「能不能用」、不合并选项；牌没声明目标条件 / 一个都没有 = 空表，2026-10-09 加 —— 改目标类技能用它，见 §9.30）。
- **内容侧事件名（牌的钩子）**：`'生效'`（对**每个目标**各调一次，按目标在行动顺序上先后；同一张牌为同一目标声明多个钩子时按声明顺序执行）；另有**只跑一次**的 `'使用'`（一次用牌一次、逐目标之前；载荷 = 这次用牌的效果实例；**声明 `: skipEffect()` 的牌到此收口** —— 这次不发起「生效」，见 §9.12；原名 `'结算前'`，2026-09-28 改；它夹在全局 `'卡牌-结算前'` / `'卡牌-结算后'` 内侧，同日 `'结算后'` 删 —— 装备牌改挂 `'使用'`），以及 **`'卡牌-进入区域'` / `'卡牌-离开区域'`**（载荷 `(card, zone, visible?)`：牌**落进 / 离开某个牌区时**由那个区发 —— 公共区（抽牌 / 弃牌 / 临时区）也发；`visible` = **这次搬动对谁可见**（`moveCard` 的第三参，不给就是空 —— 见 `architecture.md` 的「可见性收成一个模块」条）；**2026-10-09 起每个区发两份**：先给**牌自己**（`CardDef` 钩子）、再给**区的主人**（同名 —— `SkillDef:event('卡牌-离开区域')` 订的就是它，【枭姬】用它；**公共区没有主人 ⇒ 只有一份**））与 **`'被动'`**（被动**被启用**时跑一次、返回撤销函数；装备的加成与自带技能都写在这里 —— 见 §9.11）。`'生效'` 的钩子拿**两个参数** `(cardEffect, useCard)`：前者是对该目标的那一次生效（`CardEffect`，字段 `user` / `card` / `target`），后者是**这次用牌**（要临时区直接 `useCard:getTempZone()`）。钩子是**固定集合**（与启用的包无关、没有扩展需求）：清单以 `server/core/loader/env-meta.lua` 为准，拼错在编辑期就报 —— 新加钩子要同步补进那里。钩子里的 `card` **能直接读自己的分类与数据**（`card:isKind('武器')` / `card:getValue('攻击范围')` / `card.fullName` —— 牌自己记着局，见 §9.11）。
- **响应（打出）**：【杀】的每个目标在生效时问一次「要一张【闪】」（`game:askPlayCard(target, '杀', { name = '闪' })` —— 类告诉内核“这次要的是**打出去的**牌”，**条件**说“名字是闪”）；拿到了就结束这次生效，没人答上 / 答的不是选项里的牌（`ask.card` 为空）则照常造成伤害。**应答方不在内核里**：谁收到询问、怎么给出牌，由挂在局上 `'卡牌-询问'` 时机的那些订阅者决定（测试是脚本，将来是匹配系统 / 前端），**它们读 `ask.options` 拿可选项**（内核已经按条件算好了）。
- **牌的去向**：内容包**不写 `moveCard`** —— 用过的牌由**内核**在取出之后放进**这次用牌的临时区**；打出的牌由 `AskPlayCard` 在答复定下时放进**发起那次结算的临时区** —— **去向由内核一处收尾**（效果结完时把临时区剩下的牌送 `弃牌`，2026-09-24 起；见 `moe-kill-dev` 的 `references/architecture.md` 第 12 节）。
- **区域名：五个基础区由内核建**（2026-09-24 起）—— 局上 `抽牌` / `弃牌`、玩家身上 `手牌` / `装备` / `判定`；内容侧直接取（`game:getZone('弃牌')` / `player:getZone('手牌')`），**不得重建同名区**；要加自己的区才用 `game:createZone` / `player:addZone`。**区名不带尾巴**（不写「抽牌堆 / 弃牌堆」这类最后那个字，用户 2026-09-20 定）。
- **本批不做**：濒死与死亡、装备、判定、无懈可击、八卦阵 / 龙肝这类"同一响应窗口里的多个候选技能"（**目标数量已于 2026-09-29 落地、2026-10-08 收敛成 `targets` 条件**：定义上的 `targets { min, max, filter }` + 使用选项里的 `extraTargets`，见 `moe-kill-dev` 的 `architecture.md`）。

### 9.4 濒死与【桃】（已落地）

```lua
-- package/@基础/伤害.lua：结算里扣体力，扣到 ≤0 就进濒死（转交 player:enterDying）
function Damage:settle()
    local to = self.to
    to:addAttr('体力', -self.amount)
    if to:getAttr('体力') <= 0 then
        to:enterDying(self)                                      -- 当场结算；这次伤害一并交出去
    end
end

-- package/@基础/濒死.lua：求桃直接写在 Dying:settle() 里（不是时机，2026-09-28 起）
function Dying:settle()
    local player  = self.player
    local game    = self.game
    if self.left then
        return                                                      -- 已经脱离过的：不问也不杀
    end
    local condition = { name = '桃', target = player }              -- 条件：名字是桃、要能用在濒死者身上
    for asker in game.desk:actionOrder() do                         -- 一圈：顺序锚点起（内核兜底：当前回合角色 → 上一个 → 都没开过回合就 1 号位）
        for _ = 1, 1000 do                                          -- 上限 1000 次，防「答复不前进」死循环
            if not game:askUseCard(asker, '濒死', condition).useCard then
                break
            end
            if self.left then
                return                                              -- 救回来了就收工
            end
        end
    end
    player:setAlive(false)                                          -- 一圈都没人救 ⇒ 判死
end

-- package/@基础/回复.lua：体力回正 ⇒ 由回血方喊“脱离”
function Heal:settle()
    local to = self.to
    to:addAttr('体力', self.amount)
    local dying = to.dying
    if dying and to:getAttr('体力') > 0 then
        dying:leave()
    end
end
```

```lua
-- package/标准/卡牌/桃.lua
-- 【桃】（标准版）
-- 出牌阶段，对自己使用：回复 1 点体力；或令一名处于濒死状态的角色回复 1 点体力。
Card '桃'
    : targets { filter = function (player, plan) ... end }   -- 已受伤（未满）的自己 + 体力 ≤0 的存活角色
    : on('生效', function (cardEffect) game:heal(cardEffect.target, 1) end)
```

- **`@基础/濒死.lua` 提供两样**（2026-09-28 起全在内容侧，且**不再为它开专用时机**）：`Dying : Effect`（携带把它打到濒死的**最后一次**伤害；`settle()` = **直接求桃** → **没人喊 `leave()` 就没收成功 ⇒ `setAlive(false)`**；`leave()` 幂等、记「已脱离」并清账）与 `Player:enterDying(伤害?)`（**当场**结算；**状态就是这个玩家的字段 `player.dying`** —— 没有 `getDying`，直接读字段）。**“血量 ≤0 算濒死”在规则里**（`@基础/伤害.lua` 判），**“结完没脱离就死”也在规则里**（只看 `left` 标记，不看血量）—— 口径上仍是「濒死效果负责杀死玩家」。
- **一个角色同时只有一个濒死状态**（状态 = 玩家字段 `player.dying`，2026-09-28 从局上的私有字段搬来、**不走通用标签袋**）：已在濒死中又被打到（或再进）⇒ `enterDying` 返回**现有实例**并把它 `damage` 换成后一次（致死伤害 = 最后一次打他那一击，凶手也按这次算），**不重开结算**；`leave()` 过的旧实例不算「正在濒死」，再进就是新的一次。
- **濒死插在哪一刻**：由**调用点**决定 —— 现在是 `@基础/伤害.lua` 扣完血判 ≤0 那一下，所以**濒死就在那次伤害的结算里**（扣血 → 濒死（含判死 / 奖惩 / 胜负）→ 伤害这次结算才结束）。旧的「属性监听 + 记账 + 结算收尾 flush + 撤销」写法已删。
- **【桃】两种用法都是「使用」**（官方描述：出牌阶段对自己 / 濒死时令濒死角色回复）⇒ 求桃拿到牌后直接 `game:useCard`，桃的效果与去向都只写一处。
- **求桃的一圈**（官方口径，2026-09-23 改正；2026-09-28 改用现有迭代器）：**从顺序锚点起**绕一圈 —— 直接用 `desk:actionOrder()`（每名存活角色一次机会、阵亡者自动跳过、走完一圈结束）；回正之前**一直问同一个人**（答了就接着问他、答不上来才换下一个，也就是官方那个「新的『处于濒死状态时』从上次响应者 B 起到当前回合角色的上家」而不回头问前面的人）；体力 ≥1 立刻停。**锚点由内核兜底**（2026-09-28）= **当前回合角色 → 上一个回合角色 → 1 号位**：回合内是当前回合角色；**回合结束后是上一个回合角色**（官方『一名角色的回合结束后……若该角色存活，从其开始』）；都没开过回合就从 1 号位起（原来报错，已改）。
- **回复**：`Heal : Effect` + `game:heal(目标, 点数)`，与伤害对称（加体力 + 脱离濒死都写在 `@基础/回复.lua` 的 `Heal:settle()` 里）。
- **还没做**：濒死中连锁的特殊处理（如“濒死中再次进入濒死”的复杂插入——现在就是换致死伤害、返回同一实例）。（死亡奖惩见 §9.7。）

### 9.5 常用动作：抽牌（以及"动作该怎么给大家用"）

```lua
-- 任何包、任何地方：让某个人摸 3 张
player:draw(3)
```

- **`Draw` 里直接取牌**（2026-09-28 起这个类也住 `package/@基础/抽牌.lua`）：`Draw : Effect`（`kind` = `draw`，字段 `player` / `count`）在 `settle()` 里直接 `game:drawCards(player, count)`（**不走时机**；`@基础` 是默认加载包 ⇒ 任何局都有它）—— 内部就是 `game:getZone('抽牌'):draw(count)`（**内核牌区接口**，见 §9.8）→ **整批**一次 `game:moveCard` 进该玩家的 `手牌`；牌堆不够时由牌区上挂的不足回调把 `弃牌` 全部洗回（`@基础/牌堆.lua` 一处），两张堆都空时能摸多少算多少（不报错）。

### 9.6 游戏结束（胜负判定已落地）

```lua
-- package/身份场/胜负.lua（判据在内容）
game:on('玩家-死亡', function ()
    if game:getResult() then return end
    ...
    game:endGame { side = '反贼', reason = '主公阵亡' }
end)
```

- **信号在内核、判据在内容**：内核只给 `game:endGame(result)`（幂等）/ `game:getResult()` 与 **`'游戏-结束'`** 时机；结果类型 `Game.Result` = `{ side, reason }` —— `side` 取官方术语 `'主公方'` / `'反贼'` / `'内奸'` / **`'平局'`**，`reason` 是给人看的中文短句（前端可直接显示）。
- **判据（`package/身份场/胜负.lua`）**：① **主公阵亡** ⇒ 此刻只剩一个存活者且是**内奸**则内奸胜，否则**反贼胜**（含「反贼已全灭」与「内外同归于尽」两种情形，官方都算反贼胜）；② **主公活着**且存活者里已无反贼与内奸 ⇒ **主公方胜**。
- **平局的判据在基础规则里**（2026-09-23 落地）：**牌堆与弃牌堆都没牌** ⇒ `package/@基础/牌堆.lua` 挂在抽牌区上的「不足回调」洗不回来，就地 `game:endGame { side = '平局', reason = '牌堆与弃牌堆都没有牌' }` —— 平局与身份无关；一处覆盖摸牌 / 判定 / 将来任何取顶动作。发现即结束 ⇒ **这一次取牌里已经取到的牌不会再挪给谁**（见下面「结束后不再起新的结算」那条）。
- **流程会被就地收掉**：`endGame` 记下结果 → 触发 `'游戏-结束'` → `Task:cancel()` 掉这一局的流程任务（挂起中的流程协程被关掉）⇒ **回合不再转**。流程以「取消」收尾**不算失败**，是不是正常终局看 `game:getResult()`。
- **结束后不再起新的结算**：`Effect:apply()` 开头查一次结果 —— 已结束 ⇒ 这次生效以「取消」收尾（所以多目标【杀】打死主公后不会再打下一个目标、结束后也不会再起新的濒死）；**已经跑着的结算不打断**（记牌器只增，没法猜「谁还在跑」）。
- **还没做**：**再开一局**（用户 2026-09-21 定：将来做法是**重新建一个 `Game` 实例**，不是重置当前局）。

### 9.7 死亡奖惩（已落地，2026-09-22）

```lua
-- package/身份场/奖惩.lua（注册在 '玩家-死亡' 上；胜负.lua 靠 Depends { './奖惩' } 排它后面）
game:on('玩家-死亡', function (player)
    local dying  = game:getDying(player)                            -- 死亡时机里那次濒死的账还在
    local damage = dying and dying.damage                           -- 致死伤害 = 最后一次打他那一击
    local killer = damage and damage.from
    if not killer or killer == player then return end               -- 无凶手 / 自杀 ⇒ 不奖惩
    if player:getTag('身份') == '反贼' then
        killer:draw(3)                                               -- 已阵亡的凶手由 Draw 自己拦
    elseif player:getTag('身份') == '忠臣' and killer == game.desk:getPlayer(1) then
        game:moveCard(killer:getZone('手牌'):list(), '弃牌')          -- 主公杀忠臣：弃所有手牌
    end
end)
```

- **顺序**：官方是「死亡 → 奖惩 → 胜负判定」—— 两者都挂在 `'玩家-死亡'` 上，**先注册的先跑**，所以 `package/身份场/胜负.lua` 顶部写 `Depends { './奖惩' }`（依赖先加载、先注册）。用例钉住了“反贼是最后一个死的”那种情形：奖励的那 3 张必须真的摸到（若胜负先跑，`game:draw` 会因为游戏已结束被取消）。
- **凶手从哪来**：读 `'玩家-死亡'` 时死者的那次濒死 —— `死者.dying.damage.from`（规则层不认识“凶手”，只把致死伤害搬在 `Dying` 上，**不额外记标签**）。“无来源伤害 / 失去体力” ⇒ `damage` 为空 ⇒ 不奖惩；自杀（凶手 = 死者）也不奖惩。**注意读的时机**：只在 `'玩家-死亡'`（同步、还在濒死收尾之前）读得到；规则侧在 `'玩家-死亡'` 发完之后才清账。
- **已阵亡的凶手照发**（用户 2026-09-22 定）：奖励照调 `game:draw`，死者那份由内核的 `Draw` 拦掉（而不是在奖惩里写分支）。
- **还没做**：主公杀忠臣的「**装备牌**」—— 装备区还不存在（等装备与距离修正那批），现在只弃手牌；奖惩文件顶部留了说明。

### 9.8 判定（动作已落地，2026-09-23）

```lua
-- 任何包、任何地方：让某个人判定（缘由内核不解释）
local judge = game:judge(player, '八卦阵')
-- 判定结果就是判出的那张牌
local card = judge.card
```

- **形状：亮牌 → 改判 → 结果已定**（**两个时机**按次序发出，不靠注册顺序；**翻牌不是时机** —— 亮牌就是判定自己的第一步，`@基础/判定.lua` 在 `settle()` 里直接 `game:drawCards(player, 1, judge:getTempZone())` 翻进 `judge.card`，专用事件只在真有外部介入需求时才开）：
- **两个时机各发两份：全局一份 → 对判定者再发一份**（2026-10-09，`add-judge-player-event`）—— **同名**（判定没有「来源 / 目标」之分可用，与 `'阶段-开始'` / `'效果-收尾'` 同属「同名两份」那一类，见 `architecture.md` §12 的方向词规则）⇒ 文本里管「**你的**判定」的订自己那份（【洛神】【天妒】）、管「**一名角色**的判定」的订全局那份（【鬼才】）；发的时候全局先、当事人后。

| 时机 | 谁用 | 做什么 |
| ---- | ---- | ---- |
| `'判定-前'` | 技能（改判：【鬼才】订**全局**那份） | **改判窗口**：`judge:replace(新牌)` 换掉当前判定牌（新牌也进临时区，被换下的记进 `judge.replaced`；**窗口外调什么也不做** —— 写错调用不炸局）；对当事人再发的那份也在这个窗口里 |
| `'判定-后'` | 【洛神】【天妒】（均订**自己**那份）、内容侧 | 结果已定；牌的去向由**内核的默认收尾**统一处置（`Effect` 结完时把临时区剩下的牌送 `弃牌`）—— 「**获得**判定牌」类技能就在这里、趁收尾之前把它搬走 |

- **结果 = 那张判定牌**：内核**不认识花色 / 点数**（也不预设它们），调用方拿到牌后自己解释（【乐不思蜀】看是否红桃、【闪电】看是否黑桃 2~9）—— **牌面（花色 / 点数）已落地**（§9.9）：读 `judge.card.suit` / `judge.card.point`。
- **判定牌来自抽牌堆顶**：随机性由「开局洗牌 + 不足时洗回」承担（局上的随机源可注入 seed ⇒ 整局可复现），没有单独的“判定随机源”。
- **改判是同一趟里依次换**：先注册的看到旧牌、后注册的看到换过的牌；**不是**「换一次就重新发一轮」（那需要终止条件，且有死循环风险）。
- **取顶 / 洗回是牌区接口**（与摸牌共用）：`OrderedZone:draw(n)`（从区顶取 n 张，不够就少给、不报错）+ `OrderedZone:setShortageHandler(fn)`（取空了调一次这个回调补牌；`@基础/牌堆.lua` 挂的是「弃牌全部洗回抽牌 + `shuffle()`」）。
- **判定区与延时锦囊的逆序结算已落地**（2026-09-28，见 §9.12）；**还没做**：技能的改判实现（牌面已落地，见 §9.9）。

### 9.9 牌面：花色与点数（已落地，2026-09-23）

```lua
local card = game:createCard('杀', '黑桃', 7)   -- 建牌时把牌面给进去
card.suit    -- '黑桃'（花色）
card.point   -- 7（点数）
```

- **口径**：花色取值 `'黑桃'` / `'红桃'` / `'梅花'` / `'方块'`；点数取数字 **`1..13`**（A=1 … K=13，官方记法只是展示层的事）。判定要判区间（如【闪电】看是否黑桃 2~9）、拼点要比大小，数字最省事。
- **颜色由花色推**：`card.color`（2026-09-30 落地，`__getter` 当场算）—— 红桃 / 方块 ⇒ `'红'`、黑桃 / 梅花 ⇒ `'黑'`，没有花色就没有颜色。
- **内核只存不解释**（用户 2026-09-23 定）：`Card` 多两个字段 `suit` / `point`，`game:createCard(名字, 花色, 点数)`（后两个可选）；**内核不校验取值、不换算**，两个字段**直接读**（不另给 getter，项目规则见 `moe-kill-dev` 的 `references/code-style.md` 第 11 节）。
- **牌表是逐张的**（`package/标准/牌表.lua`）：`{ name = '杀', suit = '黑桃', point = 7 }` 一张一条，`@基础/牌堆.lua` 建牌时把牌面传下去。**张数与牌面还是草稿，待按官方标准版核对**（延时锦囊已进表：乐不思蜀 ♠6/♥6/♣6、闪电 ♠A/♥Q，按 biligame「标准包卡牌」的 108 张表核过；**整表核对时注意：标准包每花色 27 = 13 点 × 2 张 + 1 张 EX，同花色同点数允许是两张不同的牌**（如 ♠6 = 乐不思蜀 + 青釭剑），别按唯一性判错）。
- **判定怎么用**：`game:judge(玩家, 缘由)` 翻出的那张牌就带着牌面（§9.8），调用方直接读 `judge.card.suit` / `judge.card.point`。

### 9.10 锦囊（普通 / 非延时；已落地 10 张：无中生有 / 南蛮入侵 / 万箭齐发 / 桃园结义 / 决斗 / 五谷丰登 / 过河拆桥 / 顺手牵羊 / 借刀杀人 / 无懈可击）

```lua
-- package/@基础/卡牌/锦囊牌.lua（模板：不在牌表里、不会被造出来）
Card '锦囊牌'
    : kind { '锦囊', '非延时锦囊' }
    : zone '手牌'

-- package/标准/卡牌/无中生有.lua
Card '无中生有'
    : extends '锦囊牌'
    : targets {
        filter = function (player, plan)
            return player == plan.user      -- 官方：对自己使用
        end,
    }
    : on('生效', function (cardEffect)
        cardEffect.target:draw(2)         -- 摸两张
    end)
```

```lua
-- package/标准/卡牌/南蛮入侵.lua（万箭齐发同形，只把条件里的「杀」换成「闪」）
Card '南蛮入侵'
    : extends '锦囊牌'
    : targets {
        max = 1000,                      -- 上限不限就写大数（min 省略 = 1）
        filter = function (player, plan)
            return player ~= plan.user   -- 所有其他角色
        end,
    }
    : on('生效', function (cardEffect)         -- 每个目标各跑一次
        local target = cardEffect.target
        if game:askPlayCard(target, '南蛮入侵', { name = '杀' }).card then
            return                             -- 打出了就不受伤
        end
        game:damage(cardEffect.user, target, 1, cardEffect.card)
    end)
```

- **多目标 + 响应**：【南蛮入侵】与【万箭齐发】只需要「`targets` 筛出所有其他角色（`max = 1000`）」+「`'生效'` 里问那张牌」—— 逐目标结算、行动顺序、响应询问、伤害都是现成的（与【杀】的【闪】响应同一个写法）。
- **【桃园结义】（2026-09-23）**：官方「使用目标：所有角色」+「目标角色回复 1 点体力」+ **◆对未受伤的角色无效** ⇒ `targets { max = 1000 }`（不写 filter = 全部存活角色，**含自己**），`'生效'` 里 `game:heal(cardEffect.target, 1)` —— **“未受伤无效”落到效果上**（满体力者回复 0 点，`Heal` 受体力上限钳制），没有另做「使用结算开始时检测此牌对目标的有效性」那套机制；目标照官方给“所有角色”，不预先排除满血者。
- **【五谷丰登】（2026-09-23）**：官方「使用目标：所有角色；**指定目标后**你亮出牌堆顶的 X 张（X = 目标数）；目标角色获得这些牌中（剩余）的一张；**使用结算结束后**，剩余的牌置入弃牌堆」⇒`'结算前'` 用 `game:drawCards(useCard.user, #useCard.targets, useCard:getTempZone())` 亮出（牌直接进**这次用牌自带的临时处理区** ⇒ 牌有位置、账实一致；`'生效'` 里 `useCard:getTempZone():list()`（生效钩子的第二个参数就是这次用牌）就是「剩余」）；`'生效'` 里 `game:askCard(target, '五谷丰登', { card = 剩余 })`（**候选就是给定的一批牌**，不看被问者的牌区）⇒ `game:moveCard(选中, 目标的手牌区对象)`（**必须用目标自己的区对象**，区名会解析到当前回合角色身上）；**没有 `'结算后'` 钩子** —— 剩余由**内核的默认收尾**统一送 `弃牌`（效果结完时把临时区剩下的牌送 `弃牌`，2026-09-24 起）。**“没人答” = 不获得**（那张牌留在剩余里一起进弃牌）；逐目标顺序就是**顺序锚点起的行动顺序** —— 使用者是当前回合角色时他第一个选（官方 3.2 的案例）。
- **【决斗】（2026-09-23）**：官方「**由目标角色开始**，其与你轮流打出【杀】，直到其中一名未打出；然后未打出的角色受到**另一名角色造成的** 1 点伤害」⇒ `'生效'` 里这两个角色在循环里互换，每轮 `game:askPlayCard(当前, '决斗', { name = '杀' })`，谁没打出来谁吃 `game:damage(另一方, 他, 1)`；打出的【杀】由 `AskPlayCard` 放进发起那次结算的临时区、收尾时进 `弃牌`（内容侧不写 `moveCard`）。两人来回打很多张也只是**同一次用牌结算**里的多轮询问（不是嵌套结算），手牌有限 ⇒ 必然结束。
- **锦囊与基本牌共用同一套用牌链**（§6 / §9.2）：`targets` 筛出合法目标 → `canUse` 校验 → 内核把牌放进这次用牌的临时区 → 按行动顺序逐目标 `'生效'` → 收尾统一送 `弃牌`。**这两批锦囊大部分没有新内核机制**（多目标、逐目标生效、筛选与次数都现成）；只有【五谷丰登】要几个**通用**口子：牌自己的 `'使用'` 钩子（当时叫 `'结算前'`）、`AskCard.Condition.card`（候选就是给定的一批牌）、以及 `Effect` 的**临时处理区 + 收尾时机**（`getTempZone()` / `'效果-收尾'` —— 结算期间暂存一批牌的标准做法，判定与打出的牌也已迁过来）。
- **分类**：即时锦囊是 `{ '锦囊', '非延时锦囊' }`、延时锦囊是 `{ '锦囊', '延时锦囊' }` —— 两个模板（`锦囊牌` / `延时锦囊牌`）都写在 `@基础/卡牌/锦囊牌.lua` 里，后者 `: extends '锦囊牌'` 再 `: kind { '锦囊', '延时锦囊' }`（分类**覆盖**，把 `非延时锦囊` 替掉；`zone '手牌'` 等字段随继承而来），另带「置入判定区」与「判定区同名过滤」（见 §9.12）。
- **不限次**：锦囊按官方每回合不限次 ⇒ 不写 `: limit(...)`（兜底 1000 = 事实上不限）。
- **【过河拆桥】（2026-09-23）**：官方「使用目标：一名区域里有牌的其他角色；作用效果：你弃置其区域里的一张牌」⇒ `targets` 的 filter 排掉**身上一张牌都没有**的角色（`player:hasCard()` —— 内核读法，不传参数 = 他所有牌区；装备子区里的牌也算）；`'生效'` 把**目标身上有牌的区**交给询问（`game:askCard(user, '过河拆桥', { zone = 那些区 })` ⇒ 那些区里的牌**逐张**都是候选），挑中哪张就 `game:moveCard(牌, '弃牌')`。
- **【顺手牵羊】（2026-09-23）**：与【过河拆桥】同一套「从别人的区域里拿一张」，只差两处：目标要距离 **1 以内**（用基础规则的 `distance(user, player) <= 1`，不是 `desk:getDistance`）；拿到的东西 `game:moveCard(牌, user:getZone('手牌'))` 进**自己的**手牌。
- **【借刀杀人】（2026-09-24）**：官方「出牌阶段，对装备区里有武器牌的一名其他角色使用。你指定其攻击范围内的一名其他角色：该角色需对其使用一张【杀】，否则将其装备区里的武器牌交给你」⇒ ① `targets` 的 filter = 其他角色 + **装备区里有武器牌**（按分类 `isKind('武器')` 认，不认槽位名）+ **其攻击范围内还有别的存活角色**；② `'生效'` 里用 `game:askPlayer(user, '借刀杀人', { players = 他能打到的人 })` 让**使用者**指定一名角色（候选名单由内核摆好，**答复不在名单里由内核拒收** ⇒ 按「没指定」处理，不报错）；③ 拿 `askUseCard(被借刀者, '借刀杀人', { name = '杀', target = 被指定的角色 })` —— 答复由现成的 `AskUseCard` 校验（次数用满 / 目标不在范围内 ⇒ 选项为空 ⇒ 用不出来），**答复到手就直接用出去**（读 `ask.useCard` 判断有没有用出来）；④ 没用出来 ⇒ 武器牌 `game:moveCard(武器, 使用者:getZone('手牌'))`（官方「交给你」= 进手牌）。**被指定的那名角色不是这张牌的目标**（不进 `targets`，不触发「成为目标」类技能、也不进多目标结算顺序）；**换装后修正自动撤**（武器离开装备区 ⇒ 攻击范围回落），无需写「卸下」。
- **「区域里有牌」与区名**（2026-09-23，2026-09-24 扩充）：玩家的区域有三个 —— `手牌` / `装备` / `判定`（判定区与判定阶段已落地，见 §9.12；判定区现在是有**序**区）；`装备` 区已能装牌（见 §9.11）。
- **服务器侧不看明暗**（2026-09-23 用户定）：不可见是**与客户端通讯时**的隐瞑 ⇒ 内核 / 规则层一律看得见所有牌（这两张牌因此**逐张**给候选、应答方直接挑）；`手牌` 标着 `setVisible(各自的持有者)`（**2026-10-09 起的名单语义**：`setVisible(某人)` = 只有他看得见），那是**协议层遮蔽**要读的声明（将来客户端把该区域的牌换成「未知卡牌」，选完服务器映射回来或丢弃重抽）。
- **用过的牌的去向**不用自己写：基础规则已经把 `'使用'` 的牌放进临时区、收尾时送 `弃牌`（§9.2 的「两套去向」）。
- **【无懈可击】（2026-09-24，本批唯一新内核机制的一张）**：官方「使用时机：一张锦囊牌对一个目标生效前；使用目标：一张对一个目标生效前的锦囊牌；作用效果：抵消此锦囊牌」+ §2.7「抵消」= **此牌对该目标不生效**（另有『取消』= 令其不再是此牌的目标，本批不用）。落地形状：
  - **它是一次「使用」，走一支专门的「对一张牌使用」**（与「对角色使用」并列）：内核有 `UseCardToCard`（使用）/ `CardEffectToCard`（对那张牌的一次生效）/ `AskUseCardToCard`（询问），入口 `game:useCardToCard` / `canUseToCard` / `askUseCardToCard`，目标声明用 **`cardTargets { filter }`**（2026-10-08，原『获取卡牌目标』钩子；谓词 `fun(card, plan)` 逐候选牌判认不认，`plan.targets` = 发起方要对的那批）。**声明条件 = 这张牌能被「对一张牌使用」**（不声明整条 = 进不了那一支）；目标牌**由发起方给定**（这类目标只在发起它的那次结算里存在，内容侧枚举不出来）。
  - **窗口写在牌自己的文件里**（`package/标准/卡牌/无懈可击.lua` 顶层 `game:on('效果-能否生效', …)`）：只认上面那两种「生效」，锦囊牌与牌都要 `isKind('锦囊')`（所以要抵消的是锦囊），按**行动顺序**问一圈要不要**对这张牌使用【无懈可击】**，净结果是被抵消就**返回原因**（内核据此不结算这次生效）。**规则随牌走**：没装这张牌的规则集不会多问一圈。
  - **窗口只回报原因、不删任何东西**：`cardTargets` 条件只回答「能对哪张牌使用」（无懈：锦囊），**阻止生效仍然只能由被阻止的那次结算自己的问句来做** ——【无懈可击】的窗口跑在它自己的效果里，阻止不了**外层**那张锦囊（能阻止的只有外层自己的那个问句）。被抵消 = 不跑那张牌的 `'生效'` = 官方「跳过生效时与生效后」；被抵消的牌**照常**进弃牌堆。
  - **一圈 = 每人一次机会，只有「这张牌被抵消」才终止这一圈**（2026-09-24 用户改正，官方依据在下面）：从顺序锚点起按行动顺序依次问；**有人用了无懈但那张无懈自己又被抵掉了 ⇒ 这张牌还没被抵消 ⇒ 接着问下一个人**（不是就此结束）。官方依据：① 3.2「生效前：可以对此牌进行响应…响应的结果可能会令此牌被抵消，即此牌对目标不生效，**"生效前"终止**」⇒ 终止的条件只有「此牌被抵消」；② 4.1 插入结算顺序「在 B 技能的使用结算完毕后，**继续进行 A 技能的使用结算**」⇒ 插入的无懈结完就继续那张牌的生效前；③ 4.1 同一时机多名角色「依次触发/决定」，且注意里写「**先发动的技能的效果可能会导致此时机结束**」⇒ 没结束就接着问；④ 旁证是濒死那一圈（3.14）：一张【桃】**不结束这一圈**，救不回来就接着问下一个。
  - **两种「生效」都走同一个窗口**（2026-09-24 定；2026-09-28 更正为两种）：窗口认 `effect.kind == 'cardEffect'`（锦囊 × 一个角色 —— 使用期逐目标，以及**判定阶段结算延时锦囊**的那一次，见 §9.12）与 `'cardEffectToCard'`（无懈 × 一张牌 —— 就是官方写的「抵消另一张【无懈可击】产生的效果」），**不认 `useCard` / `useCardToCard`**（那不是「生效前」）。**没有「生效」的结算不进这个窗口**（延时锦囊的使用期：要到判定阶段才生效 ⇒ 使用期只把它置入判定区，官方不允许此刻无懈）。于是**嵌套天然来自事件本身**（用出去的无懈自己也是一种效果、也会走一遍窗口），不需要手写递归；奇数层抵消、偶数层照常是**结果**而不是算法。官方是**嵌套**而非"同一张牌收多张按奇偶判定"：第二张无懈的对象是**上一张无懈**（使用目标是一张牌），且「被抵消 ⇒ 生效前终止」⇒ **同一张锦囊不会被连续无懈两次**。每层各自从顺序锚点起问一圈（换了一层重新算，所以刚用过无懈的人也能对新目标再表一次态）。
  - **每一层的抵消都落在「被抵消的那次生效」上**：被抵消的那一次（锦囊对该目标的 `CardEffect` / 无懈对那张牌的 `CardEffectToCard`）在它自己的「能否生效」里被**阻止**（原因 = `'无懈可击'`）。**不能改成阻止「那次使用」**：取牌发生在 settle 里，阻止使用会让那张无懈留在手里（违背「被抵消的牌照常进弃牌堆」）。
  - **判决不用另发明标记，直接读那张无懈自己的状态**（2026-09-24）：「上面那张无懈到底没到底」就是「它那次「对牌生效」成不成」—— `game:useCardToCard(...)` 返回的那次使用的 `childs` 里找 `cardEffectToCard`，看它的 `.err`（空 = 生效了 ⇒ 它把上面的牌抵掉了）。
  - **跨层阻止没有别的路**（探针实测 2026-09-24）：从别的效果的执行体里取消外层**不是空操作、但也没用** —— 外层任务当场以 `canceled` 收尾（`.err` 读得到、收尾也跑了）但**外层的执行体照旧跑完**（`settle()` 照跑）⇒ 要阻止外层只能让它自己的窗口给出原因（本批把这个跨层套一整个去掉了：`Effect:remove()` 已删）。
  - **「这次使用不能被无懈」= `UseOptions.unnullifiable`**（2026-10-09，【离间】起）：使用者在使用时声明（`game:useCard(…, { unnullifiable = true })`），窗口开头读 `effect.useCard?.useOptions?.unnullifiable` ⇒ **连问都不问**（候选自然也不会呈现出来；不用改 `cardTargets`）。**这个字段住内容侧**：内核的 `Game.UseOptions` 只列**内核自己要读**的那几条，`unnullifiable` 由「无懈可击」这一包**自己注入类型面**（`package/标准/meta.lua`）、**自己消费** —— 与「内核不预设时机名 / 区域名 / 属性名」同一条口径（选项名同理）。
  - **逐目标**：多目标锦囊能只抵消其中一个（`'效果-能否生效'` 本来就逐目标触发）；答复方要知道"这次冲谁来的" ⇒ 读这次询问的父效果（`ask.parent` 就是那次 `CardEffect`）。
  - **它主动用不出去**：没有「对角色使用」那一支 ⇒ 出牌阶段候选里没有它（`canUse` 报「没有声明目标条件」）；它只在窗口里被使用。牌表里那 4 张已存在。
  - **延时锦囊的窗口只有判定前那一次**（2026-09-28 更正：使用期没有窗口 —— 官方不允许；见 §9.12）；还没做：「谁能响应」的技能干预（如《看破》）、把【闪】迁到「生效前」；"打出"与"使用"的位置差异见 §9.2 与本条。

### 9.11 装备（武器 + 坐骑 + 装备子区；已落地 8 武器 / 6 坐骑，2026-09-24）

装备的加成由**类别基类自己的 `'被动'` 钩子**写进属性 —— **进对应子区启用（加上）、离开停用（撤销）**，没有「装上 / 卸下」这对函数（启停由装备模板接管：`add-card-passive`，2026-09-29）。

```lua
-- package/@基础/卡牌/装备牌.lua（模板：不在牌表里、不会被造出来）
-- 只管「使用时进装备子区」：按分类找子区 ⇒ player:equipCard(牌)
-- （四个子区由 @基础/装备.lua 在「游戏-开始」里给每个玩家 addZone）
Card '装备牌'
    : kind '装备'
    : targets { min = 0, max = 0 }    -- 官方装备牌不指定目标
    : zone '手牌'
    : on('卡牌-进入区域', function (card, zone)
        local owner = zone.owner
        -- 进的正好是「本人的、与分类对应的」那个子区才启用被动
        if owner and owner:equipZoneOf(card) == zone then
            card:enablePassive()
        end
    end)
    : on('卡牌-离开区域', function (card, zone)
        local owner = zone.owner
        if owner and owner:equipZoneOf(card) == zone then
            card:disablePassive()
        end
    end)
    : on('使用', function (useCard)
        useCard.user:equipCard(useCard.card)   -- 认不出分类就不放（牌随收尾进弃牌堆）
    end)

-- package/@基础/装备.lua（装备的四个子区与「一个子区只能有一张」都归这里）
local ZONE_NAMES = { '武器', '防具', '进攻马', '防御马' }
game:on('游戏-开始', function ()
    for _, player in ipairs(game.desk.players) do
        for _, name in ipairs(ZONE_NAMES) do
            player:addZone(name)
        end
    end
end)
-- player:equipZoneOf(牌)：按分类找子区；player:equipCard(牌)：同子区已有牌就先送弃牌堆、再放新的
-- player.equipCards：四个子区里的装备牌（奖惩等要用）

-- package/@基础/卡牌/武器牌.lua（类别定义：被动生效时把攻击范围加成写进持有者的属性）
Depends { './装备牌' }                -- 同类文件按名字排序，必须显式声明先加载
Card '武器牌'
    : extends '装备牌'
    : addKind '武器'
    : on('被动', function (card, zone)
        local range = card:getValue('攻击范围')
        if not range then
            return
        end
        return zone.owner:addAttr('攻击范围', range - 1)   -- 属性初值是 1，加的是描述值与它的差值
    end)

-- package/@基础/卡牌/坐骑牌.lua（两种马功能一模一样 ⇒ 先把共性写在坐骑牌上，再各给一个定义）
Depends { './装备牌' }
Card '坐骑牌'
    : extends '装备牌'
    : addKind '坐骑'
    : on('被动', function (card, zone)   -- 被动生效时按自己那条分类决定改哪条修正
        local name = card:isKind('进攻马') and '进攻修正' or '防御修正'
        return zone.owner:addAttr(name, card:getValue('距离修正'))
    end)

Card '进攻马'
    : extends '坐骑牌'
    : addKind '进攻马'
    : value('距离修正', -1)           -- 两种马的修正逐张都一样 ⇒ 写在马定义上

Card '防御马'
    : extends '坐骑牌'
    : addKind '防御马'
    : value('距离修正', 1)

-- package/标准/卡牌/麒麟弓.lua（攻击范围 5；牌上写的就是描述里的值，与默认 1 的差值由武器牌钩子去减）
Card '麒麟弓'
    : extends '武器牌'
    : value('攻击范围', 4)

-- package/标准/卡牌/赤兔.lua（进攻马 -1；具体马连数据都不用写）
Card '赤兔'
    : extends '进攻马'
```

- **用牌链一行不改**：装备牌与其它牌共用同一条链（`canUse` → 取牌 → `'卡牌-结算前'` 进临时区 → **「使用」钩子里进装备区** → 逐目标生效（空转）→ 收尾），区别只在「**不指定目标**」这一个声明上。
- **装备子区由内容侧建**（2026-09-29 起；原来是一个带四条槽位的 `SlotZone`，已删）：官方口径里装备区本来就分成子区 ⇒ 把 `武器` / `防具` / `进攻马` / `防御马` 直接建成**四个普通牌区**，`@基础/装备.lua` 在 `'游戏-开始'` 里给每个玩家 `addZone`（内核只建 `手牌` / `判定`，`player:getZone('装备')` 不再存在）。**子区名单是公开的扩展点**：`rule.equipZones`（`rule` 是**装载器每轮装载给的共享袋**，与 `game` / `Card` / `Depends` 同属注入项；名单本身由 `@基础/装备.lua` 建，见 `architecture.md` §9.6）—— 想加子区（特殊坐骑 / 宝物…）的包在**加载期**往后追加一条（`rule.equipZones[#rule.equipZones + 1] = '宝物'`）再给自己那张牌 `addKind '宝物'` 就行，`@基础` 一行都不用改（`@基础` 是默认包、排最前，所以它的文件一定先跑）。**另有「自己的区域」`rule.ownZones`**（= 手牌 + 装备子区，2026-10-08 加）：凡「**一张你的牌**」（【武圣】【奇袭】的素材、【制衡】要弃的牌、【急救】的桃）都读这一条，**判定区不在其中**（判定区的牌不属于该角色）；它是**快照**（`@基础/装备.lua` 加载时算好）⇒ 追加子区的包记得给它也补一条。**装上去写 `player:equipCard(牌)`** —— 它用 `equipZoneOf` 找到分类对应的子区、**同子区已有牌就先 `game:moveCard(旧的, '弃牌')`**（官方：同一子区的旧装备置入弃牌堆）、再放新的；认不出分类就不放（牌随结算收尾进弃牌堆）。取回来：武器用 `player:getZone('武器')`、所有子区的装备用 `player.equipCards`。
- **加成随被动启停**：「装备牌」模板在 `'卡牌-进入区域'` / `'卡牌-离开区域'` 里判「**这个区是不是本人的、与这张牌分类对应的那个子区**」（`zone.owner:equipZoneOf(card) == zone`）⇒ `card:enablePassive()` / `disablePassive()`；**加成写在各类别基类的 `'被动'` 里**（`host:bindGC(player:addAttr(...))` —— 修正挂进内核给的容器、停用时释放）⇒ 牌一离开子区（拆 / 抢 / 换装 / 死亡弃牌）修正自动撤，**一条「卸下」都不用写**，也没有集中式的 `equip` 函数。**进错子区不会启用被动**（用例守着）。
- **分类既说「是什么」也给出去哪个子区**：`{ '装备', '武器' }` / `{ '装备', '防具' }` / `{ '装备', '坐骑', '进攻马' }` / `{ '装备', '坐骑', '防御马' }` —— 技能判「你装备了坐骑」看 `'坐骑'`，子区匹配看 `'进攻马'`（拿子区名去分类里查，**顺序无关**）；**不另写一份「子区名」数据**。分类写法：**每个具体类别一个定义**，具体牌只 `: extends` 一个并写自己的数据 —— 类别定义负责「带分类」（`武器牌` ⇒ `'武器'`；两种马各一个定义：`进攻马` / `防御马` 分别 `extends '坐骑牌'` 再 `addKind` 自己那条），**不要**在具体牌上写 `kind`（那是覆盖，会把基类带的分类清掉）；要追加分类用 `addKind`（只往里加）。
- **数据只给数值**（`CardDef:value`，内核只存不解释）：武器写 `攻击范围` —— **就是描述里的那个值**（麒麟弓 ⇒ `5`），差值由武器牌的钩子减（`range - 1`，因为属性「攻击范围」的初值是 1）；坐骑的 `距离修正` 也与描述一致（进攻马 `-1` / 防御马 `1`）且逐张都一样 ⇒ 写在 **`进攻马` / `防御马` 两个定义**上，具体马只 `: extends` 其中一个；攻击范围与距离的读法见 §5。
- **已做十个技能（2026-09-29 ~ 30）**：**【方天画戟】**（`add-fangtian-halberd`）——`event('卡牌-来源-使用选项', …)`（**使用者头上那一份**；全局那份之外还有使用者那份，名字按方向词规则插「来源」）：装备主使用【杀】、且此【杀】是其**最后手牌** ⇒ 返回 `{ extraTargets = 2 }`（放宽上限；最终仍不超合法目标数），「最后手牌」在校验时判（牌还在手里）；**【仁王盾】**（`add-renwang-shield`）——`event('效果-目标-能否生效', …)`（三段式的第三段；2026-09-29 起 —— 只有它主人被指定为目标时才被问）：对装备主的【杀】+ 牌面**黑色**（2026-09-30 起 `card.color == '黑'`） ⇒ 返回原因（**阻止这次生效** = 官方「无效」；逐目标拦、**连**「要闪」**都**不跑）；**【诸葛连弩】**（`add-zhuge-crossbow`；2026-09-30 上限账挪到玩家后简化）——『被动』一行 `return owner:addLimit('杀', '出牌', 1000)`：**修正挂玩家**、装上即生效、离槽随被动自动撤，每个出牌阶段自然不限（不再订阅阶段 / 补记 / 手动撤销）。三个的启停仍由装备模板管（离开子区 ⇒ 被动停用 ⇒ 订阅 / 修正一起撤）；用例见 `rule/equip`（含目标数量违规一组）。
- **【青釭剑】（`add-qinggang-sword`，2026-09-29）**：`event('卡牌-来源-指定目标后', function (card, useCard, target) …)`（**使用者头上那一份**；逐目标「指定目标后」时机，2026-09-30 独立成时机并从 `'卡牌-结算前'` 迁来；声明式订阅见 §9.11 末条 / §9.15 的三条路）⇒ 对**这个目标** `useCard:bindGC(target:addBuff('防具无效', useCard))` —— **压 + 兜底一起**：状态挂给**这次使用**（第二个参数），这次使用收场（含半路取消 / 目标根本没轮到生效）时效果被删、状态随之被删；这个 buff 在 `'获得'` 里把自己挂到的**防具子区** `disable()`（区级压制，`Zone:disable` 返回的撤销函数交给 `bindGC`）⇒ 子区里的防具被动全部撤下（【仁王盾】那类订阅也撤）。**撤销按目标**（官方「对某人的效果结束」）：状态自己订 **`buff.owner:on('效果-收尾')`**（收尾在**当事人头上也发一份**），只要 `effect.useCard == 它拿到的那次使用` 就 `buff:remove()`。**压制挂给这次使用**（`useCard:bindGC`）⇒ 窗口**不随剑 / 使用者消失**（裁定一：甲结算里剑被拿走，丙照样被无视）。
  - **判定用牌名**（`useCard.card.name == '杀'`）：分类（kind）里只有 `基本` / `武器` / `防具`… **没有牌名** ⇒ 不写 `card:isKind('杀')`（与【仁王盾】同一写法）。
  - **已知边界**（写清，不默默略过）：**窗口内失去防具、其「失去时」技能仍不能发动**（裁定二）做不到 —— 牌一离开子区，区级那层压制就松了（`rework-zone-disable` 的离区口径）；军争牌（【白银狮子】等）到齐时再定怎么补（可能是「buff 记牌、离区时也不松」）。

### 9.12 锦囊（延时；已落地 2 张：乐不思蜀 / 闪电，2026-09-28）

官方流程：**使用**（**使用期没有无懈窗口** —— 2026-09-28 按官方口径更正；此前的「可被无懈」是错的）⇒ 目标通过校验后**置入其判定区**（闪电的目标是使用者自己）⇒ 目标的**判定阶段逆序结算**判定区（后置入的先判）⇒ 结果交给牌自己 ⇒ **还留在判定区的进弃牌堆**（闪电判不中时自己移走，见下）。

- **判定阶段对每张判定牌发起一次「生效」**（2026-09-28 起；原专用效果类 `延时锦囊结算` 退役）：`Card:doEffect()`（**现在是内核方法**（`server/core/card.lua`）；判定者 = 它所在区的主人；`@基础/延时锦囊.lua` 已删）—— 内部建一次 `CardEffect`（判定阶段形态：没有 `useCard`）并驱动。**无懈窗口恰好在判定前**（`'效果-能否生效'` 在结算之前发）⇒「被抵消 = 不判定、不跑牌的逻辑」；**逐张**各自一个窗口（官方）。
- **牌自己的结算逻辑 = `'生效'` 钩子**（2026-09-28 统一，`'判定结果'` 撤掉）：**判定在牌自己的 `'生效'` 里做**（`game:judge(target, card.name)` 拿到局部的 judge、直接按结果处理）——「进行一次判定然后根据判定结果产生效果」就是牌面描述的直译，不写回、不经过载体。
- **模板 `延时锦囊牌`**（`@基础/卡牌/锦囊牌.lua`，`: extends '锦囊牌'` + 分类覆盖 + **`: skipEffect()` 声明**）：`targets` 通用过滤（判定区已有同名牌的目标去掉；多次 `targets` 的 filter **叠加** ⇒ 与具体牌自己的目标天然叠加）+ **`'使用'` 置入目标判定区**（一次用牌一次、从 `useCard.targets` 取目标；使用期不进无懈窗口 ⇒ 置入不可被抵消）。
- **驱动住 `@基础/阶段/判定阶段.lua`**（订阅 `'阶段-开始'`，`phase.name == '判定'` 时跑本地函数）：从尾往头逐张；**结算前先确认这张还在判定区里**（快照可能过期：被拿走 / 清掉就跳过）；逐张 `card:doEffect()`；结算完**还留在判定区 ⇒ 送弃牌堆**（被抵消的、判完没走的都走这条）；**回合角色死了就停**（阵亡清算还没做，死者的牌暂时留在判定区；那批做了之后这层可撤）。
- **判定区里那张实体牌「代表哪张延时锦囊」**（2026-10-09，为【国色】补）：模板在**置入判定区之后**写 `card:withZone(card:addModifier { name = card.name }, function (zone) return zone?.name == '判定' end)` —— 转化的牌（【国色】把方块牌当【乐不思蜀】）靠这一步把身份落到**那张实体牌**上（官方 `Ch2/S5:76`「系统会将此牌**对应的实体牌**置入 B 的判定区」），于是判定期 `card:doEffect()` 读到的 `def` 就是那张锦囊的定义。**寿命的判据 = 「进的还是判定区就留」**：判完送弃牌 / 被拆 / 被顺 ⇒ 撤；被挪到**另一个判定区**（【巧变3】那类）⇒ 身份跟着走。普通延时锦囊也照挂（同名、行为不变）⇒ 一条路径不分支。详见 §9.31。
- **判定期那张牌全程留在判定区**（2026-10-09 复核确认）：判定阶段逐张 `card:doEffect()`、跑完才送弃牌堆；`Judge:settle()` 进临时区的是**判定牌**与被改判换下的牌，跟这张牌无关 ⇒ **没有「判定区 → 判定效果的临时区」这一步**（曾按这条设想过机制，查清现状后不需要）。
- **判定区是有序区**（内核用 `moe.orderedZone.create` 建）：进入顺序 = `list()` 顺序（先进在前），结算从尾往头 = 后入先出：注意 `draw` 都从**顶**取（最先放入的那张），判定区结算不用它。
- **跳过阶段 = 该阶段不发生**（官方口径）：跳过记在 **`Turn`（回合）对象**上（`runTurn` 建、挂 `player.turn`；`turn:skipPhase(阶段名)` 记、`turn:takePhaseSkip(阶段名)` 读掉 —— 回合结束对象就没了，**不会漏到下一个回合**），`runTurn` 命中就 **`goto continue`（连 `enterPhase` 都不进）** ⇒ 该阶段的 `'阶段-开始'` / `'阶段-结束'` 都不发。**记的时机**：`takePhaseSkip` 在 `enterPhase` 之前读 ⇒ 只要是**上一个阶段跑完之前**记上的就行（【乐不思蜀】在判定阶段里记、【克己】在出牌阶段结束时记）。**「本阶段（自己）用过 / 打出过某名」读阶段实例上的两本账**（`phase:getUseCount(名)` / `phase:getPlayCount(名)`）—— 使用账由用牌路径记、打出账由 `AskPlayCard` 记，**都只记在自己的阶段上**。
- **乐不思蜀**（`package/标准/卡牌/乐不思蜀.lua`）：`targets` 的 filter = 其他存活角色；`'生效'`（判定期）：自己判定，判牌不是红桃 ⇒ `cardEffect.target.turn:skipPhase('出牌')`。
- **闪电**（`package/标准/卡牌/闪电.lua`）：`targets` 的 filter = 自己；`'生效'`（判定期）：自己判定，黑桃 2~9 ⇒ `game:damage(nil, cardEffect.target, 3)`（**无来源伤害**，第一个真实用例）；否则沿**行动顺序**（`desk:actionOrder`）从下家起找第一个合法目标（存活 + 判定区里没有闪电）并移过去。
- **无懈可击只认两种 kind**（2026-09-28）：`cardEffect` / `cardEffectToCard` —— 判定阶段那次就是 `cardEffect`（判定前发窗口）；**使用期不进窗口**（见上）。
- **回合内死亡 ⇒ 结束这个回合**（`runTurn` 每个阶段前查存活、死了 `break`）—— 闪电会打死回合角色，不这么做流程会继续问死人要牌。
- **本批不做 / 待办**：**阵亡清算**（判定区 / 手牌 / 装备的牌进弃牌堆）→ 记到以后的**「死亡规则」批次**（本批死后判定区里剩的牌**留在原地**）；**兵粮寸断**（军争，跳过摸牌阶段 —— 机制已就绪）；判定区的技能交互（获得 / 移动判定区的牌）；闪电找不到合法目标（只可能 2 人局两张闪电都在场）先按弃置，待官方 FAQ 校准。

### 9.13 虚拟牌（已落地，2026-09-30）

官方口径：**使用 / 打出的真正对象是「牌的信息」（虚拟牌），不是实体牌**（规则集 Ch2/S1）—— 可以对应**零张**实体牌（如【八卦阵】判红视为打出的【闪】），也可以对应若干张；**单张属性不一一对应、或实体牌多于一张**就称「**转化的牌**」（Ch2/S5）。**每一张虚拟牌相互独立**（不存在两张相同的虚拟牌）。

```lua
local jink   = game:createVirtualCard('闪')                  -- 没有实体牌（八卦阵那类）
local slash  = game:createVirtualCard('杀', { 手牌甲, 手牌乙 })  -- 两张实体牌（丈八蛇矛那类）
jink.suit    -- 一张原始牌 ⇒ 抄它；零张 / 多张 ⇒ 无
slash.subcards  -- 对应的实体牌（普通牌是空表）
slash.physical  -- 读法：对应的实体牌（普通牌就是它自己、虚拟牌是它的素材）
```

- **花色与点数默认从原始牌算**（用户 2026-09-30 定）：**一张 ⇒ 抄它，其余 ⇒ 无**；官方没写属性推导，这条是自定口径；**颜色同 §9.9 由花色推**（`card.color`）。
- **虚拟牌能当一张「要用的牌」**（2026-09-30，`add-view-as-in-use`）：`canUse` / `useCard` 对**虚拟牌**跳过「在使用者手上 / 所在区被禁用 / 声明的牌区」三条（它不进任何牌区）—— **次数限制照旧算**（丈八的【杀】占出牌次数）。于是「视为」声明能作为一个**选项**出现在出牌阶段的候选里（目标由玩家在答复里给，与正常用牌同形），答复落定之后内核才收素材、造出真牌。
- **虚拟牌进不了任何牌区**：收牌唯一入口 `Zone:accept` 收到虚拟牌就**改把它 `subcards` 里的实体牌收进来**（「搬虚拟牌 = 搬它的实体子牌」，2026-09-30 `add-zhangba-spear` 起；**虚拟牌自己既不进区、也不注销** —— 同日在 `guard-card-in-place` 里去掉注销）—— 「要把它放进弃牌堆」这个动作对虚拟牌就是「销毁虚拟牌 + 实体子牌去哪里」（用户 2026-09-30 记的口径）⇒ 弃牌堆里永远不会出现虚拟牌，而【丈八蛇矛】那两张手牌照样走 手牌 → 处理区 → 弃牌堆。实体牌的处置不受影响（打出的牌进处理区、结算完进弃牌堆的仍是**实体牌**）。

### 9.15 技能定义（已落地，2026-09-30 / 10-01）

底本（Chapter1/Section2）：技能按**是否有发动时机**分**状态类技能**（没有）与**触发类技能**（有）；且**「是否必须发动」与「锁定技」标签无关** —— 「关键是要找是否有『可』这个字」（专题一按语）。底本（Chapter2/Section5）：**「锁定技」已经只是一个标签**（作用是「令带有此标签的技能不被克制」）；另有「限定技」（一局一次）、「觉醒技」（**视为附带锁定技与限定技**）、「主公技」（见 §9.14）。

```lua
-- package/标准/武将/曹操.lua（技能与该武将同文件，见 §9.14）
Skill '奸雄'
    : auto(true)                  -- 被动触发时默认自动同意（不写 = 每次问）
    : tags { '锁定技', '主公技' }   -- 标签（可多次调，取并集）
```

- **两个正交维度**：**「自动同意」`auto`** 与**标签 `tags`** 分开 —— 前者只是**玩家的偏好默认值**（被动触发时要不要问；技能实例上可读可写，玩家随手切），与「是否必须发动」**无关**（强制由技能自己写：不调 `confirm` 就是不问）；后者是纯数据，各被对应机制读（锁定技 = 不被克制；限定技 = 一局一次；主公技 = 装配时只给主公）。
- **按钮状态不单独声明**（用户 2026-10-01 定）：按钮**总要显示**（技能名 + 悬浮描述），它能不能点由「**有没有主动发动的钩子**」推导 —— 那个钩子就是 `'使用'`（2026-10-08 已做，见 §9.16）。
- **发动要包一层 `Skill:cast(函数)`**（2026-10-01，`add-cast`）：那是**归因** —— 函数里起的结算（如【奸雄】那次挪牌）都挂在它下面，用 `moveCard.parent` 就能追到「这是哪个技能做的」；装备同理 `Card:cast(函数)`。它是普通效果（照跑「能否生效」、失败读 `.err`）；在时机回调里调 ≢ 根效果 ⇒ 不进记牌器（本该如此：它是响应）。
  - **顺序：「先 `confirm()`、再 `cast()`」**（用户 2026-10-09 纠正过一处写反的）。少写一行就用 **`Skill:tryCast(函数)`**（2026-10-09）：问一句、同意才起那次发动，不同意返回空 —— **嵌套写反这件事就结构上不会发生了**；要循环发动（【洛神】）就 **每一轮各调一次 `tryCast`**（**一轮 = 一次发动**，别把整个循环包进一个 cast），拿 body 的返回值用 **`cast.result`**。**全库已统一用它**（奸雄 / 集智 / 克己 / 铁骑 / 鬼才 / 反馈 / 刚烈 / 洛神）。
  - **例外：写在 viewAs 的 `'发动'` 回调里的询问**（【护驾】【激将】）仍只写 `skill:confirm()`** ——那次发动由内核 `auto-cast` 自动包（见下一条），自己再包就是嵌套归因。
  - **凡是技能引发的事都要套一层**（2026-10-09 用户定）：**连只改值的也套**（【救援】就是 `skill:cast(function () heal.amount = heal.amount + 1 end)`）—— 归因是「这件事是这个技能做的」，不是「这件事起了几个结算」。
  - **三类不套**：① **持续性**（`addAttr` / `addLimit`：武器范围、张飞【咆哮】、马超【马术】、诸葛连弩）—— 那是「装上就有的」，不是一次发动；② **同步收集式时机里的返回值**（`'卡牌-使用选项'` / `'卡牌-目标数修正'`：回调在 `game:collect` 里跑、不能 await，包不了）—— 方天画戟 / 【奇才】就属于这类；③ **延时效果的「后续执行」**（2026-10-09，【许褚】裸衣的 +1）—— 它发生在后面的某个时点（本回合的伤害改值）、不属于「一次发动」，而且套了反而与「失去技能也照旧执行」那条裁定相冲（技能一没、`cast` 就起不来）—— **发动那一次照旧套**。
- 读法：`skill.auto`（可写）/ `skill:hasTag(名字)` / `skill:getTags()`（快照）；**「觉醒技」在 `hasTag` 里派生**（`hasTag('锁定技')` 与 `hasTag('限定技')` 也为真）；**要不要发动就问 `skill:confirm()`**（开关开着直接放行、否则问一句 `'发动'`）—— **写在事件回调里的技能自己调 `skill:tryCast(函数)`**（先问、后 `cast`；**每次 `confirm()` 后都是一次 `Cast`**）；**「视为」声明的确认不写在 `'发动'` 里、而是声明上写 `options.confirm = true`**（内核排在 `cast` 之前问，装备那边是 `Card:confirm()`）。
- **技能名与牌名、武将名是三个独立命名空间**（同包同名不冲突）；官方描述照卡牌那样写在文件顶部（§9.3）。
- **「反复询问」的循环用带上限的 `for`，不用 `while`**（用户 2026-10-09 定；细节见 `moe-kill-dev` 的 `code-style.md` §14）：【洛神】反复判定、【遗计】反复分配、【濒死】反复求桃都是这种形状 —— `for _ = 1, 1000 do` + 退出条件挪进循环体（`break`）；**`while` 只留给流程驱动**（`回合.lua` 里的整局主循环）。
- **能用一次询问表达「要不要发动」时，就别另问 `confirm`**（用户 2026-10-09 定）：一次答复里已经包含了表态（取消 / 选空 = 不发动）⇒ **不调 `tryCast`**、**把询问放在 `cast` 之前**（不发动就连一次空 `cast` 都不起；【青龙偃月刀】是首例、【突袭】同形）。反过来，**只有「发动后有额外动作」的技能才需要 `tryCast`**（【洛神】/【遗计】那种：问一次「发动」、同意才拿牌）。
- **技能写「时机」有三条路**（2026-10-09，`add-skill-event-decl`）：① **声明式「视为」**（`: viewAs(…)`）—— 只要「把某牌当另一张用」就用它；② **声明式订阅**（`: event(名, 回调)` 订自己 / `: globalEvent(名, 回调)` 订局）—— 内核启用时挂好、停用 / 离场 / 被克制自动撤，**载荷原样给回调**（第一参是技能自己）⇒ 内容侧只写「条件 + `skill:tryCast(…)`」（不写 `on('被动')` / `host:bindGC`）；③ **`'被动'` 兜底**（`host:bindGC(owner:on(…))`）—— 它承载的是「**启用时做点什么**」：建持续性状态（【马术】`addAttr`、【咆哮】`addLimit`）。**两条硬口径**：**(a)** 订自己（`event`）与订局（`globalEvent`）**不可互换** —— **看技能文本管的是谁的**：管「一名角色的判定」的订局（【鬼才】`'判定-前'`）、管「**你的**判定」的订自己那份（【洛神】【天妒】—— 判定两条时机各发两份，见 §9.8）；**(b)** **条件写在 `tryCast` 之前** —— `event` 只转发、内核不替技能问，所以「不满足条件就不问」仍然成立（切勿把条件挪到询问之后，否则无关触发也会问一次）。**三样东西（牌 / 状态 / 技能）同形**：`CardDef` 也有这套声明（2026-10-09 同一批落地）—— `event` 订**这张牌的主人**头上那份（牌不在谁名下就不订，也不报错）、`globalEvent` 订局上那份，回调第一参是**这张牌**，**要主人就自己取**（`local zone = assert(card:getZone())` + `assert(zone.owner)` —— 订阅只在有主人的牌上，这是类型窄化不是防御）；「要不要发动」同样自己写（`card:cast(…)`）。**标准包武将 11 处订阅 + 装备 7 处订阅 2026-10-09 已全部迁完**；两边各保留「持续性」写法（【马术】/【咆哮】、武器牌 / 坐骑牌 / 诸葛连弩）。

- **已能生效**（2026-09-30，`add-skill-effect`）：定义里 `: on('被动', 回调)`（回调收 `(skill, host)`）是**启用钩子** —— `player:addSkill(名字)` 挂上即启用（跑一次、给它 `host`），内容侧在那里 `host:bindGC(…)` 挂持续性资源 / 建状态（**订阅时机现在走 `event` / `globalEvent`**，见上一条）；**停用（被克制 / 封印）与恢复用 `skill:disablePassive()` / `enablePassive()`**，摘掉时容器跟着放掉（**与装备技能同一套写法**）；**「问不问」由技能自己写**（`skill:confirm()`）。第一个真技能 **【奸雄】**（`package/标准/武将/曹操.lua`，与武将定义同文件）：`: auto(true)`（默认自动同意），`event('伤害-目标-生效后', …)` 里判 `damage.cardsInPlace` 为空就不问；`skill:tryCast` 放行就把那些牌移进手牌（那次发动有归因 ⇒ 追得到）。**发动的对象得还在原处**（2026-09-30）：读 **`damage.cardsInPlace`**（getter）= 这次伤害涉及的**实体牌里还在原处的那些**（虚拟牌看它的素材；**只看有没有动过、不看它在谁手里**，所以【闪电】那种「造成伤害时牌就在判定区」照常工作）—— **一张都拿不到就不发动也不问**；只有一部分还在时**能拿几张拿几张**（官方 `获得X张<牌>` 按 `min{其能获得的<牌>数, X}` 执行）；不这么写就会从别人手里把牌抢过来。

### 9.16 主动技（已落地，2026-10-08）

```lua
Skill '仁德'
    : cards { zone = '手牌', max = 1000 }            -- 这次发动要带的牌（照 AskCard.Condition；min 不写 = 1、max 不写 = min）
    : targets { filter = function (player, skill)    -- 这次发动要的目标（同上，min 不写 = 1、max 不写 = min）
        return player ~= skill.owner                 -- 逐角色谓词（省略 = 所有存活角色）
    end }
    : on('使用', function (cast)                     -- 主动发动：玩家在出牌阶段点了它才跑
        …                                            -- cast.source = 技能；cast.use = { cards, targets }：拿到确定的牌与目标，直接做事
    end)
```

- **能不能主动发动 = 有没有 `'使用'` 钩子**（`skill:hasHandler('使用')`）：没有它的技能不进「用技能」的候选（§9.15 的「按钮能不能点」就是这个推导）。
- **只要牌、不要目标也行**（【制衡】）：`: cards { zone = rule.ownZones, max = 1000 }` 不写 `targets` ⇒ 答复只给 `skill` + `cards`。
- **发动走 `Skill:use()`**：跑 `'使用'` 钩子 + 包一层 `cast`（归因、`from` = owner ⇒ 钩子里的 `moveCard.parent` 追得到「这是哪个技能做的」）；**不问 `confirm`**（玩家点了它 = 已经表态）。
- **目标与消耗是发动的前置（官方 Chapter1/Section2）**：触发类技能六要素 = 时机 / 条件 / 发动角色 / **目标** / **消耗** / 效果；「发动者*声明*技能名，并**选择发动此技能的所有目标**，并由相应角色**开始执行所有消耗**，所有消耗执行完毕即其发动了此技能」。所以技能像卡牌一样用**声明**给出「能挑什么」：**`: cards(条件)`**（照 `AskCard.Condition`）与 **`: targets { min, max, filter }`** —— `askUseSkill` 收集选项时**逐技能跑一遍**（凑不齐前置的不进选项），客户端在范围内选完，**一次答复**把「技能 + 牌 + 目标」一起交回；发动时内核跑 `'使用'` 钩子、递上这次发动（一个 `SkillCast`：`cast.source` / `cast.from` / `cast.use`）。**依赖结算中信息才能定的选牌（如【突袭】要别人手里的牌、【雌雄】由目标选牌）仍留在钩子里自己问** —— 声明是可选的。
- **出牌阶段是两路并行**（`@基础/阶段/出牌阶段.lua`）：同一个玩家身上同时挂着「要一次用牌」与「要一次技能发动」两条询问，**谁先给出答复算谁**（另一条当场取消）；**两路都不答 = 他不想出了 ⇒ 这个阶段就到这**（旧口径「没给出牌 ⇒ 结束出牌阶段」的重写）。所以规则上「玩家放弃出牌」= 什么都不选。⚠️ 将来接倒计时 / 「结束阶段」按钮时要在这条链上加一路（现在没有）。
- **从简落地，还没做**：声明了前置的技能已在选项阶段筛掉凑不齐的；没声明前置的技能不做「能不能发动」的进一步判断（点下去才失败）；倒计时与超时那一路没做。

### 9.17 失去体力（已落地，2026-10-08）

```lua
-- package/@基础/失去体力.lua
function LoseHp:settle()
    player:addAttr('体力', -self.amount)
    if player:getAttr('体力') <= 0 then
        player:enterDying()        -- 没有来源 ⇒ 这次濒死没有致死伤害
    end
end
```

- **它不是伤害**（底本 Chapter2/Section5：「失去体力和受到伤害均会导致角色扣减体力」，但「失去体力与受到伤害是不同的事件，比如失去体力没有来源，角色因失去体力而死亡没有角色需要执行奖惩」）⇒ 独立效果 `LoseHp`（`kind` = `loseHp`），入口 **`Player:loseHp(点数)`**（挂 `Player`：**单方、与 `Player:draw` 同族** —— 伤害那种「来源 → 承受者」的两方关系才用 `game:`）。
- **一个时机都不发**（没有「失去体力时 / 后」，也没有「防止失去体力」）—— 等真有消费者（防具 / 技能）再开，按「专用事件只在真有外部介入需求时才开」的口径。
- **因它死亡不奖不惩**是天然结果：`player:enterDying()` 不带伤害 ⇒ `'玩家-死亡'` 里读 `player.dying?.damage` 为空（奖惩那条就是拿它当凶手）。
- **【苦肉】已实现**（`package/标准/武将/黄盖.lua`）：主动技 `on('使用', …)`，**先 `owner:loseHp(1)`，再判 `owner:isAlive()` 才 `owner:draw(2)`** —— 顺序就是技能文本的「失去 1 点体力，**然后**摸两张牌」；体力 1 时发动 ⇒ 先走濒死，**救回来才摸两张**、没救回来就不摸。**没有前置声明**（不要牌不要目标）；文本里没有「限一次」⇒ **可反复发动**。

### 9.18 夏侯惇【刚烈】（已落地，2026-10-08）

```lua
Skill '刚烈'
    : event('伤害-目标-生效后', function (skill, damage)
        local from = damage.from
        if not from then return end              -- 无来源伤害（【闪电】那类）不发动
        skill:tryCast(function ()
            local judge = game:judge(skill.owner, '刚烈')
            if judge.card?.suit == '红桃' then return end
            -- 一次要两张，允许取消：给不满或取消 ⇒ 挨那 1 点
            local cards = game:askCard(from, '刚烈', { zone = '手牌', min = 2, max = 2 }).cards
            if #cards == 2 then
                game:moveCard(cards, '弃牌')
                return
            end
            game:damage(skill.owner, from, 1)
        end)
    end)
```

- **那 1 点伤害有来源，就是发动者本人**（底本：`Chapter1/Section1.md`「郭嘉-曹仁选择受到荀彧-夏侯惇造成的 1 点普通伤害」；`Chapter2/Section5.md`「夏侯惇-张辽在受到自己造成的 1 点伤害后再次发动【刚烈】」）—— 不要写 `game:damage(nil, …)`。
- **手牌不足两张 ⇒ 只能挨那 1 点、不弃牌**：官方「选择一项」时**不能选无法执行的选项**（`Chapter2/Section5.md:193`：「对于包含消耗的选项，其不能选择……不能执行的选项」）。
- **实现口径（用户 2026-10-08 定）**：不另开「二选一」询问，改成**一次 `askCard(min = 2, max = 2)`** —— 交满两张就是「弃两张」、给不满或直接取消就是「挨 1 点」。与官方在「手牌不足」这一点上结果一致；差别只在于官方允许手牌够的人**主动**选挨打，我们靠「取消」实现同一件事。
- **`cancelable` 是本次新加的内核能力**（**默认允许取消** —— 这里用默认值就够了；`false` 只留给「玩家无权拒收」的那几处）：见 `architecture.md` 的 `askCard` 行。

### 9.20 马超【马术】【铁骑】（已落地，2026-10-08）

```lua
Skill '马术'
    : tags '锁定技'
    : on('被动', function (skill, host)
        host:bindGC(skill.owner:addAttr('进攻修正', -1))
    end)

Skill '铁骑'
    : event('卡牌-来源-指定目标后', function (skill, useCard, target)
        if useCard.card.name ~= '杀' then

        end
```

- **【马术】就是一条距离修正**：`addAttr('进攻修正', -1)` —— 返回的撤销函数交给 `host:bindGC`，技能停用 / 重载自动撤（`进攻修正` 是 `@基础/距离.lua` 定义的属性：`距离 = 座位距离 + 我的进攻修正 + 对方的防御修正`，最小 1）。
- **【铁骑】的「指定目标后」订「来源」那一段**：内核在 `UseCard:settle` 里**逐目标**发三段（全局 / 来源 / 目标）—— 马超是用【杀】的人，所以订 `'卡牌-来源-指定目标后'`，回调收 `(useCard, target)`。
- **「该角色不能使用【闪】响应此【杀】」的做法 = 往这次使用的选项里记一笔**：`useCard:addUseOptions { unrespondable = target }`；**由询问层判**（2026-10-08 改）：【杀】的 `'生效'` 把「这次响应冲哪次使用」**显式传进去**（`game:askPlayCard(目标, '杀', { name = '闪' }, { responseTo = useCard })`），内核在发询问前查 `UseCard:isResponseBanned(被问者)` ⇒ 名单里的目标**连问都不问**、直接挨伤害。
  - 这是**「响应限制」的通用做法**（不是【铁骑】专用）：任何「该角色不能响应此牌」的技能都往 `UseOptions.unrespondable` 里记。写法有四种：**一个角色 / 一串角色 / `true`（= 这次的全部目标）/ 谓词（按这次的目标筛）** —— 内部统一归一成名单，可累加。
  - **哪些询问会认它、得显式传 `responseTo`**：打出族四张（【杀】/【万箭齐发】/【南蛮入侵】/【决斗】）都传了自己那次使用；【无懈可击】那个窗口没接 —— 它要判的是「**这张牌**不能被无懈可击」（判据在**牌**上），与「**谁**不能响应」不是一条口径（「这张牌不能无懈」另走 `UseOptions.unnullifiable`，见 §9.10，2026-10-09）。
- 判红 = `judge.card?.color == '红'`（与【洛神】的「黑」对称）。

- 时机订**使用者**那份 **`'卡牌-来源-结算前'`**（全局那份叫 `'卡牌-结算前'` —— 对当事人再发一份带方向词；只收自己的用牌、不用再判 `user`）—— 它对应官方的「使用结算开始时」。
- **【奇才】用「这次使用的选项」**：由**使用者**在收集时加上 `ignoreDistance` ⇒ 射程判断（`Player:isInRange` 直接算在）⇒ 带距离的锦囊（【顺手牵羊】）不受限；**只管锦囊**（【杀】照旧受射程限制）。
- `ignoreDistance` 的消费者要接的是**判射程的地方**：内容侧写 `user:isInRange(对方, nil, plan.useOptions)`（**射程给 `nil` = 自己的攻击范围**；要显式射程就写数字，如【顺手牵羊】的 `isInRange(对方, 1, plan.useOptions)`）——【杀】与【顺手牵羊】的 `targets` filter 都是这么写的，裸写 `user:distance(对方)` 就认不到它。

### 9.22 孙权【制衡】【救援】（已落地，2026-10-08 / 09）

```lua

    : cards { zone = rule.ownZones, max = 1000 }
    : on('使用', function (cast)
        game:moveCard(cast.use.cards, '弃牌')
```

```lua
Buff '裸衣'
```

**【遗计】**（同一个文件）：

```lua
-- 【遗计】当你受到 1 点伤害后，你可以观看牌堆顶的两张牌并任意分配它们。
Skill '遗计'
    : auto(true)
    : event('伤害-目标-生效后', function (skill, damage)
        -- 「1 点伤害」是粒度 ⇒ 受 N 点就发动 N 轮
        for _ = 1, damage.amount do
            skill:tryCast(function (cast)
                -- 观看 = 抽到自己这轮的临时区（分完 / 取消后不会剩牌）
                local shown = cast:getTempZone()
                game:drawCards(skill.owner, 2, shown)
                for _ = 1, 1000 do
                    if shown:count() == 0 then
                        break
                    end
                    local ask = game:askCardWithTarget(skill.owner, '遗计', {
                        card = {
                            zone = shown,
                            min  = 1,
                            max  = shown:count(),
                        },
                    })
                    if #ask.cards == 0 then
                        -- 取消 = 剩下的全归自己
                        game:moveCard(shown:list(), skill.owner:getZone('手牌'))
                        break
                    end
                    game:moveCard(ask.cards, assert(ask.target):getZone('手牌'))
                end
            end)
        end
    end)
```

- **「观看」= 抽到自己这轮的临时区**（`cast:getTempZone()`，用户 2026-10-09 定的形状）—— 牌一旦离堆必须有去处，而本技能保证「要么分出去、要么取消时归自己」⇒ **整段不会剩牌**，也就不需要「置回牌堆顶 / 底」那套能力。
- **反复询问用现成的 `askCardWithTarget`**（**不必新开询问**）：条件分**两半具名**（2026-10-09 收成 `card` / `target`）—— **牌那半**：`zone` 传**区对象** ⇒ 候选就是临时区里的牌，`min = 1`、**`max = 当前剩余张数`**（一次答复可以给同一个人 1~N 张）；**角色那半整条不写** ⇒ 默认正好一个目标；`cancelable` 默认允许取消（`AskCard.Condition` 的字段都写在 `card` 那半）⇒ **取消 = 剩下的全归自己**、这一轮结束；循环写成 **`for _ = 1, 1000 do`（带上限，不用 `while`** —— 用户 2026-10-09 定，见 `moe-kill-dev` 的 `code-style.md` §14；【濒死】求桃那圈也照此改了）。
- **分配权在被问者（郭嘉）手上**，不是让被给的人挑（与【五谷丰登】的「逐目标自选一张」相反）—— `askCardWithTarget` 问的是发起方。
- **「观看」的可见性：把这块临时区只指给郭嘉看**（2026-10-09 定）：临时区默认全桌可见（它也是「处理区」，亮牌 / 判定都靠这一点），而官方是「**你**观看」⇒ `shown:setVisible(skill.owner)`（**`setVisible` 的名单语义**：给一名或一批角色 = 只有他们看得见；`true` = 所有人、`false` = 无人）⇒ 协议层遮蔽照 `isVisibleTo` 读即可。**这是第一个私有处理区**。**牌级可见性（展示 / 覆盖）还没有** —— 官方「展示」（所有人可见）与「观看」（只有你）是两个动作，等【反间】或协议层那批一次定透。

### 9.25 张辽【突袭】（已落地，2026-10-09；顺带产出两条写法）

```lua
Hero '张辽'
    : kingdom '魏'
    : sex '男'
    : hp(4)
    : skills { '突袭' }

-- 【突袭】摸牌阶段，你可以改为获得至多两名其他角色的各一张手牌。
Skill '突袭'
    : event('阶段-开始', function (skill, phase)
        if phase.name ~= '摸牌' then
            return
        end
        local victims = table.filter(game.desk.alivePlayers, function (player)
            return player ~= skill.owner and player:getZone('手牌'):count() > 0
        end)
        if #victims == 0 then
            return
        end
        -- 不问「发不发动」：选几个就是几个，一个都不选 = 不发动（照常摸牌）
        local ask = game:askPlayer(skill.owner, '突袭', { player = victims, min = 0, max = 2 })
        if #ask.players == 0 then
            return
        end
        skill:cast(function ()
            -- 「改为」= 本阶段不摸牌（摸牌数的下界是 0，减一个大数就是清零）
            phase:bindGC(skill.owner:addAttr('摸牌数', -1000))
            for _, victim in ipairs(ask.players) do
                -- 盲取：不看牌面，从他的手牌里随机拿一张
                local hand = victim:getZone('手牌')
                local card = hand:list()[game.random:nextInt(1, hand:count())]
                game:moveCard(card, skill.owner:getZone('手牌'))
            end
        end)
    end)
```

- 底本：「摸牌阶段，你可以**改为**获得**至多两名**其他角色的**各一张手牌**。」
- **「改为」= 把本阶段摸牌数改掉**（用户 2026-10-09 定：**`addAttr('摸牌数', -1000)`**，照【诸葛连弩】/【咆哮】里「`1000` = 事实上不限」的同一个惯例 —— 这里 `1000` = 事实上归零，属性下界就是 0）—— 修正挂在**本阶段**上（`phase:bindGC`），阶段一离开自动撤；摸牌业务在 `'阶段-生效'` 里读这个属性 ⇒ 在 `'阶段-开始'` 改它就来得及（与【裸衣】同一个口子）。
- **一次选 0~2 名用 `askPlayer` 的 `min` / `max`**（2026-10-09 给 `AskPlayer` 补的能力，形状照 `askCard` 的张数区间）：`max = 2` = 至多两位，`min = 0` = **可以一个都不选** —— 而「一个都不选」在这里就**等于不发动**（见下条）；答复读 **`ask.players`**（恒列表）。**条件里的候选叫 `player`**（一名 / 一批 / `true` = 不限 / 谓词 `fun(player: Player): boolean`，2026-10-09 从 `players` 改名并扩成四态）—— 候选名单 = 其他存活角色里**手牌非空**的（自己不能拿、空手牌的无意义），**候选为空就不问也不发动**（免得白弃摸牌）。
- **盲取一张**：手牌区是**无序区**、也不能把牌面暴露给玩家 ⇒ 从 `hand:list()` 里用**局随机源** `game.random:nextInt(1, hand:count())` 随机挑一张（可复现靠局随机源）；每个人只拿一张（同一名不会被选两次 —— `min` / `max` 那条「不重复」保证）。
- **不问「发不发动」，选 0 名就是不发动**（用户 2026-10-09 定）：一次询问就把「要不要用这个技能」表达了（「至多两名」本身就允许一个都不选）⇒ **不调 `tryCast`**、询问直接放在时机里，**拿到人再 `skill:cast(…)`** —— 这样「不发动」连一次空 `cast` 都不会起（照「拒绝 ⇒ 不起 `cast`」的既有口径；【青龙偃月刀】是同一形状的首例）。**⚠️ 不这么做就有一个陷阱**：`tryCast` 会先问一句 `askChoice`（`reason` 与技能同名）—— 测试脚本若只按 `reason` 匹配，会把「选人的名单」回给那个确认问题 ⇒ 被拒收 ⇒ 技能根本不发动（踩过）。
- 用例：`rule.hero-skill` 突袭 4 条（发动 ⇒ 不摸牌 + 拿两张 / 不表态（nil）⇒ 照常摸两张 / **一个都不选（空表）⇒ 也不发动、照常摸两张** / 别人都没手牌就不问且照常摸）。

### 9.30 大乔【流离】（已落地，2026-10-09；官方「转移」的落地 + 换目标）

```lua
Hero '大乔'
    : kingdom '吴'
    : sex '女'
    : hp(3)
    : skills { '流离', '国色' }

-- 【流离】当你成为【杀】的目标时，你可以弃置一张牌并选择你攻击范围内为此【杀】合法目标（无距离限制）的一名角色：若如此做，该角色代替你成为此【杀】的目标。
Skill '流离'
    : event('卡牌-目标-指定目标后', function (skill, useCard, target)
        local owner = skill.owner
        if target ~= owner or useCard.card.name ~= '杀' then
            return
        end
        -- 「此【杀】的合法目标」不判距离（底本那句「无距离限制」）；「攻击范围内」是另一条判据、要判
        ---@type Game.UseOptions
        local options = table.copy(useCard.useOptions or {})
        options.ignoreDistance = true
        local candidates = table.filter(game:getLegalTargets(useCard.user, useCard.card, options), function (player)
            return player ~= owner
               and owner:isInRange(player)
        end)
        if #candidates == 0 then
            return
        end
        local ask = game:askCardWithTarget(owner, '流离', {
            card = {
                zone = rule.ownZones,
                min  = 1,
                max  = 1,
            },
            target = {
                player = candidates,
            },
        })
        -- 没答 = 不发动（弃牌与转移是一件事的两半，不分开问）
        if not ask.target then
            return
        end
        skill:cast(function ()
            game:moveCard(ask.cards, '弃牌')
            -- 官方「转移」：取消此目标，再生成一个新目标加入目标列表
            useCard:removeTarget(owner)
            useCard:addTarget(ask.target)
        end)
    end)

-- 【国色】你可以将一张方块牌当【乐不思蜀】使用。
Skill '国色'
    : viewAs('乐不思蜀', {
        condition = {
            suit = '方块',
            zone = rule.ownZones,
        },
    })
```

- **官方「转移」的落地 = `UseCard:removeTarget(谁)` + `UseCard:addTarget(谁)`**（2026-10-09 当天晚些从 `replaceTarget` 收成这两个 —— 用户定「叫 removeTarget 吧，和 Lua 的习惯一致」）。规则集 Ch2/S5「转移」条写得很清楚：「**取消此目标**并**生成**一个与角色 B 具有对应关系的**新的目标**并将此目标**加入此牌的目标列表**，然后**将所有还未生成过『成为目标时』的目标重新排序**」。⇒ ① 是**取消 + 追加**（不是原地换）；② 新目标**会生成「成为目标时」** —— 它被追加到序列末尾、**由后续生成照发**三份（全局 → 使用者 → 新目标），链式因此成立（流离触发流离）；③ 「重新排序」= 追加之后把「还没轮到的那批」按行动顺序重排（`desk:sortPlayers`）⇒ 追加的排到它该在的位置。**两个方法只在「成为目标时」的生成期间有效**。

- **转给「本次【杀】已有的目标」合法，那人会挨两刀**（官方口径确认，2026-10-09）：候选**不排除** `useCard.targets` 里的人 —— **取消自己那条、再追加一条同一个角色**后，最终列表里就是两条，内核按「**每条目标各结算一次**」处理（生成轮走 `desk:sortPlayers`、生效轮走 `desk:actionOrder`，两者都按名单里出现几次给几次）。**「不能重复指定同一个目标」只约束「答复 / 使用时的目标列表」**（拦客户端答错），不约束内核在结算期用「取消 + 追加」造出的重复。
- **【国色】已落地（2026-10-09，变更 `add-daqiao-guose`）**：`: viewAs('乐不思蜀', { condition = { suit = '方块', zone = rule.ownZones } })` —— 素材取**手牌 + 装备子区**（照【武圣】【奇袭】【急救】的 `rule.ownZones`）。**必须走虚拟牌**：虚拟牌过 `canUse` 时会跳过「声明的牌区」那条（【乐不思蜀】自己声明 `zone '手牌'`），普通牌会被它挡掉 ⇒ 装备区的方块牌才当得成。**判定区那一步**（官方 `Ch2/S5:76`「若此牌为延时锦囊牌，系统会将此牌**对应的实体牌**置入 B 的判定区」）由延时锦囊模板统一做：置入判定区**之后**给这张牌挂上身份 ⇒ 判定期跑的是【乐不思蜀】的定义、离开判定区自动撤销 —— 见 §9.31。
- 用例：`core.effect.play` +2（换目标 ⇒ 生效跑新目标、旧目标不生效 / 新目标收到补发的三份）；`core.can-use` +3（全量合法目标不受这次目标收窄影响且不问「能否使用」/ 按调用方给的选项算 / 牌没声明目标条件给空表）；`rule/hero-skill` +4（转移并弃一张 / **能触发流离**（两个大乔）/ 不答不发动 / 攻击范围内没合法目标时连问都不问）。**反向验证**：拆掉补发 ⇒ 红 2（补发那条 + 链式那条）；`getLegalTargets` 丢掉调用方的选项 ⇒ 红 4。

### 9.31 「转化」（虚拟牌与实体牌，2026-10-09 查底本）

- **两层概念**（`Chapter2/Section1.md`）：**实体牌** = 「放置在**某一个区域**里的实际存在的游戏牌」；**虚拟牌** = 「角色**使用和打出的对象**」—— 「角色进行使用或打出结算，其实是对**牌的信息**而不是一张实体牌进行结算，即这组信息（而非牌）才是结算的真正对象」「多数情况下使用或打出牌是需要将若干张实体牌**置入处理区**的，可以理解为类似于是使用或打出此虚拟牌的**消耗**」；还有「`在游戏中出现的每一张虚拟牌都是相互独立的，即不存在两张相同的虚拟牌`」。
- **转化**（`Chapter2/Section5.md`）：「在使用/打出一张牌的流程中发动……或通过发动【国色1】、【默识】、【逆乱】、【慎断】或【伺盗】来使用/打出此牌，均称为使用/打出**转化的牌**」；判据 = 「此牌对应的实体牌的数量为 1 且此牌与此牌对应的实体牌的**牌名、属性、花色、颜色、点数不一一对应**；或此牌对应的实体牌的数量大于 1」。
- **官方实例：只改被点名的那几个字段**（`Chapter2/Section8.md`）：【武神1】——「关羽受到【武神1】的影响能弃置一张**红桃【麒麟弓】**进行响应，因为**此牌的牌名视为【杀】**」⇒ 那张牌的**花色**（红桃）与它是什么装备都照旧；【红颜】改的是**花色**（`Ch2/S1` / `S8`）⇒ **不同字段各自独立改**。
- **同字段冲突官方无明文**：`Ch2/S5` 的转化节只给判据；`Ch1/S1` 的冲突原则（技能描述＞牌面＞规则、**否定优先**、同机时的发动优先级）都不覆盖「两个转化改同一字段」⇒ **本项目自定：后挂的覆盖先挂的**。
- **作用域：不含判定区**（`Ch2/S5`）—— 同节把「`<角色>的<……>牌`」定义成「即其**手牌区和装备区**里的……牌」，并特意举例：「小乔的黑桃**手牌**、**装备区**里的黑桃牌和黑桃**判定牌**的花色均会受到【红颜】的影响视为红桃，但小乔**判定区**里的黑桃牌的花色不会受到影响」。⇒ 「**你的牌视为 X**」这类改不到判定区里的牌。
  - 顺带一句：这条也说明「**判定牌**」（判定翻出来的那张）与「**判定区里的牌**」是两个东西，别混。
- **转化不叠成链**：底本里所有「视为」的作用对象都是**区域里的实体牌**（【武神1】「你的红桃牌」、【红颜】「你的黑桃牌」、【国色1】「一张方块牌」），找不到「以虚拟牌为素材再转化」的例 ⇒ 作用对象恒为实体牌（与「实体牌 = 放置在区域里的牌」自洽）。实现上虚拟牌也会记一份转化，那不是「链」—— 是**同一次转化在两层都留了记录**（见下面「落地」）。
- **两处「对应的实体牌」的措辞**（判定区里躺的是实体牌、它对应着那张虚拟牌）：`Ch2/S5:76`（转移规则末句）「……最后若此牌为延时锦囊牌，系统会将此牌**对应的实体牌**置入 B 的判定区」；`Ch2/S6:13`（【闪电】例）「B 于其额外回合的判定阶段**开始【闪电】的使用流程**进行判定……系统将此【闪电】**对应的实体牌**置入 B 的下家 C 的判定区」；`Ch2/S8:40`（【巧变3】例）「能将 A 的判定区里的【兵粮寸断】**对应的实体牌**置入……B 的判定区」。
- **实现：两条寿命别混**（2026-10-09 定；官方 `Ch2/S1:80` 的【奸雄】例子把这条钉死了）
  - **这次使用/打出的信息**（结算期读值）→ 属于那张**虚拟牌**（`UseCard.card`）、寿命 = **这一次使用**：例子里「小乔使用的黑桃【杀】（**此【杀】的花色受到【红颜】的影响视为红桃**）」，曹操中途用【奸雄】**拿走那张实体牌**，轮到于禁结算时**此【杀】的花色仍是红桃**。
  - **实体牌 ↔ 虚拟牌的对应** → 记在那张**实体牌**上、寿命 = **它在某个区域里的这段时间**：【国色】/延时锦囊「判定区里那张实体牌代表【乐不思蜀】」。
- **落地**：`card:addModifier { name?, suit?, point? }`（挂 / 撤与读法见 `moe-kill-dev` 的 `architecture.md`；**虚拟牌上调用时自己也挂、另给每张素材各挂一份**）+ **`card:withZone(撤销函数, 判据?)`**（牌离开它现在所在的那个区就撤销；**判据 `keep(新位置)` 返回真就算「没离开」**；虚拟牌上调用 = 转给素材）。**延时锦囊模板**（`@基础/卡牌/锦囊牌.lua`）在**置入判定区之后**写 `card:withZone(card:addModifier { name = card.name }, function (zone) return zone?.name == '判定' end)`（判据直接比区名 —— `Zone` 记着自己的名字） ⇒ 【国色】这类转化的牌到判定期仍代表那张锦囊；**进别的区才撤**（判完送弃牌 / 被拆 / 被顺），挪到另一个判定区则身份跟着走（【巧变3】那类）。**顺序不能反**：`withZone` 是「离开**它当时所在的**那个区」，先挂后搬的话 `moveCard` 那一下就把撤销触发了。
- **已知缺口**（别当成已解决）：**普通使用不造虚拟牌**（`useCard.card` 就是那张实体牌）⇒ 第一类「这次使用的信息」目前靠现读实体牌，实体牌进处理区 / 被人拿走之后就不一定读得到当时那份信息。真要做【红颜】那类效果，得让「每次使用都有一张信息快照」—— 另开变更。
- **曾以为的边界（已解决）**：转化后的【闪电】在判定区之间转移曾经会掉身份 —— 白名单第一条（**进的还是判定区就留**）落地后不会了，用例「挪到别人的判定区，身份跟着走」钉着。（底层还顺手修了一处：`Zone:takeIn` 中间不再插一次 `card:unbindZone()`，否则一次搬牌会看起来像「先变无主、再进新区」两次离区。）

### 9.32 吕布【无双】（已落地，2026-10-09；「一次响应要两张牌」）

```lua
Hero '吕布'
    : kingdom '群'
    : sex '男'
    : hp(4)
    : skills { '无双' }

-- 【无双】锁定技，当你使用【杀】指定目标后，其使用【闪】抵消此【杀】的方式改为需连续使用两张【闪】；
--         当你使用【决斗】指定目标后，或当你成为【决斗】的目标后，你令其打出【杀】响应此【决斗】的方式改为需连续打出两张【杀】。

--- 让他「在这次使用里响应时」要连出两张：订阅挂到这次使用上（活到这次使用结束 ⇒ 中途失去技能也不中断）
local function requireTwo(useCard, other, name)
    useCard:bindGC(game:on('卡牌-答复后', function (ask)
        if ask.responseOptions?.responseTo ~= useCard or ask.to ~= other then
            return
        end
        -- 追一张：拿不出来就吊销这次响应
        if not game:askPlayCard(other, ask.reason, { name = name }).card then
            ask:cancel('无双')
        end
    end))
end

Skill '无双'
    : tags '锁定技'
    : event('卡牌-来源-指定目标后', function (skill, useCard, target)   -- 我用【杀】/【决斗】⇒ 对方要两张
        local name = useCard.card.name
        if name == '杀' then requireTwo(useCard, target, '闪')
        elseif name == '决斗' then requireTwo(useCard, target, '杀') end
    end)
    : event('卡牌-目标-指定目标后', function (skill, useCard, target)   -- 我成为【决斗】目标 ⇒ 使用者要两张
        if useCard.card.name == '决斗' then requireTwo(useCard, useCard.user, '杀') end
    end)
```

- **官方依据**（`武将牌/标准包.md:121` + 规则集）：
  - `Ch2/S5:99`（张角例）：两张【闪】是**两次独立的「使用」**（第一张的结算跑完、第二张响应时能**再次**发动【雷击】）⇒ 实现必须是「**再追一次询问**」，不能是「一次询问要两张」；「第一张给出、第二张拿不出」时第一张**照常消耗**（我们：那张照常进弃牌堆，伤害照常结算）。
  - `Ch1/S2:46`（神吕布例）：负担在**对方**身上（【无双2】没发动时 B 只需一张）⇒ **吕布自己始终只出一张**（用例钉着）。
  - `Ch1/S2:139`（蔡文姬例）：要求在「指定目标后」写下之后**不因中途失去技能消失** ⇒ 见下面那条宿主口径。
  - 对照 `Ch2/S5`「没有『依次』这个关键词的操作均指 X 张……一次性同时操作」（【贯石斧】弃两张）——【无双】写「连**续**」⇒ 逐个来。
- **落地形状**（用户 2026-10-09 提的「`cardUse` 时 tryCast、`bindGC` 到 `cardUse` 上」的简化版）：**订阅挂在这次使用上** + 在「答复后」**吊销**那次响应：
  - **时机选 `'卡牌-答复后'`**（不是 `'效果-来源-被响应'`）：`ask:cancel` 会当场停住这次询问的结算（`Task:cancel` 在自己就是执行体时让出、不再唤醒）⇒ 吊销发生在「被响应」那两段时机**之前** ⇒【青龙偃月刀】【贯石斧】不会被误触发（两张出齐才算被响应掉）。
  - **追的那张不带 `responseTo`**：它不是一次**新的响应** ⇒ 订阅的过滤条件天然排除它（不递归）；牌照常进临时区、照常记打出账、【八卦阵】/【龙胆】/【丈八蛇矛】照样能顶上。
  - **误触发过的写法**：把吊销放在 `'效果-来源-被响应'` 里 —— 那时【青龙偃月刀】【贯石斧】（同订这个时机）已经排上队了，订阅顺序决定谁先跑。
- **「挂谁 = 活多久」**（本批定下来的通用口径，详见 `moe-kill-dev` 的 `architecture.md`）：可叠加操作挂到哪个对象上就活到那个对象被收掉；**写「这次使用怎么结算」就挂 `useCard`**（本阶段挂 `phase`、本回合挂 `turn`、一段状态挂 `buff`）。**「失去技能不中断」的判据是别挂 `host`**（`skill:disablePassive()` 会把被动容器整个 `Delete`）。**内核不给这类规则开专属字段**（曾考虑 `useCard:setResponseCount` 之类 —— 用户否：每条新规则都开一个口子不可持续）。
- **顺带修的一处内核**：一次**响应**的答复若是**空表**（玩家主动「不出」），以前会被当成「答复成立」⇒【杀】被白抵消；现在 `AskPlayCard` 在定结果之前作废它（`beforeResolve`），于是 `.success` 假 ⇒ 照常造成伤害。
- 用例：`rule/hero-skill` 8 条（【杀】只出一张 / 出齐两张且「被响应」只发一次 / 一张都没有 ⇒ 不插手 / 空答复不追 / 【决斗】两种方向 / 吕布自己只要一张 / 中途失去技能要求照旧）。
