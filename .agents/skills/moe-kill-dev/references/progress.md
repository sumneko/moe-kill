## 2 下一步：出牌阶段的使用限制（用户已选，**尚未开工**）

**为什么**：`package/@基础/回合.lua` 的 `playPhase` 把「要哪张牌」整个交给应答方，**用牌没有任何"能不能用"的校验**（只有牌自己的 `'获取目标'` 管"能选谁"）。

- 现在只要手上有【杀】就能无限杀（官方是**每个出牌阶段限一次**）。
- 应答方给一张**用不了的牌**（或给了牌没给目标）时：`UseCard:settle()` 的校验（牌不在手 / 没牌名 / 没定义 / `'获取目标'` 返回空 / 目标是空表 / 目标不合法）**全走 `error`** ⇒ 收进 `.err`、**不抛给调用方**；而失败发生在 `zone:take()` **之前**、牌没动 ⇒ 手牌没变 ⇒ 应答方给同样的答复就一直转下去。
  - **现在用有界循环兜住了**（2026-09-22 用户定）：`playPhase` 改成 `for _ = 1, MAX_PLAY_COUNT do`（**1000**）—— 跑满就结束这个阶段。**上限的理由不是上面那个异常场景，而是规则本身允许"无限出牌"**（例：某个技能让玩家可以无限使用【无懈可击】）⇒ 阶段需要一个终止条件。用例：`rule.turn` 拿"一直答同一张牌"构造"结束不了"，断言回合照常跑完、那张牌一次也没出去。
  - **没解决的**：应答方还是会被再问 1000 次；而且"用不了的牌出现在可选项里"本身就是错的（前端/AI 会选到）—— "用不了的牌"是这一批要修的**校验缺失**，与上面那个上限是两件事。

**要做的东西**

1. **使用前的校验点**：内核给一个可否决的使用前时机（`ctx:reject(原因)`），或退一步只在内容侧做 —— **待拍板**（见下）。
2. **`game:canUse(user, card)`**：把 `UseCard` 的校验段抽出来，可独立跑、不结算、**不进记牌器**。
   - 不能靠"试一次 `useCard`"代替：每次 `Effect:apply()` 都会 `game:addEffect`，试探会把记牌器灌满垃圾。
3. **出牌阶段的候选过滤**：`playPhase` 询问前先筛掉用不了的牌（这是死循环的正解）。
4. **「每出牌阶段每张牌名限一次」**：官方粒度是**牌名**（普通杀 / 火杀 / 雷杀共用计数），且**只有【杀】受限**、别的牌不限 ⇒ 得是一张**上限表**（默认 `{ 杀 = 1 }`），作用域 = 每个出牌阶段；放宽（诸葛连弩 / 咆哮）是**改数据**，不是改流程。

**待用户拍板的三条口径**

| # | 问题 | 我倾向 |
| --- | --- | --- |
| ① | 限制落在哪层：内容侧只做（内核零改动，但绕过回合流程直接 `useCard` 就不受限）／ 内核给"可否决的使用前校验点" | 内核给校验点（后面锦囊 / 装备 / 技能都要用） |
| ② | 「校验不过」怎么表达：现在全用 `error`，与 2026-09-20 定的「`error` 只表示报错」冲突 | 给 `Effect` 加「不成立」状态，照搬 `CANCELED` 那套标记（不记 `.err`、不进错误日志） |
| ③ | 「每阶段使用上限」写成数据（规则数值 / 玩家标签）还是先硬写在 `@基础` | 数据表（将来放宽类技能靠它） |

## 3 用户已表态、还没做的方向

- **询问家族**：将来加 `timeout` 与 `askSkill`，**timeout 与答复做 race**。`Ask`（通用决策询问，答复是 `any`）现在只剩弃牌阶段在用，用户认为它"意义不明" —— 等那批到位再谈去留（**不要擅自删**）。
- **回合时限**：真游戏靠它兜住"玩家不答"与"误选"，还没实现。用户给的形状：

  ```lua
  local countDown <close> = player:countDown(30)
  while countDown:leftTime() > 0 do
      local ask = ...
      if ask.card then
          local useCard = game:useCard()
          if not useCard.err then countDown:reset() end
      end
  end
  ```

  并指出**忙等解决不了问题** —— 得在节点上让出（`moe.await.sleep(...)`），否则事件循环根本不跑、定时器永不触发（连测试的 5 秒看门狗都抓不住）。
  归属：**内核**（时间 + 让出能力），`30` 这个数字是**规则数值**。
- **死亡奖惩**（官方时序「死亡 → 奖惩 → 胜负」里唯一没做的；落点 = `'玩家-死亡'` 上、注册在胜负判定**之前**）。
- **判定机制**（`game:judge`：翻牌 → 改判时机 → 结果入弃牌）—— 「抽牌 / 弃置 / 获得 / 判定」四个常用动作里**唯一没做**的。
- **即时锦囊 + 无懈可击**（缺的是"无懈的嵌套询问窗口"）、**装备与距离修正**、**武将技能**（前置是武将系统）。
- **会话 / 协议**（前端接线）—— 按用户节奏放最后。
